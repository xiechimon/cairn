# Subscription quota sources — 2026-11-28

Question: what can Cairn show next to each already-connected subscription, without another login or a model request? Measured means a command, endpoint, checked-in live capture, or first-party source was inspected; Inferred is a recommendation derived from that evidence. The examples below describe structures only, not the owner's balance.

| Subscription | Evidence | Decision |
|---|---|---|
| Claude | Measured: Claude Code documents [`/usage`](https://code.claude.com/docs/en/costs#using-the-%2Fusage-command); Cairn already reads the compatible OAuth account usage contract and SDK rate-limit events in [verification](../../apps/server/src/services/claude-subscription-verification.ts) and [rate-limit ingestion](../../apps/server/src/services/claude-rate-limit.ts). [Anthropic API limits](https://platform.claude.com/docs/en/api/rate-limits) are separate. | Inferred: keep account windows; do not treat absent windows as fully available. |
| Antigravity | Measured: [Google plans](https://antigravity.google/docs/plans) describe both refresh cadences; the existing [runner reader](../../apps/daemon/src/backend/antigravity-usage.ts) consumes `/usage` JSON groups with fractional remaining and reset times, using the selected account's login. See [CLI contract and auth boundary](antigravity-integration-2026-11-24.md). | Inferred: retain the runner source and its separate pools; don't add them together. |
| ChatGPT | Measured: [App Server](https://developers.openai.com/codex/app-server) documents `account/rateLimits/read`; using the already authenticated Codex 0.166.0 locally returned one 10080-minute primary window and a null secondary. The same CLI's [backend source](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/backend-client/src/client/rate_limit_resets.rs) calls `GET /wham/usage`; the existing local CLI login returned HTTP 200, `rate_limit.primary_window` with numeric `used_percent`, `limit_window_seconds`, `reset_after_seconds` and `reset_at`, and `secondary_window: null`. [Typed window](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/codex-backend-openapi-models/src/models/rate_limit_window_snapshot.rs). [Codex pricing](https://developers.openai.com/codex/pricing) confirms limits can vary by plan; [API limits](https://platform.openai.com/docs/guides/rate-limits) meter a different account surface. | Inferred: read this endpoint from Cairn's server-side Coordinator runtime, which owns the matching existing ChatGPT device login; never substitute the machine's unrelated default Codex login. Use reported duration, not primary/secondary position, for the label. |
| Devin | Measured: installed `devin` 3000.15.14 help has no account usage command; the [CLI reference](https://docs.devin.ai/cli/reference/commands.md) says `/usage` reports estimated **session** credit/ACU. [Desktop plan docs](https://docs.devin.ai/desktop/accounts/quota.md) confirm daily/weekly budgets and the [usage instructions](https://docs.devin.ai/desktop/accounts/usage.md) point to an authenticated web Settings page. The installed binary references a `GetUserStatus` RPC; a JSON probe to the binary's Codeium host using the existing CLI login returned HTTP 400, not a usable quota payload. [CodexBar’s Windsurf investigation](https://github.com/steipete/CodexBar/blob/main/docs/windsurf.md#authentication-flow-automatic-mode) identifies separate browser-session inputs for `GetPlanStatus`, not a CLI-token contract. No reusable per-account quota response was verified through the local runner login. | Inferred: report observed Cairn activity, not estimated credits or the desktop plan as remaining balance. This does not claim the web account has no balance; a same-login read still needs evidence before adoption. |
| Doubao | Measured: the installed CLI help has login status and model list but no quota command; the [logged-in 2.38.4 ACP capture](doubao-cli-2026-11-27.md#8-live-spike-on-macbook-2026-11-28) shows `stopReason` without usage, and no `usage_update`. [Ark Coding Plan](https://docs.volcengine.com/docs/82379/1925114) belongs to a different account and credential. Doubao runtime is already on main. | Inferred: report observed Cairn activity; don't map Ark limits to the QR account. |
| Other subscriptions | Measured: ACP [usage](https://agentclientprotocol.com/announcements/session-usage-stabilized) defines session/context usage and optional cost, not remaining account quota. | Inferred: route future subscription editors through the same presentation and use the same activity fallback when their runs can be attributed. |

Keep two meanings separate: the vendor knows what is left and when its allowance resets; Cairn knows the work recorded against a connection and when that work was limited. A planned reset is displayed only when a real signal provided its time. Local time windows are rolling lookbacks, not an estimate of the vendor's plan. No prompts, new credentials, or payment are needed to open Settings.
