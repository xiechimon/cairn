# Test integrity gates prior art (2026-11-26)

| Source | How it judges test quality | Trade-off for Cairn | Link |
|---|---|---|---|
| Stryker Mutator | Mutates production code and expects tests to fail; a passing test suite means the tests did not detect the behavior change. | Full mutation testing is too slow for the <30 s `check` gate, but the same inversion principle is already used by `regression-inversion-gate.mjs`. | https://stryker-mutator.io/docs/ (measured first-hand) |
| PIT mutation testing | Calls mutation testing the gold standard because line coverage does not prove assertions detect faults; explicitly names tests without assertions as the extreme failure. | Confirms that assertion presence/strength is a meaningful static signal, but does not provide a fast diff gate by itself. | https://pitest.org/ (measured first-hand) |
| Playwright assertions | `expect` supports behavior matchers such as `toHaveText` and generic matchers such as `toEqual`; visibility matchers only establish visibility/attachment, not the behavior value being correct. | A visibility assertion is legitimate as one step in a journey, but replacing a value/behavior assertion with visibility weakens the oracle. | https://playwright.dev/docs/test-assertions (measured first-hand) |
| Cairn-specific gate (this change) | Statically scans each commit in the PR range for deleted test files, net removed assertion lines, strong-assertion-to-visibility/existence weakening, and a regression-test ledger whose entries must remain present and enabled. | Fast and mechanical; it cannot judge semantic equivalence, so intentional removal or weakening needs an explicit commit-message reason trailer. | this repository (inferred) |

Recommendation: keep mutation-style runtime inversion for `fix*` commits and add the cheaper static integrity gate for every commit. The two mechanisms cover different holes: inversion proves a new regression test fails before the fix; integrity prevents later deletion, skipping or oracle weakening (inferred). Relevant code: `scripts/test-integrity-gate.mjs`, `scripts/regression-test-ledger.mjs`, `scripts/prepush.mjs` and `.github/workflows/ci.yml` through the existing `check-core` prepush step.
