# How settings pages explain a section (2026-11-20)

Question: for a group of settings, where does "what this group is for" live: a subtitle, a tooltip/info icon, a "Learn more" link, a footer note, or nothing? And how does that differ from a single row's hint? Trigger: Cairn's "Frequent models" section carries a muted one-sentence paragraph under its title; the owner finds it noisy and suggested a tooltip.

Labels: Measured = read first-hand this session (short quote), Inferred = derived from Measured, Guess = not verified. Apple HIG/SwiftUI text was read from developer.apple.com's JSON endpoints (the rendered pages are JS-only).

## Pattern that fits Cairn

- Verdict across sources: nobody read puts a section's purpose in a tooltip. Where a section has an explanation it is visible text (Apple footer, Stripe group `description`, Linear docs prose); where it has none, the title stands alone (t3code, Amp) and the detail lives in row hints. The rows are what t3code and Amp keep (Inferred from the two captures).
- Tooltip rules (Apple, Primer, NN/g, Geist) all say the same: a tooltip is for a short label of an interactive control, and "essential information" must be visible. WCAG 1.4.13 adds a cost: a hover/focus card must be dismissible, hoverable and persistent. A section info icon would need that work and fails on touch.
- The Frequent models sentence is not optional trivia (Inferred): it states the default ("Tasks use the Coordinator's model by default") and the behaviour ("the Coordinator picks one per task by difficulty"). Without it a user sees an empty list and no reason to fill it. That is the "essential" case Primer and NN/g exclude from tooltips.
- The noise is a density problem, not a placement problem (Inferred). The paragraph is two clauses and sits above the content; Apple puts the same kind of text below the group as a footer, and t3code/Amp shorten or drop it.
- Row hints stay: t3code and Amp both show muted one-line hints per row, and Primer's caption is per field.

## Recommendation

(a) Frequent models specifically (decision, reversible):
1. Do not move it into a tooltip.
2. Keep the sentence visible but shorter and one idea: "Add models for the Coordinator to choose from by task difficulty." The default ("Coordinator's model by default") belongs on the empty state or the row of the default model, where it is true state rather than prose. Open question for the owner: if he still finds even one line noisy, the fallback that matches Apple is a footer under the list, not a tooltip. Guess that a footer reads quieter; it needs a before/after screenshot.
3. Keep the "Add" action as the section's single control; do not add an info icon next to the title.

(b) General rule: yes, but narrow. Tooltips are not the wrong tool everywhere; they are wrong for the section's purpose. A global "no section subtitles" rule would contradict Stripe and Apple, and a global "tooltips for section explanations" rule contradicts four sources. Candidate DESIGN-RULES line:

> A settings section title stands alone when its rows say enough; add one visible muted sentence (max ~1 line, no tooltip, no info icon) only when the section's behavior or default cannot be read from its rows, and put row-level detail in a muted line under the row label. Tooltips are for icon-only controls and never carry information needed to use the section.
