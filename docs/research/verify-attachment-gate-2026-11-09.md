# Attachment recordings at the merge gate

Scope: implement rollout step 3 of [the accepted evidence design](../design/verify-evidence-out-of-tree.md), refs #3513. Baseline: `origin/main` at `e03bb0c2e3c8707649dc50e1bb85f8d56fefe44b`.

Claim marks: `实测` means read first-hand on 2026-11-09; `推断` means derived from those reads; `猜测` means unverified. This note compares evidence transport and provenance; it does not change the accepted design or repository settings.

The designated CI/repository-automation sources are covered above: GitHub Actions, branch protection, rulesets, Mergify, and the artifact action's own source. No third-party Action is introduced or modified by step 3.

## Fit and implementation boundary

`推断`, from the comparison and accepted design: separate storage plus producer identity fits Cairn's existing attachment uploader without introducing another service. Use `build.evidenceStore`, never the current project setting, when constructing gate inputs and deciding whether repository evidence needs presence probes.

The implementation sites are:

- `merge-gate-run.ts`: project only eligible recordings belonging to the current verification step/task/team into `recordingAttached`; pass the build snapshot to the gate and GitHub fact reader.
- `merge-gate/readiness.ts`: retain repository raw-link acceptance; attachment mode requires a passing current-digest verify verdict with its eligible recording. Links, stale verdicts, failed verdicts and a missing snapshot cannot substitute.
- `merge-gate/github-facts.ts`: skip repository evidence presence probes in attachment mode; preserve unrelated GitHub fact reads.

`实测`: the accepted design places evidence presence predicates outside the TLA+ transition model. Step 3 therefore requires rerunning its existing configurations without changing model properties. PR comments remain rollout step 4 and are outside this implementation.

## Evidence and autonomous decisions

- `实测`: 26 new cases fail on unchanged baseline production sources, then pass with step 3. They execute the actual gate service, worker uploader, SQLite and attachment filesystem; the GitHub port is a stateful fake. Pure readiness is checked separately for raw links, stale digests and repository mode.
- `实测`: the existing targeted prompt/dispatch/daemon/verdict/gate suites pass 349 cases. `pnpm lint`, `pnpm typecheck`, `pnpm spec:parse` and `pnpm prepush` pass. The model runner's 29 current configurations all match `expected.txt` (the design's count of twelve is stale). No model or expected-result changes. The runner prints its historical drift list; this PR does not reset its sync marker or claim a new historical model audit.
- `推断`: a ready metadata row alone cannot establish readability. The gate therefore reads eligible files and checks recorded size and SHA-256 before accepting them; missing/corrupt files remain blocked. This is reversible by reverting this PR and introduces no setting.
- `实测`: the startup scheduler previously lacked `attachmentsDir` in its build dependencies even though HTTP services already receive it. This PR supplies that existing directory to the scheduler so production polling can use the same gate path. Deployed scheduling is not exercised locally.
- `推断`: keeping rollout step 4 separate preserves the accepted ordering and one-change scope. This PR references #3513 and closes only its own step ticket #3803.

Local test fixture corrections were intercepted before commit: runtime uploader setup exposed a missing directory, and TypeScript exposed omitted `MachineDeps` fields. The static compiler and the recording-trigger assertions are the existing safeguards; no new process rule was needed.
