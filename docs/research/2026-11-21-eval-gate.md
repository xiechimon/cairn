### Langfuse details that changed since the 2026-11-09 research

- `experiment.run` is the current SDK entry (`dataset.runExperiment` too); `item.link()` was removed in JS v6. `langfuse/experiment-action` (v1.0.13) wraps it and fails on `RegressionError`. `实测`, [SDK ref](https://js.reference.langfuse.com/classes/_langfuse_client.ExperimentManager.html), [action](https://github.com/langfuse/experiment-action)
- API-key presets (v4.64+/v4.82): no single preset gives "read datasets + write scores, cannot edit evaluators". VIEWER reads; INGEST/Application writes; Developer (Member scopes) does both **and** `evaluator:CUD`/`datasets:CUD`. The accepted design's tamper story therefore needs **two keys** (VIEWER + INGEST), not one. `实测`, [changelog](https://langfuse.com/changelog/2026-10-16-project-api-key-permissions), [RBAC](https://langfuse.com/docs/administration/rbac)
- Code evaluators on self-host need a dispatcher: `insecure-local` (no sandbox — worker code exec), `aws-lambda`, or `external` (your own HTTP executor — an option the 2026-11-09 research predates). SDK evaluator functions inside `experiment.run` execute in our own process and need no dispatcher. `实测`, [docs](https://langfuse.com/self-hosting/configuration/code-evaluators)
- Evaluators are API-editable (`/api/public/v2/evaluators`), so version history plus the gate's "same evaluator version on both arms" check is what binds the ruler. `实测`, [changelog](https://langfuse.com/changelog/2026-08-27-stable-evaluator-api)

### What each would cost cairn specifically

The suite shape this question needs — replay a real Coordinator turn inside a disposable in-server stack seeded from a captured world, then assert on a normalized decision/tool record — is something only Langfuse's SDK runner, promptfoo's `exec:`/`file://` provider, or a hand runner can express. Harbor, Braintrust and Inspect all assume the *task itself* is the env (container or python solver), which does not match a sqlite-seeded in-process replay; they would wrap our runner rather than replace it. `推断`

## 2. Pattern that fits cairn

**Keep the accepted Langfuse plane; restore a thin runner in the repo; keep the judge and the answers outside the candidate's reach.** Reasons, all `推断` from the rows above:

1. The task set must contain harvested real Coordinator conversations — private owner content that cannot live in this public repo, and expected outputs that must never be readable by the candidate under test (Harness²'s rubric-download lesson). Langfuse datasets give both ACL and versioning in one place; a repo-YAML approach (promptfoo, Inspect, Harbor) fails the privacy half, and a private-repo mirror would rebuild what Langfuse already is.
2. promptfoo and Inspect are good frameworks for the wrong layer: they assume the eval target is a model call or a python solver, not a disposable Coordinator stack seeded from sqlite. We would write the same runner either way, then pay their abstraction tax. The one thing Inspect does better than anyone — first-class confidence intervals — is already solved in-repo by the accepted design's exact sign test.
3. Harbor solves container isolation for bench tasks, which this gate does not need (a turn replay needs no container; build-level replay is the shelved E2 territory and is the only place Harbor stays relevant).
4. The exporter/pack line is the capture substrate, not the gate: snapshots feed harvesting; `openExperimentClient` carries run traces; the pack schema remains the record format for real builds. Nothing in the gate edits them — they stay protected judge surface.
5. The 11-16 deletion removed the *directory*, not the *direction*: dataset, evaluators, snapshot capture and the Langfuse client all remain. The design re-adds only the runner+gate, under `scripts/eval/` (protected by the existing `**/scripts/**` glob).

The one genuinely new decision is where Langfuse lives: the omarchy host is offline and the Mac is excluded, so the options are an always-on tailnet node reached through `tailscale/github-action`, Langfuse Cloud, or a per-job ephemeral Langfuse container — compared in the design's open questions.

## 3. Concrete recommendation and code areas

- Runner + gate + suite config: `scripts/eval/` (protected) — resurrect the deleted `integration/eval/coordinator-routing/` selectively (it exists at commit `31092d98d`).
- Trigger: extend the `changes` classify step in `.github/workflows/ci.yml` with an `eval-needed` output and a conditional `eval` job feeding `check`; `promote.yml` then binds the verdict automatically.
- Harvest: a snapshot→dataset CLI reading sealed `coordinator_turn_snapshot` rows and writing Langfuse items (owner-run, like the deleted `199b89fbe` path).
- Extend the protected eval surface at implementation time: `apps/server/src/services/coordinator-turn-*.ts`, `packages/shared/src/langfuse.ts`, `apps/server/src/runtime-otel.ts`, `packages/shared/src/genai-conventions.ts`, `scripts/eval/**` (already covered), `.github/workflows/ci.yml` (already covered) — the "no change may edit what judges it" rule applied to the new judge pieces.
- Eval runs record themselves in Langfuse experiment runs (fingerprint: base/candidate SHA, prompt sha256, dataset version, judge SHA, model); a weekly main run is the baseline trend.
