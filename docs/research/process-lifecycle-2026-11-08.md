# Owner-bound process and workspace lifecycle: prior art

Date: 2026-11-08

Question: how do other tools make sure the processes, servers, containers and workspaces an owner starts are torn down when the owner exits, crashes, is SIGKILLed or is interrupted, and how do they tie a workspace (git worktree) lifetime to a PR or archive event?

Labels: 实测 = run or read first-hand in this research pass; 推断 = derived from the measured or read facts and checkable; 猜测 = everything else. Source pins: Playwright 1.63.0, Vite 8.3.0 and Vitest 5.0.1 are read from cairn's installed `node_modules/.pnpm`; GitHub sources are pinned to the commit named in each link.

## Per-source notes

**Playwright webServer** (installed 1.63.0). `launchProcess` spawns with `detached: process.platform !== "win32"` and a comment that this makes the child a group leader so the tree can be killed with `.kill(-pid)` (`node_modules/.pnpm/playwright-core@1.63.0/node_modules/playwright-core/lib/coreBundle.js:9314-9322`). `killProcess` runs `process.kill(-spawnedProcess.pid, "SIGKILL")` (`:9409`). The `exit` handler runs `killSet` synchronously; the first SIGINT runs graceful close, the second force-kills (`:9271-9298`). The webServer plugin passes `stdio: "stdin"`, which maps to `["pipe","pipe","pipe"]` (`:9311`), with `shell: true`, and optional `gracefulShutdown: {signal, timeout}` sends the signal to `-pid` (`playwright/lib/runner/index.js:870-892`). On SIGKILL no JS runs, so the only remaining kill path is the child seeing stdin EOF (推断). A `detached` webServer is also outside the owner's process group, so killing the owner's group does not reach it (推断; matches the cairn leaks).

**Vite.** `setupSIGTERMListener` installs `process.once("SIGTERM")` and, unless `process.env.CI === "true"`, `process.stdin.on("end", ...)` (`vite@8.3.0/.../dist/node/chunks/node.js:3058-3063`); dev server and preview server both register it (`:24467`, `:35055`). This is a parent-pipe EOF watch, which beats polling: on the owner's SIGKILL the kernel closes the pipe and Vite exits at once (推断).

**Vitest.** `globalSetup` teardowns run in reverse from `_teardownGlobalSetup` (`vitest/dist/chunks/index.DzobfTyw.js:12123-12125`), called only from `Vitest.close()` (`:21411`). The logger's `SIGINT`/`SIGTERM`/`exit` handler only restores the cursor and calls `process.exit()` 1 ms later (`:14090-14100`). So a server started in `globalSetup` leaks on any signal and on SIGKILL (推断).

**testcontainers / Ryuk.** Ryuk reads newline-delimited `label=k=v` filters per connection and ACKs each one (`testcontainers/moby-ryuk@0509b37 reaper.go:236-280`). `pruneWait` counts clients; when the count hits zero it schedules prune after `ReconnectionTimeout` (default 10 s), and with no first connection it prunes after `ConnectionTimeout` (60 s) (`reaper.go:304-345`, `config.go:13-38`). Clients keep one socket open for the life of the process: node uses an `unref()`ed socket and writes `label=org.testcontainers.session-id=<id>` (`testcontainers/testcontainers-node@c79a5a5 packages/testcontainers/src/reaper/reaper.ts:134-170, 185-187`); Go dials once and blocks on a channel (`testcontainers/testcontainers-go@7b01710 reaper.go:538-551`); Java runs a daemon thread that reconnects and replays the filter list (`testcontainers/testcontainers-java@f74d167 core/src/main/java/org/testcontainers/utility/RyukResourceReaper.java:80-125`). The design rests on "the kernel closes my socket when I die, however I die". The reconnection grace absorbs reconnects.

**Bazel.** `linux-sandbox` documents that "if linux-sandbox itself gets killed, the process and all of its children will be killed" (`bazelbuild/bazel@a765dc1 src/main/tools/linux-sandbox.cc:15-31`). It sets `PR_SET_PDEATHSIG(SIGKILL)` first thing (`:336-339`), clones pid1 with `CLONE_NEWPID`, and runs a pipe handshake so the child can prove the parent was still alive after its own `prctl` (`:255-267`); pid1 also sets pdeathsig (`linux-sandbox-pid1.cc:219`) and relies on PID-namespace teardown to SIGKILL all descendants when it exits (`:960-966`). The non-sandboxed `process-wrapper` becomes a child subreaper, `setsid`s the child, and on timeout or child exit kills the whole group, SIGTERM then SIGKILL (`process-wrapper-legacy.cc:55-125`, `process-tools.cc:94-110`).

**Buck2.** Local commands get `cmd.process_group(0)` and are killed with `killpg(SIGKILL)` or graceful TERM+KILL (`facebook/buck2@444b95f app/buck2_execute_local/src/unix/process_group.rs:50, 141-162`). With resource control each action has a cgroup; `kill_remaining_pids` lists `cgroup.procs` for reporting and writes `1` to `cgroup.kill`, described as race-free against forks (`app/buck2_resource_control/src/cgroup.rs:297-335`). The daemon expects to be started "with something like systemd-run" with `Delegate=yes` (`buck_cgroup_tree.rs:100-108`), and the tests probe `systemd-run --user --scope` (`cgroup.rs:782-790`). The forkserver gets its channel and a state-dir lease as inherited fds (`app/buck2_forkserver/src/launch.rs:66-78`).

**GitHub Actions runner.** `process.clean` defaults to true; the worker sets `RUNNER_TRACKING_ID` in its own environment so every step inherits it, and snapshots `pid_name` pairs (`actions/runner@5ba5044 src/Runner.Worker/JobExtension.cs:588-603`, `src/Runner.Common/Constants.cs:42`). At job finalize it reads each new process's environment and kills those whose id matches (`JobExtension.cs:891-937`). Users opt out by overriding `RUNNER_TRACKING_ID`, which is the known escape hatch (推断 from the env check).

**systemd.** systemd.kill(5): `KillMode=` is `control-group` (default, all remaining processes in the cgroup), `mixed`, `process` ("not recommended!") or `none`. systemd.scope(5): scopes "manage externally created processes", have no main process, and live as long as at least one process is in them. systemd-run(1): with `--scope` the command is executed by systemd-run itself and inherits the caller's environment; `--expand-environment=no` disables `$` expansion, which with `--scope` is done by systemd-run itself. cgroup-v2: writing `1` to `cgroup.kill` SIGKILLs every process in the cgroup tree. A scope is not bound to any one pid, so the owner's death does not end it; `BindsTo=` only binds to units, and the owner (a Claude Bash shell) is not a unit (推断).

**tmux / zellij.** tmux forks the server with `proc_fork_and_daemon` → `daemon(1, 0)` (`tmux/tmux@a73616d server.c:190`, `proc.c:375-388`) and keeps looping unless `exit-empty` is on and no sessions remain (`server.c:291-297`); `kill-server` destroys everything (tmux(1)). zellij daemonizes the server (`zellij-org/zellij@43c8710 zellij-server/src/lib.rs:3286-3290`), and `on_force_close` decides between `detach` (default) and `quit` when the client gets SIGTERM/SIGINT/SIGQUIT/SIGHUP (zellij options docs). Both expect an explicit kill, never owner death.

**Claude Code.** Docs: "Background tasks are automatically cleaned up when Claude Code exits. On macOS and Linux, when you stop a background task from `/tasks` or Claude Code stops it at exit, processes that detached from the task's shell, such as ones started under `setsid` or `timeout`, stop too" (code.claude.com/docs/en/interactive-mode, background Bash commands). A command a foreground subagent started stops when that subagent's run ends; one started by the main conversation or a background subagent keeps running after the final response (code.claude.com/docs/en/tools-reference, "When a background command stops"). Local sessions have no time limit on background commands. Tool memory limits are applied through a memory cgroup on Linux (same page). The host measurement below shows subagent-end cleanup did not kill a `setsid` grandchild (实测), so the documented escapee handling is not on that path (推断), and foreground `&` jobs are not tracked at all (实测).

**OpenAI Codex CLI.** `spawn_child_async` comments "If this Codex process dies (including being killed via SIGKILL), we want any child processes ... to also be terminated", then in `pre_exec` calls `detach_from_tty` (`setsid`, falling back to `setpgid(0,0)` on EPERM) and on Linux `set_parent_death_signal(parent_pid)`, which sets `PR_SET_PDEATHSIG(SIGTERM)` and raises SIGTERM if `getppid()` already changed; spawn ends with `kill_on_drop(true)` (`openai/codex@748ab55 codex-rs/core/src/spawn.rs:98-144`, `codex-rs/utils/pty/src/process_group.rs:25-80`). Exec timeout kills the process group; cancellation sends TERM to the group, waits a grace period, then KILLs; Ctrl-C kills the group (`codex-rs/core/src/exec.rs:1024-1080`). PTY sessions `setsid` + `TIOCSCTTY` (`utils/pty/src/pty.rs:662`), and `ProcessHandle` terminates on drop (`utils/pty/src/process.rs:277-281`). The bubblewrap helper also sets pdeathsig (`codex-rs/linux-sandbox/src/linux_run_main.rs:632-643`). No cgroup use was found. Grandchildren that `setsid` again escape once Codex is gone (推断). Because pdeathsig fires on parent *thread* exit (prctl man page), a child spawned from a short-lived runtime thread can be killed early (推断).

**Conductor.** Workflow and review docs: after merge, "archive the workspace so it leaves your active work list"; archived workspaces are restored from the History pane with chat history (conductor.build/docs/concepts/workflow, /docs/guides/review-and-merge). `scripts.archive` runs "before Conductor archives a workspace" to clean up resources outside the workspace directory (/docs/reference/scripts). The docs read describe no automatic archive on PR merge and no dirty-tree check (实测: absent from the pages read; the closed app was not inspected).

**Sculptor (Imbue).** Each workspace is a git worktree by default, and "your current branch and uncommitted work are never touched" refers to the user's checkout (`imbue-ai/sculptor@5435bd4 docs/help/workspaces.md:1-5`). The branch policy on delete is `never` / `delete_if_safe` (`git branch -d`) / `always` (`-D`) (`docs/help/workspaces.md:59-60`, `sculptor/sculptor/services/workspace_service/environment_manager/environments/worktree_strategy.py:82-125`). The delete path stops PTY terminals first so no orphan keeps the cwd, cancels setup, runs `git worktree remove` without `--force` and swallows failures, then `delete_environment` rmtrees the whole directory on a background thread; `cleanup_stale_environments()` on startup removes leftovers (`sculptor/sculptor/services/workspace_service/default_implementation.py:540-600`, `.../environment_manager/default_implementation.py:135-175`).

**t3code.** Settings `worktreeOnMerge`, `worktreeOnDelete`, `worktreeUnchanged`, `worktreeAfterDays`, `worktreeSettledAfterDays`, all off or null by default, and `worktreeKeepWhen` = `uncommitted-changes` by default (also `tracked-changes`, `any-local-files`) (`pingdotgg/t3code@ade4730 packages/contracts/src/settings.ts:1052-1071, 1223-1234`). Merge detection requires `state === "merged"` and either the branch is integrated or the PR's `headRef`/`baseRef`/`headSha` match the worktree exactly, so a later push is never deleted after a squash merge (`apps/server/src/storageCleanup.ts:263-283`). The worktree is kept while any thread in its group is not idle, while a terminal is starting or running with its cwd inside, when it is shared by several threads, or on local changes (`git status --porcelain=v1 -z --untracked-files=all`) (`:320-340, 640-667, 910-925`). Activity is re-checked just before removal (`:1078`). The sweep repeats every hour (`:1437`). Removal uses `git worktree remove` with `--force` only when the rules allow it (`apps/server/src/vcs/worktreeRemoval.ts:36-60`).

## Measured on this host

omarchy, Linux 7.2, systemd 262, Claude Code 2.1.317 in the Claude desktop app.

- 实测: a foreground Bash tool call that starts `sleep &`, `nohup sleep &`, `setsid sleep &` and `(sleep &)` returns, and all four keep running, reparented to `systemd --user` (pid 1092, the user-manager subreaper). Claude Code's bash runs with job control, so each `&` job gets its own process group, and killing the tool shell's group would not reach them.
- 实测: a `run_in_background` task stopped with TaskStop: the task's bash and its `&` / `nohup` children are all killed.
- 实测: a subagent that leaves two background tasks running and ends: both tasks are killed, but a `setsid sleep &` child (already reparented to systemd --user) survives.
- 实测: Node `spawn(..., { detached: true })` + `unref()` (as `.claude/skills/verify-cairn/scripts/launch.mjs` does) puts the child in a new session; once the launcher exits the child is reparented to systemd --user and is in no harness process tree.
- 实测: every leftover process sits in the Claude desktop app's cgroup scope `app-com.anthropic.Claude-<pid>.scope`, so leftovers only die when the desktop app exits.
- 实测: `systemd-run --user --scope --collect --quiet --expand-environment=no --unit=<name> -- cmd` execs `cmd` in place (same pid, same parent) inside a new transient scope; writing `1` to that scope's `cgroup.kill` (or `systemctl --user kill <unit>`) kills every member, including a `setsid` grandchild. Without `--expand-environment=no`, systemd-run expands `$$` in the command line.
- 实测: a `claude -p` run that started a `run_in_background` task and then exited left nothing running; an orphaned Claude Code bash (`ppid` 1092, its task output file already deleted) shows that a session process that exits some other way leaves its background shells behind (推断).
- 实测 (this pass): parent-pipe EOF survives SIGKILL. A Node parent spawned a `detached` sentinel with `stdio: ["pipe", ...]` and then SIGKILLed itself (exit 137); the sentinel's `process.stdin` `end` fired and it reported `ppid=1092`, i.e. reparented and still notified.
- 实测 (this pass): util-linux 2.42.4 `waitpid PID:inode` (inode from `getino PID`) blocked on a non-child, `setsid`-reparented `sleep 2` and returned 1998 ms later, at its exit, with no polling loop. With a wrong inode it refused with an error (`could not open PID ...`), so a reused pid cannot match.

## Pattern that fits cairn

Candidate: `scripts/owned-process.mjs` (a) runs each child in its own transient systemd user scope on Linux, falling back to a process group on macOS or without a user manager; (b) spawns a sentinel that watches the helper and its ancestor chain (pid + start time) and kills the scope or group when any of them dies; (c) kills the scope when the main child exits so detached grandchildren cannot outlive it; plus a systemd timer that removes clean, idle worktrees whose PR is merged or closed.

Where it matches prior art:
- (a) is the Buck2 model (`systemd-run --user --scope` + `cgroup.kill`) and systemd's own `KillMode=control-group`. Cgroup membership is the only mechanism in this list besides Bazel's PID namespace that catches `setsid` escapees and Playwright's `detached` webServer without the cooperation of the process tree (推断).
- (b) is Ryuk keyed on owner liveness instead of a socket.
- (c) is Bazel `process-wrapper` killing the group after the child exits, and `KillMode=mixed` semantics.
- The worktree timer is t3code's hourly sweep.

Where it is weaker, and what to change:
1. **Polling vs events.** Every robust source uses a kernel-delivered event: Ryuk's socket EOF, Vite's stdin EOF, Bazel's pdeathsig and PID-namespace teardown, Buck2's inherited fd. Change: give the sentinel the read end of a pipe whose only write end the helper holds (no other child may inherit it); EOF means the helper died, SIGKILL included (实测 above). For ancestors above the helper, use one `waitpid PID:inode ...` (pidfd, event-driven, immune to pid reuse; 实测) on Linux; keep start-time polling only for macOS and for hosts without util-linux ≥ 2.40.
2. **Sentinel is a single point of failure.** If the sentinel is OOM-killed or killed by a harness sweep, the scope lives forever, and it now lives outside the Claude app scope, so not even app exit cleans it (推断). Change: add a lease backstop, like Ryuk's 60 s no-client timeout. Set `--property=RuntimeMaxSec=<ceiling>` on the scope and have the sentinel `systemctl --user set-property --runtime` it forward as a heartbeat, or at least set a generous fixed ceiling per call site. Also wrap the main child in `setpriv --pdeathsig KILL` so the direct child dies with the helper even if the sentinel is gone (the cheap Codex/Bazel layer; it does not cover grandchildren, the scope does).
3. **macOS fallback cannot catch `setsid` escapees** (process group only). Change: add the GitHub runner marker. Export `CAIRN_OWNER_ID=<uuid>` into the child's environment, and on cleanup also kill own-user processes whose environment carries it (`ps -E -o pid=,command=` on macOS; `/proc/<pid>/environ` on Linux as a cross-check). It misses env-clearing children, which is acceptable for a fallback.
4. **Start time alone is not enough for pid reuse on macOS** at 1 s resolution of `ps -o lstart` (推断). Compare pid + start time + command; or on Linux use the pidfd inode.
5. **Kill-on-main-exit (c) changes behavior** for any call site that relies on a daemonizing command (for example a script that spawns a server and exits). Make (c) the default and give the call site an explicit opt-out naming the reason; never silently keep.
6. **systemd-run availability.** Probe once per run (`systemd-run --user --scope --quiet true`), as Buck2's tests do; on failure fall back and print which mode is active. Always pass `--expand-environment=no` and `--collect`, and pick unit names that encode the owner (`cairn-owned-<lane>-<pid>.scope`) so `systemctl --user list-units 'cairn-owned-*'` is the inventory.
7. **Vitest `globalSetup` and Playwright handlers are graceful-only.** Anything they start must itself be launched through the helper; do not treat their teardown as the cleanup guarantee.

Worktree reaper, following t3code and avoiding Sculptor's rmtree gap:
- Remove only when the PR is merged and its `headRefOid` equals the worktree `HEAD` (or HEAD is an ancestor of `origin/main`); for closed-unmerged PRs, only if the remote branch contains HEAD.
- Never remove when `git status --porcelain --untracked-files=all` is non-empty, when there are commits not on any remote, when any process has its cwd inside the worktree (`/proc/*/cwd`, like t3code's open-terminal check), or when the tree was touched within an idle threshold.
- Use plain `git worktree remove` (never `--force`, never `rm -rf`), delete the branch only with `git branch -d`, re-check right before removal, and log every keep reason.
- Run hourly from a systemd user timer.

## Recommendation

Build `scripts/owned-process.mjs` as the single launch path, in this order:
1. Linux: transient scope (`systemd-run --user --scope --collect --quiet --expand-environment=no --property=RuntimeMaxSec=...`) around `setpriv --pdeathsig KILL -- cmd`.
2. A detached sentinel woken by helper-pipe EOF and `waitpid PID:inode` on the ancestor chain; it writes `cgroup.kill` (or `systemctl --user kill`) and exits.
3. Kill the scope when the main child exits, with an explicit opt-out.
4. macOS: process group plus `CAIRN_OWNER_ID` env-marker sweep and start-time polling, with the weaker guarantee printed.

Code areas: `scripts/owned-process.mjs` (new); `.claude/skills/verify-cairn/scripts/launch.mjs` (replace `detached` + `unref`) and `cleanup.mjs` (kill by unit, then marker); `scripts/heavy-slots.mjs` (tie the slot lease to the scope's life); `scripts/e2e-affected.mjs` and `scripts/prepush.mjs` (run Playwright and its webServer inside one owned scope); `scripts/test-temp-run.mjs`; `scripts/dispatch-agent.mjs`; a worktree reaper under `scripts/ops/host/tools/` with its `.service` + `.timer` under `scripts/ops/host/units/`.

Prove each change with a test that SIGKILLs the owner (and a separate one that SIGKILLs the sentinel) and asserts that no pid carrying the marker survives.

## What was built (PR for this note)

`scripts/owned-process.mjs` follows the recommendation with one deviation:
- Linux: `systemd-run --user --scope --collect --expand-environment=no --property=RuntimeMaxSec=43200` around `setpriv --pdeathsig KILL --` around the command. The helper hands systemd-run its own `XDG_RUNTIME_DIR` / `DBUS_SESSION_BUS_ADDRESS` and strips them plus `INVOCATION_ID` again with `env -u`, so the command sees exactly the environment it was given (a minimal-env caller, the orb canary, broke without this; 实测).
- A detached sentinel per child exits on helper-pipe EOF (event, covers helper SIGKILL) and polls the owner chain every 500 ms by pid plus kernel start time. Deviation: `waitpid PID:inode` is not used, so ancestors are polled rather than awaited; the poll keys on start time, so pid reuse cannot fool it on Linux, and the lease bounds the cost of a dead sentinel.
- The scope (or, without systemd, the process group plus every process carrying `CAIRN_OWNER_ID=<uuid>`) is killed with TERM, a grace period, then KILL when the main child exits, on SIGINT/SIGTERM/SIGHUP, on `--timeout-ms`, and when the sentinel fires.
- `launchOwnedDetached` is the only sanctioned way to outlive a tool call (`scripts/dispatch-agent.mjs`): it binds to the nearest `claude`/`codex` ancestor instead of the parent chain.
- `scripts/spawn-ownership.test.mjs` fails on `detached` or child `unref()` anywhere in `scripts/`, `.claude/skills/` or `.cursor/skills/` outside the helper; the one exception is the canary attacker, which runs in a sandbox that does not contain the helper.
- The worktree reaper follows t3code's merge rule (exact head SHA), Sculptor's lesson (plain `git worktree remove`, never `--force` or `rm -rf`) and the busy check (any process cwd inside the tree), with a 30-minute grace after merge or close.
