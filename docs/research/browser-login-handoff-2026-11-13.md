# Browser login handoff: how agents detect a login, hand it to a human, and fill passwords

Status: research, 2026-11-13. No code changed. Question: when the Coordinator drives the orb browser and meets a login page or a human check (CAPTCHA, slider, SMS or 2FA code), how do other products (a) detect it, (b) hand control to the human and resume, and (c) fill a password without the model seeing it? Should Cairn's agent fill the owner's password by reference and hand over only for CAPTCHA, slider and SMS code?

Evidence labels: `实测` = read first-hand in this session (page fetched, or source read at the commit named), `推断` = follows from `实测` facts, `猜测` = everything else. Source commits: Rakazo `d89f1bf4` (2026-11-13), Skyvern `9768ceb7` (2026-11-12), browser-use `dfb6a73d` (2026-11-12), agent-browser tag `v0.41.2` (`d52a5e90`), Cairn at `57fbe8889`.

Builds on `docs/research/agent-small-computer-2026-11-08.md` (rows for Grok, Rakazo, dots, Duet, re-checked here against the primary pages rather than copied), `docs/design/job-applications.md`, `docs/design/computer-login-handoff.md` (the M2 draft) and `docs/design/secret-gateway.md` (#4084, #4101).

### Answers to (a), (b), (c) across products

- **(a) Detection.** Harness-side, fixed: Browserbase and Browser Use, for CAPTCHA only, through solver events; Cairn's draft, for login fields. Model judgment: Grok, Rakazo, dots, ChatGPT agent, Stagehand, Skyvern (`SOLVE_CAPTCHA`) and Browser Use for 2FA. Site-specific rules: ChatGPT agent's "watch mode" (`实测`; the mechanism is unpublished). No source documents a vision classifier for login or CAPTCHA detection (`实测`, across every page read). Browserbase is the one primary source that argues the point: the wait has to live in the tool because "a prompt alone cannot do that" (`实测`).
- **(b) Handoff.** All use the same shape: one button to take control and one to give it back (Take over / Return control, Take control / I'm done, Take control / Stop controlling). Resume is either a fresh turn with a fixed note (Rakazo continuation, Browser Use follow-up run) or the same run continuing (ChatGPT agent) (`实测`). Only ChatGPT agent states that screenshots stop during takeover (`实测`). Only Rakazo states what the agent may do meanwhile: shell and file tools stay on, screen tools are gated (`实测`). Rakazo uses the same 15-minute lease as Cairn's draft (`实测`).
- **(c) Password filling.** By reference, model never sees the value: Grok (Vault, 1Password, Secure Form), Rakazo (`fill_secret`, `fill_code`), dots (private form, saved login after confirmation), Skyvern (placeholders), Browser Use (`type_secret`), Stagehand (variables), agent-browser (`auth login`), Browserbase with 1Password Agentic Autofill, and Duet by claim (`实测`). Human types it during takeover: ChatGPT agent, and Cairn's draft. The model sees it: the Anthropic computer-use guidance, and Browser Use with a 1Password service account (`实测`).

## 2. The pattern that fits Cairn

Cairn's setup: the Coordinator runs in the server (D114). It drives agent-browser inside an nspawn orb computer through the daemon (`apps/daemon/src/computer/browser.ts`). Secrets are encrypted on the server (`apps/server/src/services/secrets.ts`). The owner is on a phone and gets a push and a noVNC live view with Take control (`computer-control.ts`).

The pattern that fits is **Rakazo's, with Browserbase's rule that detection lives in the tool**:

1. **Detection stays harness-side, as drafted.** It is deterministic, the model cannot alter it, and it gives the server something to gate on (`推断`). Browserbase is the primary precedent for putting this in the tool (`实测`). Add page-level CAPTCHA and slider signals: an iframe from a known challenge origin, or a full-page block. That keeps the gate from depending on the model when no password field exists, the case the current script misses (`推断`). Keep `request_takeover` as a model tool for anything the script cannot see, as Rakazo does (`实测`).
2. **Handoff copies Rakazo's run semantics.** Rakazo uses a waiting state, resume with a fixed note, and a skip or expiry path whose note tells the model the step was not done (`实测`). Cairn's draft already has the 15-minute lease and "take a fresh snapshot" (`实测`). Two additions come from the sources. First, stop `browser_snapshot` and `computer_observe` frames while the owner holds control (ChatGPT agent, `实测`); the draft allows snapshot during the handoff, and a snapshot taken while the owner types a code would copy a prefilled code into `computer_call.resultText` (`推断`). Second, say on the result that skip or timeout means "not done" (Rakazo, `实测`).
3. **Fill by reference reuses Rakazo's mechanics on Cairn's pieces.** Cairn already has the same CLI (agent-browser), the same server-held vault shape (`secret` rows with a delivery policy, #4101) and the same takeover lease (`实测`). agent-browser 0.41.2 can take commands on stdin through `batch --json` (`实测`), so the value never needs to be in argv or in `computer_call.params` (`推断`). Use agent-browser's `auth save` vault inside the computer only with care: its key file sits in the agent's home, which the agent's `shell` tool can read (`推断`, since `guard.ts` only blocks `.browser-profiles` and `--user-data-dir`, `实测`).
4. **Codes go through a code card, not noVNC typing.** Grok's Secure Form, dots' private form and Rakazo's `oneTimeCode` all let the human type a code into the product's own UI (`实测`). Browserbase says mobile keyboards are not supported in live view (`实测`). Typing on noVNC from a phone is the weakest step in Cairn's draft (`推断`). A server-rendered code card in the Cairn app fits the phone-first owner better (`推断`).

Why not the alternatives:

- **Takeover-only** (ChatGPT agent, the current draft) is safe, but it costs the owner a remote-desktop session for every login, and sessions expire (`推断`).
- **Placeholder swap at egress** (Managed Agents, Cairn's secret gateway) fits API headers, not login forms. Many login pages hash or encrypt the password in page JavaScript before posting, so the proxy never sees the placeholder in a form it can rewrite (`推断`). The gateway design's scope is `http` header delivery (`实测`, `secret-gateway.md`).
- **Host-browser attach** (`job-applications.md`) keeps credentials in the owner's own browser. The owner overrode it for login on 2026-11-13 (`实测`, `computer-login-handoff.md`).

## 3. Recommendation

### Should the agent fill the owner's password by reference?

**Yes, as a second milestone after the M2 handoff ships, with these bounds.** Precedent: Grok, Rakazo, Skyvern, Browser Use, Stagehand and agent-browser all type a stored password the model never sees (`实测`). dots does the same but asks for confirmation on each new sign-in with a saved login (`实测`). Grok and Rakazo do not ask (`实测`). Only ChatGPT agent and the Anthropic computer-use guidance leave it with the human, or with the model (`实测`).

Bounds, each from a source:

1. **Bound to an origin, checked at type time in the receiving frame.** Rakazo uses a CDP isolated world in the field's frame; Browser Use uses the frame URL as the browser reports it; agent-browser's `--no-navigate` rechecks the origin before each fill (`实测`). With plain `agent-browser eval`, the check and the fill must happen in one script. A login inside a cross-origin iframe is refused and goes to takeover (`推断`; Rakazo notes that agent-browser scripts run "only in the top page's own world", `实测`).
2. **Hidden values only into `type=password`.** Visible fields (phone, username) go only into text, email or tel inputs (Rakazo, `实测`).
3. **Value never in model context or `computer_call`.** Params store `{secret, field}`. The daemon gets the value on a separate frame field and pipes it on stdin (`batch --json`, `实测` that it reads stdin). Results are scrubbed of the value before `receiveComputerFrames` stores them. `redactSecrets` (`packages/shared/src/secret-redaction.ts`) already takes a list of known values, but only replaces them in plain form, and `machine-computer.ts` calls it with no list (`实测`). It needs the filled values for that computer, plus their URL, form and base64 encodings, as Rakazo and Browser Use do (`实测`).
4. **Scrub every result from that computer, not only browser ones.** The agent's `shell` runs on the same computer and could run `agent-browser get value` on the filled field (`推断` from the tool list in `packages/shared/src/protocol/computer.ts`, `实测`). Rakazo scrubs shell output and file reads for this reason, and says plainly that this is not a boundary against a determined bot (`实测`).
5. **Approval.** Recommended: no per-fill approval for a login the owner saved for one origin (Rakazo and Grok, `实测`). Show "filled from saved login X" on the activity row. The dots-style per-use confirmation is the stricter option to offer if the owner wants it (`实测`). This is the owner's call.
6. **Handover stays for what a reference cannot fill.** CAPTCHA, slider, QR scan, passkey, device approval. The SMS code also goes to the owner until a code card exists. That is the Grok and Rakazo list (`实测`). No CAPTCHA solving: `job-applications.md` already forbids it (`实测`).

### Risks

- **The value sits in the DOM until submit, beside a shell the model controls.** A prompt-injected turn could read and exfiltrate it through any host the egress relay allows (`推断`). Mitigations: scrubbing (rule 4), a short window, and a scoped login. This is a residual risk, the same one Rakazo documents (`实测`).
- **"Show password" toggles and sites that echo values** put the value in screenshots and page text (Rakazo, Skyvern, `实测`). Mitigation: scrub snapshot text. A screenshot taken after a reveal cannot be scrubbed (`推断`).
- **The session cookie itself is the long-lived credential.** Today `browser.ts` passes only `--session` and `--headed` (`实测`). agent-browser persists state only with `--restore` or `--profile` (`实测`), so a computer idle-stop likely drops the login and every run re-logs in (`推断`; verify on the orb). Adding `--restore` writes plaintext session tokens under `~/.agent-browser/sessions/` unless `AGENT_BROWSER_ENCRYPTION_KEY` is set, and that directory is readable by the agent's shell (`实测` for the file, `推断` for the reach). The same exposure applies with or without password fill.
- **Password logins can trigger more risk checks than the site's default code login** (`猜测`). Measure it on the target site before building fill.
- **Site terms and account flags.** Unchanged from `job-applications.md` (`实测`).

### Code areas

M2, the handoff already drafted, plus the additions from section 2:

- `apps/daemon/src/computer/browser.ts`: the fixed detection script; add challenge-iframe and block-page signals. Decide `--restore` (owner decision, see Risks).
