# Cairn launch competitive landscape — 2026-11-23

## Newcomer and evidence rules

**Inferred — The user to win is a developer who already pays for a model and wants one assistant to do a repo task and a personal task without moving the control plane to a vendor.** On a Mac, their first encounter is a download, Gatekeeper's manual override, then a model sign-in and a Runner readiness check. To do real mail work they must additionally connect their own mailbox; to work away from the Mac they need a private route and pairing or their own chat bot. Cairn does not charge for the app; model providers and optional services still have their own terms and costs. Local state is not the same as offline inference. A sleeping/offline host, unavailable sandbox or failed sign-in can stop the first task. The launch test is whether a second person can reach both results without the maintainer's credentials, machine or help. See [positioning §2](../spec/18-positioning-and-differentiation.md#2-criterion-a-second-person-can-run-it-owner-decision-2026-11-14), [install and cost](../../README.md#install), [pairing, storage and provider setup](../getting-started.md), and [mail source](../../apps/server/src/services/mail-connector.ts).

**Evidence convention.** Measured — directly observed in named first-party code, documentation, API metadata or a running UI; `read`, `API`, and `live UI` are different evidence levels. A vendor's documented capability is not an independent execution or safety test. Inferred — conclusion from linked observations, including scoped negatives and competitive judgments; absence of public evidence is not proof of absence. Guess — rollout/adoption hypothesis, not a launch claim. Repo metrics are a 2026-11-23 snapshot; stars signal attention, and commit dates signal recency, neither measures active usage. `No evidence` below means only that the linked public sources did not demonstrate the capability. A worktree, distinct local account/session, process sandbox, container and VM are not interchangeable. An execution permission, an approval tied to a named external effect and a repository admission gate are three different things. Likewise, agent self-review, a test/benchmark, a protected regression gate and automatic adoption are not equivalents.

## 2. Where Cairn is ahead, where it is not

### Shipped and verifiable

- **Measured (pinned release/source) — Cairn is not shipping the product merge-gate pitch in spec 18.** The release tag `desktop-v0.1.698` resolves to `9ba0821`; it has both Mac architectures. [Delivery commit](https://github.com/xiechimon/cairn/commit/e599f10366d2b775f30e8ad3ceac25192e71aa2f) finishes code work without a merge decision; [#5345](https://github.com/xiechimon/cairn/issues/5345) and [cleanup](https://github.com/xiechimon/cairn/commit/90cebe206fac2718c2c9a8441abfe287e9989fbb) remove the mandatory gate's leftover UI/server path. The explicit merge path retains target checks and repository protections. Cairn's own tested-SHA queue does not make every install enforce independent review. This overrides the historical evidence-bound autonomous merge claim in [spec 18](../spec/18-positioning-and-differentiation.md#11-capabilities-carried-over-from-the-2026-11-01-thesis) for launch copy; see [removal decision](../design/remove-product-merge-gate.md) and [maintainer CI process](../design/tested-sha-landing.md).
- **Measured (release/source); Inferred (advantage) — a useful combination already exists:** a self-hosted server plus registered Runners, multiple real backends, retained code outputs, and a non-repo assistant with routines, memory, mail/connector capability. The README still labels personal affairs broadly as planned; the implemented SMTP and connected-mail paths are narrower than that whole promise. The narrow safety example is more specific than “the agent asked me before running shell”: a mail-triggered Coordinator turn's connected SMTP reply requires approval bound to the specific outbound message, and no approval is needed simply to produce a code result. The action-registry code deliberately treats an owner-started turn differently: it can send without the card, despite the broker's human-facing tool description saying otherwise. This is a meaningful combination against code-only workbenches or hosted-by-default alternatives, not proof of category-wide uniqueness or of complete personal-work parity. See [README](../../README.md), [Runner setup](../getting-started.md#run-builds-on-your-own-machines), [action enforcement](../../apps/server/src/services/action-registry.ts), [connector broker](../../apps/server/src/services/connector-broker.ts), [mail design's v1 note](../design/mail-connector.md#v1-for-the-desktop-install), [scheduler](../../apps/server/src/services/scheduler.ts), [Composio integration](../../apps/server/src/services/composio-connectors.ts).
- **Measured (source); Inferred (advantage) — real host confinement is more than a branch.** The Mac Runner's shipped source includes Seatbelt and an availability probe; a worktree by itself only separates checkout state. A protected workspace and credential scoping are defensible on that Mac path, not equivalent to a VM or full network/data confinement. Linux docs require compatible bubblewrap, user namespaces and systemd for readiness, but at the pinned commit the task-session confiner returns null off macOS and `launchConfined` is used for preflight, not the ordinary Linux task launch. Do not sell cross-platform task confinement. Compare [Mac implementation](https://github.com/xiechimon/cairn/commit/2e6ab61a80bbe27a40bed5436baf31ad46f877b9), [Mac trust exceptions](../design/mac-session-confinement.md#threat-model), [source](../../apps/daemon/src/backend/confine-session.ts), [runtime-homes warning](../design/runtime-home.md), [Linux follow-up #5401](https://github.com/xiechimon/cairn/issues/5401).
- **Measured (CI run) — protected maintenance eval is more than a roadmapped mock.** `EVAL_ENABLED` returned `true`; the [Nov 23 manually dispatched weekly workflow](https://github.com/xiechimon/cairn/actions/runs/45096942610) completed the suite on `9ba0821`, including Devin CLI setup, with **no candidate arm**. The [push workflow](../../.github/workflows/ci.yml) wires the qualified paired gate and takes the exam from the base where present; sampled [recent CI](https://github.com/xiechimon/cairn/actions/runs/45100918471) skipped the eval job. No paired run was confirmed in that sample. The [design](../design/eval-gate.md#8-how-the-exam-stays-isolated) documents residual candidate-harness trust. This is an engineering differentiator versus a UI that only runs unit tests, not proof Cairn performs better than peers with their own evals.

### Planned, opt-in, or not demonstrated

- **Measured (source/roadmap) — distinguish host sandbox, opt-in container, and any future VM.** `CAIRN_EXECUTOR=orb` opts in to nspawn on supported Linux hosts; it is not a universal default. Don't equate separate worktrees, browser profiles, or Seatbelt with a guest VM. Linux parity work [#5401](https://github.com/xiechimon/cairn/issues/5401) is outside the pinned release. [Executor selector](../../apps/daemon/src/orb/select.ts), [confinement design](../design/2026-11-22-task-confinement-and-credentials.md).
- **Measured (source/roadmap) — adapter code is not polished mobile onboarding.** Slack DM is marked Done; Telegram and WeChat have a landed basic slice but still have Todo roadmap cards and need user-owned bot setup. Slack's own app and tokens, WeChat's QR/session limits, paired web routing, an unreleased native-iOS roadmap item and [iMessage live validation #5392](https://github.com/xiechimon/cairn/issues/5392) are different states, not interchangeable phone availability. [Adapter design](../design/im-connections.md), [roadmap](https://github.com/users/xiechimon/projects/2), [release assets](https://github.com/xiechimon/cairn/releases/tag/desktop-v0.1.698).
- **Measured (source/roadmap); Inferred (claim boundary) — there is no launched job-application product or general guarantee on all outward actions.** [#5340](https://github.com/xiechimon/cairn/issues/5340) and its [removal](https://github.com/xiechimon/cairn/commit/014dead033a2ae58b70b8aab78c9fb08ca6f0fc2) retire the dedicated job-applications stack, not the possibility of drafting in a thread. Composio plumbing does not prove every toolkit works out of the box; the catalog remains Todo. A registered action's confirmation is not proof every browser/shell/connector path to the same effect is mediated. Sell named and tested effects, not “anything irreversible is safe.” [Action rules](../../packages/shared/src/action-registry.ts), [owner actions](../ops/launch-owner-actions.md), [roadmap](https://github.com/users/xiechimon/projects/2).
- **Measured (design/CI) — no judged self-evolution.** Weekly maintenance eval is real. A newcomer has no verified shipped loop that learns from failures, runs a held-out counterfactual, elects a better harness, and rolls it out. The old trajectory packs and adoption judge were removed; replay/telemetry, memory, and a locked exam are not that loop. [Canon](../CANON.md), [eval design](../design/eval-gate.md#9-deletion-the-old-skeleton), [baseline run](https://github.com/xiechimon/cairn/actions/runs/45096942610).

### Behind

- **Inferred — Cairn's biggest deficit is the second hour of onboarding, not the twentieth selectable engine.** Mac download has an OS warning; Linux desktop requires building, npm on some platforms requires owner-token work, and phone reach adds another access problem. Latest desktop artifacts are Mac-only, and the npm registry's package `0.1.2` is a distinct, materially older version line, not proof it carries the desktop release's feature set. [Getting started](../getting-started.md), [Mac assets](https://github.com/xiechimon/cairn/releases/tag/desktop-v0.1.698), [npm registry metadata](https://registry.npmjs.org/@xiechimon%2fcairn/latest), [owner release blockers](../ops/launch-owner-actions.md).

- **Inferred — weaker where the competitor's default is the user's daily habit.** T3 already publishes phone clients; managed Claude, Codex, Cursor and Amp offer paths that don't require keeping the laptop awake. OpenClaw and Hermes have mature channel surfaces; the verified [OpenClaw CN fork](https://api.github.com/repos/mf-yang/openclaw-cn) offers localized setup and packages notwithstanding its older default-branch head. Cairn's WeChat adapter is relevant, not exclusive. [T3 remote](https://github.com/pingdotgg/t3code/blob/main/docs/user/remote-access.md), [Claude cloud](https://code.claude.com/docs/en/claude-code-on-the-web), [Amp Orbs](https://ampcode.com/docs/orbs), [Cairn IM](../design/im-connections.md).
- **Inferred — weaker isolation in the default local lane than peers that start in a container or VM.** A Mac workspace is not the default per-session container documented by NanoClaw, let alone a Cursor cloud microVM; the trade is local control and less separate infrastructure, not stronger isolation. Pair any safety message with which effect is blocked, which process has which boundary, and what makes it fail closed. [NanoClaw security](https://github.com/nanocoai/nanoclaw/blob/53099d281f894521049e3930ee9e56d0dad7c1cf/docs/SECURITY.md), [Cursor security](https://cursor.com/docs/cloud-agent/security), [Cairn Mac scope](../design/mac-session-confinement.md#threat-model).
- **Inferred — distribution gap, not a quality ranking.** Five Cairn repo stars against hundreds of thousands for OpenClaw and Hermes is evidence that Cairn cannot rely on community reach or ecosystem reputation for launch; it is not evidence of lower retention or accuracy. The install/use/return funnel is still unmeasured, and "self-improving" cannot be a wedge against products with demonstrable memory loops unless Cairn can show an actual evaluated adoption loop. [Cairn](https://api.github.com/repos/xiechimon/cairn), [OpenClaw](https://api.github.com/repos/openclaw/openclaw), [Hermes](https://api.github.com/repos/NousResearch/hermes-agent), [eval boundary](../design/eval-gate.md).

**Inferred — the honest launch wedge:** one self-hosting developer; two repeatable outcomes in the same app; one place to find work and decide what leaves; choose the machine and account. “Autonomous software engineer,” “all your apps,” “sandboxed everywhere,” and “self-improving harness” are different promises that the release evidence does not meet.
