# Prior art: keeping agent work moving when the agent asks the user mid-task (2026-11-08)

Question: how do autonomous coding-agent systems represent "waiting on the user", surface the question, route the answer back to exactly the waiting task, time out or escalate, attribute cancellation, and surface errors?

Labels: **Measured** = read first-hand in this session from the primary source (source code, schema, or official doc page; doc pages were read through a fetch tool that returns quoted extracts). **Inferred** = derived from Measured facts and checkable. **Guess** = everything else, including any behavior that was not seen in a primary source. Every row names its links; a cell that says "not documented" means the primary page was read and is silent on it.

Source snapshots: `openai/codex` main, `OpenHands/OpenHands` tag `0.59.0` (the legacy Python controller; `main` no longer ships it) plus `OpenHands/software-agent-sdk` main, `pingdotgg/t3code` main tarball, `@earendil-works/pi-durable@1.5.0` and `@earendil-works/pi-coding-agent@1.4.0` from the cairn `node_modules/.pnpm` store, all fetched 2026-11-08.

## Patterns that recur

- **Waiting is a sub-state of "active", not a terminal state.** Codex puts `WaitingOnApproval` / `WaitingOnUserInput` as flags inside `Active`; Devin puts `waiting_for_user` / `waiting_for_approval` as `status_detail` under `running`; t3code ranks `Pending Approval` and `Awaiting Input` above `Working`. Approval and free-form input are always two distinct values. (Measured, rows above)
- **Answers are correlated by request id, not by "latest message".** Codex ops carry `id` + `turn_id`; Claude Code `defer` re-fires the same `tool_use` id on resume; t3code `runtime-request.respond` names `requestId`; Temporal's cookbook drops a decision whose `request_id` is not the pending one. Free-text replies (Devin messages, Copilot `@copilot`, Cursor follow-up runs) resume the session but not a specific question. (Measured)
- **Durable waits outlive the process.** Claude Code `tool_deferred` + `--resume`, Temporal `wait_condition`, pi-durable `waiting`/`sleeping`, Devin `suspended` + auto-resume on message, Claude cloud "answer when you come back, up to environment expiry". The in-memory callback forms (`canUseTool`, pi `ctx.ui.confirm`) are documented as pending indefinitely only while the process lives. (Measured)
- **Timeouts resolve to a defined outcome, rarely to a human escalation.** Codex `ReviewDecision::TimedOut` (action does not run), Temporal cookbook timeout result, Devin `inactivity` suspension, Copilot's 59-minute cap, Claude cloud environment expiry. No primary source showed a built-in "escalate to another person" chain. (Measured for the outcomes; Inferred for the absence of escalation)
- **Unattended mode removes the ability to ask instead of blocking.** Codex `AskForApproval::Never` returns failures to the model; Claude `-p --permission-prompts none` removes `AskUserQuestion` and tells Claude not to retry; Amp defaults to allow-all. (Measured)
- **Cancellation records a reason far more often than an actor.** Codex `TurnAbortReason`, OpenHands `ERROR_ACTION_NOT_EXECUTED_STOPPED` vs `..._ERROR`, Devin `user_request`, pi `aborted {reason}`, Cursor `CANCELLED`. Only Temporal records `identity` on cancel/terminate/signal events. (Measured)
- **Errors become a state transition with a reason string on the event stream.** OpenHands `AgentStateChangedObservation(reason=last_error)`, Codex `ErrorEvent` + `TurnAborted.error`, pi `RunFailure.detail`, Claude `system/api_retry` and `permission_denials`; Cursor's run object lacks an error field, with detail only on the SSE stream. (Measured)
- **Budgets end a run in an explicit, resumable way.** OpenHands raises its iteration/budget limits when the user resumes from `ERROR`; pi `turn_limit` is continuable; Codex `BudgetLimited` abort reason; Devin `max_acu_limit` and usage-limit suspension reasons. (Measured)
