# Cairn vs Claude Duet and the open field — 2026-11-24

Owner question: where does cairn stand against the other open-source projects, can it be called an open-source Claude Duet, should it focus on different directions, and what blocks launch sooner.

Evidence convention (same as [competitive-landscape-2026-11-23](competitive-landscape-2026-11-23.md), which this note extends rather than replaces): **Measured** = read first-hand in the cited page, source or API; **Inferred** = derived from linked observations; **Guess** = the rest. Repo metrics are a 2026-11-24 `gh api` snapshot: stars signal attention, `pushed` signals recency; neither measures active use.

**It is a personal chief-of-staff, not a coding-task orchestrator.** The closest Anthropic product to "one coordinator dispatching coding tasks to agents" is **Claude Code Projects** (public beta, Pro/Max/Ultra): one ongoing conversation that starts a thread per task, each thread usually a cloud session, parallel threads steerable from the phone, a "Waiting on you" surface, project instructions and shared memory, optional thread-on-your-computer via Remote Control. Measured: [claude-projects docs](https://code.claude.com/docs/en/claude-projects), fetched 2026-11-24. Adjacent primitives: [cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web), [scheduled tasks](https://code.claude.com/docs/en/routines), experimental [agent teams](https://code.claude.com/docs/en/agent-teams), [Managed Agents](https://platform.claude.com/docs/en/managed-agents/quickstart) for developers.

So "open-source Claude Duet" splits into two claims: the Duet attention loop (brief + background sweep + quiet outreach + approvals) and the Projects dispatch loop (coordinator + parallel threads). Cairn is compared against both below.

**Direct answer (Inferred):** cairn today is *not* an open-source Claude Duet — Duet's defining loop (morning brief, periodic outside-world sweep, reach out only when needed, per-action approvals on connected apps) is exactly the part cairn retired (the 08:00 digest was dropped in November; feature map marks report history read-only) or still has on the roadmap (#1784, #2522, #2488). What cairn *already is*: an open-source, self-hosted counterpart to **Claude Code Projects** — coordinator + parallel threads on your own machines — plus real slices of Duet (push digest, bound approvals, memory, one thread) that Duet cannot reciprocate on the code side (no repos, no local machines, single model).

**Shortest list of gaps to earn the claim:**

1. Outward morning brief built from the ledger (#2522) — the digest code was retired, the concept survives. M
2. Quiet-by-default push policy (#1784): notify only when a human is needed, fold the rest into the brief. S–M
3. Daytime outside-world sweep (#2488 watchdog): PR staleness, CI, deploy SHA, mail — deterministic checks that wake the model only on fire. M
4. One finished personal workflow end-to-end: mail triage → drafted reply → bound approval → sent receipt (connector is partial today). M
5. Phone surface good enough to approve from: polished paired mobile web; native iOS stays deferred. M

## 4. Where cairn should focus differently

Three directions, each with evidence:

1. **Code + personal affairs in one loop, under one approval mechanism.** Nobody else ships this: Duet cannot touch repos or local machines; Projects and the workbenches cannot do personal affairs; OpenClaw/Hermes do affairs but deliver no gated code; Multica is a team board. Cairn's action registry already binds approvals to named outward effects — the wedge is finishing *one* demonstrable personal workflow next to the repo workflow, not adding engines. ([spec 18 thesis](../spec/18-positioning-and-differentiation.md), [action registry](../../apps/server/src/services/action-registry.ts), [mail design](../design/mail-connector.md))
2. **Your machines, your subscriptions, your data — as a product feature, not a deployment option.** Every proprietary alternative keeps compute in its cloud (Duet, Projects, Cursor, Devin, Conductor-cloud); the open chat assistants run as the operator's user. Cairn's Runner/worktree/Seatbelt/orb plus write-only secrets with audit is the structural answer for the self-hoster. Sell the specific boundary, not "sandboxed everywhere" — Linux confinement is still a gap (#5401). ([confinement design](../design/2026-11-22-task-confinement-and-credentials.md), [Mac scope](../design/mac-session-confinement.md))
3. **Verifiable gates instead of promises.** The eval gate reads the exam from the merge-base checkout and protects its own config; the merge/step-claim protocols are TLA+-checked; the tested-SHA queue lands only green heads. No open workbench in the table ships an equivalent — it is the engineering moat and the answer to "why trust your agent". Keep it as capability proof, not as the pitch (the mandatory product merge gate is already removed). ([eval design](../design/eval-gate.md), [tested-SHA landing](../design/tested-sha-landing.md))

**Inferred — deprioritize:** more runtimes, more IM adapters, native mobile apps, team features, hosted compute. The crowd is already there; cairn loses nothing by conceding those rows.

## 5. What blocks a public launch, ordered

| # | Blocker | Why it blocks | Size |
|---|---|---|---|
| 1 | macOS notarization | Every new Mac user hits Gatekeeper's manual "Open Anyway"; kills the second-person funnel before first run. Owner action: Apple Developer Program ($99) + cert backup (owner actions 1–2). | S effort, hard gate |
| 2 | Clean-machine first result | The criterion is a stranger reaching a result unassisted in ~15 min; today that is unproven — npm on Mac/Windows needs owner-token steps, model connect and Runner readiness have failure paths a newcomer cannot read. | M |
| 3 | Launch copy vs shipped behavior | README/site still imply the mandatory merge gate and broader isolation; the gate was removed and Linux confinement is opt-in. Public launch on stale copy is a credibility bug. | S |
| 4 | One supported phone route | Paired web over tailnet is partial; Slack works, Telegram/WeChat await owner bot tokens. Ship one route, label the rest beta. | M |
| 5 | Windows/Linux story | Mac DMG only; Linux archive is build-from-source with systemd+bwrap requirements; Windows unsigned/nonexistent. Either publish the Linux archive and declare Windows out, or stay Mac-first explicitly. | M–L |
| 6 | The attention loop | If the launch pitch leans "personal assistant" (which the Duet comparison invites), items 1–3 of section 3's gap list are the product claim itself. | M |
| 7 | Public surface for feedback | 5 stars, 2 open issues, private roadmap; launch needs issues/discussions as the intake and a public launch checklist. | S |

**Inferred — fastest honest launch:** Mac-only, one repo workflow + one mail workflow, paired-web phone approvals, corrected copy, notarized DMG, two clean-machine proofs recorded. That is smaller than "finish the platform" and it is the only launch the evidence supports today.
