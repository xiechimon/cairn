## Cloak API, release and identity findings

1. **Read:** JS package version is `0.7.2`. Latest listed GitHub binary release is `chromium-v156.0.8078.47.1-pro`, published 2026-11-03; its public GitHub assets are `SHA256SUMS` and `SHA256SUMS.sig`, not the binary archive. The website advertises v156 for Linux x64, Linux ARM64, Windows x64 and macOS. Config supports Linux x64/arm64, macOS x64/arm64 and Windows x64; Windows ARM64 is not listed. **Unverified:** a current licensed download and launch on the actual target; listing is not proof of successful completion.
2. **Read:** `buildLaunchOptions({headless:false,...})` supports headed mode and returns `ignoreDefaultArgs: ["--enable-automation", "--enable-unsafe-swiftshader"]`. It defaults to headless true. `launchPersistentContext({userDataDir,...})` uses Playwright persistent-context launch and passes `persistentSeedArgs(...)` before building launch options. Merely calling `buildLaunchOptions` does not persist a fingerprint seed for a profile.
3. **Read:** persistent wrapper launches store decimal seed 10000–99999 in `<userDataDir>/.cloakbrowser-seed`; explicit `--fingerprint=...` (including `off`) or `stealthArgs:false` bypasses that mechanism. Missing seed creates one; corrupt seed warns and regenerates identity. Default nonpersistent argument construction generates a random seed on every call. **Inference:** direct binary/Rust launches must explicitly reuse the same durable seed for both agent and human phases; sharing cookies alone is insufficient. Preserve a valid seed rather than silently rotating it.
4. **Read:** defaults spoof `--fingerprint-platform=windows` on Linux/Windows and `macos` on macOS. Locale sets both `--lang` and `--fingerprint-locale`; timezone uses `--fingerprint-timezone`. Headed wrappers add `--ignore-gpu-blocklist` and normally `--start-maximized`. Wrapper defaults include `--no-sandbox`. **Inference:** freeze and reuse platform, locale, timezone and seed across handoffs, reconcile real desktop dimensions/fonts/GPU, and separately evaluate sandbox safety rather than copying defaults blindly. **Unverified:** actual reported fingerprint consistency across restarts and both CDP/no-CDP modes.
5. **Read:** the binary can be selected directly using its executable path; wrapper local override is `CLOAKBROWSER_BINARY_PATH`. Direct launch skips wrapper download/verification and may skip its denial-file error mapping and helper behavior. **Inference:** a provisioned executable is viable for both phases, but verified provisioning and license setup remain necessary; do not assume a plain path grants entitlement.

## Rust compatibility: exact boundaries

- **Read:** Rust launcher exposes executable_path, headless, profile and args, not a Playwright launch-options bag or a browser-environment map. It does not implement `ignoreDefaultArgs`. The base launcher does not add `--enable-automation`; it adds `--enable-unsafe-swiftshader` only when effectively headless. Headed mode avoids both of the specific flags Cloak's wrapper suppresses, but retains other agent-browser defaults. **Inference:** copying a JSON `ignoreDefaultArgs` property will not remove native defaults. The intended headed path avoids this particular incompatibility without inventing an unsupported option. Full parity with wrapper behavior is **Unverified**.
- **Read:** `actions.rs` lines 5494–5511 selects `connect_cdp_when_listening` and returns from that branch; it does not fall through to local Chrome launch on connection failure (`await?` propagates the error). `browser.rs` connect creates `browser_process: None`, discovers/attaches existing targets and enables CDP domains. `handle_snapshot` takes `mgr.client` and the active session into `snapshot::take_snapshot`; `handle_click` uses the same manager/client/session. **Inference:** explicitly supplying CDP to an independently launched headed Cloak process permits snapshots and actions without intentionally spawning another browser. No Cloak-specific protocol interoperability was executed.
- **Read:** normal `close` routes through `handle_close` and backend cleanup; browser manager `close_with_timeout` lines 1650–1668 sends `Browser.close` and waits/kills only when `browser_process.is_some()`. External CDP connections only close the client. **Inference:** normal close after external attach leaves the external browser running. This differs from tab-close actions, explicit raw CDP Browser.close, or an independently issued service stop; those are not protected by this rule.
- **Read:** `blocks_default_idle_shutdown()` returns true for an external connection or headed local browser; its comment explicitly says an explicit `AGENT_BROWSER_IDLE_TIMEOUT_MS` still applies. Local ChromeProcess Drop kills the owned process tree. **Inference:** neither default idle behavior nor external-close semantics proves Cairn daemon-restart independence; service ownership and Cairn teardown paths still require coordinator inspection.
- **Read:** Cloak's repository integration shell example says agent-browser cannot attach over CDP. That statement is stale for the pinned Rust version above; use pinned driver source rather than the example as compatibility authority.
- **Recommendation / Inference:** retain the owner-approved two-phase launch path. Use one Cloak engine/profile/stable fingerprint, but agent phase has CDP and human phase has no debugging port. Stop and wait for the outgoing process/profile lock to release before launching the next phase. A permanently CDP-attached browser is an available technical alternative, not the default handoff plan and not an override of the owner decision.

## License, secrets and update constraints

- **Read:** wrapper is MIT; binary is proprietary under BINARY-LICENSE. README and current site say latest build is free with an email-issued key and one concurrent session; paid tiers increase concurrent sessions. Website currently lists Solo 5, Team 20, Business 200 and Scale 2000 sessions. Source `ensureBinary` discards version pins for free plans; paid keys retain exact pin/rollback. README documents old keyless v146 (v145 on macOS) via wrapper <0.7 / JS 0.6, but says it is no longer updated.
- **Read:** license v1.3 still states latest-major access requires a paid subscription, while current README/site explicitly advertise latest free with a key. **Unverified / blocking:** reconcile this discrepancy with vendor terms before relying on a free entitlement for production. A website claim does not amend the pinned license by inference.
- **Read:** internal controlled browsing is allowed, and merely listing a dependency whose users download from official channels is not redistribution. Bundling, embedding, exposing browser functionality through an API, or providing third parties technical control over sessions/settings requires a separate OEM/SaaS agreement; no ordinary paid tier itself grants those rights. **Inference:** personal/internal deployment differs materially from shipping Cairn-controlled browser capability to customers. Confirm intended distribution and entitlement; do not bundle the binary in Cairn images/releases by default.
- **Read:** `buildLaunchEnv` injects `CLOAKBROWSER_LICENSE_KEY` into the browser child env when needed; default `~/.cloakbrowser/license.key` may be read directly by the binary. `CLOAKBROWSER_LICENSE_STATUS_FILE` communicates denial status. Param/custom-file keys need injection; an existing environment key is inherited. The binary performs operational license validation/concurrency monitoring. **Unverified:** behavior during prolonged license-server failure and an indefinitely resident session; closed-source binary prevents proving that policy from wrapper reads.
- **Recommendation / Inference:** keep entitlement resolution inside the trusted browser launch/provisioning boundary and inject only into the browser child. Do not export the key into the general agent shell, return it in tools, log launch options/env, or place it on argv. A same-UID shell able to read the license file or inspect the browser process environment can still retrieve it: browser-only env injection is not an isolation boundary. The coordinator must verify OS/service-account separation or explicitly record that unresolved threat; a global user-service environment is insufficient.
- **Read:** first official download verifies pinned Ed25519 signatures on SHA256SUMS, binds signed version to requested version, and verifies archive SHA256 before extraction. Verification errors are surfaced instead of masked by cached fallback. Transient fetch/download failure can fall back to an existing cached version. Local override bypasses this acquisition verification. Cached executable checks are not a fresh integrity attestation on every launch.
- **Read:** unpinned launches query latest with an hourly rate limit; `CLOAKBROWSER_AUTO_UPDATE=false` keeps a ready cached build and skips server lookup, but does not supply a missing first build. Exact paid pin bypasses latest selection. Free pins are ignored. **Recommendation / Inference:** provision and verify outside interactive agent commands, explicitly control update windows, record wrapper SHA/binary version/hash, and test an upgrade before selecting it. Do not mutate a running instance automatically. Free-plan freeze behavior in source is not a contractual promise of permanent support or rollback.

## Resident desktop recommendation and blocking checks

- **Read:** `Restart=always` restarts clean/nonclean exits, whereas `on-failure` does not cover all clean exits. Explicit `systemctl stop` or equivalent stop jobs suppress automatic restart; start-rate limits can also prevent recovery. Lingering keeps the user manager across logout and starts it at boot.
- **Inference:** separate three requirements: remove application-level idle/last-viewer shutdown, restart unexpected process exits, and keep desktop/browser service ownership independent of Cairn daemon lifecycle. `Restart=no` currently provides no crash recovery (deployment value supplied by coordinator). Existing `Linger=yes` already covers the logout hosting prerequisite, not those other requirements. Never promise literal availability through host power loss, suspend, OOM, license denial or explicit shutdown.
- **Recommendation / Inference:** maintain one desktop lifecycle path in HostDesktops/systemd, with no unattended/last-client idle stop and with a defined unexpected-exit restart policy. Preserve intentional lifecycle transitions needed for the owner-approved browser handoff; desktop persistence does not require a single immortal browser process. Coordinator owns exact Cairn file mapping and enumeration of stop/dispose/reconcile paths.

Blocking unknowns before implementation acceptance:

1. **Unverified:** vendor reconciliation of free-latest versus license text, entitlement for exact-version reproducibility, and OEM/SaaS scope for the actual delivery model. No payment or registration was performed.
2. **Unverified:** on the deployed Linux x86_64 desktop, authorized later probes must show headed rendering, durable profile and stable seed, matching platform/locale/timezone across agent-to-human-to-agent handoffs, no overlap/profile-lock race, and absence of a debugging listener during human use.
3. **Unverified:** pinned Rust snapshot, click/type and screenshot interoperability with the selected Cloak build; attach failure must remain a surfaced error, normal external close must leave its browser alive, and no unintended local browser may appear. These are source-supported hypotheses, not runtime passes.
4. **Unverified:** license/concurrency denial and network failure behavior, browser-only secret visibility, and upgrade/rollback entitlement. A resident browser consumes an active session even without an operator according to concurrency wording; exact accounting must be confirmed rather than assumed.
5. **Unverified:** coordinator must prove application idle paths no longer stop the desktop, user logout leaves it running, process crash recovers, and Cairn daemon restart reconnects without destroying desktop state. This note does not claim those Cairn changes already exist.

No promotional detection score is accepted as effectiveness evidence. Reduced automation recognition is an objective requiring authorized target-specific observation; it is not a guarantee of bypassing site controls. No reference-product UI study is required for this dependency verification.
