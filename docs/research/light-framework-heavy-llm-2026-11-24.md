## 2. Detailed Primary-Source Findings by Axis

### 2.1 Sub-Agent Handoff & Return

1. **Foreground vs. async-with-yield, and why Coordinator needs foreground-in-turn** `` `实测` `` / `` `推断` ``:
   - Goose (`summon.rs#L452-L545`, `subagent_handler.rs#L82-L187`) and Claude Code `-p`/SDK run foreground blocking tool calls (parallelism comes from the parent model issuing multiple tool calls in one assistant turn); OpenClaw (`sessions_spawn` + `sessions_yield`), Letta (`Agent`), Claude Code interactive (v2.1.302+), and Codex (`spawn_agent` + `wait_agent`) run async background children and wake or inject results back into the parent.
   - For Cairn's **Coordinator**, Cairn *already* owns an asynchronous durable task unit (`create_todo` / Cairn Tasks). What Cairn is missing is the **fast, in-turn sub-harness call** that executes and returns straight into the Coordinator's active turn without creating a task thread, worktree, or wake round-trip (`` `推断` ``). Foreground blocking tool calls (with parallel fan-out when the Coordinator emits multiple `subagent` calls in one turn) match Goose's `delegate` and `pi-durable`'s foreground `tx.createConversation({ ownership: { kind: "task", taskId } })` primitive directly.
2. **Fresh vs. Fork context (prompt-cache economics)** `` `实测` ``:
   - Claude Code (v2.1.302+ fork default), Codex (`fork_context: true`), OpenClaw (`context: "fork"`), and Letta (`fork_context: true` default) all support **forking the parent conversation** so the child hits the provider's prompt cache and sees recent context without the parent rewriting a long brief.
   - Hermes (`delegate_task`), Goose (`delegate`), and Amp (`Task`) start **fresh** by default to isolate context windows and prevent parent clutter from polluting the child.
   - Supporting **fresh by default + opt-in `fork` mode** (with automatic fallback to `fresh` when parent context is near compaction, as in OpenClaw `docs/tools/subagents/tool-reference.md#L94-L98`) captures both benefits (`` `推断` ``).
3. **Strict depth cap, bounded return payload, and output scanning** `` `实测` ``:
   - Goose (`summon.rs#L875-L877`), Hermes (`delegate_tool_config.py#L19`), and Codex V1 (`multi_agents/spawn.rs#L77-L83`) enforce **depth = 1** by default; OpenClaw caps fallback child returns at **8,000 chars/child** (`docs/tools/subagents/announce.md#L12-L89`); Claude Code runs **subagent output scanning** on every final report to defuse injected `<system-reminder>` / role tags ([sub-agents#subagent-output-scanning](https://code.claude.com/docs/en/sub-agents#subagent-output-scanning)).
   - Every product hides subagent raw intermediates from top-level thread lists and returns only a concise final result to the parent context (`` `实测` `` across all 7 agent runtimes).

### 2.2 Fixed Workflows vs. User-Defined Preferences

- **Unanimous convergence across all 7 agent runtimes** `` `实测` ``: **None** of Claude Code, Codex CLI, Amp, OpenClaw, Hermes Agent, Letta, or Goose hardcode a mandatory `plan -> confirm -> implement -> review` pipeline in product code.
  - At most, Claude Code and Codex offer a binary `Plan` mode toggle (`ModeKind::Plan`).
  - Repeatable multi-step processes are universally expressed as **user-editable Skills (`SKILL.md` / `agentskills.io`)**, **Declarative Recipes** (Goose YAML, OpenClaw optional `@openclaw/lobster`), **Plugins/Hooks** (Amp `agent.end`, Claude Code hooks), or **Dynamic Workflows** (Claude Code & Letta JS scripts).
- **Conflict with Cairn's current gates** `` `实测` `` / `` `推断` ``: Cairn's `SESSION_BRIEF` (`packages/shared/src/records/prompts.ts:226-237`) still forces a 4-stage ritual on every session step, `build-undelivered.ts:15-96` blocks completion with a mandatory `ask_user` whenever a code step produces no diff/PR, and `ci-loop.ts` / `pr-wakes.ts` / `research-stuck.ts` hardcode retry and stuck-research state machines. Following prior art means **replacing these hardcoded rituals with a light default brief and moving strict pipelines into editable user preferences/skills**.

### 2.3 Editable Prompts & Control Plane

- **Two proven patterns for exposing every control** `` `实测` ``:
  1. **Canonical plain-text files loaded in deterministic order** — OpenClaw (`AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `MEMORY.md`, editable in Control UI), Letta **MemFS** (git-backed `$MEMORY_DIR/*.md` with root-in-prompt / subdir-lazy split), Hermes (`SOUL.md` + frozen `MEMORY.md`/`USER.md` + cache-preserving skill delta notes), Claude Code (`CLAUDE.md` + `.claude/rules/*.md` + `.claude/agents/*.md`).
  2. **Explicit override hooks & prompt-cache boundary discipline** — OpenClaw (`docs/concepts/system-prompt.md#L9-L71`) and Hermes (`website/docs/developer-guide/prompt-assembly.md#L38-L120`) strictly separate the **stable editable prefix** (above the prompt-cache breakpoint) from volatile per-turn state (below it), so user edits or memory updates never thrash prompt caching mid-session.
  - Goose (`prompt_manager.rs#L53-L57`), Codex (`config_toml.rs#L261-L286`), Claude Code (`--system-prompt`), and Amp (`omitDefaultSystemPrompt`) all allow replacing or appending to the base system prompt directly.

### 2.5 Default Read / Write / Delete Permissions

Primary sources split cleanly into two philosophies `` `实测` ``:
- **Autonomous-first without local OS sandbox** (Amp, Goose `Auto`, OpenClaw `sandbox: "off"`, Letta CLI `unrestricted`) — zero friction, relies on cloud VMs (Orbs / Cloud Sandboxes) or opt-in LLM classifiers / plugins for safety.
- **OS-sandbox-first** (Codex `workspace-write` via Seatbelt/Landlock; Claude Code opt-in Seatbelt/bwrap + `auto` LLM classifier + hard critical-path `rm` protection that no mode bypasses).

**Notice the gap across ALL 8 reference products** `` `实测` ``: **none of them ships a Trash-by-default recoverable delete layer** — every one executes `rm` directly (at best prompting or blocking `/`, `~`, `$HOME` like Claude Code's critical-path guard and Hermes's dangerous-command approval). Cairn already has a stronger macOS Seatbelt credential boundary than most reference products (`confine-seatbelt.ts`), so combining **open non-credential reads + workspace/user-folder writes + recoverable Trash deletes + unified hardline guard across all harnesses** puts Cairn ahead on both low friction and safety (`` `推断` ``).

## 3. Pattern That Fits Cairn & Recommended Changes

1. **Adopt light-framework defaults and retire hardcoded scaffolding** (`` `推断` ``):
   - **Coordinator sub-agents (A)**: Single foreground `subagent` tool executing on the Coordinator's own runtime by default (`pi-durable` task-owned child conversation for in-server turns; native `Agent` or child session for daemon turns), depth 1, fresh default + optional `fork`, 8K output cap + tag scanning, inline collapsible trace in chat.
   - **Workflows as preferences (B)**: Strip the mandatory 4-step ritual from `SESSION_BRIEF` (`packages/shared/src/records/prompts.ts:226-237`), relax `build-undelivered.ts` false-blocks, remove legacy `plan`/`confirm`/`review`/`verify` deadwood, and offer `plan -> implement -> review` as an optional editable Skill.
   - **Editable Control Plane (C)**: Centralize all active system prompts, step briefs, tool policies, and automation caps into a layered, versioned Control Registry (`default -> team -> project`) with UI viewing, diffing, editing, and Reset-to-default, while keeping the prefix-cache boundary intact (`apps/server/src/coordinator/runtime/volatile.ts`).
   - **Smallest Real RSI Loop (D)**: Reuse Cairn's existing SQLite signals (`build_feedback`, steers, `build.errorMessage`, `gate_verdict`, `action_journal`) with a delta-watermarked, tool-restricted reflector (OpenClaw/Hermes/GEPA synthesis) producing versioned proposals/diffs with 1-click Undo and hard refusal on security/permission/ruler surfaces.
   - **Open-Read / Light-Write / Trash-Delete Permissions (E)**: Build on `confine-seatbelt.ts` and the parallel `open-confine` lane (without duplicating Coordinator `user_computer_shell` or `attach_file`): keep open reads minus credentials, allow writes inside workspace + approved user folders, route task deletes to recoverable Trash by default, wire `command-gate` into `claude-code` (`canUseTool`), and wire Linux `bwrap` into `createSessionConfiner`.
