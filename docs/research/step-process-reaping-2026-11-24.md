# Killing a step's whole process tree — detached and setsid'd grandchildren included

Research date: 2026-11-24. Question: agent sessions started by the Cairn daemon spawn dev servers, builds, Playwright workers and browsers; when the agent exits or the daemon dies, the grandchildren reparent to launchd (macOS) / init and keep running. What do existing systems use to guarantee *nothing a step started survives the step*?

Marks per claim: **measured** = read the file, ran the probe or fetched the source first-hand this session; **inferred** = derived from measured; **guessed** = unverified lead. In-repo claims cite paths.

## TL;DR

1. **There are exactly three durable mechanisms**: a *container boundary* the kernel enforces (PID namespace, cgroup, Windows Job Object), a *reaper ancestor* the kernel reparents orphans to (Linux `PR_SET_CHILD_SUBREAPER`, FreeBSD `PROC_REAP_ACQUIRE`, container shim), and an *env marker + process-table scan* (GitHub Actions' `RUNNER_TRACKING_ID`). Process-group kill alone — what most supervisors do — never catches a descendant that called `setsid`. `measured`.
2. **macOS has no cgroup and no subreaper.** Bazel's commit message states it verbatim: "Unfortunately I couldn't find any feature like this on macOS, so this is the only OS that will still have this race condition." launchd's per-job cleanup is process-group based too. On macOS the reachable guarantee is layered: pgroup kill + env-marker scan + a watchdog/janitor using `EVFILT_PROC NOTE_EXIT` + a stale-marker sweep at daemon boot. `measured`.
3. **Linux is nearly solved inside Cairn already**: the daemon runs under a `systemd-run --user` unit (`KillMode=control-group` default) and `launchConfined` already creates per-launch transient units with `BindsTo` + `KillMode=control-group` + `ExitType=cgroup` + a `populated=0` proof. The gap is coverage: not every step-root process goes through it. `measured` (`apps/daemon/src/{supervisor,backend/confine}.ts`).
4. **The env-marker scan is validated at industry scale** by the GitHub Actions / Azure Pipelines runner, and its documented failure modes are precise: a process that *clears its own env* escapes, and a single snapshot-then-kill pass misses children forked mid-pass. Both are worth copying *and fixing* — the marker approach is exactly what `process-tree.ts` already implements. `measured`.

## Platform primitives

### macOS

- **No subreaper, no cgroup.** Bazel's commit is the canonical statement; proc-janitor's README confirms no unprivileged process-creation event exists (`EndpointSecurity` needs the `com.apple.developer.endpoint-security.client` entitlement; `NOTE_TRACK` returns `ENOTSUP`). `measured`.
- **`EVFILT_PROC`/`NOTE_EXIT`**: `kqueue` watches *any* same-uid pid's exit, unprivileged — the macOS substitute for `PR_SET_PDEATHSIG`. Used by sglang ([PR #27190](https://github.com/sgl-project/sglang/pull/27190)), Bun's `BUN_DIE_WITH_PARENT` ([PR #29859](https://github.com/oven-sh/bun/pull/29859)) and proc-janitor. `measured` (sources read).
- **`posix_spawn` attrs**: `POSIX_SPAWN_SETPGROUP` + `posix_spawnattr_setpgroup` give the child its own pgroup; Darwin extension `POSIX_SPAWN_SETSID` (0x0400) gives a new session. Node's `spawn({detached:true})` on non-Windows "will be made the leader of a new process group and session" — i.e. `setsid`, so `kill(-child.pid)` hits its whole group. `measured` ([xnu spawn.h](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/spawn.h), [Node docs](https://nodejs.org/api/child_process.html#optionsdetached)).
- **Reading another process's env**: `sysctl(KERN_PROCARGS2)` / `ps -E` works same-uid *except for SIP-restricted platform binaries*. measured probe on this Mac (macOS 27.2.1, arm64): `CAIRN_PROBE_TEST` visible via `ps -E` on Homebrew `python3`, `/usr/bin/python3` and `/opt/homebrew/bin/node`; **invisible on `/bin/sleep`** (Apple-restricted binary shows argv only). Consequence for the marker scan: leaked dev servers, vite, Playwright, browsers — all unsigned — expose the marker; a detached Apple-shipped binary does not. (The earlier `2026-11-22-task-confinement-prior-art.md` reported `ps -E` returning nothing; this probe shows env *is* readable for non-restricted binaries — the difference is the target's signing, not the OS version.)
- **launchd** reaps only the job's process group (`launchd.plist(5)` `AbandonProcessGroup`). Orphans reparented to launchd sit there forever. `measured` (man page read).
- Private `responsibility_*` spawn attrs exist for TCC attribution (which app "owns" a process); they carry no kill semantics — guessed, noted as an unexplored lead only.

### Linux

- **`PR_SET_CHILD_SUBREAPER`** (3.4+): orphaned descendants reparent to the nearest marked ancestor, keeping the ppid chain — and `waitpid` visibility — inside the subtree. Cairn already launches computer commands through a python shim that calls `prctl(36,1)` (`contained-spawn.ts:4-12`). `measured`.
- **cgroup v2**: delegation is the supported unprivileged path — `systemd-run --user` is the packaged form. `cgroup.kill` (5.14+) atomically SIGKILLs every process in a cgroup (closes the fork-during-kill race); `cgroup.events` `populated=0` is the emptiness proof Cairn already asserts (`confine.ts:354`). `measured` ([kernel doc](https://docs.kernel.org/admin-guide/cgroup-v2.html), [LWN](https://lwn.net/Articles/855924/), [containerd book](https://thecontainerdbook.com/chapters/part-2/05-cgroups-v2)).
- **PID namespace teardown**: `--unshare-pid` (already in `confinementArgs`, `confine.ts:231`) makes the first child ns-PID1; kernel kills the namespace when it exits. `measured`.
- **`pidfd_open`/`pidfd_send_signal`** (5.3/5.1): an fd pinned to the process — `ESRCH` after death, immune to pid reuse; only fully race-free if opened while the process is provably alive (e.g. right after `fork`). Node exposes no pidfd API — reachable via a small helper or a `/proc` fd. `measured` ([pidfd_open(2)](https://man7.org/linux/man-pages/man2/pidfd_open.2.html), [pid reuse analysis](https://dixon.cx/blog/linux-pidfds-closing-pid-reuse-race.html)).
- **`/proc/<pid>/environ`** is readable same-uid (subject to `hidepid`/`ptrace_scope`); the marker-scan input `process-tree.ts` already uses. `measured`.

### Windows

Job Objects (table row above): `KILL_ON_JOB_CLOSE` + assign-before-resume covers detach/`CREATE_NEW_PROCESS_GROUP`/`start /b`; nothing escapes unless the job allowed `BREAKAWAY`. Cairn's daemon targets macOS+Linux first; if Windows lands, this is the single mechanism to build around. `measured` (MS docs).

## The pattern that fits Cairn

**On Linux, the cgroup-per-step model — the one Cairn already built for confinement — is the answer**, because it is the only mechanism on the table that catches *everything a step spawned* including setsid'd, double-forked and reparented processes, and it survives daemon death (`BindsTo=` the daemon unit; the daemon's own `KillMode=control-group` sweeps anything that stayed in its cgroup). Prior art agreement: systemd `control-group` (the default `KillMode`), containerd's `runc kill --all` over `cgroup.procs`, kubelet's per-pod cgroup kill+destroy, and Codex's `--unshare-pid` namespace mode all implement the same "kernel holds the membership, userspace never enumerates" idea. The daemon already gets the outer shell of this for free on Linux via `supervisor.ts`'s `systemd-run` path.

**On macOS there is no membership primitive, so the honest design is layered and it must include a sweep** — matching the only two systems that really solved host-side leak cleanup there: GitHub Actions' marker scan (industry scale, documented escapes) and proc-janitor's `NOTE_EXIT` watchdog. Concretely:

1. **Spawn every step-root process detached** so `kill(-pid)`/pgroup legs of `ProcessTree` actually fire (Claude sessions currently spawn *without* `detached` — `claude-code.ts:1405` — while hooks, pi-host, ACP adapters and computer commands already pass `detached: true`).
2. **One marker env name for everything a step starts** (`CAIRN_SESSION_TREE` exists; extend it — or a step-level variant — to ACP adapters, pi host, workspace hooks, orb-spawned helpers), so `ProcessTree`'s `ps -E`/`/proc/*/environ` scan finds escapees regardless of ppid/pgid.
3. **The `ProcessTree` kill pass needs a second sweep after the kills** — GH issue #4601 shows the single-pass version leaves children forked mid-pass; `ProcessTree.kill()` already loops `collect(true)` up to 20× while signalling, so the fix is mostly ensuring *all* callers go through it (hooks and ACP don't today).
4. **A daemon-boot sweep**: scan for processes carrying a Cairn marker whose owning session/step isn't live in this daemon's journal, and kill them — this is what turns "the daemon was SIGKILLed" from an unbounded leak into a bounded one, and it's the direct analogue of the existing `sweepOrphans` worktree pass (`machine-loop.ts:831`).
5. **Optional per-step janitor** (the Bazel/proc-janitor shape): a tiny detached helper spawned with each step that watches the daemon's pid via `EVFILT_PROC`/`NOTE_EXIT` and, on daemon death, kills the step's pgroup + every marker holder it can see. It is strictly better than today's nothing for daemon-SIGKILL on macOS, but it can itself be killed — so it must be *belt-and-suspenders over the marker sweep*, never the only mechanism.

**Windows** (future): Job Object with `KILL_ON_JOB_CLOSE`, create-suspended → assign → resume. Single mechanism, no scan.
