# Self-deploy starvation: primary-source comparison

Research date: 2026-11-09. Scope: Host ops (systemd, SQLite and the repository's deployment/runtime implementation). Docker and Tailscale are not used by this deploy mechanism, so their documentation does not decide its drain behavior. “Measured” means read firsthand in this research; it does not imply production execution.

| Source | Measured behavior | Trade-off / implication | Primary reference |
|---|---|---|---|
| systemd service lifecycle | Measured: restart performs stop then start. An explicit service stop suppresses `Restart=always`; a stop timeout can escalate to the final kill signal. | Inferred: an asynchronous signal request alone does not establish either safe drain completion or claim resumption. | [systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html#ExecStop=) |
| systemd process termination | Measured: default `KillMode=control-group` sends termination to the unit's remaining processes; timeout can escalate to SIGKILL. `mixed` initially signals only the main process, but still kills remaining processes later. | Inferred: stopping the current daemon unit before draining can terminate its running child steps. Changing KillMode alone cannot guarantee a bounded, safe deploy. | [systemd.kill](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html#KillMode=) |
| SQLite online backup | Measured: the backup API supports copying an online database while other users continue operating; completed backup is a snapshot. | Inferred: obtaining a consistent rehearsal backup does not inherently require stopping daemon claims. Restoring an old snapshot after new writes still requires the existing write-preservation rollback policy. | [SQLite Online Backup API](https://sqlite.org/backup.html) |
| Current Cairn deploy | Measured: `assert_idle` requires zero claimed non-digest steps unless all are stale past the wait threshold. Both core units are stopped for every deploy. | Inferred: healthy continuous traffic has no finite completion bound; the stale-step escape cannot solve it. | [deploy-self.sh](https://github.com/xiechimon/cairn/blob/2d61872c2491a18a896c6dce3f0b373d02b0ac3f/scripts/ops/deploy-self.sh) |
| Current daemon loop | Measured: stream disconnects reconnect with backoff; stream `shutdown` calls `stop`. Claim failures retry. `stop` sets `stopping`, aborts claim and stream controllers, and completion waits for in-flight work. | Inferred: a server transport restart need not stop the step backend, but completion RPCs during downtime and recovery must be tested before claiming restart survival. Existing terminal `stopping` is not a reversible pause. | [machine-loop.ts](https://github.com/xiechimon/cairn/blob/2d61872c2491a18a896c6dce3f0b373d02b0ac3f/apps/daemon/src/machine-loop.ts) |
| Proposed Cairn repair | Inferred: preserve the daemon for a proven server-only artifact change; for a required daemon replacement, acquire a reversible first-class claim pause before waiting for a safe point. | Inferred: avoids idle starvation without changing configured runtime eligibility. A deadline must return a clear nonzero result if no safe point exists; forcibly killing healthy work is not a safe bounded deploy. | Sources above; prospective implementation must prove its own state transitions. |

## Recommendation and proof obligations

Inferred: first prove one real daemon step survives a same-port server restart, including reconnect, subsequent heartbeat and final completion. A stream-only fake proves less than this requirement.

Inferred: classify a server-only deployment from actual daemon/runtime/shared dependency artifacts, not solely from `apps/daemon/src` paths. If daemon replacement is necessary, use one reversible pause mechanism observed by every claim entry path, including an already pending long poll. Pause must remain separate from `enabledRuntimes`.

Inferred: use explicit states `accepting -> draining -> safe -> switching -> accepting`, with `draining -> accepting` on timeout or pre-switch failure. Prevent the check/claim race with the same synchronization boundary that publishes pause. Resume in trap/finally, read the state back, and preserve a nonzero exit on failed resume. Recovery after process interruption must remove or expire abandoned ownership without clearing another deploy's pause.

Inferred: a finite wait bound guarantees an attempt terminates; it guarantees successful deployment only if a step has a proven bounded safe point. If work can run forever, the honest timeout outcome is abort-and-resume rather than silently killing a healthy step. Document this limit and test it.

Inferred implementation areas: `scripts/ops/deploy-self.sh`, `scripts/ops/deploy-watch.sh`, matching operational tests and `docs/ops/self-deploy.md`; the chosen first-class gate may additionally touch daemon loop/state or protected server machine claim files. Keep the hold gate. Remove the superseded stale/idle mechanism rather than retaining two deployment policies.
