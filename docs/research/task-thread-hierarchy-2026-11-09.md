# Research: visual tiers in an agent task thread (2026-11-09)

Question. Cairn's task thread renders every system row as a full-size line: workspace hook output, the git credential-source line, the multi-line `构建步兜底报告` with a raw git error, and a rework notice that repeats the same git error all sit at the same weight as the agent's answer, and the answer's `[#3411](url)` link renders literally (owner screenshot `~/.cache/ui-refs/task-thread-hierarchy-2026-11-09.webp`). How do agent products separate the user's message, the agent's answer, tool calls, setup and hook diagnostics, system notices, and errors in one transcript?

Evidence labels: **measured** = seen or read first-hand in this run (running product, official doc page, or source at a pinned commit); **inferred** = derived from measured facts; **guess** = everything else, not used as a design basis. Screenshots live in `~/.cache/ui-refs/thread-hierarchy-priorart/`.

## Summary

1. Every product that was measured keeps exactly two reading tiers in the thread: the user's message and the agent's prose at full contrast, and everything else (tool calls, background work, notices) as one-line summaries in a secondary colour, collapsed by default (measured: claude.ai/code, ChatGPT, t3code source, Multica source; Claude Code and Amp docs say the same for their CLIs).
2. Raw hook and setup output never enters the conversation in the products whose docs cover it. Claude Code writes successful hook stdout only to the debug log and shows a one-line `<hook name> hook error` notice on failure; Cursor sends hook output to a separate output channel (measured, docs). t3code shows worktree setup as one card that collapses to a summary when done (measured, source).
3. A failure inside the work trace is shown as a red count inside a neutral summary line (claude.ai/code: summary `…, 1 failed` stays secondary; the red `1 failed` appears only in the expanded group, measured). Only run-level failures get a stronger treatment (t3code: an inline error row in `text-destructive` plus a thread banner, measured in source; that design can show the same error twice, inferred).
4. Hover on trace rows changes text colour, not background (claude.ai/code `group-hover/tool:text-primary`, measured; t3code shows only the timestamp on hover, measured).
5. Agent prose always renders markdown links as real anchors (claude.ai/code: `rgb(23,87,172)`, underline at 40% alpha, 3px offset, measured; ChatGPT and t3code too).

## Which pattern fits cairn

The claude.ai/code pattern fits, with Claude Code's hook rule and t3code's setup card as its two extensions (inferred from the table):

- Cairn already follows claude.ai/code for the work summary line and the status line, and `docs/research/chat-markdown-polish-2026-11-08.md` measured the same `StatusLine` values. The gap is not the styling of `StatusLine`; it is that setup output, credential info and failure dumps are routed into it as if they were status sentences (measured: `mappers.ts:747` pushes any non-empty system text as a `note`).
- The root cause is at the data source: the daemon and server write diagnostics as untyped `system` text, so the mapper cannot tell a hook dump from a notice. The fix is to give these rows a `kind` (the mapper already parses JSON system rows with `systemKindOf`, `mappers.ts:291`), not to hide text by pattern in CSS (inferred).
- The serif answer is kept: claude.ai chat sets the answer in serif as the reader's setting (measured 2026-11-08). The Code tab sets it in sans (measured today), so the serif is not what separates tiers there; colour and folding are. Nothing here argues for dropping cairn's serif voice.

## Recommendation

Two reading tiers plus folded evidence. "Primary" = foreground colour, `text-card-title`; "secondary" = `StatusLine` (sans, `--text-secondary`, one line, truncate); "folded" = inside a collapsed work group, body in mono `text-meta` when expanded.

Errors appear exactly once: in the failure block. The work summary does not repeat the reason, the rework notice links to it, and no banner is added (t3code's banner plus inline row is the duplication to avoid, inferred).

Failure modes to cover with tests before the change (for the implementing session): a hook dump still rendered as a `note`; a failed hook not visible without expanding (summary must still say a hook failed); the failure reason text appearing twice in one transcript; a rework row without a link target when the failure row is missing (older builds); old untyped system rows in stored conversations still rendering (migration or a typed fallback for the exact old prefixes); `[text](url)` inside code spans not becoming a link.

## Not covered

- Claude desktop Code tab, Codex cloud task view, and Cursor's IDE agent panel were not operated (reasons in the table). Their rows rest on docs or a stand-in and are not a design basis beyond what the docs state.
- Dark mode values were not measured this run.
- claude.ai/code was measured on one live session; an in-thread hook error notice and an API error line were not present there, so the Claude Code CLI docs are the only evidence for those.
