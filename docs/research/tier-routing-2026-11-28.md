# Tier Routing Prior Art

- Date: 2026-11-28
- Workstream: `tier-routing`
- Scope: How coding agents and routers pick models per task automatically without asking the user, and how Cairn should derive tiers from any connected model source's catalog.

## Prior-art comparison

All claims below come from first-party product documentation fetched on 2026-11-28 and existing source code read directly in this repository.

| Product | How it chooses a model per task | Trade-offs | Primary source & evidence |
|---|---|---|---|
| Cursor Auto / Cursor Router | `[observed]` A server-side classifier evaluates each agent request's task type and complexity when Auto (`Balance` or `Intelligence`) is selected, sending simple requests to fast, low-cost models and complex multi-step work to frontier models. Respects enterprise model allowlists and prompt-cache continuity. `Cost` mode falls back to legacy Auto billing; `Balance` and `Intelligence` bill per routed model and hide the chosen model in responses by default unless an admin enables display. | Opaque curated model pool tied to Cursor's hosted routing classifier and Cursor billing/token rate; cannot operate autonomously over arbitrary user-supplied provider catalogs without Cursor's classifier service. | [Cursor Router Docs](https://cursor.com/docs/cursor-router), [Models & Pricing](https://cursor.com/docs/models-and-pricing) |
| Amp (`smart`/`rush` -> Mode Dial & Staff Pick) | `[observed]` Originally shipped `rush` (a fast/cheap model such as Haiku with lighter prompt/tools for small, well-defined edits: 67% cheaper and 50% faster per token, but slower/costlier on complex refactors due to mistakes) vs `smart` (frontier model). Later evolved to a Staff Pick default plus an Effort dial (`low`/`medium`/`high`/`ultra`) and explicit per-thread overrides ("the model you pick for a thread always wins"). Avoids mid-thread model switches because prompt caches are per-model. | Manual mode selection puts the burden of judging task complexity on the user up front; `rush` had to be picked manually per thread. | [Rush Mode](https://ampcode.com/news/rush-mode), [Model Selector](https://ampcode.com/docs/model-selector) |
| OpenRouter Auto (`openrouter/auto`, `openrouter/auto-code`) | `[observed]` Five-stage pipeline: (1) narrow model pool by guardrails, ZDR, capabilities, and BYOK keys; (2) fast decision model rates task type, complexity, speed sensitivity, and codebase needs; (3) routing policy weighs rating against live pricing, prompt cache status, and benchmarks within an optional `cost_tier`; (4) provider routing applies health, latency, and fallback rules; (5) keeps sessions sticky while progressing smoothly and exposes the selected model in `response.model`. | Adds an extra classifier call per request and depends on OpenRouter's centralized benchmark/spending telemetry across its aggregated catalog. | [OpenRouter Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router.md) |
| Claude Code model aliases | `[observed]` Exposes semantic tier aliases (`haiku` for simple tasks, `sonnet` for daily coding, `opus` for complex reasoning, `fable` for longest/hardest work, plus `opusplan` which uses `opus` in plan mode and switches to `sonnet` for execution). Resolves each alias per provider to the newest version in that family, while explicit model names or `ANTHROPIC_DEFAULT_*_MODEL` env overrides always win. | Single-vendor family aliases; does not automatically classify task difficulty (the user or caller must choose `haiku` vs `sonnet` vs `opus`). | [Claude Code Model Config](https://code.claude.com/docs/en/model-config.md) |
| Devin (`Adaptive`, `Fusion`, CLI models) | `[observed]` `Adaptive` analyzes each prompt and routes routine/simple tasks to fast, efficient models and complex tasks to stronger frontier models while preserving prompt caching across turns and respecting org model allowlists. `Fusion` pairs a frontier lead model with a cost-efficient sidekick (`SWE-2` / `SWE-2 Flash`). Explicit `/model` or `--model` overrides always win. | Proprietary router coupled to Cognition's hosted model catalog and ACU/credit metering; enterprise admins must enable `Adaptive`. | [Devin Adaptive](https://docs.devin.ai/cli/adaptive.md), [Devin CLI Models](https://docs.devin.ai/cli/models.md) |
| Cairn (current & proposed) | `[observed]` Today `packages/shared/src/capability-routing.ts` hardcodes 4 models (`gpt-6.1-sol`, `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`) behind `isAutoRoutedSessionRule` in `apps/server/src/services/routing-rules.ts`; teams using any API provider or Antigravity/Devin get zero automatic tiering (`routing_rule` runs one default model for everything). **Proposed**: derive 2–3 tiers (`easy`/`standard`/`hard`) automatically from each connected source's catalog metadata (cost, reasoning/thinking depth, context window, generic size/class tokens, family dedup) with zero hand-kept model list and zero new settings; let the Coordinator judge `difficulty` when creating tasks; stay sticky once claimed; fall back across tiers and sources on quota/429/unavailable errors using the existing fallback notice; honor explicit task `model` pins. | Relies on catalog metadata quality and Coordinator task-creation judgment; heuristic metadata tiering for unpriced custom relays can misrank unusually named models if the relay supplies no cost or thinking metadata. | `packages/shared/src/capability-routing.ts`, `apps/server/src/services/routing-rules.ts`, `apps/server/src/services/providers.ts` |

## Pattern that fits Cairn

1. **Zero-config, invisible to the user**: Unlike Cursor's optimization mode picker or Amp's Effort dial, Cairn's owner explicitly rejected adding user-facing tier settings (`"不应该让用户知道，让coordinator里自行挑选"` / "should not let the user know, let the Coordinator choose on its own", and `"如果用户接入了一个provider就自动从中抽2～3个作为简单/中等/复杂任务"` / "when a user connects a provider, automatically pick 2–3 of its models for simple/medium/complex tasks").
2. **Zero-extra-latency difficulty judgment**: Unlike OpenRouter Auto's extra classifier LLM call, Cairn already runs the Coordinator on every user request before `create_todo` (`apps/server/src/services/coordinator-request.ts`, `packages/shared/src/protocol/chief-tools.ts`). Passing `difficulty` (`easy` | `standard` | `hard`) directly in `create_todo` costs zero extra round trips, while `classifyDifficulty` in `packages/shared/src/capability-routing.ts` remains the deterministic fallback for board-created or GitHub-imported tasks.
3. **Catalog-driven, source-agnostic tier selection**: Instead of Claude Code's vendor-specific aliases or Cursor/Devin's curated pools, Cairn already normalizes every connected API provider (`provider` table + `pi-ai` builtin metadata) and subscription runtime (`claude-code`, `antigravity`, `devin`) in `apps/server/src/services/providers.ts` and `apps/server/src/coordinator/runtime/provider.ts`. Ranking models by catalog metadata (`cost`, `reasoning` / `thinkingLevels`, `contextWindow`, parameter/class signals, plus `newestPerFamily` snapshot deduplication from `packages/shared/src/records/provider-presets.ts`) generalizes across every current and future provider without hand-kept model lists.
4. **Sticky in-flight execution & visible auditability**: Matching Amp and OpenRouter Auto, an active claimed/started step stays on its chosen model (`decideStepRoute` in-flight guard) to preserve prompt caches and avoid mid-session drift, while `step.ranModel` continues to show the exact model that ran each task.
5. **Cross-tier and cross-source fallback**: Matching OpenRouter Auto's provider/model fallback layer, if a tier model is rate-limited, over quota, dead, or unsupported by an older runner, Cairn falls back to the next tier on the same source or another connected source, recording `step.fallback` and emitting the existing `"已换备用模型"` (`Switched to fallback model`) notice.

## Concrete recommendation & code areas

- **`packages/shared/src/tier-selection.ts`** (exported via `packages/shared/src/index.ts`): pure metadata-driven `selectSourceTiers` and `tierFallbackOrder` with no hardcoded model list.
- **`packages/shared/src/capability-routing.ts`**: generalize `routeWork` from the 4-model `RANKING` to ordered `(provider, modelId)` tier+source candidates with `desired` and `fellBack` flags while preserving `classifyDifficulty` and in-flight stickiness.
- **`packages/shared/src/protocol/chief-tools.ts`** & **`apps/server/src/services/chief.ts`**: instruct Coordinator to silently judge and supply `difficulty` on `create_todo` without exposing tier mechanics to the user.
- **`apps/server/src/coordinator/runtime/provider.ts`**: expose `catalogModelMetadata` from existing `pi-ai` catalog helpers for cost, context window, and reasoning metadata enrichment.
- **`apps/server/src/services/source-tiers.ts`**: unify connected source discovery (`provider`, `claude-code`, `antigravity`, `devin`), catalog metadata enrichment, and cross-source fallback chain assembly.
- **`apps/server/src/services/step-route.ts`**, **`apps/server/src/services/routing-rules.ts`**, **`apps/server/src/services/model-fallback.ts`**, **`apps/server/src/services/machine-finish-step.ts`**: route all unpinned worker steps via source tiers, suppress fallback notices on normal tier selection, emit the existing fallback notice when falling back across tiers or sources (pre-claim or mid-step), and skip candidates an old runner cannot execute.
