# What Cairn's computer card should show once the built-in VM is deleted

Date: 2026-11-24. Status: read-only research, no product code changed.

Question: with Cairn's built-in Linux VM and task sandbox being deleted so agents operate each user's own machines directly (local desktop on macOS, Windows, or Linux, plus remote runners on macOS, Windows, Linux X11/Wayland including Arch, user-owned VM guests such as Hyper-V/Parallels/UTM, and headless machines), **what should Cairn's computer card show when an agent operates a computer, and how?**

Evidence labels used throughout this report:
- **measured** — verified first-hand in this session against this repository's source/docs, local host output (`macOS 27.2.1`, `arm64`), or a directly fetched official primary document or open-source repository file.
- **inferred** — derived directly from measured facts, documented API contracts, or credible secondary summaries where the primary page blocked automated fetches.
- **guessed** — unverified hypothesis where primary sources are silent or closed-source.

---

## 1. The newcomer, why this matters, and scenarios

### The newcomer

Imagine someone who installs Cairn today on their own computer — a Mac, a Windows PC, or a Linux desktop (Ubuntu, Arch, etc.) — and has never heard of VNC, ScreenCaptureKit, DXGI, PipeWire, or CDP.

- **Where they meet the computer card and why it is there:** They click the laptop icon in the top-right corner of Cairn to open the Computers side panel (`apps/web/src/board/machines-panel.tsx`, measured). That card is their dashboard for every machine they connect to Cairn: the computer they are sitting at, any remote Mac/Windows/Linux workstation, any VM guest (Hyper-V, Parallels, UTM), and any headless server. They open it to answer three plain questions: *"Is this machine online? What is the agent doing on it right now? How do I watch, step in, or stop it?"*
- **What they must already know:** Nothing about display servers, virtual monitors, or remote desktop protocols. They only need to understand that an agent operating a real machine works inside the apps/browser they allow, and that on OSes without background GUI input (notably physical Windows desktops) the agent shares their cursor while acting and stops the moment they move the mouse.
- **Accounts, payments, keys, and OS grants asked of them:** No paid cloud sandbox, no third-party remote-desktop subscription, and no API key for screen viewing. OS permissions depend only on what that machine's OS requires:
  - **Browser work (all OSes):** zero OS screen-recording permissions for an agent-owned browser window over CDP; optional browser extension pairing only if the user opts into their personal signed-in Chrome.
  - **macOS native apps / remote Mac view:** **Accessibility** (to inspect/click native UI) and **Screen Recording** (optional for text-only observation; required for screenshots or remote viewing).
  - **Windows physical desktop:** no initial OS wizard for standard apps, but elevated/admin apps and UAC Secure Desktop prompts stay blocked by Windows security (UIPI) unless the user handles them directly.
  - **Linux (X11, Wayland/Arch, headless):** zero Wayland portal popups or real-desktop permissions when running GUI/browser work inside Cairn's isolated headless compositor (`Xvfb` / headless `labwc`).
- **Where state is stored:** Machine enrollment metadata and tool-call activity live in the user's own Cairn server database; screenshots captured during agent steps are transient tool results (never captured while the user holds takeover control). No screen pixels leave the user's own infrastructure to a third-party vendor relay unless the user configures their own remote access path.
- **Where they get stuck and what they see when it fails:**
  - *macOS Screen Recording denied or expired (macOS 15+ monthly re-prompt):* Text-first browser and Accessibility work still runs, while visual preview shows a plain one-line notice ("Screen Recording needed" + button to open System Settings) instead of a broken black canvas.
  - *Locked machine, Session 0 Windows Server, or headless Linux without a display:* The card explicitly states why no live desktop exists ("Screen is locked", "Headless server — browser & shell only", or "VM session disconnected") rather than spinning forever on "Connecting to screen…".
  - *Windows physical desktop conflict or UAC prompt:* Before foreground GUI control starts, the card clearly flags `Using screen (foreground — move mouse to pause)`, and if a UAC prompt appears, pauses with `Needs you at this PC (UAC prompt)`.

### Why deleting the built-in VM breaks today's card

Today (`measured` in [machines-panel.tsx](../../apps/web/src/board/machines-panel.tsx#L381-L490) and [computer-screen.tsx](../../apps/web/src/board/computer-screen.tsx#L76-L220)), every online machine card mounts an **always-on `16:10` noVNC canvas** streamed over WebSocket from `x11vnc` on the VM's private Xvfb desktop. That worked only because the VM desktop was an empty, isolated `#1e1e2e` Linux box. Putting the same always-on whole-screen stream onto users' **real machines across every OS** fails in four concrete ways:

1. **Same-device Hall-of-Mirrors and wasted resources (macOS, Windows, and Linux):** Whenever a user opens the Computers panel on the same machine the card represents, streaming that machine's whole real screen into a 300 px box inside the Cairn window is redundant (they are already staring at that screen), causes infinite Droste recursion unless the OS capture filter excludes Cairn's own window, and burns continuous GPU/CPU/battery encoding frames. On macOS 15+, always-on capture additionally triggers recurring monthly Screen Recording warnings (measured: Cairn's Mac build is ad-hoc signed with `identity: '-'` and `hardenedRuntime: false` in [electron-builder.yml](../../apps/desktop/electron-builder.yml#L43-L46), so it cannot hold Apple's restricted `com.apple.developer.persistent-content-capture` VNC entitlement).
2. **Privacy leak across real desktops:** Unlike an empty VM, a real Mac, Windows PC, or Linux desktop holds chat DMs, email, bank tabs, password managers, and OS notifications. An always-on whole-screen thumbnail (also visible from paired web/phone clients) turns every enrolled machine into live desktop surveillance.
3. **Most work is text-first and headless:** Cairn already operates computers text-first — Layer 1 browser DOM/accessibility, Layer 2 native accessibility tree, Layer 3 screenshots as last resort ([computer-operation-layers.md](../design/computer-operation-layers.md), measured). Streaming 30 fps desktop pixels while an agent runs shell commands or reads DOM text is pure waste.
4. **Heterogeneous fleets cannot all show a "real screen":** Headless Linux servers have no display; Windows Server / Session 0 and disconnected Hyper-V Enhanced Sessions break DXGI; locked Macs block ScreenCaptureKit; Linux Wayland (including Arch/Hyprland) requires portal consent and lacks uniform remote-input portals. One hardcoded VNC box guarantees broken cards across a real multi-OS user base.

## 2. What Cairn's computer card does today (baseline)

All facts in this section are **measured** from the current worktree source:

- **Card layout & always-on stream:** [apps/web/src/board/machines-panel.tsx](../../apps/web/src/board/machines-panel.tsx#L381-L490) renders `MachineScreenSurface` inside every `MachineCard` whenever `desktopControlOnline(machine, computer)` is true and no VM download is pending. `MachineScreenSurface` ([apps/web/src/board/computer-screen.tsx](../../apps/web/src/board/computer-screen.tsx#L85-L142)) immediately opens a `view` WebSocket via `@novnc/novnc` (`RFB`) through Cairn's server gateway ([apps/server/src/services/computer-screen.ts](../../apps/server/src/services/computer-screen.ts#L82-L120)) to the daemon's `OutboundComputerScreens` ([apps/daemon/src/computer/screen-channel.ts](../../apps/daemon/src/computer/screen-channel.ts#L36-L115)) and `x11vnc` Unix sockets (`view.sock` / `vnc.sock`, [apps/daemon/src/computer/host-desktop.ts](../../apps/daemon/src/computer/host-desktop.ts#L127-L128)).
- **Hover-to-control in fullscreen:** Clicking the preview opens `ComputerScreenDialog` ([apps/web/src/board/computer-screen-dialog.tsx](../../apps/web/src/board/computer-screen-dialog.tsx#L71-L175)), wired to `useScreenHoverControl` ([apps/web/src/board/screen-hover-control.ts](../../apps/web/src/board/screen-hover-control.ts#L7-L10)): hovering the pointer for **150 ms** acquires an exclusive `control` lease (switching to interactive VNC) and leaving releases it after **800 ms** (or **60 s** during login handoff).
- **Login takeover & model blinding:** `TakeoverCard` ([apps/web/src/chief/takeover-card.tsx](../../apps/web/src/chief/takeover-card.tsx#L94-L215)) surfaces `request_takeover` in the Coordinator thread with a 15-minute countdown and an `打开画面` button; while the owner holds control, the server refuses `browser_snapshot` and screen capture ([computer-login-handoff.md](../design/computer-login-handoff.md#L53-L76)).
- **Own-Mac & Owner-Chrome plumbing already in the repo:** Cairn already bundles `agent-desktop` inside the Mac app ([electron-builder.yml](../../apps/desktop/electron-builder.yml#L34-L35)) behind `AgentDesktopHostScreen` ([apps/daemon/src/computer/host-screen.ts](../../apps/daemon/src/computer/host-screen.ts#L158-L250)) — which refuses raw coordinate clicks without a proven target receiver and refuses any window showing Cairn itself — and supports `Browser MCP` for driving the owner's Chrome in background tabs ([browsermcp-owner-chrome.md](../design/browsermcp-owner-chrome.md)).

## 3. Options compared

Beyond the four base options (A–D), four hybrids capture the realistic design space: **H1** (action-triggered surface + on-demand live stream), **H2** (scoped target window/tab capture), **H3** (virtual display / second desktop session), and **H4** (foreground takeover with input lock / curtain / explicit takeover).

| Option | What the computer card shows | User experience | Mouse & keyboard stealing | Privacy | Latency & bandwidth | Per-OS feasibility & engineering cost |

| **A. Whole real screen, live (always-on, local or remote)** | Continuous live mirror of the machine's physical display(s) inside the card, fullscreen on click. | **Poor locally, noisy remotely.** On your own Mac, causes Hall-of-Mirrors recursion and duplicates what you already see; 4K/5K desktops shrink to unreadable mush in a 300 px card. Useful only for remote full-desktop triage. | Does not solve stealing by itself — if paired with global input (`CGEventPost`, `SendInput`, `ydotool`), agent hijacks the user's cursor/focus. | **Worst.** Streams personal apps, DMs, banking tabs, notifications, and passwords continuously to every paired client; macOS 15+ triggers recurring TCC bypass nags. | **Highest.** VNC/RFB on HiDPI: ~2–15 Mbps continuous; WebRTC H.264: ~1–6 Mbps continuous + constant GPU encode battery drain. | **Patchy.** Breaks on headless Linux, Windows Session 0, locked macOS, UAC Secure Desktop, and Wayland without portal consent. |

### Three non-obvious traps revealed by primary sources

1. **The macOS Virtual Display Myth:** Adding a virtual display on macOS via `CGVirtualDisplay` (used by DeskPad and BetterDisplay) creates another rectangle in WindowServer's coordinate space, **not** a second pointer or keyboard focus (`measured` in [DeskPad README](https://github.com/Stengo/DeskPad/blob/main/README.md) and [Cua macOS internals](https://cua.ai/blog/inside-macos-window-internals)). Any `CGEventPost` click on that virtual monitor yanks the user's real cursor off their physical monitor and steals focus. True background driving on macOS comes from **per-process / Accessibility delivery + per-window `ScreenCaptureKit`**, not from a virtual monitor.
2. **The Accidental Hover-Control Hazard:** Cairn's current fullscreen dialog acquires an exclusive control lease after 150 ms of mouse hover ([screen-hover-control.ts](../../apps/web/src/board/screen-hover-control.ts#L7-L52), measured). On a disposable VM that felt slick; on a real Mac or Windows runner, brushing the pointer across a watch window would silently grab control and inject stray scroll/key events into the live machine. Real machines need an **explicit `Take over` click** (with `Give back` to resume, matching ChatGPT/Codex Cloud, Manus, Mariner, and Cursor).
3. **Why Cursor and Amp diverged on macOS vs. Linux desktop sharing:** Both Cursor (`--share-desktop` is Linux-only, isolated TigerVNC+Xfce — [cursor.com/docs/cloud-agent/self-hosted/computer-use.md](https://cursor.com/docs/cloud-agent/self-hosted/computer-use.md), measured) and Amp (`--desktop` shares the real Mac display on macOS, but spawns an isolated headless `labwc` Wayland compositor on Linux — [ampcode.com/docs/cli/runners](https://ampcode.com/docs/cli/runners), measured) independently reached the same architectural split: **on Linux, never capture the user's real Wayland session — spawn a private headless compositor; on macOS, there is no clean lightweight private GUI session, so operate on the signed-in session with explicit opt-in and permission controls.**

## 4. Per-OS feasibility: which systems can show a real screen and which cannot

### Quick verdict: can it show a real screen?

- **YES (reliable real screen):**
  - **Unlocked macOS with a display (or dummy plug / `CGVirtualDisplay`)** — via ScreenCaptureKit, once the user grants Screen Recording (and re-confirms monthly on macOS 15+ without Apple's restricted VNC entitlement).
  - **Unlocked Windows interactive console session** (physical PC, Parallels/UTM Windows guest, or Hyper-V Basic Session / active console) — via WGC or DXGI, **except** UAC Secure Desktop & elevated windows without `uiAccess=true`.
  - **Linux X11 (Xorg) desktop session** — via `XShmGetImage` / `XDamage` / `x11vnc`, no consent dialog.
  - **User-owned VMs with a logged-in desktop** (Parallels Window mode, UTM QEMU/SPICE or `VZGraphicsDisplay`, Hyper-V with active console) — isolated from host input.
- **CONDITIONAL / FRAGILE (real screen exists, but capture or input often breaks):**
  - **Linux Wayland desktop (Arch/Hyprland, Sway, GNOME, KDE)** — `xdg-desktop-portal` `ScreenCast` + PipeWire requires interactive user consent via a picker dialog; `restore_token` persistence varies by portal backend; `xdg-desktop-portal-hyprland` lacks native `RemoteDesktop`/`libei` input; Wayland lock/login screens cannot be captured without privileged DRM workarounds. **Better path:** run an isolated headless compositor (`Xvfb` or `labwc` + Waymote) so the user's real Wayland screen isn't needed at all!
  - **Hyper-V Windows guest using Enhanced Session Mode (RDP over VMBus)** — works while VMConnect/RDP is attached, **freezes/blanks DXGI** when the user disconnects Enhanced Session unless an Indirect Display Driver (IDD) is installed or the session is returned to the console via `tscon`.
- **NO (cannot show a real screen):**
  - **Headless Linux servers** (SSH-only, no Xorg/Wayland compositor running) — no real screen exists. Can only show an **agent-owned browser viewport (CDP)** or a **daemon-started virtual compositor (`Xvfb` / headless `labwc`)**.
  - **Headless Windows / Windows Server in Session 0** (daemon running as a Windows Service with no logged-in interactive user session) — DXGI fails (`DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`) and WGC is unsupported across Session 0 isolation. Can only show headless browser (CDP) unless an interactive user session + Virtual Display Driver (IddCx) is configured.
  - **Locked, FileVault-at-boot, or display-sleeping macOS** (including headless Mac mini sitting at loginwindow with no monitor/dummy plug) — ScreenCaptureKit cannot capture across the lock screen or create frames without an active graphical display. Only a privileged Apple Authorization Plug-in (like ChatGPT's "Locked use") can temporarily unlock behind a curtain.

## 6. Five good ideas for Cairn

1. **Same-Device vs. Remote-Viewer Split ("Focus locally, stream remotely")**
   Stop treating "the computer right in front of the user" and "a remote runner (or viewing any machine from a phone)" as the same widget. Whenever a user views Cairn on the **same machine** the agent is operating (whether macOS, Windows, or Linux), never stream a live video mirror of that machine's whole screen inside the Computers panel — show a crisp live activity line (`Chrome · github.com — clicking "Export"`), an optional step thumbnail of the target tab/window, and a **`Show window` / `Pause`** button that jumps straight to the real local window. Reserve live streaming strictly for **remote machines** and **remote clients** (phone, tablet, another computer).

2. **Target-Scoped Capture by Default ("Window or Tab, Never the Whole Monitor")**
   Whenever Cairn *does* show pixels (step keyframes on the card, or an on-demand remote `Watch` stream), capture **only the specific browser tab** (`CDP Page.startScreencast`) or **single target app window** (`ScreenCaptureKit` `SCContentFilter(desktopIndependentWindow:)` on macOS; `Windows.Graphics.Capture` per-HWND on Windows). Never stream the whole desktop by default. This simultaneously eliminates Hall-of-Mirrors recursion on every OS, keeps private apps/notifications/password managers off the wire, and makes a 300 px card thumbnail actually readable. Keep a `Full screen` switch only inside the enlarged remote viewer for multi-window debugging on remote desktops and VM guests.

3. **Action-Triggered Step Keyframes + On-Demand WebRTC (Retire Always-On noVNC)**
   Replace the always-on `@novnc/novnc` connection per card with a three-gear pipeline that works across every OS:
   - **Gear 0 (Idle):** Nothing captured, no dark box on the card.
   - **Gear 1 (Agent acting):** Push lightweight WebP/JPEG keyframes **only when GUI/browser tool calls execute** (~0.5–2 fps burst, 30–80 KB/frame) with a client-drawn synthetic cursor dot + 1-line step pill (Antigravity's pattern). Zero continuous video encoding, zero idle OS capture prompts, works cleanly over mobile/Tailscale.
   - **Gear 2 (User clicks `Watch` or `Take over`):** Spin up an on-demand interactive stream — **CDP screencast + synthetic input** for browser-only sessions (universal across all OSes, including headless servers), or **WebRTC H.264/WebCodecs** (Waymote on Linux headless `labwc`, ScreenCaptureKit→WebRTC on macOS, WGC/DXGI→WebRTC on Windows and VM guests) — and tear it down the instant the viewer closes.

4. **OS-Honest Isolation Ladder (Zero Fake Virtual Displays; Headless Compositor on Linux)**
   Work *with* each OS's actual windowing model instead of fighting it:
   - **macOS:** Text-first + background browser (CDP / extension tab group) + background native apps (`AXUIElement` / `agent-desktop` / Cua ladder) + single-window ScreenCaptureKit. Skip `CGVirtualDisplay` (private API + still steals the single global pointer).
   - **Linux (X11, Wayland incl. Arch/Hyprland, and headless servers):** Never touch the user's real Wayland desktop or trigger `xdg-desktop-portal` pickers for routine agent work. Run an isolated headless compositor per scope (**keep Cairn's existing `Xvfb` path now; evaluate migrating to Amp's open-source headless `labwc` + Waymote WebRTC stack**). That makes X11 desktops, Arch/Hyprland Wayland desktops, and headless Linux servers behave identically with zero cursor stealing and zero portal popups.
   - **Windows & user-owned VMs (Hyper-V, Parallels, UTM):** Background CDP + UIA where available; for raw GUI driving on a physical Windows PC, be explicit (`Foreground mode — takes mouse & keyboard`) and **auto-pause immediately if the physical user moves the mouse**. Inside a Hyper-V/Parallels/UTM VM runner, foreground driving is naturally isolated from the host user.

5. **Explicit Click-to-Take-Over + Soft-Yield + Model Blinding (Drop Hover-Control)**
   Replace Cairn's 150 ms hover-to-take-control ([screen-hover-control.ts](../../apps/web/src/board/screen-hover-control.ts#L7-L52)) with an **explicit `Take over` / `Give back` button** (matching Codex Cloud, Manus, Mariner, and Cursor):
   - **On the same machine (macOS, Windows, or Linux desktop):** `Take over` pauses the agent, blinds capture, and raises the real local app/browser window (or opens the isolated Linux compositor viewer if the browser/app lives inside `Xvfb`/`labwc`); a compact `You're in control · Give back` bar in Cairn resumes the agent.
   - **On any remote machine (or from a phone/tablet):** `Take over` acquires the exclusive lease, pauses the agent, blinds all screenshots/snapshots/playback history (Mariner's blank-playback rule, already half-built in Cairn's `computer-login-handoff.md`), and enables input inside the enlarged stream.
   - **Host safety escape:** Whenever an agent uses foreground input on a physical desktop (e.g., Windows `SendInput` or explicit macOS foreground fallback), show a subtle non-stealing status pill on that desktop (`Cairn is driving <App> — move mouse or Esc×3 to pause`) and yield instantly on local user input — no invasive DLL input-lock hooks.

## 7. Product recommendation: one design for every user and every OS

**Adopt Hybrid H1 + H2 ("Quiet Card + Action-Triggered Scoped Surface + On-Demand Stream") as Cairn's single product design across every OS.**

There are no platform-specific modes or toggles for users to learn: **every computer card obeys one contract**, while each OS runner fulfills that contract using the cleanest native mechanism that OS actually supports.

### The one card contract (same UI for every user and every machine)

1. **Gear 0 — Idle (all machines, all OSes):** Delete the always-on `MachineScreenSurface` preview box from `MachineCard`. An idle machine renders one clean row: OS icon, online dot, machine name, strain badge when strained, and menu. Zero dark empty boxes, zero idle video/VNC streams, zero unprompted OS screen-capture nags.
2. **Gear 1 — Active Surface (only while an agent is operating a browser or GUI on that machine):** The machine row expands a compact collapsible panel showing:
   - **One status line:** target app or origin + current action verb (`Chrome · github.com — clicking "Merge"`, `Excel — reading sheet`), plus a `Pause` button and, when foreground input is active, an explicit `Using cursor` indicator.
   - **Scoped step thumbnail (16:10):** updated **only on GUI/browser tool calls** from the **target tab (CDP)** or **target window (ScreenCaptureKit / WGC / isolated Linux compositor)** — never the user's whole desktop, never Cairn's own window — with a client-drawn synthetic cursor dot at the last click point.
   - **Context-aware primary action (viewer location, not OS preference):**
     - **Same machine** (user is viewing Cairn on the same machine whose native window/browser is on screen): **`Show window`** (focuses the real local window/tab; for login/takeover, pauses + blinds the agent + focuses the local window, with a `Give back` button — no redundant VNC mirror). *(Exception: on Linux where GUI runs inside an isolated headless compositor, `Show window` opens that compositor's local viewer.)*
     - **Remote machine or remote client** (any remote runner, or viewing your desktop from a phone/tablet/browser): **`Watch`** (opens Gear 2 enlarged on-demand stream) and **`Take over`** (explicit click — acquires exclusive lease, pauses agent, blinds model and history, enables interactive input until `Give back`).
3. **Gear 2 — On-Demand Enlarged Stream (opened only when user clicks `Watch` or `Take over`):**
   - Defaults to the **scoped target surface** (CDP browser screencast for browser tasks; single-window stream or isolated Linux desktop for app tasks), with an explicit **`Full screen`** switch for multi-window troubleshooting on remote desktops and VM guests.
   - Uses **explicit `Take over` / `Give back`** (retiring 150 ms hover-to-control) and keeps `TakeoverCard` in the Coordinator thread ([takeover-card.tsx](../../apps/web/src/chief/takeover-card.tsx)) as the primary human-in-the-loop prompt.
4. **Honest capability degradation (no silent hangs):** When a machine cannot provide a screen or input (locked Mac, Windows UAC/Session 0, expired macOS Screen Recording, disconnected Hyper-V Enhanced Session, headless SSH box without browser), the card states the exact reason and recovery step in one line while keeping shell and text-first tools running.

### Phased rollout (smallest slice first, zero new user settings)

- **Phase 1 (ships alongside VM deletion — works across all OSes on day 1):**
  - Remove the always-on card noVNC canvas; render the quiet Gear 0 row when idle.
  - Render Gear 1 **action-triggered step keyframes** in the card (reusing the images Cairn's `browser_*`, `host-screen.ts`, and `desktop-screen.ts` already capture on tool calls — minimal daemon changes).
  - Switch `ComputerScreenDialog` from 150 ms hover-to-control to **explicit `Take over` / `Give back`**; on same-device local handoffs (macOS/Windows), focus the real local window instead of opening a VNC modal.
  - Keep Cairn's existing Linux isolated `Xvfb` desktop for Linux (X11, Wayland/Arch, headless) on-demand `Watch` / `Take over`.
- **Phase 2 (cross-OS live browser + scoped window streaming):**
  - Add on-demand **CDP `Page.startScreencast` + input** so **every OS (macOS, Windows, Linux, VMs, headless servers)** gets fast, low-bandwidth interactive browser `Watch` / `Take over` with zero OS screen-recording permissions.
  - Add on-demand single-window live capture (`ScreenCaptureKit` on macOS, `Windows.Graphics.Capture` on Windows) when a remote viewer clicks `Watch` on a native app.
- **Phase 3 (WebRTC full-desktop transport across all runner OSes):**
  - Replace noVNC/x11vnc for full-desktop remote `Watch` / `Take over` with WebRTC H.264/WebCodecs: evaluate open-source **Waymote + headless `labwc`** on Linux, native `ScreenCaptureKit`→WebRTC on macOS, and `WGC`/`DXGI`→WebRTC on Windows and VM guests.

### Open product decisions & spikes before implementation

1. **Card interaction contract:** Confirm removing the always-on idle preview box and replacing 150 ms hover-to-control with explicit `Take over` / `Give back` across all OSes. (Recommended: **yes**.)
2. **Release signing & OS permissions (distribution work, never user settings):**
   - **macOS:** Moving from ad-hoc signing (`identity: '-'`) to Developer ID + notarization stabilizes Accessibility/Screen Recording grants across app updates and is a prerequisite if Cairn ever applies for Apple's `com.apple.developer.persistent-content-capture` entitlement.
   - **Windows:** Decide whether the Windows runner stays standard-integrity (UIA + foreground `SendInput` for non-elevated apps, pause on UAC) or later ships a code-signed installer in `%ProgramFiles%` with `uiAccess="true"` for elevated windows.
3. **Linux compositor baseline (`Xvfb` vs. headless `labwc` + Waymote):** `Xvfb` works across every Linux distro today (Ubuntu LTS, Debian, Arch, headless servers); `labwc` + Waymote gives modern WebRTC H.264/WebCodecs + Wayland clipboard, but requires `labwc >= 0.9.0` / `wlroots >= 0.19.3` (available on Arch and Debian 14 / Ubuntu 26.10, not Ubuntu 24.04 LTS — measured in [Amp Runners docs](https://ampcode.com/docs/cli/runners)). Recommend keeping `Xvfb` as universal baseline in Phase 1–2 and piloting `labwc` + Waymote as an automatic upgrade when `labwc >= 0.9.0` is present.
