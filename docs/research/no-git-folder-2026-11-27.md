# Prior-art research: Plain local folder projects (no-git) with shadow repo and copy-on-write (2026-11-27)

Question: how do coding agents and workspace managers track diffs, run tasks safely, isolate parallel work, and undo changes on a plain local folder without mutating or requiring a user `.git` directory?

## Comparison

## Pattern that fits Cairn

Cairn runs multiple autonomous worker tasks concurrently against a single `local` project (`apps/daemon/src/workspace.ts`) while keeping the owner's local folder clean and free of unexpected `.git` metadata. Neither DuskBot nor Gemini CLI nor Cline isolates parallel tasks: all three operate in-place on one working tree. By pairing DuskBot's sanitized shadow repository with macOS APFS copy-on-write clones (`cp -c -R`), Cairn gives each task on a normal-sized plain folder an instant isolated working directory (`<workspacesRoot>/<conversationId>`) at near-zero disk overhead, computes diffs in the shadow repo, and uses `git merge-tree --write-tree` to 3-way merge changes back into (or cleanly undo them from) the real folder while preserving concurrent user edits and sibling-task deliveries.

For folders exceeding `2 GiB` after built-in excludes (where even CoW directory tree metadata cloning or multi-GB index staging per task would degrade UX), Cairn degrades gracefully to serialized one-task-at-a-time execution in place with a silent pre-task shadow snapshot and safe 3-way delta undo.

## Concrete recommendation and code areas touched

1. **Shared contracts (`packages/shared`)**:
   - `packages/shared/src/plain-folder.ts` & `packages/shared/src/node/plain-folder-path.ts`: shared exclude list (`PLAIN_FOLDER_EXCLUDES`, `isPlainFolderExcluded`), `protectedFolderReason`, `PLAIN_FOLDER_HUGE_BYTES` (`2 GiB`), `PLAIN_FOLDER_GIT_TIMEOUT_MS` (`120_000`).
   - `packages/shared/src/records/project.ts` & `packages/shared/src/git-ops.ts`: add `protected_folder` and `not_directory` to `PROJECT_LOCAL_ERROR_REASONS`, extend `PreparedWorkspace` with optional `plainFolder` metadata and `release()` hook.
   - `packages/shared/src/protocol/machine-wire.ts` & `rest.ts`: add `localFolderAction` (`undo` | `merge`) step command/report schemas, `plainFolder` completion metadata on `MachineDoneBody`, and `POST /api/builds/:id/undo`.
2. **Daemon (`apps/daemon/src`)**:
   - `apps/daemon/src/shadow-repo.ts`: shadow git initialization, stripped `GIT_*` env + private `GIT_INDEX_FILE`, `CACHEDIR.TAG` detection, exclude-aware size probe, APFS `cp -c` CoW cloning with fallback and `ENOSPC` cleanup, 120 s timeout disable, `git merge-tree --write-tree` 3-way merge and undo, safe `diff-tree` delta application.
   - `apps/daemon/src/workspace.ts`, `step-workspace.ts`, `step-closing-git.ts`, `step-deliver.ts`, `step-done-body.ts`, `step-local-folder-action.ts`, `runner.ts`: wire plain-folder `isolated` vs `in-place` prepare/lease/commit/merge-back/diff/undo into the step lifecycle without disturbing existing local git worktree behavior.
3. **Server (`apps/server/src`)**:
   - `apps/server/src/services/git.ts`: reject protected folders on project creation; support plain-folder file listing/reading/README/branches without `.git`; attach `plainFolder` state to `GET /api/builds/:id/changes`.
   - `apps/server/src/services/local-folder-action.ts`, `build-merge-request.ts`, `routes-builds.ts`, `machine-claim.ts`, `machine-finish-step.ts`, `step-queue.ts`, `runner-offline.ts`, `build-stop.ts`, `build-abandoned-sweep.ts`: enqueue, claim, and settle `undo`/`merge` actions for plain folders.
4. **Web (`apps/web/src`)**:
   - `apps/web/src/api/hooks.ts`, `board/thread-changes.ts`, `board/side-chat.tsx`, `i18n/en.ts`: render the single `"Undo this task's changes"` (`撤销此任务的改动`) button and conflict/undone state inside `ChangesCard` for plain-folder builds.
