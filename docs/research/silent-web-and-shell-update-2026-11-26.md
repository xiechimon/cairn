# Silent Web-Bundle Refresh and Quiet Desktop-Shell Updates (2026-11-26)

> **Question.** How do web-backed desktop applications and production web apps keep users on the latest web UI and desktop shell without persistent "New version available" toasts or attention-seeking sidebar update dots—and what guards are required so silent reloads never drop drafts, IME composition, open dialogs, or active streams? This note is Step 1 (prior-art research) for Cairn's **Option A (Unified Quiet Updates)**.
>
> **Evidence marks.** Every substantive claim is marked inline as:
> - **`实测`** — read or executed first-hand in this session (upstream GitHub source at a named path, local macOS `.app` bundle / `app.asar` inspection, live `claude.ai` inspection in the owner's Chrome via `browsermcp` + production JS bundles, or Cairn's own source/tests).
> - **`推断`** — derived directly from `实测` evidence and verifiable.
> - **`猜测`** — everything else.
>

## 1. For someone who installed Cairn today

If Option A (Unified Quiet Updates) ships, a newcomer who installed Cairn today—whether using the Mac desktop app (`apps/desktop`) or opening Cairn in a browser (`apps/web`)—should almost never have to think about "updating the web page" vs. "updating the desktop app":

- **Where they meet it & why it is there:**
  - **Web UI updates (browser and desktop shell):** When the Cairn server deploys a newer web build (`apps/web/dist`), Cairn checks the served entry script quietly in the background and swaps to the new page automatically at safe moments—when the tab is hidden, when you switch back to Cairn, or on a clean navigation/idle boundary—without popping a permanent `"有新版本 · 点此刷新"` toast across your workspace (`推断`).
  - **Desktop shell updates (Mac app):** The desktop app downloads and verifies signed updates in the background and installs them quietly when Cairn quits or sits idle (screen locked, no input, no active turn/step/dialog), without keeping an ochre dot or `"离开时自动更新到 …"` badge parked in the sidebar footer during normal operation (`实测` baseline [idle-update.ts](../../apps/desktop/src/idle-update.ts) + `推断` Option A).
  - **Where you still see version/update controls:** You can always inspect the connected server and app versions or trigger a manual check/install in **Settings → Account / About** (`apps/web/src/routes/account-page.tsx`). Only **actionable problems**—such as a failed install, an unsupported read-only `/Applications` path, or a desktop shell whose bridge is too old for the server—surface an inline `"更新 Cairn"` / `"Retry"` prompt (`推断`).
- **What you must know / accounts, keys, payments:** None. No extra accounts, API keys, or payments are required. Updates use the connected Cairn server's existing `/assets/*` and `/` HTTP origin for web bundles, and Cairn's existing signed GitHub Releases feed (`DESKTOP_MANIFEST_URL`) for desktop shell bundles (`实测` [main.tsx](../../apps/web/src/main.tsx), [desktop-update-while-closed-2026-11-25.md](./desktop-update-while-closed-2026-11-25.md)).
- **Where data is stored:**
  - Browser / WebView reload-loop guard timestamp: `sessionStorage['cairn.staleBuildReloadAt']` (`实测` [stale-build-reload.ts](../../apps/web/src/stale-build-reload.ts)).
  - In-progress composer drafts: `localStorage` + debounced server draft sync (`useServerDraft` / `DraftSync`) and `cairn-chief-outbox` IndexedDB for Coordinator sends (`实测` [draft-sync.ts](../../apps/web/src/overlay/draft-sync.ts), [outbox.ts](../../apps/web/src/chief/outbox.ts)).
  - Desktop shell update metadata: `<userData>/update-state.json` and `update.lock` (`实测` [version-skew.md](../design/version-skew.md)).
- **Where they can get stuck or what they see when it fails:**
  - If a chunk fetch fails (`vite:preloadError`) or a new deploy lands while a page is open, `sessionStorage` limits automatic reload to once per `30 s` (`RELOAD_GUARD_MS`). If the reload still fails (for example, server unreachable or reverse-proxy cache mismatch), Cairn stops reloading rather than looping and lets the user retry manually (`实测` [stale-build-reload.ts](../../apps/web/src/stale-build-reload.ts)).
  - If a background or active-session reload happens while an unsent message, open dialog, IME composition, or unsaved settings form is present, Option A's reload guards hold the reload and preserve user input instead of wiping work (`推断`).
  - If the desktop shell cannot self-update (`unsupported`: `not-in-applications`, `read-only`, `development`) or hits an update error, Cairn still surfaces that specific blocker clearly rather than hiding it (`实测` [desktop-update.tsx](../../apps/web/src/board/desktop-update.tsx)).

## 3. Why Option A Fits Cairn's Server-Owns-Web-UI Architecture & Code Areas Touched

### 3.1 Architectural fit (`docs/design/version-skew.md`)

In Cairn, **Server owns Web UI** (`实测` [version-skew.md](../design/version-skew.md#L40)):
- Both the browser and the Electron desktop shell load `apps/web/dist` directly from the connected server's origin (`apps/server`), never from a stale web bundle frozen inside `Cairn.app`.
- Consequently, **two independent update clocks** exist:
  1. **Server / Web UI clock** (fast: server restarts or deploys ship new hashed Vite assets `/assets/index-*.js`, while `apps/web` runs in open tabs or Electron windows).
  2. **Desktop Shell clock** (slower: `apps/desktop` updates via signed GitHub Releases, staged in background and applied on quit, `createIdleWatch`, or closed-app updater).

Keeping loud, persistent notifications on both clocks violates Cairn's UX principles in [`AGENTS.md`](../../AGENTS.md) (*"the system carries the complexity — what it can decide it decides, what it can do for the user it does, and what is useless right now does not appear"*):
- When the web bundle updates, asking a user to click `"有新版本 · 点此刷新"` interrupts flow for something the app can switch into silently at the next safe boundary (navigation, blur/background, idle, or `vite:preloadError`) (`推断`, matching `claude.ai`'s `reload-on-nav` + `vite:preloadError` pattern).
- When the desktop shell downloads an update in the background, `createIdleWatch` (`apps/desktop/src/idle-update.ts`) and `before-quit` already apply it automatically (`实测`). Showing an ochre dot on `DesktopUpdateButton` in the sidebar footer for routine `available` / `ready` states teaches users to click a button for work the system already does automatically—while reserving visible UI strictly for **exceptions** (`error`, `unsupported`, or `needs-update` bridge skew per `version-skew.md`) (`推断`).

## 4. Critical-Flaw Audit: Silent Reload on Navigation, Idle, and Blur

An unguarded silent `window.location.reload()` triggered on route navigation, idle timeout, or window `blur` can break live product invariants. Inspecting Cairn's `apps/web/src` reveals **five concrete failure modes** and the exact guards needed to close them.

### 4.1 Audit of critical flaws in Cairn today

1. **Active SSE streaming views (`apps/web/src/api/sse.ts`, `sse-connection.ts`):**
   - **What happens (`实测`):** Cairn's `useTeamStream` and `useConversationStream` maintain ephemeral in-memory streaming state in `liveTextStore`, `liveThinkingStore`, `activityStore`, and `agentTodoStore` ([sse.ts](../../apps/web/src/api/sse.ts#L296-L328)). Persisted messages live on the server and re-fetch on reload, **but** a `window.location.reload()` mid-stream tears down the `EventSource`, wipes the unpersisted token buffer in `liveTextStore`/`liveThinkingStore` until the next DB flush/SSE replay, and flashes the conversation pane while the user may be watching live output (`推断`).
   - **Verdict:** **Safe on `blur`/unseen** (user is not watching; on return `useConversationStream` reloads messages + `activeRun` cleanly from server), **unsafe while `visible()` during active visible streaming** unless deferred until the stream settles or the user navigates away / blurs.

2. **Active IME composition (`isComposing`, `compositionstart` / `compositionend`):**
   - **What happens (`实测`):** `apps/web/src/main.tsx:57-63` only checks `field.value !== ''` and `field.innerText.trim() !== ''`. When typing CJK text with a macOS IME on an initially empty `<textarea>`, `<input>`, or `contentEditable`, the DOM `.value` can remain `''` while the IME candidate window holds uncommitted pre-edit characters! Furthermore, Cairn's composer, search panel, and dialog handlers explicitly track `isComposing` / `compositioncancel` ([composer-wire.ts](../../apps/web/src/overlay/composer-wire.ts#L465-L601), [search-panel.tsx](../../apps/web/src/overlay/search-panel.tsx#L320)), whereas `main.tsx` does not.
   - **Verdict:** **Critical flaw on idle/blur reload** unless composition state is tracked globally via `compositionstart` / `compositionend` / `compositioncancel` and treated as `busy() === true`.

3. **Open modals, dialogs, and overlays (`[role="dialog"], [role="alertdialog"]`):**
   - **What happens (`实测`):** Cairn's desktop shell idle watcher explicitly blocks shell restarts when a dialog is open via `useDesktopActivityReport()` querying `[role="dialog"], [role="alertdialog"]` ([desktop-activity.ts](../../apps/web/src/chief/desktop-activity.ts#L7-L13)). By contrast, `apps/web/src/main.tsx:51-64` **does not check for open dialogs at all**! If a user has a confirmation dialog, Settings modal, `ApiKeyCreateDialog`, `ProjectNewPage`, or `AntigravityReloginDialog` open and switches away briefly (`blur`) or idles, an unguarded reload closes the modal and discards local modal state (`useState` in `api-key-create-dialog.tsx`, `project-new-page.tsx`, `project-settings-page.tsx`).
   - **Verdict:** **Critical flaw** on blur/idle reload; must be gated on `[role="dialog"], [role="alertdialog"]` (and consider open menus/popovers `[role="menu"], [role="listbox"]` per [hotkeys.ts](../../apps/web/src/overlay/hotkeys.ts#L23) when visible).

4. **Unsaved form state & outbox entries missed by `document.activeElement`:**
   - **What happens (`实测`):**
     - `main.tsx:57-63` only inspects `document.activeElement`. In multi-field forms backed by React `useState` rather than `localStorage`—for example `ProjectNewPage` ([project-new-page.tsx](../../apps/web/src/pages/project-new-page.tsx#L102-L115)) and `ProjectSettingsPage` ([project-settings-page.tsx](../../apps/web/src/pages/project-settings-page.tsx#L156-L161))—if the user types a project name or goal and then clicks a `<Select>`, toggle, or another window (`blur`), `document.activeElement` is no longer the `<input>`! `busy()` returns `false`, and a blur/idle reload wipes the form.
     - `useServerDraft` ([use-server-draft.ts](../../apps/web/src/overlay/use-server-draft.ts#L57-L67)) writes `localStorage` synchronously on `edit()`, debounces server `save()` by `500 ms` (`DRAFT_SAVE_DEBOUNCE_MS`), and flushes on `cairn:prepare-reload` and `pagehide`. **Gap:** `apps/desktop/src/preload.ts:180` dispatches `cairn:prepare-reload`, **but `apps/web/src/stale-build-reload.ts` never dispatches `cairn:prepare-reload` before calling `window.location.reload()`** (`实测`).
     - **`taskOutbox` vs. `chiefOutbox` (`实测`):** `chiefOutbox` uses `indexedDbOutboxStore()` ([outbox.ts](../../apps/web/src/chief/outbox.ts#L436)) and survives page reload, whereas `taskOutbox` uses an **in-memory-only** `createOutbox()` ([task-outbox.ts](../../apps/web/src/board/task-outbox.ts#L20)). `main.tsx:53-54` only checks `entry.state === 'sending'`; a `state === 'failed'` entry in `taskOutbox` waiting for the user to click retry/discard would be silently lost on reload!
   - **Verdict:** **Critical flaw** on blur/idle/navigation reload unless non-focused dirty inputs, `taskOutbox` pending/failed entries, and `cairn:prepare-reload` flush are handled.

5. **Navigation-triggered reload pitfall (SPA routing vs. in-flight user action):**
   - **What happens (`推断`):** Reloading *during* a route transition (`router.subscribe`) avoids interrupting reading on the old view, **provided** the navigation isn't opening a route with transient query/hash state that `reload()` drops or happening while `outbox` sends / `cairn:prepare-reload` haven't settled. Because `window.location.reload()` reloads the URL **after** React Router updates `window.location` (assuming history push has committed), dispatching `cairn:prepare-reload` and checking guards *after* the route URL updates—but before settling into the new page—lands the user cleanly on the destination route on the new build. (Edge case: never reload mid-OAuth callback `/app/machines/authorize` or query-driven one-shot flows until settled.)

### 4.2 Exact Guards Required for Option A

Every silent reload path (`reloadOnNewDeploy` on unseen/blur/idle/navigation, and `reloadOnStaleBuild` where safe) should enforce this checklist:

1. **Outbox guard (`chiefOutbox` + `taskOutbox`):**
   - Block reload whenever `chiefOutbox.entries().some((e) => e.state === 'sending')` or `taskOutbox.entries().some((e) => e.state === 'sending' || e.state === 'failed')` (`实测` [main.tsx](../../apps/web/src/main.tsx#L53-L54), [task-outbox.ts](../../apps/web/src/board/task-outbox.ts#L20) — or persist `taskOutbox` to IndexedDB like `chiefOutbox`).
2. **IME composition guard:**
   - Track global `compositionstart` / `compositionend` / `compositioncancel` on `document` (plus `(event as InputEvent).isComposing`) and block reload whenever composition is active (`实测` pattern in [composer-wire.ts](../../apps/web/src/overlay/composer-wire.ts#L601)).
3. **Dialog / alertdialog / overlay guard:**
   - Block reload whenever `document.querySelector('[role="dialog"], [role="alertdialog"]') !== null` (matching [desktop-activity.ts](../../apps/web/src/chief/desktop-activity.ts#L7)), and also guard visible `[role="menu"], [role="listbox"]` when foregrounded (`实测` [hotkeys.ts](../../apps/web/src/overlay/hotkeys.ts#L23)).
4. **Input / textarea / `contentEditable` / dirty-form guard:**
   - Block reload not only when `document.activeElement` is a non-empty `HTMLInputElement` / `HTMLTextAreaElement` / `isContentEditable` ([main.tsx](../../apps/web/src/main.tsx#L57-L63)), **but also** when any visible editable field in the active view holds unsaved non-empty draft/form text (or an explicit dirty-form marker on `ProjectNewPage` / `ProjectSettingsPage` / inline rename) that is not backed by `localStorage` (`实测` gap).
5. **Active visible streaming guard:**
   - When `visible()`, block idle/navigation reload if `hasInFlightWork` / `conversationsInFlight()` / `liveTextStore` or `liveThinkingStore` is actively streaming to the viewed thread (defer until stream settles or the window becomes hidden/blurred) (`实测` [sse.ts](../../apps/web/src/api/sse.ts#L392-L395)).
6. **`cairn:prepare-reload` draft flush:**
   - Before calling `window.location.reload()`, dispatch `window.dispatchEvent(new Event('cairn:prepare-reload'))` so `useServerDraft` / `DraftSync` flushes any debounced `500 ms` changes with `{ keepalive: true }` (`实测` [use-server-draft.ts](../../apps/web/src/overlay/use-server-draft.ts#L58-L67), [preload.ts](../../apps/desktop/src/preload.ts#L180)).
7. **30 s `RELOAD_GUARD_MS` loop breaker:**
   - Keep `RELOAD_GUARD_MS = 30_000` in `sessionStorage['cairn.staleBuildReloadAt']` and fail closed (`return false`) when `storage === null` ([stale-build-reload.ts](../../apps/web/src/stale-build-reload.ts#L1-L11)) so a broken proxy, offline server, or stale HTML never triggers an infinite reload loop (`实测`).
