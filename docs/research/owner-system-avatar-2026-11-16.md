# Server account avatar research

The requirement is an OS-account fallback, not a new avatar editor. No reference-product UI is being copied. Evidence labels distinguish source inspection from platform execution; this Linux host cannot validate macOS or Windows integration.

| Source | Evidence | Mechanism and trade-off |
| --- | --- | --- |
| [AccountsService source](https://github.com/pop-os/accountsservice/blob/master/src/user.c) and [daemon](https://github.com/pop-os/accountsservice/blob/master/src/daemon.c) | Source inspected, not a live host-account lookup | Uses the home `.face` and per-user files in its icon directory. Try the current server account's `.face`, then `/var/lib/AccountsService/icons/<username>`; no directory scans or other users. |
| [Apple dscl manual](https://keith.github.io/xcode-man-pages/dscl.1.html) and [plutil manual](https://keith.github.io/xcode-man-pages/plutil.1.html) | Manuals inspected; command composition inferred, not tested on macOS | `dscl -plist` reads attributes; `plutil -extract … raw` returns a data value as base64 or a string as its path. Read `JPEGPhoto` before `Picture`, with fixed executables, argument arrays, timeouts and output bounds. The raw format requires macOS 12; failure leaves initials. |
| [Microsoft deprecated account-picture API](https://learn.microsoft.com/en-us/uwp/api/windows.system.userprofile.userinformation.getaccountpicture) and [modern User.GetDefault](https://learn.microsoft.com/en-us/uwp/api/windows.system.user.getdefault) | Official API documents inspected | The old API is unsupported on Windows 10+. The modern API describes the default user, not necessarily the server process's account, so do not accidentally select the interactive/default user. |
| [Windows account-picture changer source](https://github.com/helloyanis/windows-account-picture-changer/blob/main/account-picture-changer.ps1) | Implementation inspected; read compatibility inferred, not tested on Windows | Writes `Image448` and other sizes under the process account SID's `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AccountPicture\Users` key. A fixed read-only PowerShell command can query that same SID without elevation. This is an implementation convention, not a documented Microsoft compatibility promise; an absent or unreadable entry falls back to initials. Never run this project's write/elevation commands. |
| [OWASP file-upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) and [Sharp constructor](https://sharp.pixelplumbing.com/api-constructor/) | Guidance and installed Sharp 0.35.5 types/source inspected | Bound compressed bytes and decoded pixels; allow raster signatures and formats only; decode and re-encode without metadata. Reject Sharp as a runtime addition: its native modules would need new Docker and dual-architecture desktop distribution plumbing. Keep it development-only for independent fixture generation and decoding. |
| [Photon](https://github.com/silvia-odwyer/photon) 0.3.3 and [image-size](https://github.com/image-size/image-size) 2.0.2 | Installed declarations/source and existing server image bridge inspected | Photon exposes decoding, resizing, WebP/JPEG encoding and explicit image disposal. Its WASM already ships in the server bundle, Docker and desktop staging. image-size provides a maintained pure-JS format/dimension parser to reject large inputs before the WASM decoder allocates pixels. Neither requires a new platform-native runtime module. |

Use a bounded, server-only reader, image-size and Photon WASM to produce an at-most-8-KiB static thumbnail data URL with no original metadata. Only apply it to the in-memory seeded user when the persisted avatar is null. Existing HTTP session/me/member reads already use that user object. This avoids schema changes, filesystem URLs, arbitrary file-serving routes and provenance guesses: a persisted avatar always wins, while the OS fallback is recomputed at restart. GitHub profile persistence and manual override tracking remain in the approved identity-v2 work.
