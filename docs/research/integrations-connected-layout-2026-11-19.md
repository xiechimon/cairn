# Connected vs available integrations: layout and per-channel account management

Recommendation: one card per channel. A connected channel's card moves into "Connected" with a "Manage" button; "Manage" opens that channel's account list (add, remove, rules). "Available" holds only channels with no account. Do not show a "connected" chip on an Available card, and do not render one card per account.

Evidence date: 2026-11-19. Walked in the owner's signed-in Chrome, read-only (nothing connected, disconnected, authorized or changed). Screenshots are kept outside the repo in `/tmp/integrations-research/` and are not committed; they contain personal data, so this note describes them generically. Labels: verified = operated or read first-hand this run; inferred = derived from verified; guess = the rest.

## Key findings

1. verified: No product I could open shows the same integration in both a connected area and an available area. Claude.ai and Notion keep one catalog with the connected state shown in place (check mark or no "Connect" button) plus a separate connected list; ChatGPT and GitHub list only what is installed and put the catalog behind another button. The "connected chip in the catalog" Cairn uses today is the only duplicated form.
2. verified: Where multiple accounts exist, they live one level down. ChatGPT's plugin page has the closest match to the owner's intent: installed list, one row per plugin, and inside it "Connected accounts" plus "Connect another account". Rakazo's code does the same for Slack workspaces, with an "Add workspace" row.
3. verified plus inferred: The list level is per channel, the detail level is per account. Slack docs and ChatGPT both put remove or revoke inside the app's detail page, not on the list. Zapier is the exception (accounts are the list), and it suits a product whose unit is "a connection used in a workflow", which is not Cairn's case.
4. verified: A "Manage" button on the connected row is a standard entry point (Notion). Claude.ai and ChatGPT use whole-row click instead. For Cairn's cards, a visible "Manage" button is the owner's stated intent and matches Notion.
5. verified: Per-channel settings beyond accounts (permissions, capability types, rules) sit on the same detail view as the account list (ChatGPT: Permission above Connected accounts; Notion: capability types). Cairn's per-mailbox rules fit there.
6. Not covered: Linear, Zapier (first-party), Slack and Vercel live UIs and the Raycast app, because they sit behind logins I did not use. Findings 1 to 3 do not depend on them, but the table says which cells are blocked.

## Recommended pattern for Cairn

- Card level: one card per channel (WeChat, QQ Mail, Gmail, Other mailbox, Slack, Telegram). The verified rule is that a channel appears in exactly one section.
  - "Connected" holds channels with at least one account. The card shows the channel name, a one-line summary (for example "2 accounts, last mail 17:42" or the account name when there is one) and a "Manage" button.
  - "Available" holds channels with zero accounts and keeps its "Connect" button. Remove the "connected" chip from catalog cards.
- Manage level: "Manage" opens a dialog or a sub-page for that channel (pick by existing Cairn settings pattern, see open questions) with:
  1. Account rows: address or name, status (connecting, connected, error), per-account actions (edit rules, remove).
  2. A "Connect another account" row (ChatGPT) or "Add" row (Rakazo "Add workspace").
  3. Channel-level settings if any.
- Removing the last account moves the card back to "Available" (inferred from the above, same as ChatGPT uninstall).
- Telegram, Slack and WeChat already have one `ImConnectionRecord` each; they use the same card shape, with Manage showing a single account row until a second is possible.

Code areas this touches:
- `apps/web/src/routes/im-page.tsx`: group `connections` by platform; replace `connectionCard` (per-account cards, line 278) with a per-channel connected card plus Manage; make the catalog list only channels absent from `connectedPlatforms`; drop the `StatusChip` on catalog cards (lines 416-419, 439-442, 462-465).
- `apps/web/src/routes/mail-page.tsx`: the mailbox section and mailbox cards; its per-mailbox rules editor becomes the Manage content for the mail channels. QQ Mail, Gmail and Other mailbox collapse into the same grouping logic if they stay separate channels (see open questions).
- `apps/web/src/fixtures/scenario-data.ts` (scenario `mail-connected`) and `apps/web/src/i18n/en.ts`: fixtures for 0, 1 and 2 accounts per channel; strings for "Manage", "Connect another account".
- Verification: per `.claude/skills/verify-cairn/feature-map.json` and design-cairn, compare against ChatGPT's plugin detail page and Notion's Connected tab; seed the missing states (a channel with 2 accounts, an account in error).

## Open questions

1. Should QQ Mail, Gmail and Other mailbox stay three channels, or become one "Mail" channel with a provider picker inside Manage? The owner listed QQ Mail and Gmail separately, which this note follows; one "Mail" channel would match ChatGPT/Claude's single Gmail entry better. Recommendation: keep separate cards, since their connect flows differ (authorization code vs app password vs IMAP server).
2. Manage as dialog or sub-page? Notion and Rakazo use a modal or inline group; Claude.ai and ChatGPT navigate to a detail page with a back link. Recommendation: dialog, to stay inside the existing Settings dialog without nested routing; check against design-cairn first.
3. Does an account in an error or "connecting" state keep the channel in "Connected"? Recommendation: yes, show the worst status on the card summary.
4. Does WeChat (QR login) allow a second account? If not, Manage shows one row and no add row.
5. Linear, Zapier, Slack and Vercel live pages remain unwalked; if any of them is decisive for a later change, the owner must sign in or give a workspace URL.
