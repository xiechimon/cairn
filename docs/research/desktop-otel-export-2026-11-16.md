# Desktop OTel export: configuring the exporter and reaching the collector (2026-11-16)

Question: the Mac desktop app (`apps/desktop`) forks the server (`utilityProcess.fork` in `apps/desktop/src/main.ts`) and spawns the Runner (`apps/desktop/src/runner.ts`) with a copy of `process.env`. Launched from Finder or the Dock, the app has launchd's environment, so `CAIRN_OTEL_ENDPOINT`, `CAIRN_OTEL_HEADERS` and `CAIRN_OTEL_ENVIRONMENT` never reach either child and nothing is exported. Separately, the collector (self-hosted Langfuse, OTLP/HTTP) binds `127.0.0.1:3000` on another Linux host (`docs/ops/langfuse.md`, "Binding to this machine or the LAN").

Labels: 实测 = read first-hand in the linked primary source or run on the machines this session; 推断 = derived from 实测 facts; 猜测 = the rest.

## Pattern that fits Cairn

1. Configuration: an app-owned file, read by the main process and injected into the children's env. Every comparable product that must work when GUI-launched keeps the exporter config in a user-level file the app reads itself (Claude Code settings `env`, Codex `config.toml`, Copilot `settings.json`) (实测). Shell-env resolution (VS Code, `shell-env`) and `launchctl setenv` both widen the blast radius of an ingestion secret and add startup cost or a legacy mechanism (实测 + 推断). Cairn's children already consume `CAIRN_OTEL_*` through `parseOtlpTarget`, so injecting those three keys at fork/spawn time needs no change in the server or Runner (实测, repo).
2. Format: dotenv with the existing `CAIRN_OTEL_*` names, mode 0600, matching the deployment host's `~/.config/cairn/*.env` files (实测). Node ships `util.parseEnv`, so no new dependency (推断).
3. Precedence: products split here. Claude Code desktop and Copilot let the launch environment win over the file; the OTel declarative-config spec says the file wins and env is ignored (实测). For Cairn the file-only rule is the better fit: the packaged app is never shell-launched in normal use, and one source avoids a dev build silently exporting with a stale shell value (推断). Revert path: swap the merge order in one function.
4. Environment tag: default it to a value that marks Mac traces (Codex defaults its tag to `"dev"`) so they never mix with the deployment's (实测 for Codex; 推断 for Cairn).
5. Transport: Tailscale Serve, which already publishes omarchy's Langfuse to the tailnet over HTTPS without changing its loopback bind; SSH forward and LAN bind stay as fallbacks for a host without Tailscale (实测 for current state).

## Recommendation

- `apps/desktop/src/otel-config.ts` (new module): read `<userData>/otel.env` once at boot with `util.parseEnv`; accept only `CAIRN_OTEL_ENDPOINT`, `CAIRN_OTEL_HEADERS`, `CAIRN_OTEL_ENVIRONMENT`; refuse a file readable by group or others with one log line; default the environment to a Mac-specific value when an endpoint is set; export a helper that strips inherited `CAIRN_OTEL_*` and merges the file values.
- `apps/desktop/src/main.ts`: in `boot()`, call the reader once; pass the result to `startServer`, which builds the `utilityProcess.fork` env through the merge helper (before deleting `ENV_VARS.token`/`auth`, as today).
- `apps/desktop/src/runner.ts`: add the result to `RunnerOptions` and merge it in `runnerEnv`. The Runner's own children stay governed by `apps/daemon/src/backend/otel.ts`, which already strips `CAIRN_OTEL_*` for CLI children (实测).
- Endpoint on the owner's Mac: `https://<host>.<tailnet>.ts.net:8443/api/public/otel` with the Langfuse Basic header in `CAIRN_OTEL_HEADERS`. Nothing endpoint- or key-shaped goes into the repo.
- Tests: absent file, 0600 file, missing endpoint, group-readable file, extra keys ignored, inherited `CAIRN_OTEL_*` removed for both children. Live check: launch the packaged app from Finder and find a `mac`-tagged trace in Langfuse.
- Not chosen: shell-env resolution (startup cost, runs rc files, secret in every child), `launchctl setenv` (legacy, session-wide), SSH-forward LaunchAgent (extra process, slow recovery after sleep), LAN bind (cleartext key on the LAN, remote compose change).
