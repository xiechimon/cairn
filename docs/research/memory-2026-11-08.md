## Existing implementation findings

**Measured**: [memory.ts](../../apps/server/src/services/memory.ts) already has capped injection, overlap candidates, exact duplicate rejection, team/project/layer/thread scope, versioned updates and hard deletion. Its 3,000-token cap was absent when the earlier research was written; do not dispatch that existing change again.

**Measured**: [memory-consolidation.ts](../../apps/server/src/services/memory-consolidation.ts) already adds a weekly bounded pass to the digest and applies validated merges/expiry. The older research's propose-only suggestion is not the current implementation.

**Measured**: [routes-agents.ts](../../apps/server/src/routes-agents.ts) exposes the row-backed team list, promotion and deletion routes. No HTTP edit endpoint existed at this baseline; the new edit contract belongs to #3677.

**Inferred**: the backend baseline needs explicit tests for team/project/thread isolation, stale-version writes, destination conflicts and consolidation input versions. Backend capability alone does not establish frontend reachability. Keep canonical history separate from curated memory and preserve the pre-compaction failure boundary.
