## Kernel ownership correction (PR #3601)

Measured by the implementation session: a delayed stale-lease racer produced two winners and an ENOENT while deleting a reclaim guard. Inferred: asynchronous liveness followed by path unlink is a time-of-check/time-of-use defect; adding another token check before unlink cannot make the filesystem operations atomic. The previous exclusive-create/reclaiming-file mechanism must be replaced, rather than patched with another ownership check.

| Primary source | Measured contract | Inferred application |
|---|---|---|
| [Linux flock(2)](https://man7.org/linux/man-pages/man2/flock.2.html) | Locks belong to the open-file-description; dup/fork descriptors reference the same lock, and the last close releases it. Independent opens contend. LOCK_NB returns EWOULDBLOCK when occupied. | Parent Node may retain a lock acquired by Python on an inherited duplicate FD. Keep each guard inode permanent. |
| [Apple XNU flock manual](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/flock.2) | dup/fork create references to the same lock; explicitly unlocking from a child also unlocks the parent's lock. | Never issue LOCK_UN; close only the caller's descriptors. This supplies the macOS contract, not a macOS runtime experiment. |
| [Node stdio contract](https://nodejs.org/api/child_process.html#optionsstdio), [bundled libuv Unix implementation](https://github.com/nodejs/node/blob/v24.14.0/deps/uv/src/unix/process.c) | Numeric stdio entries share parent descriptors with the child. libuv uses dup2 or posix_spawn_file_actions_adddup2 for descriptor mapping. | Pass the opened guard FD at stdio index 3; the child acts on the parent's open-file-description rather than independently reopening the pathname. |
| [Python fcntl.flock](https://docs.python.org/3/library/fcntl.html#fcntl.flock) | The standard-library wrapper operates on a supplied FD and raises OSError on failure. | Use a small bridge over the kernel primitive, without implementing another lock algorithm or adding a dependency. Convert only EAGAIN/EWOULDBLOCK to reserved busy status 75; propagate everything else. |

Measured on Node 24.14.0/Linux: Node opened two independent FDs for the same `/tmp` guard inode. A synchronous Python child received the first FD as descriptor 3, acquired LOCK_EX|LOCK_NB and exited zero. A second Python invocation on the independently opened rival FD returned 75 after that child had exited. Closing the parent owner's FD allowed the rival invocation to acquire and exit zero. This establishes retained parent ownership after helper exit and release on parent close; macOS runtime behavior remains unverified here.

Coordinator review: approve the kernel-guard replacement recorded in design sections 2-5 before implementation. Each slot uses one never-unlinked guard inode; hold its FD for the lease lifetime and clean JSON metadata before closing the FD. Under the guard, respect an existing live legacy owner before replacing stale metadata. Remove the entire exclusive-create/stale-unlink/reclaiming branch. Keep FIFO ordering and socket-backed waiter liveness within this same allocator. Failed helper execution, interrupted execution, metadata I/O failure and live-legacy rejection must all close candidate FDs and preserve the real failure status.

Inferred limitations: this is an advisory lock for cooperating upgraded runners on the shared local filesystem. A concurrently active older reclaimer that ignores kernel guards cannot be made mutually exclusive by the new protocol alone; honoring live legacy metadata supports existing holders, not arbitrary old-code stale-claim races. Do not unlink guard files during cleanup or a runner's lifetime, since a replacement inode would create another independent lock domain. Required regressions include the actual delayed-racer failure, helper-exit retention, parent-death release, live-legacy preservation, busy/error distinction and equal-PID foreign namespace contention.
