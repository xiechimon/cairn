# Coordinator compaction threshold: how hosts lower it per runtime

Question: how does a host lower the automatic compaction threshold of an embedded agent runtime so a long Coordinator conversation compacts near 150K tokens, not near the end of a 1M window. Labels: measured = read or run this round; inferred = follows from measured, re-checkable; guessed = otherwise.

## Newcomer view

A user who installed Cairn today picks a Coordinator runtime and talks to it for days. Quality drops and cost rises long before a 1M window fills. They need compaction at the same point whatever runtime they chose, and the context meter must show where that point is. Nothing here asks for accounts, keys or settings; a field the user must set would be a product failure.

## Pattern that fits Cairn

One product constant, `COORDINATOR_COMPACTION_TOKENS = 150_000` (today `BACKGROUND_COMPACTION_AT` in `apps/server/src/coordinator/runtime/compaction.ts`), translated per runtime by the thin layer that owns that runtime, then read back so the meter shows what the runtime will really do.

- Hosts converge on a host-set, per-launch knob: Codex `-c model_auto_compact_token_limit`, Claude Code window env, Gemini settings file. inferred
- Units differ (absolute tokens, percent, fraction), so the translation is per backend and the read-back is the truth. inferred
- The meter reads `compactAt` already (`apps/web/src/chief/context-meter-ring.tsx`, `apps/server/src/services/coordinator-steps.ts`), so feed it the runtime's reported threshold, never the constant. measured files exist; wiring per backend guessed

## Recommendation

1. Claude Code (`apps/daemon/src/backend/claude-code.ts`, option builder near line 1495): set `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in the SDK `env` (it outranks every settings file, including a user's own). Value so the trigger lands on 150K: with the observed formula and no pct override use `163000` (150000 + 13000; superseded, see Open items: the measured reserve is 33000, so `183000`); alternatively `200000` plus `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=75` gives `min(150000, 187000)`. Prefer the first (one variable). inferred; confirm by calling `getContextUsage()` once on a live session and checking `autoCompactThreshold` equals 150000, then adjust the offset. Apply to Coordinator sessions only, not worker/step sessions.
2. Report the real threshold: after each turn read `getContextUsage().autoCompactThreshold` (fallback `raw_max_tokens - 13000`) into the usage event that carries `compactAt`.
3. Gemini: write `{"model":{"compressionThreshold": 150000/contextWindow}}` into the session's isolated Gemini home settings (carrier `GEMINI_CLI_HOME`); needs a live check because requires-restart applies per process, which is per session here. guessed until run.
4. Devin and Antigravity: no documented host knob. Do not ship a guess. Either leave their threshold as runtime default and show the meter with the runtime's own number (or none), or run a controlled probe (set the key/env in a scratch session, watch for a compaction event or `CompactionNotification`) before adopting. Devin's env route needs the `DEVIN_*` strip in `acp.ts` relaxed for this one name; the config-key route does not.
5. Keep pi-durable as is: already one path with `modelOverrides` per model.
6. Add one test per backend asserting the launch carries the 150K-equivalent (env or settings), and one that the meter shows the runtime-reported threshold. Do not add a user-facing setting.

## Open items

- Devin and Antigravity value semantics: guessed (strings only). Probe before relying on them.
- Claude Code formula: measured on the bundled 0.3.330 with `getContextUsage()`: no knob gives `rawMaxTokens` 1000000 and `autoCompactThreshold` 967000; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 163000, 187500 and 200000 give thresholds 130000, 154500 and 167000, so the threshold is window minus 33000 at these sizes, and 183000 lands on 150000. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=15` alone left 967000. Shipped: window 183000 (`apps/daemon/test/claude-coordinator-compaction.test.ts` asserts 150000 against the real binary).
- Gemini was not run (binary absent); Amp blocked as stated.

- Gemini CLI 0.70.0 (the version the ACP registry pins), measured from the npm tarball bundle: compression runs when `originalTokenCount >= threshold * tokenLimit(model)`, `threshold = config.getCompressionThreshold() ?? 0.5`, and `tokenLimit` is 1048576 for every Gemini model and 256000 for `gemma-4-31b-it` and `gemma-4-26b-a4b-it`. `Storage.getSystemSettingsPath()` returns `GEMINI_CLI_SYSTEM_SETTINGS_PATH` when set. Not run: no Gemini login on this Mac.
- Devin 3000.14.30821, inferred from strings of the installed binary: besides `agent.compaction_threshold_tokens` it has clap arguments `compaction_thresholds` and `sidekick_compaction_thresholds`, both hidden from `--help`; the value is an untagged enum whose shape the strings do not show. Its ACP `usage_update` carries `used` and `size`.
- Antigravity `agy` 1.5.14, inferred from strings: `HarnessConfig.compaction_threshold` is a `uint32` proto field sent to the local harness, and `AGY_CLI_AUTO_COMPACT_OVERRIDE` sits next to settings UI text; the unit is not shown. Its ACP layer names `usage_update` with `used` and `size`.
- Decision for Devin and Antigravity: no supported knob, so Cairn starts a fresh session carrying the recent conversation once the last turn's context reached 150K, measured from ACP `usage_update.used`.
