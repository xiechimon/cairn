# Packaged-app journeys and screenshot baselines

This note was written after the first implementation pass in this lane; it is kept as the prior-art record and as input to the follow-up review.

| Source | What it does | Trade-off for cairn | Evidence |
|---|---|---|---|
| Playwright visual comparisons | `expect(page).toHaveScreenshot()` writes golden images under `<spec>-snapshots`; snapshot names carry browser and OS because rendering differs by platform; the same environment should generate and compare them. | Fits the existing Playwright e2e lane directly. Linux CI needs Linux goldens; macOS goldens are local-only and the repo already ignores `*-darwin.png`. | observed https://playwright.dev/docs/test-snapshots |
| Playwright snapshot updates | `--update-snapshots` refreshes goldens; without it a pixel mismatch writes actual and diff artifacts and fails. | The gate can treat a modified golden as an intentional surface declaration, while an undeclared modification is rejected by the fast diff gate. | observed https://playwright.dev/docs/aria-snapshots and https://playwright.dev/docs/api/class-pageassertions |
| Playwright Electron | `_electron.launch` can launch an Electron executable and drive its windows through Playwright locators, evaluation and screenshots. Electron support is experimental and packaged apps need `executablePath`. | Fits the existing `apps/desktop` smoke harness; reuse its `mainWindow` helper rather than `firstWindow` because the tray is also a window. | observed https://playwright.dev/docs/api/class-electron and the Playwright source note that packaged apps may handle their own command line |
| Electron automated testing guide | Electron does not maintain one test runner; its guide points at Playwright's experimental CDP-based Electron support. | No better first-party packaged-app driver exists; keeping the journey in the existing desktop-mac job is less machinery than a new harness. | observed https://github.com/electron/electron/blob/main/docs/tutorial/automated-testing.md |
| GitHub Actions artifacts | `upload-artifact` is the supported way to retain test output, failure screenshots and logs; Playwright's CI guide uploads reports/results after test runs. | Upload `apps/web/test-results/` on failure so the actual/expected/diff images named by Playwright are reviewable without rerunning CI. | observed https://docs.github.com/en/actions/tutorials/store-and-share-data and https://playwright.dev/docs/ci-intro |
| This lane's design | A fast static diff gate maps feature-owned files to feature rows and requires a registry entry covering both local-server and remote-server modes; a separate fast gate requires modified baselines to be named by a `Visual-Surfaces:` trailer. | Static gates stay below 0.3s and live in `check-core`; heavy proof stays in the existing e2e and desktop-mac jobs instead of a new required job. The risk is registry drift, so the registry is validated and the desktop job executes the registered script. | inferred from the sources above and the repository constraints |

## Recommendation

Keep the implemented shape: Playwright goldens only for canonical fixture surfaces, Linux goldens committed for CI, failure artifacts uploaded by the existing e2e jobs, and packaged journeys driven through Playwright Electron in the existing desktop-mac package job. Do not resurrect the removed `parity/` side-by-side system: it solved a different cross-product comparison problem and was removed in `e52d09e8` (observed `docs/spec/06-open-source-and-divergence.md`).
