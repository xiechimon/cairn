# OpenTelemetry SDK versus Langfuse SDK for cairn's tracing (2026-11-08)

Labels: `实测` = read or run first-hand in this pass; `推断` = derived from `实测` and re-checkable; `猜测` = the rest.

Question: cairn hand-builds OTLP JSON and POSTs it (`packages/shared/src/otel.ts`). Which established library should replace that code for a self-hosted Langfuse v4 in `events_only` mode, while keeping derived trace and span ids, past start and end times for offline replay, and `TRACEPARENT` for the harness CLIs?

Baseline: cairn `origin/main` `45f00e7f8`. Packages installed with `--ignore-scripts` into a scratch tree outside the repo, at the latest versions on npm today: `@opentelemetry/api` 1.10.0, `@opentelemetry/sdk-trace` 3.1.0, `@opentelemetry/exporter-trace-otlp-http` and `-proto` 0.301.0, `@opentelemetry/resources` and `core` 3.1.0, `@opentelemetry/semantic-conventions` 1.45.0, `@langfuse/otel`, `@langfuse/tracing` and `@langfuse/core` 6.1.1. Langfuse is the running `langfuse/langfuse-worker:4.68.0` container; its ingestion source was copied out of the container and read (`@langfuse/shared/dist/src/server/otel/OtelIngestionProcessor.js`). No package has an install script (`实测`, grep of every `package.json`).

SOURCES.md row: "Observability and tracing": Langfuse docs, Langfuse source at the deployed version, OpenTelemetry GenAI semantic conventions. All three are in the table.

## Pattern that fits

Use the vendor-neutral OTel SDK 3 with the OTLP HTTP/JSON exporter, take attribute keys from the pinned GenAI conventions and from `@langfuse/core`, and keep only id derivation and attribute mapping in cairn. The Langfuse processor is rejected on its merits, against the Langfuse docs' recommendation. It pins cairn to the deprecated SDK 2, it filters spans, it needs Langfuse keys, and its SDK identity changes how metadata is decoded (`推断` from the rows above).

Recommendation and call sites: `docs/design/otel-sdk-migration.md`.
