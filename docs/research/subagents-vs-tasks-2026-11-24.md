# Subagents Inside a Harness vs. Cairn Tasks

Date: 2026-11-24. Scope: primary-source research comparing harness-native subagents against Cairn Tasks across every harness Cairn ships (and adjacent reference products), evaluating whether the Coordinator and Tasks should leverage subagents, and diagnosing the "export resume as PNG" trace. Research only; no product code changed.

Owner's question (verbatim):

```text
coordinator本身的harness 能调用subagent吧？那我们的cairn调用的task和他的subagent有什么区别呢？应不应该把这个调用subagent能力给利用起来？（所有的harness）
```

English translation: *"The Coordinator's own harness can invoke subagents, right? Then what is the difference between a Cairn Task and its subagent? Should we make use of this subagent capability (across all harnesses)?"*

## 1. The Newcomer, Problem, and Scenarios

### For someone who installed Cairn today

Imagine a new user who installed Cairn today and has never heard of `pi-durable`, ACP, worktrees, or subagents `[Inferred]`:

- **Where they meet this:** In two places — chatting with the Coordinator in a channel, and watching a Task run in the Tasks panel. They should never have to learn two competing jargon systems ("Task" vs. "Subagent") just to ask a question or get a file converted.
- **What they expect:** Quick lookups, multi-item status checks, and simple one-shot utilities ("export this resume as PNG") should feel immediate and stay inside the chat trace without spawning a project board card and a formal plan step. Real multi-minute work that edits repositories, runs on a specific computer, produces a branch/PR, or may fail and need steering/retry should become a visible Task they can track, steer, pause, and review.
- **Accounts, payments, and keys:** No new accounts or API keys are required. Enabling harness subagents consumes tokens/credits from the **same** model provider or subscription the user already configured for that Coordinator or Task — which means silent model inheritance or unthrottled parallel subagents can unexpectedly multiply token spend unless model/budget/visibility rules are explicit (`[Measured]` in [Claude Agent SDK cost docs](https://code.claude.com/docs/en/agent-sdk/cost-tracking.md) and [Devin CLI subagent docs](https://docs.devin.ai/cli/subagents.md)).
- **Where state is stored:** Coordinator subagent turns live inside the Coordinator's existing per-thread SQLite store (`<dataDir>/coordinator/<threadId>.sqlite`, `[Measured]` in [`apps/server/src/coordinator/runtime/thread-harnesses.ts`](../../apps/server/src/coordinator/runtime/thread-harnesses.ts#L9-L12)); Task subagent summaries and `bg_task` rows live inside the Task's existing `message` table (`[Measured]` in [`apps/server/src/services/machines.ts`](../../apps/server/src/services/machines.ts#L781-L789)); native harness transcripts stay on the runner under that harness's isolated home (`~/.claude/projects/.../subagents/` etc., `[Measured]` in [`apps/daemon/src/step-env.ts`](../../apps/daemon/src/step-env.ts#L147-L168)).
- **Where they get stuck or what fails:** Today, if a Task spawns a background subagent on Claude Code, the live card disappears the instant the last subagent finishes and hides its nested tool calls (`[Measured]` in [`apps/web/src/api/mappers.ts`](../../apps/web/src/api/mappers.ts#L725-L732) and [`L1031-L1049`](../../apps/web/src/api/mappers.ts#L1031-L1049)). On Devin ACP, child tool calls vanish completely because `bg_task` rows are never emitted (`[Measured]` in [`apps/daemon/src/backend/devin-acp.ts`](../../apps/daemon/src/backend/devin-acp.ts#L14-L57)). And on the Coordinator side, a 20-second file export ("export resume as PNG") gets forced into a full Task lifecycle instead of a lightweight execution path.

### Why this matters (measured baseline facts)

1. **The Coordinator's in-server harness (`pi-durable` 1.5.0) already supports subagents at the runtime level, but Cairn installs no subagent extension** `[Measured]` ([`apps/server/src/coordinator/runtime/tools.ts`](../../apps/server/src/coordinator/runtime/tools.ts#L430-L485), [`pi-durable/README.md` L712–758](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)).
2. **Task harnesses are split across two worlds**: native SDK harnesses (`claude-code`) and managed ACP harnesses (`devin`, `antigravity`, `gemini`) have built-in subagents, whereas `pi-coding-agent` (which also runs OpenAI Codex OAuth models in Cairn) deliberately omits subagents (`[Measured]` in `pi-coding-agent@1.5.0/README.md` L19 and [`apps/daemon/src/backend/pi.ts`](../../apps/daemon/src/backend/pi.ts#L93-L98)).
3. **ACP cannot carry portable subagent lineage today**, so treating all harnesses identically produces silent blind spots (`[Measured]` across Devin, Antigravity, Gemini CLI, and T3 Code).

## 2. Facts Established First-Hand From This Repository `[Measured]`

### 2.1 How the Coordinator Actually Runs

Cairn has **two** execution paths for Coordinator turns (`step.kind === 'chief'`):

1. **In-server path (`@earendil-works/pi-durable` 1.5.0 — default for `pi` providers):**
   - [`serverTurnModel`](../../apps/server/src/services/machine-claim.ts#L189-L218) claims a `chief` step in-server whenever `coordinatorInServerEnabled()` is true and `stepRuntimeFor(model.provider) === 'pi'` (which covers Anthropic API, OpenAI API, `openai-codex` OAuth, Gemini API, and other `pi-ai` providers).
   - [`createServerRuntime`](../../apps/server/src/coordinator/runtime/server-runtime.ts#L92-L201) opens one SQLite store per Coordinator thread (`<storageDir>/<threadId>.sqlite` via [`thread-harnesses.ts`](../../apps/server/src/coordinator/runtime/thread-harnesses.ts#L9-L12)) using [`openCoordinatorHarness`](../../apps/server/src/coordinator/runtime/harness.ts#L12-L34).
   - Installed extensions in [`server-runtime.ts`](../../apps/server/src/coordinator/runtime/server-runtime.ts#L130-L173): `coordinatorToolsExtension`, `volatileContextExtension`, `coordinatorCompactionExtension`, `generationTelemetryExtension`. **No subagent extension is installed.**
   - Tools in [`coordinatorToolsExtension`](../../apps/server/src/coordinator/runtime/tools.ts#L430-L485) are remote/relay tools defined in [`coordinator-tool-defs.ts`](../../apps/server/src/services/coordinator-tool-defs.ts#L107-L139) (`CHIEF_REMOTE_TOOLS`, `CHIEF_ROUTER_TOOLS`, `CHIEF_REPLY_TOOLS`, browser/computer/phone relay tools, MCP connector tools, plus `tool_search` and `call_tool` for deferred tools). Notably, [`COORDINATOR_COMPUTER_TOOL_OFFERS`](../../apps/server/src/services/coordinator-tool-defs.ts#L40-L71) explicitly **withholds** `list_files`, `read_file`, `write_file` (`"the Coordinator delegates file work to threads"`), `attach_file`, `open_path`, and `launch_app`.
   - **What `@earendil-works/pi-durable@1.5.0` itself can do** (verified in installed `node_modules/.pnpm/@earendil-works+pi-durable@1.5.0.../README.md` L703–802 & `dist/harness/task-graph.d.ts`):
     - **Does not bundle a pre-registered `subagent` tool**, but ships first-class durable subagent primitives:
       - `tx.createConversation({ ownership: { kind: "task", taskId: api.taskId } })` creates a child conversation inside the same SQLite store, starting as a copy of its parent's `pi.agent` (model, extensions, tools, cwd).
       - `configure(tx, childId, { model, extensions: { remove: [Subagent] }, tools, maxTurns })` lets the tool pick a cheaper/faster model, restrict tools, and cap recursion depth and tool rounds.
       - `replay: "safe"` + `tx.scanConversations({ ownerTaskId: api.taskId }, 1)` + deterministic `requestId: "subagent:${api.taskId}"` makes subagent execution crash- and restart-safe.
       - `api.details({ conversationId: child })` exposes the child conversation ID for live UI attachment (`21-subagent-foreground.ts`).
       - Foreground ownership guarantees parent abort aborts the child and parent stays busy until child finishes; `{ background: true }` creates an independent background anchor surviving parent abort (`22-subagent-background.ts`).
       - `harness.usage(context)` aggregates `pi.usage` across all conversations in the store per `provider/model`.
       - Also ships **Code Mode** (`@earendil-works/pi-durable/codemode`, QuickJS sandbox with replay journal calling conversation tools as `await tools.<name>()`) and **Child Tasks** (`tx.createTask`, `waiting` with `allSettled` / `failFast`, `harness.watchTaskGraph`).

2. **Daemon harness path (subscription / CLI runtimes):**
   - Whenever the Coordinator's routed model uses a non-`pi` runtime (`claude-code`, `devin`, `antigravity`, or `gemini`), [`serverTurnModel`](../../apps/server/src/services/machine-claim.ts#L189-L210) returns `null` and a daemon claims the `chief` step via [`claimChiefCandidates`](../../apps/server/src/services/machine-claim.ts#L162-L187) / [`buildChiefClaim`](../../apps/server/src/services/machine-claim.ts#L276-L424).
   - [`composeStepSessionOpts`](../../apps/daemon/src/step-session-opts.ts#L57) sets **`lockedDown: true`** on every `isChief` step (and `remoteToolsOnly: true` on mail / memory-edit turns).
   - On **`claude-code`** (outside Orb), `locked = !parts.inOrb && parts.lockedDown` restricts `tools` to `HOST_BUILTIN_TOOLS = ['Read', 'Glob', 'Grep']` (+ `ToolSearch` when deferred tools exist) and `allowedTools` to `['mcp__cairn', 'Read', 'Glob', 'Grep']`, disabling `Bash` and omitting Claude Code's `Agent` tool ([`claude-code.ts`](../../apps/daemon/src/backend/claude-code.ts#L1057-L1059), [`L1427-L1484`](../../apps/daemon/src/backend/claude-code.ts#L1427-L1484)). *(Subtle edge case: when `inOrb === true` and `remoteToolsOnly !== true`, `locked` evaluates `false`, so `tools` is unset and Claude Code's built-in `Agent` tool would remain exposed to a Coordinator turn inside an Orb container.)*
   - On **ACP runtimes** (`devin`, `antigravity`, `gemini`), `lockedDown: true` sets `acpTurnPolicy = 'read-only'` (`'relay-only'` when `remoteToolsOnly`), causing [`decideAcpPermission`](../../apps/daemon/src/backend/acp-permission-gate.ts#L59-L65) ([`L171-L192`](../../apps/daemon/src/backend/acp-permission-gate.ts#L171-L192)) to allow only Cairn relay tools (`mcp__cairn__*`) and `READ_KINDS` (`read`, `search`, `think`), rejecting write/execute/other calls.

3. **Existing middle tier — In-Server Info Cards (`info-card-runner.ts`):**
   - Cairn already runs non-code tasks (`output` in `'info' | 'report' | 'dataset' | 'link'`) routed to `pi` **in-server** on ephemeral `pi-durable` stores (`info-${stepId}.sqlite`, up to `MAX_PARALLEL = 3`, read-only `infoCardRemoteTools`, no daemon/worktree) ([`apps/server/src/coordinator/runtime/info-card-runner.ts`](../../apps/server/src/coordinator/runtime/info-card-runner.ts#L76-L305)).

### 2.3 Current Implementation Status vs. `docs/design/task-panel-live-row-subagents-todo.md` `[Measured]`

Although [`docs/design/task-panel-live-row-subagents-todo.md`](../design/task-panel-live-row-subagents-todo.md#L3) still reads *"Status: decided by mon X (2026-11-19); nothing built yet"*, **substantial parts of B (Background sub-agents) have already shipped**, leaving **five concrete defects/gaps**:

1. **Shipped:** `BackgroundTask` schema ([`packages/shared/src/background-task.ts`](../../packages/shared/src/background-task.ts#L14-L27)), `BackgroundTaskRows` ([`claude-background-tasks.ts`](../../apps/daemon/src/backend/claude-background-tasks.ts)), `POST /api/machine/tool/:stepId` `{ kind: 'bg_task' }` persistence ([`routes-machine.ts:118`](../../apps/server/src/routes-machine.ts#L118), [`machines.ts:785`](../../apps/server/src/services/machines.ts#L785)), SQLite orphan-on-release trigger ([`0224_bg_task_orphan_on_release.sql`](../../apps/server/drizzle/0224_bg_task_orphan_on_release.sql)), `stopTask` wire route ([`machine-loop.ts:1211-1221`](../../apps/daemon/src/machine-loop.ts#L1211-L1221), [`claude-code.ts:959-962`](../../apps/daemon/src/backend/claude-code.ts#L959-L962)), and `<BackgroundTasks>` UI component ([`apps/web/src/detail/background-tasks.tsx`](../../apps/web/src/detail/background-tasks.tsx)).
2. **Gap 1 — Finished subagent work disappears completely:** [`mappers.ts:1031`](../../apps/web/src/api/mappers.ts#L1031) only emits `{ kind: 'bg-tasks' }` when `backgroundRunning > 0`, while [`mappers.ts:725-732`](../../apps/web/src/api/mappers.ts#L725-L732) strips every `toolcall` with `call.parent !== undefined` out of the main `WorkTrace` into `childSteps`. The moment the last background subagent settles, the entire `bg-tasks` card disappears and its nested tool calls become unreachable in the UI.
3. **Gap 2 — Devin ACP child tool calls are black-holed:** [`devin-acp.ts:34-35, 55`](../../apps/daemon/src/backend/devin-acp.ts#L34-L35) sets `call.parent` on subagent tool calls, so `mappers.ts:725-732` removes them from `WorkTrace` — but `devin-acp.ts` never emits `bg_task` rows, so those `childSteps` are never rendered anywhere (not even while running!).
4. **Gap 3 — `perTaskStopAffordance: true` is not set in `claude-code.ts`:** Verified via grep (`0` occurrences in `apps/daemon/src/`). Without `perTaskStopAffordance: true` in `buildClaudeSdkOptions`, whole-run `interrupt()` kills background tasks implicitly rather than separating per-row stop from whole-run stop as specified in `task-panel-live-row-subagents-todo.md` Decision #2.
5. **Gap 4 — Missing `model` / `subagentType` / `tokens` in `BackgroundTask` UI:** [`background-task.ts`](../../packages/shared/src/background-task.ts#L14-L27) has no `model` or `subagentType` field; [`BackgroundTaskRow`](../../apps/web/src/detail/background-tasks.tsx#L24-L112) renders `toolUses` and elapsed time, but omits `tokens`, `model`, and `summary`.
6. **Gap 5 — No subagent handling for Antigravity ACP, Gemini ACP, or `pi`:** Neither ACP adapter normalizes subagent events (and ACP v1 provides no portable schema for them), and `pi-coding-agent` has no built-in subagent tool.

## 6. Which Work Belongs Where `[Inferred]`

Every reference product converges on **ownership, side effects, and durability** — not raw duration alone — as the boundary between a subagent and a task:

| Work Type | Where It Belongs | Why |
|---|---|---|
| **Multi-record read-only fan-out inside one Coordinator turn** *(e.g. "summarize why 6 tasks failed today", "search 3 project channels + PR history for decision X", "inspect 4 attachments")* | **Coordinator read-only subagent** (new, `pi-durable` foreground) | Avoids filling the Coordinator's persistent conversation window with 60–150k tokens of raw logs/transcripts, runs in parallel in seconds, produces no durable artifact of its own, and should never clutter the Tasks panel. |
| **Single-turn quick check or action** *(1–2 tool calls, answer from memory, click/check a browser tab, simple host utility if tools exist)* | **Coordinator directly** (no subagent, no Task) | Zero extra latency or model overhead. |
| **Codebase exploration, grep/read fan-out, test-log triage, or parallel read-only review inside an active Task** | **Task harness's native subagent** (when harness supports it) | Isolates verbose search/build-log noise from the Task's main context window and reuses the Task's already-prepared worktree and prompt cache. |
| **Standalone multi-minute research, web/repo synthesis, or deliverable report** | **Cairn Info Card** (`output: "report" \| "info"`) | Needs an auditable, attachable report artifact, independent retry/rework (`message_thread`), and async wake back to chat while the user keeps talking. |
| **Anything that edits repositories, creates commits/PRs, needs a specific OS/machine, requires human approval/steering, or takes multiple steps/retries** | **Cairn Code Task** (`output: "code"`) | Needs worktree isolation, machine/confinement guarantees, durable `todo` visibility in the Tasks panel, mid-run steering, `ask_user`, and review/landing gates. |
| **One-shot local file/format utility** *(e.g., "export resume as PNG", "compress this PDF", "resize screenshot")* | **Direct Coordinator host/browser tool OR lightweight single-step utility (no `plan` step, no git worktree/branch)** | See Section 7 — neither a `pi-durable` in-server subagent (no filesystem/Chromium) nor a full repo Code Task with a `plan` step fits this job. |

## 7. Real Case Analysis: "Export Resume as PNG" `[Measured + Inferred]`

The owner reported that asking Cairn to **"export resume as PNG"** went through a full Task with a `plan` step, and called the trace wrong. Inspecting Cairn's code exposes **three compounding causes** (`[Measured]` in source, `[Inferred]` for this run's execution path):

1. **The Coordinator has no file or attachment-export path of its own:**
   - [`COORDINATOR_COMPUTER_TOOL_OFFERS`](../../apps/server/src/services/coordinator-tool-defs.ts#L40-L71) explicitly withholds `list_files`, `read_file`, `write_file` (`"the Coordinator delegates file work to threads"`), `attach_file`, `open_path`, and `launch_app`.
   - Even when `user_computer_shell` or `browser_*` is enabled on an owner thread, [`COORDINATOR_SYSTEM_PROMPT`](../../apps/server/src/services/chief.ts#L1856-L1862) does not distinguish a 20-second file-conversion deliverable from a multi-minute code/report deliverable, and the Coordinator cannot upload a generated local file as a deliverable attachment (`attach_file` is withheld from Coordinator and only exposed to workers via [`runner.ts:441`](../../apps/daemon/src/runner.ts#L441) and [`step-prompt.ts:146`](../../apps/daemon/src/step-prompt.ts#L146)).
   - Result: the Coordinator had to call `create_todo` (`output: "code"`, the default in [`chief-tools.ts:560-562`](../../packages/shared/src/protocol/chief-tools.ts#L560-L562)) to get a runner with `attach_file` + filesystem/browser access.

2. **Once routed as a Task, heavy software-engineering ceremony fired for a trivial conversion:**
   - A full Task provisions a workspace/worktree ([`runner.ts:321-341`](../../apps/daemon/src/runner.ts#L321-L341)), injects git branch & task-meta instructions ([`step-prompt.ts:92-98, 106-117`](../../apps/daemon/src/step-prompt.ts#L92-L98)), and either entered a `plan` step (`withPlan` / `step.kind === 'plan'`, [`step-prompt.ts:35-37, 82-84, 196-198`](../../apps/daemon/src/step-prompt.ts#L35-L37)) or emitted a harness plan/todo checklist (`open_thread` itself primes the model that *"one session plans, writes tests, implements and checks its own work end to end"*, [`chief-tools.ts:876`](../../packages/shared/src/protocol/chief-tools.ts#L876)) — turning a single Playwright/wkhtmltoimage/Chrome headless render into a multi-phase engineering trace.

3. **Crucial takeaway — Coordinator subagents alone do NOT fix this case `[Inferred]`:**
   - Spawning a `pi-durable` subagent inside the server still has no local filesystem, no Chromium binary, and no `attach_file` tool.
   - Fixing "export resume as PNG" requires **two separate things** that should not be conflated:
     - **(a) Stop forcing single-step file/utility tasks through `plan` steps or repo-worktree ceremony:** `withPlan` is already `false` by default in [`build-start.ts:144`](../../apps/server/src/services/build-start.ts#L144), so ensure neither Coordinator nor worker prompts inject plan-first instructions for non-code/utility deliverables, and allow the Coordinator (when an owner machine / browser is already attached) to produce and attach a one-shot file directly or dispatch a lightweight no-repo/no-plan machine action without creating a multi-phase engineering trace.
     - **(b) Use Coordinator subagents specifically for what they ARE good at:** read-only in-server fan-out and context isolation (investigating multiple tasks, logs, channels, PRs, or attachments without bloating the Coordinator thread).

## 8. Recommendations & Code Areas Touched `[Inferred]`

### Recommendation 1: Give the Coordinator a Narrow, Read-Only Foreground Subagent Tool (In-Server `pi-durable` First)

**Decision: Yes — with strict boundaries; do NOT enable general-purpose or write-capable Coordinator subagents.**

- **Mechanism:** Install a small `coordinatorSubagentExtension` in [`apps/server/src/coordinator/runtime/server-runtime.ts`](../../apps/server/src/coordinator/runtime/server-runtime.ts#L130-L173) using `pi-durable` 1.5.0's built-in `tx.createConversation({ ownership: { kind: "task", taskId: api.taskId } })` pattern (`21-subagent-foreground.ts`):
  - **Foreground only** (blocks the Coordinator's tool call until the child returns; parent abort aborts the child; `replay: "safe"` with deterministic `requestId` so server restart resumes cleanly). Background Coordinator subagents would duplicate Cairn's existing Info Cards and Tasks (`single path` rule).
  - **Read-only tool allowlist only:** expose only `replaySafe: true` inspection tools (`todos`, `threads`, `conversation`, `search_history`, `read_history`, `channel_messages`, `inspect_run`, `pull_requests`, `workflow_runs`, `machines`, `attachment`, `memories`, `browser_snapshot` if safe). Explicitly **exclude** `create_todo`, `message_thread`, `merge_builds`, `archive_todos`, `delete_todos`, `ask_user`, `notify_user`, `set_secret`, computer/phone `*_act`, and `subagent` itself (**depth strictly 1**).
  - **Model & turn budget:** default to the team's fast/summary model (`turn.summary` already wired in [`server-runtime.ts:260-268`](../../apps/server/src/coordinator/runtime/server-runtime.ts#L260-L268)!) with an optional override from `frequent` models, capped at e.g. `maxTurns: 12` and bounded parallel fan-out (e.g. max 4 concurrent calls).
  - **Usage attribution:** aggregate child conversation `pi.usage` into the Coordinator turn's `step_usage` / `chief_turn_usage` via `harness.usage()` delta (note: [`turnUsage`](../../apps/server/src/coordinator/runtime/turn.ts#L57-L76) currently sums only root conversation entries — it MUST include child conversations so subagent tokens are never dropped from billing!).
- **How it shows in the chat:**
  - **Never** create a `todo` row or appear in the Tasks panel (following T3 Code's `isListedThreadLineage()` rule and Claude Code's separation of subagents from `Agent View`).
  - Render as a **single collapsible inline trace row** inside the Coordinator turn's `WorkTrace` (using the existing `call.parent` / `details.conversationId` pattern): shows concise label (`Investigated 4 failed tasks · 12s · 3.1k tokens · <model>`), expands on click to show the delegated prompt and child read-only tool calls, and **stays expandable after the turn completes**.
- **Daemon-hosted Coordinator turns (`claude-code`, `devin`, `antigravity`):**
  - Keep `lockedDown: true` blocking native write/shell subagents, and fix the Orb loophole in [`claude-code.ts:1427`](../../apps/daemon/src/backend/claude-code.ts#L1427) (`locked = !parts.inOrb && parts.lockedDown`) so an Orb-hosted Coordinator turn cannot silently bypass tool lockdown and spawn unrestricted `Agent` subagents. Do **not** build a second daemon-only Coordinator subagent mechanism; if a daemon-hosted Coordinator needs parallel read-only lookups later, expose the same server-side read-only subagent tool via `mcp__cairn__` (single path across all Coordinator runtimes).
- **Code areas touched:** `apps/server/src/coordinator/runtime/{tools.ts,server-runtime.ts,turn.ts,mirror.ts}`, `apps/web/src/api/mappers.ts`, `apps/web/src/detail/work-trace.tsx`.

### Recommendation 2: Keep Harness Subagents Enabled for Tasks, Guide Read-Only Use, and Fix Surfacing Across Harnesses

**Decision: Yes — allow (and prompt for) read-only / context-isolating subagents inside Tasks; avoid encouraging multi-writer subagents on shared checkouts; close the 5 surfacing gaps in Cairn's task panel.**

- **Per-harness policy:**
  - **`claude-code`:** Keep `Agent` enabled for Tasks. Prompt/prefer `Explore` / read-only subagents for search and test-log triage; do **not** push `isolation: "worktree"` subagents yet because Claude Code branches worktrees from the repo's default branch rather than the Task's branch HEAD (`[Measured]`, [sub-agents.md](https://code.claude.com/docs/en/sub-agents.md) L270–286), which risks diverging from Cairn's single-branch delivery contract. Keep reading `result.modelUsage` (already done in [`toUsageRows`](../../apps/daemon/src/backend/claude-code.ts#L154-L231)) so subagent spend is never lost.
  - **`devin`:** Keep `run_subagent` enabled (especially `subagent_explore`, which routes to Devin's cheaper router model). Warn in docs/prompts that `subagent_general` inherits the parent's expensive model and shares the checkout. Fix Cairn's `devin-acp.ts` to emit `bg_task` rows so Devin subagents are visible instead of black-holed.
  - **`antigravity` & `gemini` (ACP):** Allow native subagents, but adopt **T3 Code's explicit capability-flag pattern** (`supportsSubagents`, `emitsSubagentLifecycle`, `canStopSubagents`) rather than faking uniform ACP controls — ACP v1 has no portable child-session protocol, so Cairn should show flat/grouped tool calls honestly until ACP v2 or vendor `_meta` stabilizes.
  - **`pi` (`pi-coding-agent` + `openai-codex` OAuth):** Keep `pi-coding-agent` without subagents for now (it deliberately omits them). If OpenAI Codex CLI (`codex app-server`) is ever added as a first-class Cairn harness later, wire its native `collabAgentToolCall` & `subAgentActivity` items directly — they give richer lifecycle and cancellation than ACP. Only consider a small read-only Pi subagent extension if telemetry shows `pi` tasks suffering heavy context bloat from read-only exploration.
- **Concrete surfacing fixes to finish [`docs/design/task-panel-live-row-subagents-todo.md`](../design/task-panel-live-row-subagents-todo.md):**
  1. **Persist finished subagent rows in the transcript:** In [`apps/web/src/api/mappers.ts:1031`](../../apps/web/src/api/mappers.ts#L1031), stop gating `{ kind: 'bg-tasks' }` on `backgroundRunning > 0`! Render settled subagents collapsed as `Subagents · N done` (matching Codex's `Active / Done · N` and T3 Code's `ProviderSubagentBar`) — or attach `childSteps` directly onto the spawning `Agent` / `Subagent: <title>` call row in `WorkTrace` — so completed subagent traces never vanish on completion or page reload.
  2. **Emit `bg_task` rows from Devin ACP:** In [`apps/daemon/src/backend/devin-acp.ts`](../../apps/daemon/src/backend/devin-acp.ts) + [`apps/daemon/src/backend/acp.ts`](../../apps/daemon/src/backend/acp.ts), emit `bg_task` start/complete transitions from `cognition.ai/subagent_started` and `cognition.ai/subagent_completed`, linking `toolCallId` so `childSteps` attach cleanly instead of disappearing.
  3. **Wire `perTaskStopAffordance: true` on Claude Code:** Set it in [`buildClaudeSdkOptions`](../../apps/daemon/src/backend/claude-code.ts#L1425-L1527), and update `ClaudeSessionHandle.stop()` to call `stopTask()` on every running entry in `this.rows.running` so per-row Stop isolates one subagent while whole-task Stop still stops everything.
  4. **Surface `model`, `tokens`, and `summary` on `BackgroundTask`:** Extend [`packages/shared/src/background-task.ts`](../../packages/shared/src/background-task.ts) with optional `model` and `subagentType`, populate them from Claude Code `Agent` tool input / `AgentOutput.resolvedModel` and `task_progress.usage`, and display them in [`apps/web/src/detail/background-tasks.tsx`](../../apps/web/src/detail/background-tasks.tsx) (matching Cursor's model-on-card cost transparency).

### Recommendation 3: Close the "Export Resume as PNG" Utility Gap Separately

- Do **not** conflate quick one-shot file utilities with subagents. Either (a) allow the Coordinator to attach an artifact produced via an already-attached host/browser tool (`attach_file` / artifact upload for owner-machine outputs), or (b) ensure single-step utility tasks never enter a `plan` step or git-worktree ceremony (a lightweight no-repo/no-plan task mode or `output: "artifact"` path) so a 20-second PNG export never prints a multi-stage software-engineering plan trace.
