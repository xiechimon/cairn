## 2. Project-by-Project Findings

### 2.1 Codex CLI (`openai/codex`)

- **Pinned commit**: `1f43c02f3f3489edd61c6426fc5d392bea236a41` (`实测`).
- **Wraps every command?**: Yes by default (`实测`). `SandboxMode` defaults to `ReadOnly` ([`codex-rs/protocol/src/config_types.rs#L104-L114`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/config_types.rs#L104-L114)), with `WorkspaceWrite` for workspace edits and `DangerFullAccess` to disable sandboxing. Per-command overrides use `SandboxOverride` (`NoOverride`, `EscalatedSandboxWithRestrictions` which broadens writes while keeping denied-read rules, or `BypassSandboxFirstAttempt`) ([`codex-rs/protocol/src/sandbox.rs#L9-L19`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/sandbox.rs#L9-L19)).
- **macOS mechanism**: Invokes `/usr/bin/sandbox-exec` per command ([`codex-rs/sandboxing/src/seatbelt.rs#L59-L63`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt.rs#L59-L63)). The base policy starts with `(deny default)` ([`seatbelt_base_policy.sbpl#L8`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt_base_policy.sbpl#L8)), allows `process-exec`, `process-fork`, same-sandbox `signal`/`process-info*`, a curated `sysctl-read` list, PTYs, and explicitly allows `com.apple.TrustEvaluationAgent` for TLS ([`seatbelt.rs#L69-L70`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt.rs#L69-L70)). Write root anchors get `(deny file-write-unlink (require-all (literal (param "...")) (vnode-type DIRECTORY)))` so sandboxed commands cannot swap a boundary directory ([`seatbelt.rs#L460-L466`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt.rs#L460-L466)), and explicit read-deny globs also deny `file-write-unlink` on every ancestor directory ([`seatbelt.rs#L580-L596`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt.rs#L580-L596)).
- **Linux mechanism**: Uses `bubblewrap` (`bwrap`) as the default filesystem sandbox — preferring system `bwrap` on `PATH` outside CWD and falling back to a bundled `codex-resources/bwrap` — combined with `PR_SET_NO_NEW_PRIVS` and `seccomp` filters in `codex-linux-sandbox` ([`codex-rs/linux-sandbox/README.md#L10-L14`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/linux-sandbox/README.md#L10-L14), [`#L53-L75`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/linux-sandbox/README.md#L53-L75)) (`实测`). Mounts `--ro-bind / /`, layers writable roots with `--bind`, isolates user/PID/network namespaces (`--unshare-user`, `--unshare-pid`, `--unshare-net` when network is restricted), and supports optional Transparent TCP via `/dev/net/tun` ([`README.md#L16-L39`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/linux-sandbox/README.md#L16-L39), [`#L139-L163`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/linux-sandbox/README.md#L139-L163)). Legacy Landlock is retained only as a fallback and not used for split/restricted policies ([`README.md#L12`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/linux-sandbox/README.md#L12)).
- **Default denied paths**:
  - **Reads**: Broad read-all by default — **no built-in `$HOME` credential read-deny list** (`实测`). Users can configure `FileSystemAccessMode::Deny` entries or `deny_read` globs (e.g. `**/*.env`), which are preserved across escalations ([`codex-rs/protocol/src/permissions.rs#L692-L760`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/permissions.rs#L692-L760), [`#L1118-L1146`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/permissions.rs#L1118-L1146)). A `:minimal` read profile is also available ([`seatbelt_read_only_platform_defaults.sbpl`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/sandboxing/src/seatbelt_read_only_platform_defaults.sbpl)).
  - **Writes**: Everything outside writable roots is read-only. Inside writable roots, `PROTECTED_METADATA_PATH_NAMES` forces four paths read-only: `.git`, `.agents`, `.codex`, and **`.aws`** ([`codex-rs/protocol/src/permissions.rs#L51-L62`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/permissions.rs#L51-L62), [`#L891-L895`](https://github.com/openai/codex/blob/1f43c02f3f3489edd61c6426fc5d392bea236a41/codex-rs/protocol/src/permissions.rs#L891-L895)) (`实测`).

### 2.2 Claude Code — Bash Sandbox (`anthropics/sandbox-runtime` + Official Docs)

## 3. Synthesis: Pattern for Cairn & Credential Deny-List Audit

### 3.1 Why Cairn's `open-confine` Pattern Fits (and Where It Sits in the Design Space)

Across the 7 projects, four distinct confinement patterns emerge (`实测`):

1. **No OS confinement** (`Goose`, `Open Interpreter v0.4.2`): Zero friction on host tasks, zero protection against prompt injection or accidental credential exfiltration.
2. **Allowlist-only workspace jail** (`nanobot`, `Gemini CLI` per-command macOS): Strongest secret isolation because `$HOME` is invisible, but incompatible with a "use my own computer" shell tool (`user_computer_shell`) that legitimately needs to inspect user projects, dotfiles, Mail/Messages/Safari history, and arbitrary directories outside a single repo (`推断`).
3. **Broad-read + workspace-only-write + egress proxy** (`Codex CLI`, `Claude Code / sandbox-runtime`, `Open Interpreter main`): Ideal for single-repo coding agents (and already closely matches Cairn's *task harness* confinement in `confine.ts` / `seatbeltProfile`), **not** for `user_computer_shell` where users explicitly ask the agent to modify files across their machine, install tools, or edit configs (`推断`). Notably, **none** of these three projects maintain a built-in `$HOME` credential read-deny list (`实测` — Claude Code explicitly documents this gap and leaves `credentials.files` to user configuration).
4. **Open-by-default (`(allow default)` / `--bind / /`) + targeted OS-level R/W deny list** (`Letta Code` cross-agent shell mode, **Cairn `open-confine`**): Preserves full host usability while enforcing hard OS-level boundaries on high-value secret stores (`实测` in `letta-code/src/sandbox/{seatbelt,bwrap}.ts`).

**Key consequence (`推断`)**: Because `open-confine` intentionally drops both workspace-only write restriction (`HOST_SHELL_WRITE_DENY_*`) and egress-proxy isolation, **Cairn's credential deny list + Seatbelt/bwrap anti-bypass mechanics become the primary defense against silent credential theft**. Prior art reveals **three** concrete upgrades we should adopt immediately:

1. **Add missing high-value credential paths** (verified absent in `confine.ts` / `confine-seatbelt.ts`).
2. **Add ancestor `file-write-unlink` Seatbelt protection** (learned from `anthropics/sandbox-runtime`, `nanobot`, and `openai/codex`) so removing `HOST_SHELL_WRITE_DENY_DIRECTORIES` does not open a trivial `mv ~/.config ~/.config2` bypass on macOS.
3. **Separate TLS trust (`com.apple.trustd`) from Keychain secret access** (learned from `Claude Code`, `Gemini CLI`, and `Codex CLI`) so normal HTTPS commands (`gh`, Go CLIs, `curl`) do not fail TLS verification on macOS.
