## Application to Cairn

- Generate 1–3 automatic next-user messages according to the number of genuinely distinct likely directions, ordered by likelihood, without padding. The owner's follow-up rejected an unconditional one-item limit: T3's one composer hint is not a universal rule for Cairn's multi-choice chips. Target 6–12 Chinese characters or 3–8 English words per item, not complete multi-clause task specifications. Reject automatic predictions above 32 Unicode code points instead of cutting off their meaning. An empty result is acceptable.
- Keep the existing 1–3-item wire reader/tool contract and the 80-code-point compatibility ceiling for project greeting choices. The automatic predictor has a shorter per-item limit, not a smaller item count.
- Render each suggestion as one 28px line. Long legacy/tool text ellipsizes inside the rounded outline; the existing composer preview exposes the full text on hover/focus, and clicking still sends the complete original text. Text must never grow a multi-line capsule or escape its parent's width.
- Preserve `ask_user` for irreversible confirmations, with pending questions suppressing suggestions.

Code ownership: `runtime/suggest-replies.ts` owns automatic prediction density; `chief/quick-replies.tsx` owns layout and existing preview/send interactions; `coordinator-quick-replies.md` records the contract. Browser regressions must check single-line height, nested text clipping, full-text preview/send, and phone/desktop widths, rather than only page-level horizontal overflow.

## Cache reuse and cost

The measurements below describe the earlier full-context implementation, not the current bounded-text task. The original plain-text miss remains undiagnosed; the accepted solution limits exposure without claiming to fix provider caching.

The [OpenAI prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), read through Agent Reach/Jina, requires an identical rendered prefix at eligible cache boundaries. Keeping a session is not a cache-hit guarantee. Provider routing, retention and cache eligibility still apply; changing model, system instructions, tools or reasoning settings may also change the rendered prefix. These are documented possibilities, not a diagnosis of any particular miss. The API guide is not a billing contract for the Codex subscription endpoint.

Isolated live Codex runs captured hashes of outgoing payloads, without credentials or prompt bodies. Three prediction requests matched their preceding answer request's session/cache key, instructions, tool definitions, reasoning settings, verbosity and complete input prefix. The intentional changes were appending the answer and prediction instruction, disabling tool choice and requesting bounded output. The installed Codex adapter does not serialize that output limit; see the follow-up investigation below. They generated two, three and two short suggestions respectively, reading 8,448–8,576 cached tokens and 341–386 new input tokens. These are measured examples, not a promised hit rate. The earlier miss lacked request fingerprints, so its cause remains unverified. Subscription catalog zeros do not establish dollar prices.

A separate deterministic regression exposed an avoidable prefix change in that earlier implementation: projecting history after appending the answer replaced the latest user image with an omission note. Projecting before appending fixed that image case, not the earlier plain-text miss. The current text-only task no longer shares that image/projection path.

An additional isolated live session exercised four independently composed messages and two messages matching a suggestion verbatim through the ordinary sending endpoint. All six prediction calls retained their preceding main request's complete input prefix and matched instructions, tools, reasoning, verbosity and session/cache key. All six reported cache reads (8,448–9,088 cached tokens), not a population hit-rate estimate. The first request after about sixteen idle minutes had zero main-answer cache reads and made no prediction call under that earlier policy. Expiry or routing are unverified explanations. The original immediate post-answer plain-text miss remains unreproduced and undiagnosed; missing request fingerprints and diagnostics cannot be recovered from usage counters.

A separate two-request Codex subscription compatibility probe sent `prompt_cache_options.comparison_response_id` for a just-completed response. The server accepted the option but returned `prompt_cache_diagnostics: {"type":"unavailable"}`; the request itself had 1,536 cached input tokens. The field therefore does not currently provide a cause for this investigation. It is not valid to label unavailable diagnostics a hit or a miss.

Conclusion (inference): cache reuse is an optimization rather than a spend guarantee. Controlling miss exposure needs a pre-request input budget or a bounded short-context task; dropping a suggestion after receiving a miss cannot refund its cost. Do not retry to chase a hit. The owner accepted the bounded-text task described below. No dollar budget is asserted for subscription traffic without a supported billing model.

### Accepted bounded-text task

- Send the latest four nonempty user/completed-assistant text messages, at most 500 Unicode code points each. Long messages retain their beginning and ending, including the latest next-step question. Omit system/tool definitions, tool results, thinking, images, older history and the main session id. Use a fixed prediction instruction, the same model, no inherited extended reasoning and no tools. This is a deliberate context/quality tradeoff, not a cache repair.
- Budget as uncached input. Keep a 16 KiB pre-transmission JSON payload guard, SSE, zero SDK retries and an eight-second deadline. Cold-cache ordinary answers become eligible. Main context length no longer suppresses suggestions or increases prediction input.
- Request 256 output tokens and verify serialization on Responses, Completions and Anthropic. Codex is enabled again with bounded input, but its installed adapter does not enforce this output limit. Use low Codex reasoning effort: the live model rejected `none`, so merely dropping the main reasoning setting was incompatible. Short-output instructions and a deadline are not a hard output/dollar ceiling. Subscription cost reporting remains token counts, not invented dollar prices.
- Regression coverage uses real installed adapters against local fake HTTP providers, including Codex, for actual serialization and one dispatch on 503. Long-history tests cover excluded context, newest-answer retention, Unicode/control-character bounds, no mutation of main context and cold-cache predictions. Live screenshots and usage belong outside the branch.

Isolated live Codex measurements of the bounded-text implementation, with the same model as the main answer:

| Result | New input | Cached input | Output, including reasoning | Serialized request | Latency |
|---|---|---|---|---|---|
| Empty prediction | 306 | 0 | 29 | 1,650 bytes | 3.226 s |
| Two chips after an ordinary statement answer | 386 | 0 | 27 | 1,999 bytes | 3.007 s |

Both calls were fully uncached, demonstrating that suggestions can work without reprocessing the full history. These are examples, not worst-case token or latency guarantees. The second turn's database usage includes 553 new input, 8,448 cached input and 89 output tokens for main answer plus prediction; its main context occupancy remains 8,677 tokens. Browser checks on the live app found two 28px single-line chips within 390px phone and desktop widths in both themes. No dollar estimate is available for this subscription channel.

## UI brief

Surface: existing Coordinator chat suggestions. This is a correction of the existing component, not a new surface. Rules: C3, C11 (question precedence), V1, V3 and V10. Reference: the T3 official single-suggestion screenshot above; Cairn keeps its existing outlined button style and touch interaction.

States: ordinary generated suggestions (isolated live app), one/two/three short suggestions, long legacy suggestion (seeded), two explicit greeting choices (existing regression), pending question (existing regression), failed send (existing regression), 390px phone and desktop in light/dark themes. Loading/error/cold-cache outcomes add no new placeholder. Screenshot evidence remains outside the branch.
