# Generative UI inside Agent Chat: Prior Art and Cairn Design

Date: 2026-11-24. Status: read-only research, no product code changed.

Question: When Cairn's Coordinator chat moves to quiet, bubble-less serif replies (see owner prototype `~/Pictures/cairn-review/_done/chat-blend-9/index.html`) with task references woven silently inline into prose, **how do leading chat products, SDKs, and open protocols let a model return structured or interactive UI inline in a conversation — and which pattern fits Cairn's Coordinator chat, existing component inventory, and safety/degradation requirements?**

Evidence labels used throughout this report:
- **measured** — verified first-hand in this session against a live product operated in the owner's signed-in Chrome (with local screenshots under `<cache>` = `~/.cache/genui-research/`, never committed), an official primary document/spec/paper, an open-source repository file, or this Cairn worktree.
- **inferred** — derived directly from measured sources and checkable against them.
- **guessed** — unverified hypothesis where primary sources are silent or closed-source.

## 1. The newcomer, why this matters, and scenarios

### The newcomer

Imagine someone who installs Cairn today and opens the Coordinator conversation on `/app` for the first time. They have never heard of MCP Apps, A2UI, JSONL patch streams, or `ChiefStreamItem`.

- **Where they meet generative UI and why it is there:** Right inside their normal conversation with the Coordinator. Instead of reading walls of Markdown describing four parallel tasks, squinting at raw diff text, typing long answers to ambiguous questions, or copying numbers into a spreadsheet to compare options, the Coordinator weaves live task status directly into its sentences, docks a clean decision card above the composer when it needs a call, drops a syntax-tinted diff or visual chart inline when showing evidence, and opens images in the full-window lightbox on click.
- **What they must already know:** Nothing about UI schemas, protocols, or sandboxes. Every interactive element looks and behaves like ordinary Cairn UI (same warm stone surface, serif prose, sans controls, dark and light themes) and always allows plain-text replies as an escape hatch.
- **Accounts, payments, and keys asked of them:** Zero new accounts, zero subscriptions, and zero extra API keys. Everything in Phase 1 runs on the user's existing LLM provider/model connection inside Cairn's own web/desktop client — no hosted UI proxy (unlike Thesys C1).
- **Where state is stored:** Structured UI payloads and answered decision receipts are stored in the user's own Cairn server database (`chief_message` rows in SQLite/Postgres), right alongside ordinary conversation messages, with plain-text fallbacks persisted on the same row. No UI state is sent to third-party SaaS UI relays.
- **Where they get stuck and what they see when it fails:**
  - *Model emits malformed chart/diff schema or unknown block version:* The server rejects invalid tool input with a Zod validation error (letting the model self-correct) or the web client falls back to rendering the block's `fallbackMarkdown` inside `SubtreeErrorBoundary` — never a blank white box, never a crashed conversation.
  - *User is on IM (Telegram/Feishu/Slack), mobile notification, history search, or copy-paste:* Every UI block carries a plain-text representation (`fallbackMarkdown` or structured Q&A text), so non-web clients and logs degrade to readable prose/tables with zero broken tags or raw JSON.
  - *Slow or interrupted stream:* Prose streams normally while tool arguments arrive; structured blocks reserve a clean skeleton or appear once validated without shifting earlier messages (Rule C23) or leaving dangling spinners on cancel.

### Why this matters for Cairn today

Measured in Cairn's current worktree (`apps/web/src/chief/`, `apps/web/src/detail/`, `apps/server/src/services/chief.ts`):

1. **Task references interrupt reading flow:** Today `foldTaskCards` + `placeTaskRefs` (`apps/web/src/chief/chief-task-refs.ts`) stacks unframed task rows with an SVG elbow above the bubble *and* renders inline mentions as bordered pill chips (`MentionChip` in `apps/web/src/detail/segments.tsx`). In the owner's serif no-bubble direction (`chat-blend-9`, Round 9/10), task references should read as ordinary words in the sentence with only a quiet 14px state glyph — no pill background, no elbow tree above the paragraph.
2. **Decisions and approvals are split across rigid chips and regex hacks:** `ask_user` (`packages/shared/src/records/message.ts:317-364`) hides option descriptions inside hover tooltips (Rule C11), making trade-off decisions hard to scan on touch or narrow screens. Meanwhile `ApprovalCard` (`apps/web/src/chief/approval-card-model.ts:119-168`) parses Chinese prose out of `question.question` with regular expressions because the wire payload lacks structured fields.
3. **Code changes, images, and quantitative comparisons still degrade to plain text:** Coordinator chat has no inline diff renderer (`ChatMarkdown` renders ```` ```diff ```` as plain monospace via Shiki rather than reusing `DiffFileBody` from `apps/web/src/detail/docpane.tsx`), withholds `attach_file` from the Coordinator (`apps/server/src/services/coordinator-tool-defs.ts:46`), clamps inline attachments to `max-h-40` thumbnails (`apps/web/src/detail/attachment-chip.tsx`), and has no data chart primitive beyond Mermaid (`pele/lazy` for flowchart/sequence/state).
4. **The industry converged sharply in 2026:** Primary sources measured in this run show **OpenAI retired ChatGPT Canvas from default models (May 2026)** in favor of inline chat blocks, **Anthropic runs Claude.ai's inline visuals on MCP Apps** (`*.claudemcpcontent.com/mcp_apps`) while keeping question cards as native host components, **Thesys archived C1** in favor of open-source OpenUI Lang, **Vercel AI SDK** discourages RSC `streamUI` in favor of typed tool parts (+ `json-render`), and **Google A2UI v1.0** + **MCP Apps SEP-1865** established a clean two-tier industry boundary: **native client-owned catalog components for first-party agent UX, sandboxed MCP Apps iframes only for third-party/open-ended apps.**

Following the `walk` and `research` skills, live consumer chat products were operated in new tabs/sessions of the owner's signed-in Chrome (`opencli` browser bridge in `--window background`, zero focus stealing, sending nothing outside each new test chat, never touching existing user chats). ### 2.1 Claude.ai — operated live across 3 generative UI surfaces (`measured`)

Test session: one new chat on `claude.ai/new` (`1280 × 726` viewport, light mode). Four turns exercised all three interactive surfaces in one conversation:

1. **Interactive Question Cards (`data-testid="hub-ask-user-question-card"`):**
   - *Observed behavior (`measured`):* While streaming, Claude emits a collapsed activity line (`正在准备两个澄清问题 >` / `Asking a question`, `<cache>/claude-t1-stream.png`). Once the tool call completes, a **native host React card** (`width: 768px`, zero iframe) docks directly above the composer (`<cache>/claude-t1-done.png`). Header shows `< 1 of 2 >` pagination and a minimize `×` button. Q1 (single-select) renders numbered rows `1..4` with bold title + muted one-line description, a pencil-icon `Something else` free-text row, and `Skip`; the main composer placeholder switches to `Or reply directly…`.
   - Clicking option `3` immediately advances to Q2 (`2 of 2`, multi-select, `<cache>/claude-t1-q2.png`), showing square `[role="checkbox"]` rows, a `Something else` checkbox row, `0 selected` counter, `Skip`, and circular Submit button.
   - Submitting Q2 dismisses the docked card and inserts a single hairline-bordered **receipt card** inline in the transcript showing each question in muted ink and the user's chosen answer(s) in primary ink (`<cache>/claude-t2-stream.png`, `<cache>/claude-t2-done.png`). Claude immediately continues its prose answer inside the **same assistant turn**.
   - *Borrow / Skip judgment:* **Borrow (already aligned with `chat-blend-9` Round 8/10)** — native docked card + inline receipt preserves prose reading rhythm while handling single-select, multi-select, pagination, and free-text cleanly.
2. **Inline Interactive Visualizations (`visualize` / Imagine):**
   - *Observed behavior (`measured`):* Prompted for an inline interactive radar chart comparing 3 coffee origins with toggle buttons, Claude streamed a collapsed progress line (`Entering the typical bean scores for each origin >`, `<cache>/claude-t3-inline-stream.png`), then mounted an **inline interactive widget directly between prose paragraphs** (`<cache>/claude-t3-inline-visible.png`).
   - *DOM & sandbox inspection (`measured`):* Crucially, Claude.ai's built-in inline visuals run on its **MCP Apps** host! The DOM contains `<iframe title="visualize: Coffee origin sensory radar" sandbox="" referrerpolicy="strict-origin" allow="clipboard-write https://<32-hex>.claudemcpcontent.com; focus-without-user-activation 'none'" src="https://<32-hex>.claudemcpcontent.com/mcp_apps?stable-origin=true&connect-src=https%3A%2F%2Fesm.sh+https%3A%2F%2Fcdnjs.cloudflare.com+https%3A%2F%2Fcdn.jsdelivr.net+https%3A%2F%2Funpkg.com&resource-src=...fonts.googleapis.com+fonts.gstatic.com+assets.claude.ai&keep=1">` with `style="width: 100%; border-style: none; background-color: transparent; height: 481px;"` (`736 × 481` px = exact reply column width).
   - *Visual feel & plain-text degradation (`measured`):* Visually exemplary — **zero outer border, transparent background, host-matched typography and muted palette**, so the chart reads like a native illustration in an essay rather than a foreign embed. However, in the DOM/screen-reader transcript (`msgTextAroundVis`), the iframe itself leaves **zero plain-text fallback**; accessibility and copy-paste rely entirely on the prose bullets Claude writes around the chart.
   - *Borrow / Skip judgment:* **Borrow the borderless, prose-width visual integration; skip iframe-per-chart codegen in Phase 1** — Cairn can achieve this exact quiet visual integration for common data charts using token-native React SVGs at < 100 ms latency and full plain-text/IM degradation, reserving MCP Apps iframes for Phase 2 third-party connectors.
3. **Standalone Interactive Artifacts (Side Panel):**
   - *Observed behavior (`measured`):* Asking Claude to build the full React coffee-tasting log took ~80 seconds (`Planning a React app build` → `Creating index.html`, `<cache>/claude-t4-artifact-stream.png`, `claude-t4-artifact-final.png`), then opened a `519 × 681` px split side pane (`<cache>/claude-t4-artifact-ready.png`, `claude-t4-artifact-loaded.png`) while leaving only a compact hairline card (`周末咖啡品鉴记录 · Artifact · Only you`), a private URL, and a prose summary in the left `761 px` chat column.
   - *DOM & sandbox inspection (`measured`):* Side-panel shell iframe points to `https://claude.ai/code/artifact/<uuid>?m=light&chrome=none&hostcaps=comment-mode+page-comments+...+export+...+save-blob&via=auto_preview&surface=chat`, with `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-downloads allow-pointer-lock allow-modals"` and `allow="fullscreen"`. Notably, Claude's own prose warned that the inner execution environment blocks direct file downloads, so it fell back to a copyable CSV textarea.
   - *Borrow / Skip judgment:* **Skip for Coordinator chat in Phase 1** — Cairn already has dedicated right-hand `SidePanel`s for Tasks, Artifacts (`成果` research reports), and the Design surface; Coordinator replies should stay lightweight and inline, not spawn a mini-IDE split pane.

### 2.2 Google Gemini — operated live (`measured`)

Test session: one new chat on `gemini.google.com/app` (`1280 × 726` viewport, dark mode, `Hydrogen` mode; `<cache>/gemini-home.png`, `gemini-more-tools.png` showing `Canvas`, `Deep research`, `Guided learning`, `Personal Intelligence`, `Create image/video/music`).

- *Observed behavior (`measured`):* Prompting *"Build an interactive visual explanation of compound interest with sliders for principal, rate, and years plus a live growth chart"* streamed an intro sentence followed by an inline dark shimmer placeholder card (`Compound Interest Interactive Explainer`, `Code | Preview | Export | Share | Fullscreen | Close`, `<cache>/gemini-t1-done.png`, `gemini-t1-final.png`). After ~25–30 s, it mounted a full interactive HTML app inline (`948 × 828` px, `<cache>/gemini-t1-complete.png`, `gemini-t1-centered.png`) with `Export` options `Google Sites` and `Download code` (`<cache>/gemini-t1-export.png`).
- *DOM & sandbox inspection (`measured`):* Mounted inside `<iframe title="Compound Interest Interactive Explainer" allow="xr-spatial-tracking; web-share" sandbox="allow-pointer-lock allow-popups allow-forms allow-popups-to-escape-sandbox allow-downloads allow-same-origin allow-scripts" src="https://<unique-hash>-h1023759661.scf.usercontent.goog/gemini-code-immersive/shim.html?origin=https%3A%2F%2Fgemini.google.com&cache=1">` — confirming Google's **SafeContentFrame** PSL domain isolation (`*.scf.usercontent.goog`) in live production.
- *Observed flaws (`measured`):*
  1. **Severe theme clash:** Inside Gemini's dark chat, the generated HTML app rendered as a glaring bright-white (`#ffffff`) slab (`<cache>/gemini-t1-complete.png`).
  2. **Heavy wait & vertical sprawl:** ~25–30 s blank shimmer wait before anything interactive appeared, and the `828 px` tall inline frame slid right underneath the floating composer bar (`<cache>/gemini-t1-centered.png`).
- *Borrow / Skip judgment:* **Borrow SafeContentFrame's unique-origin isolation lesson if Cairn ever hosts untrusted HTML; skip raw HTML/JS app generation inside Coordinator chat** — latency, white-flash theme clashes, and tall chrome boxes are the exact opposite of Cairn's calm serif stream.

## 4. Which pattern fits Cairn — and why

### 4.1 Cairn's non-negotiable constraints (`measured` from worktree)

1. **Aesthetic & typography (`~/Pictures/cairn-review/_done/chat-blend-9/index.html`, `apps/web/DESIGN.md`):** Cairn's Coordinator chat is moving toward **bubble-less editorial serif prose** (`Source Serif 4`, 15px/24px, `max-width: 576px`) on warm stone canvas (`#1b1c1b` dark / `#e7e6e1` light), restrained to three semantic hues (ochre = waiting on you, green = running, rust = failed), zero gradients/blur/nested cards (`V1`, `V3`, `V4`, `V5`), and silent inline task words. Foreign white HTML slabs (like live Gemini's `gemini-t1-complete.png`) destroy this visual calm immediately.
2. **Existing architecture & mechanical gates:**
   - Coordinator runs `@earendil-works/pi-durable` in-server (`apps/server/src/coordinator/runtime/server-runtime.ts`) with Zod-defined tools (`packages/shared/src/protocol/chief-tools.ts`), persisted as `chief_message` JSON rows (`apps/server/src/db/schema.ts:1255`) and fanned out over multiplexed team SSE (`packages/shared/src/protocol/sse.ts`).
   - Web strictly enforces:
     - **Component reuse (`apps/web/src/components/ui/INVENTORY.md`, `scripts/ui-registry-gate.mjs`):** 36 frozen shadcn/Base UI primitives; new chat components live in `apps/web/src/chief/` or `apps/web/src/components/chat/` composing `components/ui/`.
     - **Token & SVG discipline (`scripts/ui-page-style-gate.mjs`, `scripts/ui-drift-gate.mjs`):** Zero palette classes, zero hex literals outside `apps/web/src/styles/shadcn.css`, **SVG `fill`/`stroke` must use `var(--token)` or `currentColor`**.
     - **Row whitelist (Rule C26, `apps/web/src/chief/chief-row-kinds.ts`):** Raw tool calls/traces never render in Coordinator chat; every rendered row kind must be classified in `CHIEF_ROW_CLASS`.
     - **Live stability (Rule C23, `e2e/chief-live-stability.spec.ts`):** Streaming → settled must never remount or shift vertical offsets.
3. **Multi-channel & non-web degradation:** Coordinator messages also flow to IM channels (`apps/server/src/services/im/`), notifications (`notifyChiefTurn`), compaction (`compaction.ts`), history search (`chief-history.ts`), and iOS (`packages/shared/src/records/message.ts`). Any UI format that corrupts plain text (Thesys C1) or omits fallback text (raw HTML codegen) breaks those surfaces.

### 4.2 Verdict: Two-Tier Single-Path Architecture (build Tier 1 now; reserve Tier 2 for MCP connectors)

| Pattern | Fit for Cairn Coordinator Chat | Decision |
|---|---|---|
| **Tier 1 (Recommended Now): Prose-Entity Markdown + Typed Tool-Result Component Registry** *(Vercel AI SDK UI tool parts + Claude/Amp native decision controls + A2UI client-owned catalog & text-fallback discipline)* | Native Cairn tokens (dark/light), < 100 ms render, zero iframe/proxy complexity, 100% compliant with `INVENTORY.md` + `ui-page-style-gate` + Rule C23/C26, deterministic Zod validation, first-class plain-text degradation for IM/iOS/compaction. | **Adopt now (Phase 1)** |

### 4.3 How Tier 1 works end-to-end (Single Path)

To avoid minting one-off wire hacks and regex parsers per card (the tech debt visible today in `apps/web/src/chief/approval-card-model.ts`), Cairn uses **two clean emission channels — one for prose-inline entities, one for block-level structured UI**:

1. **Inline text-level entities (stay inside normal Markdown prose):**
   - Task references (`[title](todo:<id>)`, plus existing `#n` resolver) and inline images (`![caption](attachment:<teamId>/<id>.<ext>)`).
   - Streams character-by-character over existing `text_delta` SSE events with zero extra latency and natural Markdown degradation everywhere.
2. **Block-level structured UI (one unified typed contract, tool-call driven):**
   - **Interactive decisions/approvals:** Extend the existing `ask_user` / `ask_user_question` schema (`packages/shared/src/records/message.ts`) rather than inventing a second pause/resume protocol. Add optional structured `context` / `diff` / `actionSummary` fields so approvals stop regex-parsing Chinese prose, and render pending questions in the **composer-docked card** (`chat-blend-9` Round 8/10) collapsing to an inline transcript receipt (`rcpt`) on submit.
   - **Read-only / lightweight interactive inline blocks (diffs, charts, future metric/comparison blocks):** Introduce **one** Coordinator tool (`present_ui` or per-kind typed tools `show_diff` / `show_chart` that normalize into **one** persisted `chief_message` content shape: `{ kind: 'chief_ui_block', version: 1, block: UiBlock, fallbackMarkdown: string }`).
     - *Recommendation (`inferred` from tool-calling accuracy in `packages/shared/src/protocol/chief-tools.ts`):* Expose small, narrowly scoped Coordinator tools (`show_diff`, `show_chart`) so the model gets crisp Zod schemas per capability, while persisting them into **one** discriminated-union `chief_ui_block` record (`packages/shared/src/records/ui-block.ts`), mapped to **one** `ChiefStreamItem` variant (`kind: 'ui-block'`, classified `'card'` in `CHIEF_ROW_CLASS`), dispatched by **one** registry (`apps/web/src/chief/ui-blocks/index.tsx`), and wrapped in **one** `SubtreeErrorBoundary`.
   - **Mandatory `fallbackMarkdown` invariant:** Every `chief_ui_block` record requires a non-empty `fallbackMarkdown` string (validated by Zod on write — e.g., a concise Markdown table for a chart, or file-list + unified hunk for a diff). IM adapters (`apps/server/src/services/im/`), notifications, history search, compaction, copy-message, and unknown-version web clients render `fallbackMarkdown` directly.
   - **Streaming & Rule C23 stability:** Because `mirror.ts` already upserts `{ kind: 'toolcall', call }` rows as soon as a tool call starts and settles them in place, or emits a `message` row when the tool completes, keying the rendered `ui-block` by its stable server `message.id` (never by transient array position) guarantees zero remounts or scroll jumps. If progressive streaming of large chart/diff payloads is later desired, `packages/shared/src/protocol/sse.ts` can add an optional `tool_input_delta` event following Vercel AI SDK's `parsePartialJson` pattern — not required for Phase 1 because small chart/diff tool args complete in < 1–2 s.

### Recommended phased delivery (each phase small and self-contained)

1. **Phase 1A (Prose & Task Refs):** Ship bubble-less serif Coordinator replies + silent inline task references (`5.1`). Zero new backend schema; immediate visual alignment with `chat-blend-9`.
