# Prior Art & Architecture Research: Official Hosted Cairn Cloud

Research date: 2026-11-25. Builds on [`docs/research/multi-device-data-2026-11-25.md`](./multi-device-data-2026-11-25.md) (landed `e4c9faef5`), which established that personal-agent orchestrators converge on a single authoritative control plane per dataset rather than multi-master CRDT sync. Following the owner's 2026-11-25 decision to build an official **Cairn Cloud** that every Cairn user can use (hosting the Cairn "brain" — database, Coordinator, schedules, IM/webhooks, and task routing — while the user's devices act as windows and their Macs act as Runners), this note surveys primary sources across hosted personal-agent clouds, hosted dev-agent clouds, and infrastructure cost anchors, audits what Cairn already has vs. what is missing, and recommends the cloud architecture, migration policy, and pricing model.

Evidence tags used throughout: `实测` (read or run first-hand from official pricing pages, docs, legal DPAs/ToS, pinned GitHub commits, live DNS/HTTP headers, or this Cairn worktree), `推断` (derived directly from `实测` facts), `猜测` (unverified; avoided for all core claims).

## 1. Executive Summary & Core Answers

1. **How Hermes Cloud charges and who hosts it (`实测`):** Hermes Cloud (`portal.nousresearch.com/cloud`) bundles 1 always-on Cloud Agent into monthly usage-window subscriptions — **Plus $20/mo** (4 GB RAM / 25 GB disk + Shared usage), **Super $100/mo** (4 GB / 100 GB + 5× Plus), **Ultra $200/mo** (8 GB / 100 GB + 10× Plus) — or lets Free-tier users deploy standalone agents pay-as-you-go with a **$2 minimum credit balance** (per-second compute + storage billed daily in arrears; stopped = storage only). Model credits carry **zero markup** (42/409 models even discounted below `pricing.original`). Forensic proof from `NousResearch/hermes-agent` PR [#60145](https://github.com/NousResearch/hermes-agent/pull/60145), production Issues [#147564](https://github.com/NousResearch/hermes-agent/issues/147564)/[#159527](https://github.com/NousResearch/hermes-agent/issues/159527), and the exact Fly.io IATA region-code ordering proves Hermes Cloud agent instances run on **Fly.io Machines + Fly Volumes** behind **Cloudflare** (`*.agents.nousresearch.com`), with Portal/Tool Gateways on **Vercel**, Inference/Gateway on **Railway (`lax1`)**, Auth on **Auth0**, Redis/Cron on **Upstash**, and Enterprise on **Microsoft Azure**.
2. **Is self-hosted → cloud data migration sold anywhere? (`实测`):** **No.** Across Hermes Cloud (`Transfer to Hermes Cloud`: chunked streaming zip + `--keep-host` + `--messaging-off` + 1-click Undo), Letta Cloud (open-source backup/migration scripts), OpenClaw (`openclaw backup create/restore` + `openclaw migrate`), and third-party OpenClaw hosts (Hostinger, ClawCloud, OpenClaw AWS), **zero** products charge consumers for self-serve migration. Only **Hermes Enterprise** (custom contract, >500 seats) bundles "white-glove onboarding". **Recommendation:** Make local → Cairn Cloud migration **one-click and free** as a conversion bridge into recurring subscriptions; never gate it behind a one-time fee (`推断`).
3. **What Cairn already has vs. what is missing (`实测`):** Cairn already ships a production `Dockerfile`, outbound-only Runner enrollment and execution (`apps/daemon`, `routes-machine.ts`, `apps/desktop/src/runner.ts`), per-instance AES-256-GCM secret sealing (`lib/secret-box.ts`), Cloudflare Access JWKS JWT verification (`lib/cloudflare-access.ts`), and the `1dfdf679c` outbound WebSocket tunnel + Clerk OAuth client (`services/tunnel-remote.ts`, `routes-remote.ts`, `remote-access-page.tsx`). However, the relay server referenced by `tunnel-remote.ts` is **not in this repo** (`CAIRN_TUNNEL_RELAY` defaults to `null`), `apps/server` is **strictly single-tenant** (one seeded `ctx.team`/`ctx.user`, one SQLite DB with 92 tables / 81 FKs / 255 migrations, per-thread `pi-durable` SQLite files, one `secretbox.key`), and there is **no** tenant orchestrator, Clerk JWT verifier, Stripe billing, backup runner, or workspace export/import pipeline.
4. **Recommended Cairn Cloud shape & price (`推断` from `实测`):** Keep Cairn's single-tenant `apps/server` **unmodified** and run **one isolated 512 MB microVM/container per user** (exact Hermes Cloud pattern, avoiding both a 6–12 month Postgres rewrite AND the $14.23–$16.16/mo over-provisioning cost of 1 dedicated GCP `e2-small` VM per user). Launch **Phase 1 as BYOK-first Personal Cloud at $12/mo** (`$10/mo` annual; COGS `~$4.50–$5.25/mo` on Fly.io 512 MB microVMs or packed GCP gVisor nodes → ~50–56% gross margin), then add **Phase 2 Pro at $25/mo** (`$20/mo` annual, larger storage/runners + `$10` included model credits at cost/≤5% passthrough) so newcomers without API keys can start in 60 seconds.

## 3. Deep-Dive Findings from Prior Art

### 3.1 Hermes Agent & Hermes Cloud (`NousResearch/hermes-agent` @ `a39b00bf`)

- **Packaging & pricing (`实测`):** `https://portal.nousresearch.com/pricing` returns 404; official plans live on [`portal.nousresearch.com/cloud`](https://portal.nousresearch.com/cloud) and [`portal.nousresearch.com/compare/openrouter`](https://portal.nousresearch.com/compare/openrouter). Paid tiers bundle resetting daily/weekly/monthly usage windows (models + hosted Tool Gateway calls) AND one always-on Cloud Agent (`Plus $20`: 4 GB / 25 GB; `Super $100`: 4 GB / 100 GB; `Ultra $200`: 8 GB / 100 GB). API key rate limits scale by tier (`50` → `400` → `800` → `1,600 RPM`, [`/api-docs`](https://portal.nousresearch.com/api-docs)). Free users can deploy standalone Cloud Agents via Stripe credits (`$2` minimum balance). Extra/larger instances bill daily in arrears per second of uptime + storage; stopped instances pay storage only; *"Disks never shrink."*
- **Migration mechanics (`实测`):** [`backup-and-transfer.md`](https://github.com/NousResearch/hermes-agent/blob/a39b00bf378f0a9ca6e8e8ba27af4ca4bf8cd86d/website/docs/user-guide/backup-and-transfer.md), [`agent-transfer.ts`](https://github.com/NousResearch/hermes-agent/blob/a39b00bf378f0a9ca6e8e8ba27af4ca4bf8cd86d/apps/desktop/src/lib/agent-transfer.ts), [`transfer.py`](https://github.com/NousResearch/hermes-agent/blob/a39b00bf378f0a9ca6e8e8ba27af4ca4bf8cd86d/hermes_cli/web_routers/transfer.py), and [`backup_keep_host.py`](https://github.com/NousResearch/hermes-agent/blob/a39b00bf378f0a9ca6e8e8ba27af4ca4bf8cd86d/hermes_cli/backup_keep_host.py) implement **the cleanest personal-agent migration pattern in the market**:
  1. Source exports full `$HERMES_HOME` zip (`POST /api/ops/backup`).
  2. Streams in **8 MiB chunks** (up to 32 GiB, 5 retries, `offset_gap` resume) directly to target cloud agent (`POST /api/ops/transfer/chunk`).
  3. Target pauses its s6 gateway (`pause-for-update`) to drain live turns, snapshots its pre-transfer state (`backups/pre-transfer-*.zip`, first-recorded-wins undo ledger), restores with **`--keep-host`** (preserving cloud-provisioned auth/env/provider config) and **`--messaging-off`** (importing bot tokens disabled so local bots don't collide until the user flips the switch), and supports **1-click Undo**.
  4. **100% free.** Only Hermes Enterprise (>500 seats) has white-glove onboarding ([`/business`](https://portal.nousresearch.com/business)).
- **Infrastructure forensics (`实测` + `推断`):**
  - **Cloud agent compute = Fly.io Machines + Fly Volumes:** Maintainer PR [#60145](https://github.com/NousResearch/hermes-agent/pull/60145) explicitly removed Fly.io references from `hermes_cli/auth.py` (*"named Fly — the specific managed-hosting compute provider — twice"*); production Issues [#147564](https://github.com/NousResearch/hermes-agent/issues/147564) and [#159527](https://github.com/NousResearch/hermes-agent/issues/159527) log `Fly app: hermes-agent-prod-..., region lhr` and `hosted on Hermes Cloud (Fly.io, lhr)`; and `/cloud`'s 14 region cities appear in exact alphabetical order of Fly.io's 3-letter IATA region codes (`ams, arn, bom, cdg, dfw, fra, lax, lhr, nrt, ord, sin, sjc, syd, yyz` matching [`docs.fly.io/reference/regions`](https://docs.fly.io/reference/regions)).
  - **Supporting stack (`实测`):** Wildcard proxy `*.agents.nousresearch.com` on **Cloudflare** (`AS13335`); Portal & Tool/Connector Gateways on **Vercel** (`server: Vercel`, `x-powered-by: Next.js`, `sfo1/pdx1`); Inference API & Gateway on **Railway (`lax1`)** (`x-railway-request-id`, `x-railway-edge: lax1`) behind Cloudflare; Auth on **Auth0** (`*.edge.tenants.us.auth0.com`, plus WorkOS TXT); hot-path Redis cache & Hermes Cloud production crons on **Upstash Redis Enterprise + QStash** ([Upstash case study](https://upstash.com/customers/nous-research)); status on **Better Stack**; payments on **Stripe**; Enterprise on **Azure Container Apps Sandboxes & Microsoft Foundry** ([Azure post](https://nousresearch.com/hermes-enterprise-in-microsoft-teams)).
- **Privacy trade-off (`实测`):** Default Terms §12.3a–c grant Nous rights to use non-Google prompts/outputs/traces for model training and commercializing derivative models unless the user enables Privacy Mode ([`/terms`](https://portal.nousresearch.com/terms)).

### 3.2 Letta Cloud (`letta-ai/letta-code` @ `c67a0d59`) & OpenClaw (`openclaw/openclaw` @ `e80be914`)

- **Letta Cloud (`实测`):**
  - Cleanly separates **Cloud brain/memory** (Free $0 / Pro $20 / Teams Pro $20/seat) from **execution computers** — either prorated **Cloud Sandboxes** ($0.24/$0.47/$0.70/hr, stopped storage free) or **BYOM** (`letta server` outbound WebSocket from user's Mac/VPS, $0 Letta credit cost) ([`pricing`](https://docs.letta.com/pricing/index.md), [`byom`](https://docs.letta.com/platform/computers/byom/index.md)). This **Cloud Brain + BYOM Runner** topology is structurally identical to what Cairn wants.
  - BYOK and external coding plans are first-class and $0 credit cost on all tiers including Free ([`models`](https://docs.letta.com/configuration/models/index.md)).
  - **Migration gap:** Removed `.af` AgentFile import/export in v0.32.2 ([`faq`](https://docs.letta.com/reference/faq/index.md)); Teleportation works only for already-cloud agents ([`teleportation`](https://docs.letta.com/platform/computers/teleportation/index.md)); OSS scripts in [`agent-v1-to-v2-migration-guide`](https://github.com/letta-ai/agent-v1-to-v2-migration-guide/blob/61693d09bfb15320e690daefe6badd24e6f3ab80/.agents/skills/backing-up-cloud-agents/SKILL.md) restore MemFS Git history into a fresh agent with an **empty chat**. No paid migration exists.
  - **Infra:** Edge is **Cloudflare** (`api`/`app`/`chat.letta.com`), docs on **Vercel**, Postgres DB ([Ashby job](https://jobs.ashbyhq.com/letta/5375a3dc-c886-41c0-a2de-08d0412204d8)), `podId` in [`environments.ts`](https://github.com/letta-ai/letta-code/blob/c67a0d59263262a947b3dce3420b2c35b46bd829/src/backend/api/environments.ts) (`推断` Kubernetes pods); Oneleet trust center (`trust.letta.com`) publishes 0 subprocessors and Privacy Policy names no hyperscaler (and also permits training on hosted messages).
- **OpenClaw (`实测`):**
  - Explicitly refuses to run a commercial cloud (*"No subscription. No hosted tier. No token. Stewarded by an independent 501(c)(3)"*, [`openclaw.ai`](https://openclaw.ai/)). OpenClaw Enterprise is also free self-hosted OSS; Cloud Workers (`Crabbox`) targets user-owned AWS/Daytona; OpenClaw ID relay has no production default URL yet ([`experimental-features.md`](https://github.com/openclaw/openclaw/blob/e80be914e67f55072c96ae9284293c2cb5326ac4/docs/concepts/experimental-features.md)).
  - **Market signal:** Because users *do* want always-on hosting without managing a VPS, third parties immediately filled the void: **Hostinger Managed OpenClaw** ($4.99–$9.99/mo promo → $9.99–$24.99/mo renewal, 1–2 vCPU / 4–6 GB RAM), **ClawCloud** ($29–$109/mo Linux VMs + BYOK or +20% marked-up AI credits), **OpenClaw AWS** ($29–$399/mo control plane on user's AWS), and **Kimi Claw** (bundled into Kimi's ¥49–¥1,399/mo quota, verified in [`personal-agent-monetization-2026-11-17.md`](./personal-agent-monetization-2026-11-17.md)). None charge for migration; OpenClaw itself ships free `openclaw backup create/restore` + `openclaw migrate` ([`migrating.md`](https://github.com/openclaw/openclaw/blob/e80be914e67f55072c96ae9284293c2cb5326ac4/docs/install/migrating.md)).

### 3.3 Hosted Dev-Agent Clouds (Devin, Cursor Cloud Agents, OpenAI Codex Cloud)

- **Pricing unit lesson (`实测`):** All three dev-agent clouds have converged on **$20–$30/mo entry subscriptions** (`Devin Pro $20`, `Codex Plus $20`, `Cursor Premium $30`) scaling to **$100–$200/mo** power tiers, **absorbing cloud VM cost into the subscription or model token allowance** rather than exposing raw hourly VM metering to consumers. Auto-sleep/hibernation is universal (Devin 5 min idle; Cursor hibernate + 30-day snapshots) to contain idle sandbox COGS.
- **Infra lesson (`实测`):** Both **Cursor Cloud Agents** (Firecracker microVMs in a dedicated AWS account, [`cloud-agent/security`](https://cursor.com/docs/cloud-agent/security)) and **Devin** (isolated Devbox per session on AWS, [`docs.devin.ai/admin/security`](https://docs.devin.ai/admin/security)) enforce **VM/microVM-level isolation** rather than shared-process multi-tenancy whenever user code, secrets, or stateful agent environments are hosted.
- **BYOK contrast (`实测`):** Dev-agent clouds with proprietary models restrict BYOK (Codex Cloud bans API keys completely; Cursor levies a `$0.25/1M` token surcharge on Teams/Enterprise BYOK; Devin only allows ChatGPT subscription linking). By contrast, **personal-agent orchestrators (Hermes, Letta, OpenClaw ecosystem) universally treat zero-markup BYOK as table stakes** — and that is Cairn's natural positioning.

1. **No hosted relay or cloud control plane in this repository:** `apps/` contains only `daemon`, `desktop`, `ios`, `server`, `tsnet-sidecar`, `web`. `CAIRN_TUNNEL_RELAY` defaults to `null` ([`apps/server/src/index.ts:248`](../../apps/server/src/index.ts#L248)); the earlier unmounted DO relay was retired in #5341 (`docs/design/retire-connect-relay.md`). 2. **Zero in-process multi-tenancy inside `apps/server`:** [`db/seed.ts:21-51`](../../apps/server/src/db/seed.ts#L21-L51) seeds exactly one `user` and one `team`; `ctx.team` and `ctx.user` are singletons on `AppContext` ([`context.ts:58-59`](../../apps/server/src/context.ts#L58-L59)); [`routes-helpers.ts:31`](../../apps/server/src/routes-helpers.ts#L31) hard-rejects any `teamId !== ctx.team.id`. `server.db` (92 tables, 81 FKs, 42 UNIQUEs, 255 migrations), `coordinator/*.sqlite`, `secretbox.key`, `attachments/`, `repos/`, `MachineWakeHub`, `TeamStreamHub`, `scheduler`, and `im`/`mail` all assume 1 owner per process.
3. **No Clerk JWT verification & tenant routing gateway:** Needed to verify Clerk sessions at the edge, map `clerk_user_id` → tenant instance (`<tenant>.cloud.<domain>`), enforce subscription status, and mint a scoped session for that user's brain (without sending bearer tokens in URL query strings).
4. **No tenant lifecycle orchestrator:** Provisioning a new user's container/microVM + persistent volume, rolling zero-downtime image upgrades across the fleet, health checks, auto-restart, suspension on non-payment, and hard deletion on cancel.

6. **No atomic workspace export / import / migration service:** No endpoint to snapshot `server.db` (`VACUUM INTO`), `coordinator/*.sqlite`, `attachments/`, `repos/`, and `secretbox.key` into a verified chunked archive, upload it to Cloud (with `--keep-host` & IM/cron paused), or download a full `CAIRN_HOME` back to a Mac.
7. **No continuous backup & restore engine:** No Litestream WAL shipper or periodic encrypted archive sync to GCS/R2 + restore workflow.
8. **No multi-tenant security perimeter:** No per-tenant egress firewall blocking cloud metadata (`169.254.169.254`) and RFC1918 peer-tenant IPs, no per-tenant CPU/RAM/disk/PID cgroups, and no KMS envelope wrapping of `secretbox.key`.

## 6. Recommendation & Architectural Fit

### 6.1 Tenancy: One Isolated 512 MB MicroVM/Container per User (Single Path!)

- **Reject shared multi-tenant DB rewrite:** Rewriting 92 SQLite tables / 81 FKs / 255 migrations + `pi-durable` SQLite harnesses + git hosting + IM/mail sockets into multi-tenant Postgres would take 6–12+ months, permanently fork local Cairn from Cloud Cairn, and increase cross-tenant secret-leak blast radius (`推断` from `实测` schema).
- **Reject 1 dedicated GCP `e2-small` VM per user:** At `$14.23–$16.16/mo` on-demand (`$9.70–$10.92/mo` 1yr CUD) for 2 GiB RAM / 20 GiB disk when a heavy Cairn user needs only **~170 MB RSS and ~280 MB disk**, per-user VMs burn 3×–4× COGS and make a `$12/mo` Personal plan unprofitable (`实测` / `推断`).
- **Adopt 1 isolated microVM/container per user running the unmodified `Dockerfile` (`apps/server`):**
  - **Zero code fork:** Same SQLite WAL, same `pi-durable` harnesses, same `secretbox.key`, same `routes-machine.ts` Runner protocol.
  - **Hard isolation:** Separate filesystem, separate SQLite DB, separate `secretbox.key`, separate network namespace / microVM kernel.
  - **Hosting choice (for owner to pick):**
    - **Recommended for fastest launch & cleanest isolation — Fly.io Machines + Fly Volumes** (exact Hermes Cloud architecture): `~$4.50/user/mo` (512 MB RAM / 5 GB volume) to `$5.25/user/mo` (10 GB volume), native Firecracker isolation, API-driven provisioning, global regions, `$0` idle node waste.
    - **Alternative to stay strictly inside owner's GCP account/credits — GCP Host Pool with gVisor (`runsc`) containers + persistent per-user disks + GCS Litestream**: Alpha starts on 1 × `e2-medium` (`~$25/mo` total for 5–6 users); production scales on `e2-standard-4` nodes (~20 users/node → `~$4–$5/user/mo` COGS).

### 6.2 Migration Policy: Free, One-Click, Reversible

- **Do NOT sell consumer migration.** Zero prior-art products charge for it; charging taxes high-intent users at the exact moment they convert into recurring subscribers.
- Copy Hermes Cloud's verified design (`Transfer to Hermes Cloud`): atomic local snapshot (`VACUUM INTO` for `server.db` + quiesced `coordinator/*.sqlite` + `attachments/` + `repos/` + encrypted `secretbox.key`) → resumable 8 MiB chunked upload over HTTPS → Cloud pre-transfer undo snapshot → restore preserving Cloud host auth/URL while importing IM/cron connections **disabled by default** (zero bot-token collisions) → 1-click Undo + symmetric 1-click **Export to Local Mac** at any time.

### 6.3 Monetization & Governance

- **Phase 1 — BYOK Personal Cloud (`$12/mo`, `$10/mo` annual):** Always-on 512 MB Brain, 10 GB disk, up to 3 Runners, continuous encrypted backups, Clerk SSO, free 1-click migration & export, **zero-markup BYOK** + Runner-local Claude/Codex subscriptions. Gross margin ~50–56% on microVM/packed GCP.
- **Phase 2 — Pro All-in-One (`$25/mo`, `$20/mo` annual):** 1–2 GB Brain, 30 GB disk, up to 10 Runners, 30-day PITR, plus **$10/mo included Model Credits** (0–5% passthrough, strict spend caps, Stripe Radar) so non-technical newcomers can chat in 60 seconds without an API key.
- **Governance note (`实测`):** [`docs/research/personal-agent-monetization-2026-11-17.md`](./personal-agent-monetization-2026-11-17.md) noted that `docs/spec/18-positioning-and-differentiation.md` §4 previously prohibited a project-run hosted control plane and resold compute. The owner's 2026-11-25 decision supersedes that clause for Cairn Cloud; the cloud control-plane / billing / orchestrator code should live in a separate private repo (or separate commercial license) while keeping `cairn` self-hosting Apache-2.0 free.

### 6.4 Concrete Code Areas Touched (When Implementation Begins)

1. **In `cairn` repo (OSS, benefits both self-host & Cloud):**
   - `apps/server/src/lib/clerk-auth.ts` (new, modeled on `lib/cloudflare-access.ts`): verify Clerk/Cloud-Gateway RS256 JWTs for single-tenant owner admission (`CAIRN_CLOUD_OWNER_SUB`, `CAIRN_CLERK_JWKS_URL`).
   - `apps/server/src/services/workspace-archive.ts` & `routes-remote.ts`: atomic `CAIRN_HOME` export (`VACUUM INTO` + `coordinator/*.sqlite` + `attachments/` + `repos/` + `secretbox.key`), chunked resumable import (`--keep-host`, `--disable-external-connectors`), and pre-import undo snapshot.
   - `apps/desktop/src/main.ts`, `connections.ts`, `runner.ts`: Clerk sign-in → auto-discover Cloud Brain URL → auto-enroll local Mac as Runner + offline fallback bar/cache when Cloud is unreachable.
   - `Dockerfile`: optional Litestream binary + startup wrapper when `CAIRN_LITESTREAM_BUCKET` is configured.
2. **In new private `cairn-cloud` control-plane repo (owner-operated):**
   - Clerk auth + Stripe billing portal + tenant registry DB (Postgres/SQLite).
   - Tenant orchestrator (Fly Machines API or GCP host-pool gVisor orchestrator) + per-tenant egress firewall & KMS key wrapping.
   - Wildcard HTTPS auth/routing proxy (`*.cloud.<domain>` → tenant container).
