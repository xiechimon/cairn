# Warm Antigravity ACP Reuse & Coordinator First-Reply Speed — plan, 2026-11-28

## User scenario

Someone who installed Cairn today opens the Coordinator chat (backed by Antigravity / Gemini on their Mac runner) and sends a one-line question such as `3+4 等于几？只回数字。` or a follow-up question. Today, every single turn cold-spawns a fresh 228 MB `antigravity acp` child process, re-initializes OAuth/experiments/models, spawns a Node.js stdio MCP relay, reloads the SQLite conversation store, buffers the first streaming text delta for up to 250 ms, and kills the child process at turn end (while `StepReaper` polls `ps` for ~1 s, delaying the next queued turn). On cross-machine failover, the server also asks the new runner to `session/resume` a machine-local `sessionId` that only exists on the previous runner, adding another 6–12 s miss before falling back to a fresh session.

Measured stage breakdown on production (`macmini`, 2026-11-28 `server.db`, `daemon.log`, and real-UI Playwright baseline `task-265`):
- **Cold first turn** (`iqzoO4` greeting): `queue = 161 ms`, `claim → new session = 3,000 ms`, `new → firstProg = 3,486 ms`, `teardown = 8,749 ms` (tool calls + `StepReaper`).
- **Standalone follow-up turns on same machine** (baseline Turns 3–5: `5+6`, `7+8`, `9+10`, and prod `dhWCRz` / `9tDq2E`): `queue = 15–688 ms`, **`claim → continue session = 3,000 ms`**, `continue → firstProg = 1,536–2,314 ms`, `firstVisible = 5,506–6,102 ms`, **`teardown (lastProgressAt → finishedAt) = 731–1,162 ms`**. Cold ACP open + teardown accounts for ~4.0 s (~65%) of standalone follow-up wall time.
- **Cross-machine failover** (`AT_Jhz` on `jp_OyV` after `OIKkD`, `Az4e5-` on `OIKkD` after `jp_OyV`): `queue = 16–5,890 ms`, **`resume miss + fallback to new = 6,000–12,343 ms`**, `model = 4,500–5,900 ms`, `teardown = 1,288 ms`, total `19.4–30.6 s`.

Why warm pooling + cross-machine check + leading-edge first delta are all needed together: fixing only cross-machine resume leaves ~4.0 s of cold spawn + teardown on every single follow-up turn; fixing only leading-edge delta saves <=250 ms; reusing the live `antigravity acp` process + session removes the ~3.0 s per-turn cold open and ~0.9 s `StepReaper` teardown on follow-up turns, while the cross-machine check removes 6–12.3 s on failover and leading-edge delta removes up to 250 ms on multi-chunk Coordinator replies.

After this change:
- Consecutive Coordinator turns on the same runner reuse the live warm `antigravity acp` process and session already open in memory, skipping per-turn spawn, `initialize`, `session/resume`, MCP stdio launch, and `set_config_option`/`set_mode` RPCs, and skipping `StepReaper` process kill between turns.
- When a Coordinator thread switches machines for a machine-local session runtime (`antigravity`, `claude-code`, `devin`, `gemini`), the server starts a fresh session with `chief.history` (or without history on locked turns) instead of forcing a doomed `session/resume` on the new machine.
- On Coordinator (`stepKind === 'chief'`) turns, the first streaming text/thinking delta flushes immediately on the leading edge instead of waiting 250 ms; worker steps are unchanged.
- No new product setting, account, key, or storage path is added; users see the same chat, tool approval, and error behavior, only faster. When a warm session is incompatible, crashes, expires after idle TTL, or is stopped mid-turn, it is evicted and falls back cleanly to a normal cold `session/resume` or `session/new`.

## Scope

1. **Warm Antigravity ACP session pool** (`apps/daemon/src/backend/acp.ts`, `apps/daemon/src/backend/acp-tools.ts`, `apps/daemon/src/backend/antigravity-hooks.ts`, `apps/daemon/src/machine-loop.ts`, `packages/shared/src/agent-backend.ts`, `packages/shared/src/node/credential-profile.ts`):
   - Pool Coordinator Antigravity ACP sessions (`adapter?.harness === 'antigravity' && adapter.sessionResume === true && (adapter.warmSessionIdleMs ?? 0) > 0 && opts.compactAt !== undefined`) keyed by `sessionId`, bounded to `MAX_WARM_SESSIONS = 2` with LRU eviction and an idle timer (`ANTIGRAVITY_WARM_IDLE_MS = 5 * 60_000` in `machine-loop.ts`).
   - Add `AgentBackend.close?(): void` and call it when replacing `antigravityBackend` or stopping the daemon in `machine-loop.ts`, releasing `activeAntigravityVersions` so managed binary updates proceed.
   - Retain deterministic credential profile refcount (`retainDeterministicCredentialProfile` in `packages/shared/src/node/credential-profile.ts`, sharing `releaseDeterministicProfile` with `acquireDeterministicCredentialProfile`; `reapCredentialProfiles` reads `activeDeterministicProfiles` and skips active dirs) for the warm process lifetime.
   - Strip `CAIRN_STEP_TREE` (`STEP_TREE_ENV`) from the warm child's env and give it its own `createTempEnvironment` (`TMPDIR`/`TMP`/`TEMP`).
   - Update `installAntigravityTurnHooks` (`apps/daemon/src/backend/antigravity-hooks.ts`) cleanup to re-read current `hooks.json` and remove only the `cairn-relay-guard` key so external edits or another task's hooks are never overwritten.
   - Extend `openAcpTools` (`apps/daemon/src/backend/acp-tools.ts`) with `computeAcpToolsDigest`, `rebind(nextOpts)`, `unbind()`, `hasInFlightCalls()`, and `setOnStrayCall`. Track `inFlightCalls` across `CallToolRequestSchema` execution; reject parked calls (`ACP host tools are unbound between turns`) and fire `onStrayCall`.
   - Enforce `WarmAcpEntry` state machine (`opening → active ↔ parked → terminating → terminated`), `cwdOwners` contention serialization, unsolicited parked notification / permission / stray call eviction, and exit-before-resource-release teardown.
2. **Exact session-scoped cross-machine check** (`apps/server/src/services/claude-account-hold.ts`, `apps/server/src/services/machine-claim.ts`):
   - Add `chiefLastRanOnOtherMachine(db, threadId, sessionId, stepId, machineId)` querying `step` with `eq(step.buildId, threadId)`, `eq(step.kind, 'chief')`, `eq(step.sessionId, sessionId)`, `ne(step.id, stepId)` ordered by `(createdAt DESC, rowid DESC)` limit 1.
   - Gate `continuesSession` in `chiefClaimPayload` only when `LOCAL_DISK_SESSION_RUNTIMES.has(runtime)` (`antigravity`, `claude-code`, `devin`, `gemini` — NOT `pi`).
3. **Coordinator-scoped leading-edge first-delta flush** (`apps/daemon/src/delta-relay.ts`, `apps/daemon/src/step-transcript-stream.ts`, `apps/daemon/src/step-pass-controls.ts`):
   - Add `leading?: boolean` (default `false`) and serialized `inflight` promise chaining in `DeltaRelay` so `flushNow()` awaits any in-flight leading send before resolving.
   - Add `leadingFirstDelta?: boolean` to `StepTranscriptStreamOptions` and pass `leadingFirstDelta: input.stepKind === 'chief'` in `createStepPassControls`.
4. **Unchanged**: No new `CAIRN_*` env var or user setting, no wire/DB schema change, worker build/plan/review steps continue to spawn fresh per step and buffer deltas for 250 ms, `pi` Coordinator cross-machine resume stays unchanged, cold `session/resume` → `session/load` fallback stays intact, and permission gates / `.agents/hooks.json` stay enforced.

States, transitions, readers, and writers:
- `WarmAcpEntry` state machine: `opening` → `active` (owned by one `AcpSession`, `hostTools` bound, in `activeWarm`) → `parked` (atomic check: `cleanEndTurn && !cancelled && !backend.closed && entry.isAlive() && !entry.hostTools?.hasInFlightCalls()` and no unfinished tool calls; `hostTools.unbind()`, stored in `warmPool` keyed by `sessionId`, `idleTimer` armed) → `active` (atomic `takeWarm`: synchronous delete from `warmPool`, clear `idleTimer`, verify `state === 'parked' && isAlive() && !closed`, set `state = 'active'`, `rebind(opts)`). Any error, `stop()`, `cancel`, compatibility mismatch, unsolicited parked notification/permission/stray tool call, `createSession` on same `cwd`, LRU eviction (`MAX_WARM_SESSIONS = 2`), idle TTL, child `exit`, or `backend.close()` transitions to `terminating` → closes `hostTools`, `mcpBridges`, `connection`, sends `SIGTERM` (+ 1 s `SIGKILL` escalation). `cleanupHooks()`, `releaseProfile()`, `warmTemp.cleanup()`, `releaseRuntime()`, `releaseLaunch()`, `cwdOwners` deletion, and `state = 'terminated'` execute ONLY inside the `child.once('close')` handler (never on an early timeout while the child is still alive), guaranteeing the old child has fully exited before any shared `HOME`, `TMPDIR`, runtime version, or `.agents/hooks.json` is released.
- `cwd` concurrency protocol: `cwdOwners` tracks the sole warm-pool owner per `cwd`. Before a cold warm-eligible `open()` writes `.agents/hooks.json` or spawns, if `cwdOwners.get(cwd)` is `parked` or `terminating`, it calls `terminate()` and `await entry.terminated`; if `cwdOwners.get(cwd)` is `active` (two turns racing on the same `cwd`), the racing turn skips `installAntigravityTurnHooks` overwrite / `cwdOwners` registration and runs cold non-pooled or serialized behind `active` owner's exit, so two processes never concurrently mutate `.agents/hooks.json` on the same `cwd`.
- Credential profile refcount (`activeDeterministicProfiles` in `credential-profile.ts`): Turn 1 `prepareStepEnv` acquires (+1); cold warm-eligible `open` calls `retainDeterministicCredentialProfile` (+1); Turn 1 `stepCleanups` decrements (-1, stays 1); `reapCredentialProfiles` reads `activeDeterministicProfiles` and skips active dirs (cleaning only orphaned dirs after daemon crash); Turn 2 warm hit acquires (+1 → 2) and releases (-1 → 1); `terminate()` releases (-1 → 0, deletes dir).
- Cross-machine `step.machineId` & `sessionId` writers/readers: `claimPendingChiefStep` writes `step.machineId`; `machine-finish-step.ts` writes `step.sessionId`; `finishChiefTurn` (`chief.ts`) writes `chiefThread.sessionId` and `chiefThread.sessionRuntime`; `abandonStaleChiefSteps` (`chief.ts`) clears `step.machineId = null` when re-queuing. `chiefLastRanOnOtherMachine` reads `step` filtered by `(buildId, kind = 'chief', sessionId = threadRow.sessionId, id != stepId)`.
- `DeltaRelay` ordering: `private inflight: Promise<void> = Promise.resolve()` chains every `deliver(text)` sequentially; `flushNow()` awaits `this.inflight` even if `buffered === ''`, guaranteeing `transcriptDelta` always arrives before `transcriptRow` seals the segment.
