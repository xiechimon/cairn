# Release pipeline R2: decouple arm64 verification and parallelize portable Linux archive — plan, 2026-11-27

## User scenario

A user installing Cairn today receives new fixes and desktop installers only after `desktop-release` builds all four platform targets and finishes macOS smoke, feature-journey, and post-install migration checks on the arm64 bundle. Baseline live timings from post-R1 runs `45939439244` (`21m24s` active) and `45946109454` (`20m29s` active): `package (arm64)` `6m07s–8m34s`, `package (x64)` `10m41s–11m39s`, `package-win` `9m40s–9m55s`, `package-linux` `9m54s–10m39s` (~8m54s in single-threaded 7-zip gzip), `verify-arm64-smoke` `7m58s–8m02s`, `publish` `1m08s–1m10s`.

This change requires no new user accounts, keys, storage, or actions and keeps every verification check, signature, version allocation, update manifest (`desktop-latest.json`), archive top-level layout (`Cairn-$VERSION-linux-x64/`), portable `0:0` root ownership, symlink preservation, executable permissions, and failure-safety guard intact. It targets cutting release build-to-publish critical path (~20.5m -> ~14.5m unverified target, pending post-merge live runs; actual speedup depends on `pigz` availability on `ubuntu-latest` and the remaining DMG upload plus keychain cleanup tail in `package-arm64`) by starting `verify-arm64-*` immediately after `package-arm64` instead of waiting for `package-x64`, downloading only `.zip` in `verify-arm64-*`, and compressing the Linux archive with system `tar --numeric-owner --owner=0 --group=0` piped to parallel `pigz` (or `gzip` fallback) under `set -o pipefail`.

## Scope

1. Split the `package` matrix job in `.github/workflows/desktop-release.yml` into dedicated `package-arm64` and `package-x64` jobs (`needs: [decide]`, `environment: desktop-release`, no extra `permissions`, `VERSION: ${{ needs.decide.outputs.version }}`, pinned checkout at `needs.decide.outputs.sha`), keeping `vitest run test/seatbelt-tls.test.ts` on `package-arm64` and matching Go arch targets (`arm64` / `amd64`). Removing the shared matrix removes implicit cross-arch `fail-fast` cancellation: `package-arm64` failure skips `verify-arm64-*` and `publish` while `package-x64` finishes independently; `package-x64` failure still runs `verify-arm64-*` while `publish` skips so no partial release is published.
2. Split `package-arm64` uploads into `desktop-arm64-zip` (`apps/desktop/release/Cairn-${{ env.VERSION }}-mac-arm64.zip`) and `desktop-arm64-dmg` (`apps/desktop/release/Cairn-${{ env.VERSION }}-mac-arm64.dmg`), both with `if-no-files-found: error`, `retention-days: 1`, and `overwrite: true`; upload `desktop-x64` (`Cairn-${{ env.VERSION }}-mac-x64.dmg` + `.zip`) from `package-x64` with the same retention and overwrite settings; update `verify-arm64-smoke`, `verify-arm64-journeys`, and `verify-arm64-post-install` to `needs: [decide, package-arm64]` and download only `desktop-arm64-zip`.
3. Update `publish` `needs` in `.github/workflows/desktop-release.yml` to `[decide, package-arm64, package-x64, package-win, package-linux, live-verify, verify-arm64-smoke, verify-arm64-journeys, verify-arm64-post-install]`, keeping `download-artifact` (`pattern: desktop-*`, `merge-multiple: true`), 4-platform archive version validation, `desktop-latest.json` manifest writing, all 8 release asset uploads (`mac-arm64.dmg`, `mac-x64.dmg`, `mac-arm64.zip`, `mac-x64.zip`, `win-x64.exe`, `win-x64.zip`, `linux-x64.tar.gz`, `desktop-latest.json`), and `release-gate.mjs` / `release-tip.mjs` / tag / draft safety checks unchanged. Windows packaging, macOS signing, and `apps/desktop/scripts/smoke-mac.mjs` remain untouched.
4. Update `package-linux` `Package the Linux x64 archive` in `.github/workflows/desktop-release.yml` to enable `set -o pipefail`, run `pnpm exec electron-builder --linux dir --x64 -c.extraMetadata.version="$VERSION" --publish never`, run `rm -rf "release/Cairn-$VERSION-linux-x64"` before `mv release/linux-unpacked "release/Cairn-$VERSION-linux-x64"` (cleaning any pre-existing versioned staging directory left in workspace so `mv` renames instead of nesting `linux-unpacked` inside an existing directory; if `rm -rf` fails, `set -e` aborts the step), match `electron-builder` `ArchiveTarget` top-level prefix (`Cairn-$VERSION-linux-x64/`), and stream `tar --numeric-owner --owner=0 --group=0 -C release -cf - "Cairn-$VERSION-linux-x64" | $compress > "release/Cairn-$VERSION-linux-x64.tar.gz"` using `pigz -6` if present or `gzip -6` otherwise. Passing `--numeric-owner --owner=0 --group=0` preserves portable `0:0` root numeric ownership (matching `node-tar` `portable: true`) rather than leaking the build runner UID/GID, while preserving symlinks, executable modes, and top-level prefix and immediately failing on `rm`, `mv`, `tar`, or compressor errors; unpacked binaries and symlinks continue to be validated on the real Linux runner by `Check that the Linux archive holds the Runner and sidecar`.

## States, readers, writers, and artifacts

- **`decide` gate & outputs (`release`, `sha`, `version`)**:
  - Runs only when `github.ref == 'refs/heads/main'` (non-`main` `workflow_dispatch` skips `decide` and all downstream jobs).
  - Writer: `decide` (`gh api` tip lookup, full checkout, `scripts/ops/release-decide.mjs`). API or checkout failures fail the run; if no eligible green changed unreleased commit exists on `main`, `decide` succeeds with `release=false` (if `main` tip is red or pending, an earlier green changed unreleased ancestor is selected).
  - Readers: `live-verify`, `package-arm64`, `package-x64`, `package-win`, `package-linux`, `verify-arm64-smoke`, `verify-arm64-journeys`, `verify-arm64-post-install`, and `publish`. Downstream build/verify jobs check out `needs.decide.outputs.sha`; `publish` checks out trusted `github.sha` and consumes `needs.decide.outputs.sha` (`RELEASE_SHA`) and `needs.decide.outputs.version` (`VERSION`).
- **`main` branch ref, CI check evidence, and `steps.tip.outputs.on_main`**:
  - Writers: pushes/`promote` update the `main` branch ref; `.github/workflows/ci.yml` runs on `main` write CI check evidence; inside `publish`, step `id: tip` (`scripts/ops/release-tip.mjs`) writes `steps.tip.outputs.on_main` once before draft creation.
  - Readers: `decide` reads `main` ref and CI evidence once; `publish` runs a dedicated step (`Refuse to publish when the SHA's green evidence moved` via `release-gate.mjs`) and `id: tip` (`release-tip.mjs`) before draft creation, then `Publish the release` re-reads both `release-tip.mjs` and `release-gate.mjs` after uploading all 8 assets. Normal `main` advances during builds keep `on_main=true`. Leaving `main` before draft creation makes `steps.tip.outputs.on_main != 'true'`, cleanly skipping `Publish the release` with no draft created; leaving `main` or losing CI evidence after draft creation aborts `Publish the release` non-zero leaving the staged draft behind.
- **Build artifacts (`retention-days: 1`, `overwrite: true`, `if-no-files-found: error`)**:
  - Writers: `package-arm64` (`desktop-arm64-zip`, `desktop-arm64-dmg`), `package-x64` (`desktop-x64`), `package-win` (`desktop-win-x64`), `package-linux` (`desktop-linux-x64`).
  - Readers: `verify-arm64-smoke`, `verify-arm64-journeys`, `verify-arm64-post-install` read only `desktop-arm64-zip`; `publish` runs `actions/download-artifact` (`pattern: desktop-*`, `merge-multiple: true`).
  - Expiry owner: GitHub Actions automatically expires build artifacts after 1 day.
- **Diagnostic artifacts** (never read by `publish`; read by human operators debugging failures; expired automatically by GitHub Actions):
  - `live-verify-evidence-${{ github.run_attempt }}`: written by `live-verify` (`if: always()`, `retention-days: 14`, `if-no-files-found: warn`).
  - `packaged-journeys-${{ matrix.mode }}-${{ github.run_attempt }}`: written by `verify-arm64-journeys` (`if: always()`, `retention-days: 14`, `if-no-files-found: ignore`).
  - `smoke-evidence-arm64`: written by `verify-arm64-post-install` (`if: failure()`, `retention-days: 7`, `if-no-files-found: ignore`). (`verify-arm64-smoke` uploads no artifact.)
- **Update manifest (`apps/desktop/release/desktop-latest.json`)**:
  - Writer: `Write the update manifest` (`apps/desktop/scripts/release-manifest.mjs`) inside `publish`, strictly after `Check the packaged builds carry the decided version`.
  - Readers: `Publish the release` asset upload loop and, once published, Cairn desktop app auto-updaters fetching from GitHub Releases. Failure aborts `publish` before creating a GitHub draft release.
- **GitHub release drafts, tags (`desktop-v$VERSION`), and `latest` flag**:
  - Writers: `Publish the release` (using short-lived `RELEASE_APP_ID` token: `POST /releases` `draft=true` -> parallel `POST /assets` -> `PATCH /releases/$release_id` `draft=false, make_latest=true`) plus external repository operators if they manually create/edit/delete tags or drafts. `publish` never deletes tags or releases and never adopts an existing draft or tag.
  - Readers: `decide` (`release-plan.mjs` / `release-version.mjs`, skipping versions held by any tag or release, drafts included), `verify-arm64-post-install` (`last-desktop-release.mjs`, selecting highest published non-draft/non-prerelease `desktop-v*`), and `publish` guards (`require_free_tag` twice, `release-plan.mjs`, `release-version.mjs`, and `GET /releases/$release_id` verifying `[.draft, .tag_name, .target_commitish] == "true $tag $RELEASE_SHA"`).
- **Recovery transitions (in-run rerun vs fresh trigger vs first-release & PATCH outcomes)**:
  - Concurrency group `desktop-release` (`cancel-in-progress: false`) never cancels an active release run; newer triggers replace only a single pending queued wake.
  - *In-run rerun (failed jobs or `publish`)* reuses the original `decide` outputs (`sha`, `version`). Rerunning failed `package-arm64` rebuilds and overwrites both `desktop-arm64-zip` and `desktop-arm64-dmg`, re-runs `verify-arm64-*`, and unblocks `publish`. Once `publish` creates a draft holding `$VERSION`, a `publish`-only rerun cannot reuse or adopt that draft (`require_free_tag` / leftover-draft guard refuses it). If artifacts expired (>1 day), rerunning `publish` fails (`download-artifact` if all expired, version check if `.zip`/`.tar.gz` expired, or asset upload after draft create if only `.dmg`/`.exe` expired).
  - *Fresh workflow trigger* re-runs `decide` cleanly: builds only if an eligible green changed unreleased commit exists (otherwise exits `release=false`), and allocates the next free `desktop-v*` version skipping any leftover draft.
  - *First-release deadlock*: if no prior published stable `desktop-v*` release exists yet, `verify-arm64-post-install` fails on every scheduled run; recovery requires a repository operator with write access to publish a valid baseline non-draft/non-prerelease `desktop-v*` release containing `Cairn-*-arm64.zip`, after which the next run downloads that archive and passes `post-install.mjs`.
  - *Final `PATCH` failure vs response-lost*: on a genuine `PATCH` 4xx/5xx refusal before commit, `publish` exits 1, the draft stays unpublished, and the previous stable release remains `latest`. If the server publishes (`draft=false, make_latest=true`) and only the HTTP response drops, `publish` still exits 1 even though `desktop-v$VERSION` IS live and `latest` (the previous release is NOT guaranteed to remain `latest`; an operator must inspect GitHub Releases to verify).

## Out of scope

- Changing packaging format or compression tools in `package-win` or `package-x64`.
- Reusing pre-built desktop binaries from merge-queue CI runs inside `desktop-release`.
- Modifying `apps/desktop/scripts/smoke-mac.mjs` (`dismiss()` stays unchanged).
