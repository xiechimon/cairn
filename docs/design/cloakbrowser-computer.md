# CloakBrowser on the agent computer

Status: implementation design approved by the coordinating session. Scope: the owner's Linux host desktop only; resident lifecycle changes are excluded. Baseline: `f06b6af4d4d8229e6a8ae114d201feb4520b098f`. Read [the dependency research](../research/resident-cloakbrowser-2026-11-16.md) first and preserve [the login handoff decision](computer-login-handoff.md).

## Owner decision 2026-11-17: Chromium default, Cloak on request

Supersedes the "no stock-browser fallback" parts below for engine choice. Debian/system Chromium is the default agent browser on every computer (Linux host desktops and Mac VMs): no license seat, many sessions, profile `.cairn/browser-profile`, agent-browser session `<scope>`. CloakBrowser runs only when a browser tool call passes `stealth: true` (the Coordinator prompt says when: sites that block automation, or logging in to them; no keyword matching in code), with its own profile `.cairn/cloak-profile` and session `<scope>-stealth`; both may run at once. `browser` capability is offered whenever the desktop runs; `stealthBrowser` reports a present license and an acquired binary. A stealth call without a license refuses with "No CloakBrowser license; set team secret CLOAKBROWSER_LICENSE_KEY"; a rejected license or full seat refuses with the sanitized SDK reason and never falls back to Chromium. The no-CDP owner relaunch below applies to the Cloak session only; taking over the Chromium session hands control of its existing window. Everything below still governs the Cloak engine.

## Single path

Keep agent-browser 0.41.2 as the snapshot/action driver. Replace system Chromium selection with one Cloak engine resolver shared by automation, owner takeover, and the desktop launcher. Both manual entry points start the same scope-owned no-CDP systemd unit through one generated starter; the unit's observed state, not an in-memory owner flag, is authoritative after Dock launch or daemon restart. That starter returns success only after the active unit's MainPID owns a visible X11 window. Unit creation alone is not readiness: a real invalid-key probe returned control successfully before the browser exited with code 77. An already-active unit follows the same readiness check. Unit exit, missing windows or a bounded readiness timeout returns failure without forced teardown. The desktop and its existing idle policy remain unchanged. Tests may inject an engine, but production has no stock-browser fallback or engine switch.

Use the public cloakbrowser 0.7.2 SDK for signed binary acquisition, cached binary discovery, default stealth arguments, and license-error interpretation. Do not implement a downloader or copy private SDK modules. The SDK persistent-seed helper is not a public export and its persistent-context API launches a different driver; a thin adapter must persist the identity used by the Rust driver and the no-CDP owner process.

Prefer a verified cached binary; acquire through the official SDK only when none exists. Do not replace an installed build during an ordinary launch. Record the selected build for diagnosis. A free license does not promise exact-version selection or rollback; validate the owner's actual entitlement before deployment. Do not bundle a binary in Cairn releases or claim OEM/SaaS permission.

## Credentials and identity

Read a plaintext key only from a daemon-configured `CLOAKBROWSER_LICENSE_FILE`, defaulting to the upstream license-file location. The setting contains a path, never a key. Missing or unreadable credentials leave browser capability unavailable without disabling desktop/files. Key existence is not proof of validity; a successful real launch is required for acceptance.

Never add the key to the general command-environment allowlist. Automation receives browser-only environment additions when the actual executable is agent-browser. Owner and Dock launches execute one generated launcher that reads the configured key file in the final browser process environment. Never pass the license through systemd-run environment properties: even name-only `--setenv` copies the value into the generated transient unit file. Generated launchers, desktop entries and unit files contain no credential value. Do not persist launch environment maps. Errors and logs must not contain key values.

This preserves the existing trusted-host model; it does not isolate a hostile same-UID shell from process environments or credential files. File permissions and browser-only environment injection are defense in depth, not a security boundary. Record this residual risk rather than claim isolation. Deployment must not proceed under a stronger secrecy claim without a separate OS-isolation design.

Store one strict, credential-free fingerprint record per existing browser profile: SDK-generated seed/platform plus locale/timezone. Reuse it across daemon restart and agent/owner/Dock launches. Reject corrupt records instead of silently changing identity. Serialize first initialization with existing scope/input ownership and an exclusive publication; concurrent callers must observe the winning identity. Keep profile paths guarded from agent file/shell operations.

Restore the previous session on every browser entry point: a shared profile alone does not preserve session cookies across a full browser exit. Normal manual handback sends X11 `windowquit` requests to windows belonging to the manual unit's MainPID, then waits for both unit inactivity and profile-lock release. Never substitute `windowclose`, `windowkill`, or a forced unit stop: the real runtime probe lost cookies without session restoration and temporarily retained a license seat after a forced stop. Missing windows, close confirmation, a failed quit request or timeout refuses handback and leaves the manual browser intact. Maintenance/idle teardown uses this same graceful close before stopping the desktop; emergency process teardown is not evidence that the vendor seat was released.

## State and path contract

| Path | Reads / writes | Required behavior and failure |
| --- | --- | --- |
| Daemon browser preparation | key file, SDK cache; preparation readiness | Resolve a binary outside interactive commands; missing key/download/license failure reports unavailable without advertising stock Chromium. Never trigger the SDK's interactive free-key claim. |
| Capability report | preparation readiness, browser programs/driver | Browser is offered only when the configured engine and browser dependencies are prepared. Missing credentials or xdotool leave ordinary desktop view/control and files usable; an advertised browser's failed handoff still refuses rather than hiding the failure. |
| First profile launch | fingerprint record, existing profile | Create one identity without replacing another writer; corrupt identity refuses launch. |
| Agent command | profile identity, key; browser-only environment | Use Cloak executable and headed args through agent-browser; generic commands inherit no key or engine launch credentials. Preserve existing proxy, Cairn-origin, password, and takeover guards. |
| Owner takeover | existing driver/session, profile lock, identity, manual unit | Close the agent browser, check completion and wait for lock release, then use the shared manual starter without debugging flags. An already-active scope manual unit is reused, never forcibly replaced. |
| Dock launch | same engine, profile, identity, key-file path, manual unit | The desktop entry uses that same manual starter and unit, not an unmanaged browser process. No credential value enters generated files. The next agent call must discover this unit even when the desktop object is already cached. |
| Hand back / next agent call | observed manual unit/MainPID, X11 windows, profile lock | Request graceful native close, wait for unit inactivity and profile-lock release, then permit agent launch. Failure leaves ownership manual; no forced stop, overlapping launch or permanent CDP. Existing control leases continue to fence agent actions. |
| Desktop startup / rediscovery | manual unit, profile lock, Preferences, socket directory | Keep the socket directory private. Preserve a live manual profile without closing it, rewriting Preferences or importing login. For an inactive, released profile, preserve unrelated preferences and disable password storage. Close a stale Agent through its driver before writing; if browser capability is unavailable and the profile is locked, skip browser-only initialization without denying ordinary desktop access. |
| Existing profile migration | existing profile and old saved-login data | Preserve the profile and one-time login import. Take a cold backup before the real binary cutover; do not downgrade an upgraded profile without its matching backup. |
| License/driver failure | sanitized reason, exit/denial evidence | Report the real failure, never fall back. Invalid, expired, concurrency-denied and unavailable-license-server states require runtime checks. |
| Idle / shutdown | existing desktop lifecycle, observed manual unit | Keep current idle-stop scheduling and command teardown behavior. Gracefully close a discovered manual unit before desktop teardown; refusal must not kill the browser underneath it. Implementing never-idle-stop is a separate feature. |

## Red first and finish line

Write a failing test per contract row before behavior changes. Cover all three launch entry points with the same fake binary and fake key, checking stable fingerprint/profile, no debug flags in owner launch, no key in generic shell/argv/generated files, no stock fallback, failed handoff/lock contention, cached acquisition policy, corrupt identity, and readiness after preparation failure. Keep existing idle-stop assertions green.

Run related daemon tests, changed tests, affected e2e selection, lint, typecheck, spec parsing, and packaged dependency smoke checks. Inspect generated launcher artifacts, not only string constants. Real acceptance requires a separate Linux test desktop and valid owner key: automation snapshot/actions, agent-to-owner-to-agent handoff, Dock launch, license failure, and the target site's before/after behavior. Keep evidence outside the branch. No payment, live-profile cutover, or claim of reduced detection precedes that evidence.
