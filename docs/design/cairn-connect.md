# Cairn Connect

Add opt-in public HTTPS through Cloudflare Tunnel; use Worker + D1 for allocation, never application-session proxying. Execution, provider credentials and device authorization stay on the user's host. Preserve [Tailscale Serve](../deploy/tailscale-mobile.md) as the private alternative.

## Architecture and authority

- **Host:** existing Cairn and local agent/provider configuration, plus supervised, version/checksum-pinned `cloudflared`. No remote execution machine or model route is created.
- **Public entry:** dedicated loopback listener with the explicit route/auth contract below, not an unfiltered mount of the existing SPA/API. Disable both local-owner and Cloudflare Access bootstrap there. Locally managed ingress fixes this listener as its only upstream, with a 404 catch-all. Never accept a broker-supplied local service URL/configuration.
- **Cloud:** Worker + D1, official Cloudflare SDK, least-privilege Tunnel/DNS credentials. Allocate a random single-label hostname under an approved dedicated zone with wildcard TLS coverage. Allowed HTTP/SSE traffic goes through the tunnel, not the Worker; pilot WebSocket upgrades are denied. No chat storage or webhook gateway.
- **Approved pilot:** expiring invitation per host, cap 100, personal use only, no new identity-provider account. This is resource admission, not browser login. Open signup, team features and cloud-account discovery are deferred.
- **D1:** invitation hashes/expiry, environment ID, management-capability hash, resource IDs, desired state, generation and operation lease. No app credentials/content. Persist a random management capability locally before redemption; bind its hash to the invitation reservation and require possession on subsequent calls. Never fetch caller-supplied URLs.
- **Local state:** intent, resource IDs, management capability and tunnel credentials in an owner-only `CAIRN_HOME` directory, files 0600. Generate/persist the tunnel secret before allocation; only its creation call goes through the broker to Cloudflare. It grants no Cairn login authority.

## A new user pairs without network setup

1. Install/start Cairn on a supported pilot host and complete the local executor/provider/project preflight below as owner. Reuse Linux same-uid browser bootstrap; platforms without this owner handoff stop before allocation. Never copy an owner token to a phone.
2. Remote access offers **Connect without VPN**, explains Cloudflare's trust boundary, accepts the invitation and asks to enable exposure. Automatically install/verify the pinned connector; leave explicit custom binaries user-managed. Unsupported platforms stop before provisioning.
3. Reserve admission, allocate tunnel/DNS, persist credentials and start the listener/connector. Probe the exact public HTTPS descriptor without redirects. Show **Connection ready** only on matching identity; keep execution readiness separate. DNS/network failures show the failing step and idempotent Retry, not an unusable QR.
4. **Pair new device** creates the existing five-minute, one-use `/app#pair=…&env=…` QR/link. The phone or another computer removes the fragment, checks identity, and exchanges the code directly with the host for an HttpOnly device session. The Worker never receives it.
5. Submit a prompt from the paired device and obtain a result using the host's configured model. Paired devices cannot manage provider secrets; missing provider setup sends the owner back to local setup. Revoke devices individually without deleting work or private routes.

The web client is the host-served SPA, not a cross-origin dashboard. Unpaired visitors see the existing pairing gate. The host must remain awake; no cloud fallback runs its agents. Unreachable-origin errors need locally available recovery guidance; a stopped host cannot serve its own offline page.

## Public route and authentication contract

This is a deliberately limited first-result surface, not remote administration or full desktop parity. Reuse the SPA and services, but apply a positive method/template allowlist **before** the existing router, static fallback, token exemptions and upgrade handler. No prefix grants access to future routes. Parameters match one nonempty canonical path segment; method alternatives below are exhaustive, not wildcard methods. Every other method/path returns 404, even with a valid owner or independent protocol credential. Public controls outside this surface must be unavailable with a local-setup explanation, not silently fail after a click. Local and Tailscale surfaces keep their existing behavior.

| Exact method and path/template | Public admission and authorization |
| --- | --- |
| `GET /`, `GET /app`, `GET /app/*` | SPA document only, no session required; `*` is a client navigation tail, never an API or filesystem handler. No other non-API fallback. |
| `GET` / `HEAD` static files | Only exact build-manifest asset paths plus the enumerated shipped public assets required by that build (icons, fonts, manifest, service worker and boot script). No directory browsing, source maps, arbitrary files or server-generated files. A path not in that manifest is denied, not passed to the SPA. |
| `GET /api/remote/descriptor` | Anonymous, minimal environment ID/protocol version only; no network or allocation information. |
| `POST /api/remote/pair` | Anonymous transport, existing unexpired one-use grant required; exact-origin write proof, JSON and bounded body required. No owner or Access bootstrap. Returns a device credential/session only. |
| `GET /api/auth/session`, `GET /api/user/me`, `GET /api/teams`, `GET /api/projects`, `GET /api/projects/:id/todos`, `GET /api/todos`, `GET /api/tasks`, `GET /api/needs-you`, `GET /api/todos/:id` | Device credential/session required; retain existing personal-instance/team validation. No session is 401. Owner credentials are not admitted on this listener. |
| `GET /api/teams/:id/chief`, `GET /api/teams/:id/chief/threads`, `GET /api/conversations/:id/messages`, `GET /api/teams/:id/model-routing`, `GET /api/teams/:id/machines` | Same device admission; returns existing task/chat data and model/executor summaries, not provider credentials. |
| `POST /api/teams/:id/chief/threads`, `POST /api/conversations/:id/messages`, `POST /api/projects/:id/todos`, `POST /api/todos/:id/orchestrate`, `POST /api/todos/:id/messages`, `POST /api/teams/:id/chief/threads/:tid/stop`, `POST /api/teams/:id/chief/threads/:tid/questions/:requestId/answer`, `POST /api/teams/:id/chief/threads/:tid/questions/:requestId/cancel` | Same device admission plus existing schemas and authorization. Every public write, including bearer-authenticated writes, requires exact same-origin proof; no cross-origin CORS admission. These operations intentionally authorize local model execution under the owner's existing policies. |
| `POST /api/auth/stream-ticket` | Device session/credential plus same-origin write proof; one-use ticket retains device identity and existing expiry. Never issue an owner ticket here. |
| `GET /api/teams/:id/stream`, `GET /api/conversations/:id/stream` | Device session/credential or unexpired one-use **device** stream ticket only; check device still exists on ticket redemption; revocation closes registered streams. SSE is ordinary HTTP, not an upgrade. |
| `/api/auth/bootstrap`, `/api/auth/access`; `/api/remote/identity`, `/api/remote/routes`, `/api/remote/pairing` and descendants, `/api/remote/devices` and descendants; future Connect management routes | Denied on public entry, all methods/credentials. Owner uses the local listener to enable/disable/remove, create grants, revoke devices and inspect network details. |
| Provider, secrets, API-key, OAuth/GitHub setup, computer administration, server/deploy/backup, filesystem, project creation/settings, team/member settings | Denied, including reads, unless an exact method/template above already names a summary. Never infer safe exposure from the current owner-only-write list. |
| `/api/machine` and descendants, `/api/machines` and descendants (including enrollment/start/confirm), `/api/mcp`, `/api/oauth/callback`, `/git` and descendants | Denied, all methods, including valid machine/API/MCP/OAuth/Git credentials. Existing independent authentication and unauthenticated enrollment endpoints are **not** device admission. Executors use the local/private server route. |
| Uploads, attachment downloads, push registration, analytics (`/_mp/api/track` included), other non-API paths, all unlisted APIs | Denied for the initial pilot. No attachment-token exemption or implicit static fallback. |
| Every HTTP upgrade, including computer-screen WebSocket | Reject before any upgrade handler/socket handoff, independent of cookie, bearer, ticket or Host. WebSocket support needs a later explicit contract. |

The listener accepts only the allocated lowercase HTTPS authority, without an alternate port, trailing dot, duplicate Host or conflicting authority. Check raw request-target and Host before URL/router normalization: reject absolute-form targets, malformed escapes, encoded separators, backslashes, NUL/control characters, repeated slashes and dot segments (including percent-encoded/double-encoded forms). Reject conflicting framing/upgrade requests before dispatch. Query parameters never choose an auth mode or upstream. Strip forwarding/Access identity headers before application dispatch; trusted external scheme is a listener property, never a client-controlled header. The public listener never runs auth-off and accepts neither owner bearer/session nor owner stream tickets. A credential valid only for another protocol does not satisfy device auth.

Use a separate `__Host-cairn_connect` Secure, HttpOnly, Path=/, SameSite=Lax cookie, without Domain, on public entry; do not accept `cairn_auth` there or change private-route cookies. Reject duplicate public session-cookie names. All public API, pairing and SSE responses are `Cache-Control: no-store`; no service-worker caching of them. Exact-origin proof checks the allocated HTTPS Origin and rejects conflicting Fetch Metadata; bootstrap identity headers never supply it. Browser session expiry remains 30 days: show pair-again, not a perpetual retry. If redemption committed but its response was lost, the owner issues a new grant and can revoke the orphan device; never replay a consumed grant to recover its secret.

Acceptance must exercise every matrix row through the actual listener with no credential, device bearer/cookie, owner bearer/cookie/ticket and each independent credential class; assert status **and absence of route side effects** on denied requests. Include revoked/expired device and ticket cases, cookie collision, same/cross-origin writes, canonical and ambiguous raw targets, wrong/duplicate Host, all upgrade paths and a newly registered unlisted route. Then exercise the allowed SPA-to-first-result flow; missing UI dependencies require an explicit reviewed matrix addition, never a wildcard exemption. Existing private-route tests must still pass unchanged.

## State ownership, transitions and failure contract

| Read/write path | State and transition | Failure behavior and required acceptance |
| --- | --- | --- |
| Local enable | `off` to `allocating`; durably increment local intent generation, persist intent/secrets before async work | Owner + CSRF checks; auth-off/unsupported platforms create nothing; duplicate clicks share an operation. |
| Worker invitation redemption | Atomic reservation bound to environment + management hash, with expiring lease | One winner under concurrency; identical authenticated retry resumes; invalid/expired grant or global cap fails before cloud writes. |
| Worker allocation/reconcile | `reserved` to `provisioning` to `allocated`; checkpoint resource IDs with generation fences | Discover deterministic provider resource names after ambiguous timeouts before retrying creation. Stale operations cannot publish/delete newer resources. No D1 transaction spans provider calls. |
| Connector start/reconnect | `starting` to `ready` after public probe; network/crash/sleep to `reconnecting` | Check captured local generation before every spawn/publication. Bounded backoff reuses allocation. Parent exit stops child/listener. Child environment contains no model/owner/cloud-API credentials. Broker outage alone does not stop a healthy allocated data plane. |
| Route list / QR | Public route only while `ready` | Private routes remain independent. Wrong identity, downgrade or redirect receives no code/session. |
| Local pair redemption | Existing transaction: consume grant, create device/session | Reject replay/expiry/revocation; insertion failure preserves grant; paired device cannot mint grants or approve enrollment. |
| Device requests / streams | Public matrix plus existing revocation and one-use device tickets | Forged proxy identity/bootstrap fails. Revoke rejects new requests and closes streams. Test SSE reconnect and rejected WebSocket upgrade independently. |
| Local disable, including allocation/start/probe pending | Durably increment local generation and set `off`; clear Ready/QR, stop listener/connector and active public streams | Offline/cloud failure cannot delay closure. Invalidate public-route grants; retain devices, private routes and eventual stable allocation. A late allocation can be recorded as dormant but cannot activate. |
| Remove address, including allocation/start/probe pending | Durably increment local generation, set `removing`, record allocation-scoped cleanup tombstone before async deletion; close public entry as for disable | Invalidate public-route grants and public-origin sessions. Resolve even an unknown allocation by the saved reservation identity/capability. Keep secrets needed for cleanup until deletion confirmed. No re-enrollment until this allocation is retired. |
| Startup | Read intent before spawn; resume provisioning/cleanup | Invalid state/permissions fail closed. Missing/revoked allocation requires re-enrollment, not anonymous recreation. |

### Local intent and stale callbacks

One serialized local state owner handles enable, disable, remove, startup, allocation completions, probe results, child exits and reconnect timers. Serialize state commits, not waits on allocation/probe/child startup: disable/remove must be processed while those are suspended. Persist `intent` (`on`, `off`, `removing`), monotonically increasing `intentGeneration`, reservation/allocation identity and cleanup tombstone atomically in the owner-only directory. Process restart reads these before opening any listener. Public-route grants/sessions are scoped to the allocation (and grants to the current enable generation) so their invalidation does not revoke unrelated private access; implementation must add that scope before advertising these semantics. Disable preserves public device sessions for the same address; remove invalidates them.

Each async operation captures the intent generation and reservation/allocation identity. A completion may change active state, bind a listener, spawn a connector, schedule reconnect or publish Ready/QR only if those still match and intent is `on`, inside the same serialized critical section as the side effect. Cancellation signals alone are insufficient. If a spawn/probe was in flight at disable, dispose its returned handles immediately, never attach them to a newer generation. Shutdown waits for owned child/listener closure; failure is shown as stopping/error, never Off while a listener remains exposed. Stop errors do not resurrect retry timers. Startup with `off`/`removing` never spawns a listener or connector.

Disable retains an allocation even when its creation completes later: reconcile by the persisted reservation, save the credentials as dormant, keep the cap occupied. Disable followed by enable reuses/coalesces that reservation; the new generation, not the old callback, resumes and starts it after checking current intent. Remove instead drives that reservation to terminal deletion, including resources discovered later; a subsequent enable waits for deletion then requires fresh admission/address. Old callbacks may only hand allocation-scoped recovery facts to the state owner, never overwrite intent or delete resources belonging to a later allocation. Never silently reassign retired hostnames or browser-origin state.

### Provider interruption and orphan reclamation

Before the **first** provider mutation, D1 durably reserves a cap slot and operation ID, records deterministic resource names/ownership metadata and marks the allocation `provisioning`. Every provider mutation has a persisted intent/checkpoint; DNS is bound to the saved tunnel ID and allocated name. No D1 transaction spans a provider call. A lease expires the worker's authority to start another mutation, **not** proof that no resource exists. A stale worker cannot publish Allocated or delete anything; a returned resource ID is only recovery evidence for the current reconciler.

Expired provisioning, interrupted removal and any ambiguous provider timeout enter `reconciling`/`cleanup-pending`, retaining their cap slot and a tombstone. A replacement reconciler acquires a generation-fenced lease, inventories resources by saved IDs **and** operation-owned deterministic names, and either adopts a single matching resource for the same live reservation or deletes all resources owned by a canceled/removed reservation. Delete DNS before tunnel; provider Not Found is idempotent success. Conflicting ownership/multiple matches quarantine the allocation for operator inspection, never delete by a caller-supplied name. A late provider result reopens reconciliation even after a prior empty inventory.

Only a reservation whose record proves no provider mutation was ever issued can be swept as unused. Once a mutation may have been issued, slot release requires confirmed provider completion/quiescence and inventory proving every owned resource deleted; an empty read while a create may still be running is insufficient. If the provider cannot establish completion after an ambiguous call, retain the tombstone and quota and require pilot-operator reconciliation, rather than claiming automatic cleanup succeeded. Provider/D1 failure during cleanup retains the journal and retries with bounded backoff; no anonymous recreation or invitation reuse. Resource-deletion authority stays tied to that allocation's recorded generation/IDs, never to the host's current allocation alone.

Required race tests pause allocation, listener start, child spawn and descriptor probe individually; issue disable, remove, and disable→enable before releasing each callback; assert no stale Ready/QR, listener, child or reconnect. Restart at each persisted local state. Provider tests inject failure before/after every tunnel/DNS mutation and every D1 checkpoint, plus lease loss with create still in flight and a late result after an empty inventory. Assert no duplicate adopted allocation, no deletion of a newer allocation, retained quota on uncertain resources and eventual deletion/slot release only when confirmed. These are protocol obligations, not claims of tests already run.

## Management authority and recovery

An invitation admits one allocation, not a recoverable cloud identity. Keep the management capability separate from the local owner token, device credentials and tunnel secret. Broker management requests require capability possession plus the expected allocation/version; public environment ID, hostname and a consumed invitation never confer authority. No capability recovery endpoint accepts those public values as proof. Store only capability digests in D1 and never print capabilities in diagnostics.

| Read/write path | Required authority, persisted result and failure behavior |
| --- | --- |
| Healthy capability rotation, local owner only | Generate and durably journal the next capability locally before the request. D1 atomically compares current capability/version and replaces its digest/version. The old capability immediately loses all management authority, including rotation/replay. After a lost response, authenticate status with the journaled new capability; if absent, retry with the old one and expected version. Keep both locally only until the outcome is known; no dual-validity window. An unresolved conflict fails closed to operator recovery. |
| Capability suspected leaked | Local disable closes public access immediately. If the owner still has management authority, request retirement; otherwise ask the pilot operator to freeze the allocation. Rotation alone does not revoke a stolen tunnel secret, a running replica or scripts already served by a hijacked origin. Delete the old DNS/tunnel using the cleanup contract, invalidate public sessions/grants and issue a fresh invitation/address/secret only after retirement. Locally revoke any affected application credentials separately. |
| `CAIRN_HOME` lost, reinstall, uninstall without confirmed removal | There is no self-service ownership recovery in this pilot. The UI/install guide names this limitation and offers the pilot operator's contact before enable. Operator verifies the original invitation recipient through the invitation issuer's existing private contact channel; public IDs, an unverified contact claim or possession of a used invitation are insufficient. If verification fails, do not transfer control. Verified recovery retires the old allocation, never discloses its secrets or transfers its hostname, then admits a fresh installation. |
| Planned uninstall / abandon | Offer Remove public address and wait for confirmed cleanup before deleting local recovery material. Plain uninstall or deleting a directory is not cloud cleanup. An offline uninstall leaves instructions to contact the operator; its unresolved allocation still counts against the cap. |
| Inactive / abandoned allocation sweep | Record authenticated host control-plane check-ins, separately from data-plane health. After 30 days without a check-in mark it stale and notify the invitation recipient through the issuer; do not interrupt it or reclaim quota automatically. After a further 30 days without resolution the operator may authorize retirement, executing the same journaled cleanup. Uncertain resources retain quota; only confirmed retirement releases it. No cloud outage alone renews/reassigns the origin. |
| Backup restore / duplicate controller | A per-directory process lock prevents concurrent owners of one `CAIRN_HOME`; broker mutation leases serialize management by allocation/version. A copied directory is a copied authority and can run a Cloudflare replica even without a management lease. Concurrent backup clones are unsupported, not claimed prevented. A lease conflict stops that controller's management/start path with recovery guidance; a known clone requires stopping both and retiring/re-enrolling the allocation. Restore an intact backup only after confirming the old host is stopped; if uncertain, use operator recovery. |

Pilot operations must retain the invitation-to-recipient contact mapping privately, outside the public repository and D1 application-content records. The operator's audited freeze/retire actions require separately authenticated operator authority, not the host capability; freezing blocks new management/leases while retirement removes provider resources. There is no admin impersonation/session minting. Implementing or using this live operator authority, credentials and resource writes still requires mon X's approval.

Acceptance covers atomic rotate with concurrent callers, response loss, old-capability rejection on every management operation, lost/corrupt local state, verified versus unverified recovery, uninstall while offline, stale-allocation cleanup with unavailable provider and restored/cloned state. These are separate from public-entry clearance and require their own protocol re-check before management implementation.

## Supported pilot and first execution handoff

The first supported **host** is a native Linux x86-64 desktop with glibc, Node.js 22.19+ on the 22 line or Node.js 24, a normal unprivileged user with a writable private home, readable same-network-namespace `/proc/net/tcp*` and a browser running as that same user. Preflight checks these and token authentication before redeeming an invitation or making any provider call. Root-run services, headless/remote-owner-only setups, containers/WSL, ARM, macOS and Windows are not supported Connect hosts in this pilot; their existing local/Tailscale choices remain available. Later support requires its own tested owner handoff and pinned connector artifact, not a claim that Linux bootstrap works there. **Clients** are current mobile Safari/Chrome and desktop browsers; they install no connector or VPN, but their pairing/SSE behavior still needs real-device acceptance.

The wizard's local prerequisite checklist links directly to each recovery step and preserves progress across reloads:

1. **Local owner session:** install the server, open the local UI as the same user and verify owner bootstrap. On failure show local recovery; do not turn auth off or put the owner token in a URL. Connect must not bypass `CAIRN_REQUIRE_TOKEN`.
2. **Local executor:** following [getting started](../getting-started.md#run-builds-on-your-own-machines), install `@xiechimon/cairn-cli`, enroll it to this personal instance/team with a locally created API key, and start the daemon. It connects to the existing loopback/private route, never the public machine-denied listener. Check an online heartbeat and the selected runtime's reported availability; server HTTP health alone is insufficient. New onboarding must accept enrollment secrets locally without exposing them in generated command arguments or cloud payloads. Keep server/daemon launchers unambiguous because both packages expose a `cairn` binary.
3. **Model/runtime:** complete the chosen CLI login or API-key setup locally under the executing user. Verify the task's chosen runtime/model can actually answer a small request; a saved provider record is not a successful login. Missing binary, expired login, quota and provider errors each link back to the matching local setup step; never ask the phone or broker for provider secrets.
4. **Project/work directory:** create/select a project bound to that online local executor and an existing writable work directory. Do not silently choose an unrelated repository. Run an owner-confirmed tiny local smoke task there and display its actual returned text/failure. The confirmation explains any model request/cost. No cloud allocation is required for this local test.
5. **Connect and pair:** only then enable the public route. Display separate **Connection ready** and **Execution ready** checks, then create the QR. If the daemon/model later becomes unavailable, pairing/reachability can stay healthy, but new task submission explains the missing local prerequisite and provides Retry after repair; no cloud execution fallback or false first-result success.
6. **First remote result:** on a separate network with VPN off, pair, choose that project, submit a new small task and observe its streamed result. Validate the result came from the selected local executor/runtime, not from the earlier smoke task, demo data or a broker model call.

The pilot is not complete until another person follows the documented install, daemon enrollment, local model setup, project selection and phone pairing without an operator completing those steps for them. Test clean home, missing daemon, offline executor, missing runtime, expired model login, inaccessible directory, reload/resume and healthy local-then-remote result. Installer/onboarding code waits for a separate review of this support/readiness delta. A supported platform in this proposal is not yet a verified installation.

## Security boundary

Public entry follows the closed route matrix even with loopback peers, owner credentials or forged Host/identity headers. Reject ambiguous paths before filtering and reject upgrades before handoff. Require the dedicated Secure cookie, exact-origin writes and bounded pairing rates; public machine enrollment is not available.

Cloudflare terminates TLS and can inspect traffic. Compromised broker DNS/tunnel authority could serve malicious JavaScript at the trusted origin; it also sees the creation secret and could run another tunnel replica receiving application traffic. Fixed local ingress constrains this host's upstream, not integrity of the whole public origin. Local sessions and descriptor matching do not eliminate that risk; this is not end-to-end encryption against the operator. Scope credentials to a dedicated zone/account and bound resource/CPU usage.

No long-lived secrets in argv, URLs, browser storage, diagnostics or telemetry. Only a one-use grant appears in a QR fragment. Descriptor matching detects misrouting, not compromised DNS/TLS infrastructure.
