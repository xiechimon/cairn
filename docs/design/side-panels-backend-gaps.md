# Side panels: backend gaps

The computers ("sessions") and results ("make") panels were rebuilt 1:1 against the reference recording (owner 1:1 pass, 2026-11-11). The UI reads the fields below as optional web-side fields (`apps/web/src/fixtures/records.ts`: `MachineRow.hostname`, `MachineRow.folders`, `MachineRow.runningHere`, `TodoRecord.madeKind`, `TodoRecord.previewUrl`, `TodoRecord.visibility`). Only the fixtures `sessions-ref`, `sessions-ref-detail` and `make-ref` fill them. On the live stack each field is absent and the panel shows its fallback, listed per row. No server, daemon or shared wire type changed in the UI slice.

The owner dropped the hosted "In the cloud" computer: the user's own computer is the cloud computer, so no row below asks for one.

Security surfaces are the CLAUDE.md lists (`credentials`, `machineAndCommandBoundary`, `externalEntryAuth` in `packages/shared/merge-gate-paths.json`). A row marked **yes** changes a machine registration or dispatch file and goes through the owner's route.
