# In-Place Runner Token Rotation — plan, 2026-11-27

Prior art: `docs/research/runner-token-rotation-2026-11-27.md`.

## User scenario

A user installed Cairn today and paired a Runner (local desktop or remote CLI). Later they accidentally paste `machine.json` or its token into a chat, issue, or log, or want to rotate credentials on a machine they still control without losing the Runner's default flag, routing rules, or history. They open **Settings -> Runners** (`apps/web/src/resources/machine-row.tsx`), open the row `...` menu, click `更换令牌`, and confirm once inside the menu (`确认更换令牌`, no extra modal dialog). No new accounts, payments, or API keys are needed; `machine.json` on the Runner (`0o600` private file) is updated automatically when the Runner is online, and the Runner stays Online in the same row. If the Runner is offline or does not acknowledge within 5 seconds, the old token receives `401` immediately and the row displays `需要重新连接` plus the copyable reconnect command needed on that computer.

Threat-model boundary: `更换令牌` rotates credentials over the Runner's authenticated channel for leaked bearer tokens or routine rotation on hardware the owner still controls, backed by `hostKey` verification on `claim` when `machine.hostKey` is set (defeating token-only leaks such as Authorization headers or HTTP logs). If a laptop is lost/stolen, a teammate left with `machine.json` on the device, or active SSE hijacking is suspected, the owner must use `删除执行机` (or `POST /api/machines/:id/revoke`) so an untrusted machine cannot claim a pushed token.

(`packages/shared/test/snapshot.test.ts` snapshots `machineRecordSchema` and `machineStreamEventSchema`; `apps/server/test/machine-wire.test.ts` verifies `MACHINE_WIRE_EXTENSIONS`.)
2. Persisted state and product surface registration (`apps/server/src/db/schema.ts`, Drizzle migration, `scripts/product-surface-registry.json`):
   - Add `tokenReauthRequired: bool('tokenReauthRequired').notNull().default(false)` and `pendingTokenHash: text('pendingTokenHash')` on `machine`, and register both `runner-device-field` rows in `scripts/product-surface-registry.json`.
   - `findMachineByToken` continues to match ONLY `machine.tokenHash` (never `pendingTokenHash`), so normal machine endpoints never accept two tokens concurrently.
   - Clear `tokenReauthRequired = false` and `pendingTokenHash = null` on `ack`, re-enrollment (`enrollMachine` / `authorizeEnrollmentMachine`), and `revokeMachineToken`; clear `tokenReauthRequired = false` on authenticated `markConnected` and `markPresence` (both `admitOnline = true` and `false`), publishing `machine_presence` whenever `tokenReauthRequired` transitions from `true` to `false` even if `online` was already `true`.
3. Server rotation endpoints and crash-safe handoff (`apps/server/src/services/machine-rotate-token.ts`, `machine-wake-hub.ts`, `routes-machine.ts`, `routes-resources.ts`):
   - Add owner-authenticated `POST /api/machines/:id/rotate-token` (`requireOwnerSession`, `requireTeam`, `Cache-Control: no-store`, never returns plaintext tokens or hashes), decoupled from HTTP client abort so a browser disconnect during the 5s window still settles atomically.
   - Add `MachineWakeHub.pushTokenRotate(machineId, rotationId)` and `MachineWakeHub.handoffConnection(machineId, connectionId, onExpire)` (closes old SSE stream without `shutdown` and starts the 45s `offlineGraceMs` timer; if grace expires without reconnect, `onExpire` marks the machine offline).
   - Register `/api/machine/token-rotate/claim` (inside `registerMachineAuth`, bound to `(machineId, connectionId, rotationId)`, checks `body.hostKey === row.hostKey` when `row.hostKey !== null`, writes `pendingTokenHash = H(new)` in SQLite with CAS `WHERE id = ? AND tokenHash = oldTokenHash AND retiredAt IS NULL` before returning plaintext, single-use, wipes plaintext).
   - Register `/api/machine/token-rotate/ack` (exempt from `registerMachineAuth` pre-commit DB check; verifies bearer against staged `pending.newTokenHash` after `claim`, OR recovers across a server restart by matching `machine.pendingTokenHash === H(bearer)`, OR idempotently accepts an already-committed `newToken` via `findMachineByToken` when timeout/lost-response raced `ack`; atomically promotes `tokenHash = H(new), pendingTokenHash = null, tokenReauthRequired = false`, calls `handoffConnection` and `wake`, and returns `200 { ok: true }`).
4. Offline, timeout, mid-handoff fallback, and transient behavior:
   - If the Runner is offline, ignores `token.rotate` for 5s, SSE write fails, or SSE disconnects/gets replaced mid-rotation, commit `tokenHash = H(new), pendingTokenHash = null, tokenReauthRequired = true` with CAS (old token gets `401` at once).
   - If the Runner already claimed `T_new` before timeout, use `handoffConnection` (no `shutdown`) so a Runner that persisted `machine.json` self-heals on reconnect; if unclaimed, mark offline and revoke the active stream.
   - Transient handoff behavior: the Runner row stays Online across the 45s grace window and active steps' subsequent requests use `T_new` (waiting `/api/machine/tasks/claim` retries `401` immediately when `inMemoryToken` rotated). Brief per-connection disruptions during token cutover are explicit: live `computer-screen.ts` channels close on token change (releasing user control cleanly so they can reopen with `T_new`), in-flight Antigravity probes fail on disconnect and dispatch the next probe on the new `connectionId`, iMessage bridge briefly reports `degraded` until `onConnect` re-attaches it, and non-idempotent `relayTool` (`replaySafe: false`) never auto-replays on `401`.
5. Daemon rotation handoff (`apps/daemon/src/machine-client.ts`, `apps/daemon/src/machine-loop.ts`):
   - Handle `token.rotate`: claim `nextToken` (sending `hostKey`), save `prevJson`, atomically write `machine.json` (`0o600`), send `ack` with `nextToken` (1 retry on network/5xx error so server-restart `pendingTokenHash` promotion succeeds); on `200`, switch `inMemoryToken = nextToken` and reconnect SSE with `0ms` backoff without `shutdown` or `push channel down` noise; on `ack` `401`/`404`, roll back `machine.json` to `prevJson` and keep `inMemoryToken`; on disk write error, skip `ack`, keep `T_old`, and log without secrets.

## State, Readers, Writers & Failure Paths

- **`machine.tokenHash` readers**: `findMachineByToken` (`machines.ts`), `registerMachineAuth` & `executeMachineCommand` & `/api/machine/tasks/claim` & `/api/machine/stream` ping check (`routes-machine.ts`), `assertMachineClaim` (`machine-claim-scope.ts`), `machine-relay.ts`, `computer-screen.ts`, `antigravity-model-probe-authorization.ts`, `machine-routing.ts`, `runner-offline.ts`, `routes-resources.ts`, `chief.ts` (`getChiefOutage`), `demoteMigratedLocalMachines`, `seedLocalMachine`.
- **`machine.tokenHash` & `machine.pendingTokenHash` writers**: `enrollMachine`, `authorizeEnrollmentMachine`, `retireHostnameDuplicatesInTx`, `mergeMachineRowInTx` (`machines.ts`), `revokeMachineToken` (`machine-revoke.ts`), `DELETE /api/machines/:id` (`routes-resources.ts`), and `machine-rotate-token.ts` (`claim` sets `pendingTokenHash`; `ack` and offline/timeout/disconnect fallback promote `tokenHash` and clear `pendingTokenHash`).
- **`machine.tokenReauthRequired` readers/writers**: read by `toMachineRecord` (`machines.ts`), mapped to `MachineRow` by `mapMachines` (`apps/web/src/api/mappers.ts`), invalidated across tabs via `machine_presence` in `apps/web/src/api/team-stream-cache.ts`, rendered by `MachineRowView` (`apps/web/src/resources/machine-row.tsx`); written `true` by `machine-rotate-token.ts` fallback and cleared `false` by `ackMachineTokenRotation`, `markConnected`, `markPresence`, `enrollMachine`, `authorizeEnrollmentMachine`, `revokeMachineToken`.
- **`machine.json` & daemon memory readers/writers**: `apps/daemon/src/state.ts` (`loadMachineJson`, `saveMachineJson`, `forgetMachine`), `machine-enroll.ts`, `machine-loop.ts` (`inMemoryToken`, `machineJson`, `rotatingToken` guard), `cli.ts`, `config.ts`, `apps/desktop/src/runner.ts` (`readStoredMachine`, `writeMachineJson`, `verifyStoredMachine`, `enrollLocalMachine`).
- **In-memory `PendingTokenRotation` (`WeakMap<MachineWakeHub, Map<string, PendingTokenRotation>>`)**:
  - `staged` (`claimed=false, newTokenPlain !== null`) -> `claimed` (`claimed=true, newTokenPlain=null`, `pendingTokenHash` persisted in SQLite) -> settled (`pushed` or `aborted`, removed from map in `finally`, timer and `onDisconnect`/`onConnect` listeners disposed).
  - Recovery paths across Runner kinds (for custom `CAIRN_HOME`, prepend `CAIRN_HOME=<dir>`):
    - Remote CLI (browser-enrolled): `cairn logout && cairn start --server <serverUrl>` removes `machine.json` (keeps `device.json`/`hostKey`), runs browser approval (`authorizeEnrollmentMachine`), matches the existing `machine` row by `hostKey`, clears `tokenReauthRequired` and `pendingTokenHash`, and preserves `machine.id`, default, and routes.
    - Local desktop (`kind === 'local'`): restarting Cairn Desktop triggers `apps/desktop/src/runner.ts` (`verifyStoredMachine` gets `401` -> `enrollLocalMachine` -> `authorizeEnrollmentMachine` updates the local row in place); standalone local CLI runs `cairn logout && cairn start`.
    - Headless API-key (`apiKeyId !== null`): `cairn logout && cairn start --server <url> --api-key <key> --team <id>` (with the same API key) or owner-approved browser re-enrollment updates the existing row in place.
    - Version skew: an old Runner ignoring `token.rotate` hits the 5s timeout -> `401` + reconnect drawer; a new Runner on an old server never receives `token.rotate` and operates unchanged.

## Out of scope

- Scheduled or automatic periodic runner token rotation.
- Multi-token overlapping validity windows where both old and new tokens authenticate simultaneously after rotation completes.
- Remotely wiping or uninstalling `machine.json` on a lost or untrusted device (owners use `删除执行机` / `POST /api/machines/:id/revoke`).
