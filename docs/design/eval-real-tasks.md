## User scenario

Someone who installed Cairn today never sees, configures, or pays for this suite: it adds zero product settings, zero `CAIRN_*` env vars, and zero dependencies to the desktop or server install path. A first-time visitor opening `https://cairn.xmon.me/` (or `/zh-cn/`) sees the daily proof card on the homepage, where the 10 trivial Python toy tasks (`fix-bug`, `fix-typo`, `rename-var`, etc., all scoring 1/1) are replaced by 20 real non-security bug-fix tasks harvested from Cairn's own git history (`parentCommit` -> `fixCommit` regression tests).

Scope and honesty boundary: `lane` tasks measure **Devin CLI (`devin -p`) bug-fixing capability on historical Cairn snapshots**, not the end-to-end Cairn Coordinator plan -> dispatch -> verify -> land loop (that full-product loop is out of scope here). During rollout, before the next daily run finishes after landing, the site continues showing the previous `suiteVersion: 1` snapshot (marking it stale if older than 48 hours). Once the next official daily run finishes all 106 trials (`28 runtime × 3 + 20 lane × 1 + 2 canary × 1`) with `evalExitCode === 0`, `publishPublicResults` publishes `suiteVersion: 2` to `eval-results:latest.json` (and per existing `eval/run.ts` + `eval-public-results.mjs` semantics, if `EVAL_MAX_DEVIN_RUNS` caps sessions or a trial hits `incomplete`, a complete 106-trial matrix still exits 0 and publishes with those cases marked `incomplete`). Only `evalExitCode !== 0`, run timeout (`124`), or expected total trial count mismatch skips publication (`publicResults.state = 'skipped'`), while a matching count with invalid/duplicate trial keys or unsafe payload strings fails publication (`publicResults.state = 'failed'`); in both cases the prior `latest.json` remains untouched on `eval-results`. In the browser, 404/timeout/invalid JSON shows the neutral static fallback in both English and Chinese (`Home.astro` never overwrites or repairs remote data).

Only the Mac mini daily runner (`com.xiechimon.cairn-eval-daily`) runs these tasks by default using the existing isolated `EVAL_DAILY_DEVIN_HOME` and `EVAL_DAILY_LANGFUSE_ENV` inside disposable temporary directories (`eval-lane-<id>-*`). As documented in `docs/design/eval-daily-mini.md`, `EVAL_DAILY_DEVIN_HOME` is credential/session isolation rather than an OS filesystem sandbox: the single-commit baseline git repo removes `fixCommit` history from the working copy (`work`), and expected test patches stay out of `work` until after `devin` exits, so security-exploit tasks are excluded and this mechanism is framed as workspace history isolation rather than adversarial sandboxing.

Budget: each lane task has `timeoutMs <= 240_000` (default 4 min) and runs exactly 1 deterministic test command (`commandTimeoutMs = 60_000`, 1 min), giving a hard serial ceiling of `20 × (4m + 1m) = 100 min` (`<= 6_000_000` ms enforced in `eval-suite.test.ts`) plus ~3 min for snapshot/link overhead, 84 runtime replays, 2 canaries, and Langfuse export — staying inside the 120-minute `DEFAULT_RUN_TIMEOUT_MS` (`7_200_000` ms) and 135-minute launchd `--max-runtime-sec 8100` cap, and consuming 20 Devin sessions (within `devinBudget.maxSessionsPerRun: 40`).

## Scope

1. Replace the toy `eval/tasks/lane/<id>/repo/` fixture mechanism in `eval/harness/types.ts` and `eval/harness/lane.ts` with a single-path git-snapshot SWE-bench harness (`eval/harness/snapshot.ts` + `eval/harness/lane.ts`), deleting all 10 toy fixture directories (`add-config`, `add-fn`, `add-test`, `bump-version`, `comment`, `fix-bug`, `fix-typo`, `gitignore`, `rename-var`, `write-doc`). Every `LaneTask` requires `source: { parentCommit, fixCommit, testFiles, existingTestFiles }` (40-hex SHAs, safe repo-relative paths), `checks: { files, commands, allowPaths? }` with `commands` length 1, and `timeoutMs` defaulting to `240_000` (`max 240_000`). Callers pass `examDir` to `runLaneTask(task, examDir, options)`; `repoRoot` resolves via `options.repoRoot ?? resolve(examDir, '..')` with no new environment variables. Any custom `--exam` using the deleted `repo/` format is no longer supported (single path; `docs/design/eval-gate.md` remains a dated historical record per `docs/README.md`).
2. Implement `eval/harness/snapshot.ts` and update `eval/harness/lane.ts`:
   - Verify `commitExists(repoRoot, parentCommit)` and `commitExists(repoRoot, fixCommit)` before invoking `devin`; missing git objects (e.g., shallow clone) return `incomplete` (`missing git commit ...`) so infra gaps never score as model failures, and recover automatically once the host fetches full history (`macmini` clone is already unshallowed).
   - Materialize `parentCommit` via `git archive --format=tar -o <tarPath> <parentCommit>` and `tar -xf <tarPath> -C <work>` (removing `<tarPath>` in `finally` to avoid JS heap `maxBuffer` limits on ~110 MB repo archives), then run `git init -q`, `git add -A`, and `git -c user.email=eval@cairn.dev -c user.name=eval -c commit.gpgsign=false commit -qm baseline`, creating a distinct single-commit baseline SHA with `parentCommit`'s exact source tree and zero `fixCommit` history.
   - Mirror `node_modules` from `repoRoot` into `work`, repointing workspace package symlinks into `work` so agent edits to `packages/*` or `apps/*` take effect immediately; ignore `node_modules`, `__pycache__`, and `*.pyc` when computing `changedFiles(work, baseline)`.
   - After `devin` exits (and after classifying auth/quota/permission/ENOENT/timeout/ENOBUFS errors), verify every path in `existingTestFiles` and `testFiles` resolves strictly inside `realpathSync(work)`, walk every ancestor directory component inside `work` with `lstatSync` (unlinking any symlink or non-directory ancestor before `mkdirSync`) and verify `realpathSync(dirname(target))` stays inside `realpathSync(work)`, verify the target is a regular git blob (`100644`/`100755`) at the target commit, unlink any leaf symlink/file, restore `existingTestFiles` (excluding `testFiles`) from `parentCommit`, and overlay `testFiles` from `fixCommit`.
   - Run `checks.files`, `checks.commands` (with `CAIRN_LOCAL_HEAVY=1`, isolated `CAIRN_TEST_TEMP_ROOT` temp dir, `NODE_TEST_CONTEXT` deleted, and `60_000` ms command timeout), and optional `allowPaths`. If command output matches Node/Vitest module-load or ABI drift (`ERR_MODULE_NOT_FOUND`, `Cannot find package`, `NODE_MODULE_VERSION`, `Cannot find module`), return `incomplete` (`dependency drift: ...`) so lockfile drift never masquerades as a model regression. Otherwise classify command timeouts (`ETIMEDOUT` / signal), `ENOBUFS`, or spawn errors as failed `lane.tests_pass = 0` with scrubbed diagnostic prefix (`command timeout` / `command error` / `exit=<code>`). Remove `work`, `scorerTmp`, and tar files in `finally`, and perform best-effort sweep of orphaned `eval-lane-*` / `eval-lane-tmp-*` temp dirs older than 24h on startup so `SIGKILL` leftovers do not accumulate.
3. Add `eval/harvest-git.ts` supporting `--scan` (helper to list recent non-security `fix(` commits with compatible source/test file counts) and `--verify [id]` (validates `eval/tasks/lane/`: checks `parentCommit === fixCommit^`, runs **baseline** on un-overlaid `parentCommit` for `existingTestFiles` / pre-existing `testFiles` requiring exit 0, runs **nop** on `parentCommit` + `linkDependencyDirs` + overlaid `testFiles` from `fixCommit` requiring a real test failure rather than dependency/missing-module failure, and runs **oracle** by applying `git diff <parentCommit> <fixCommit>` non-test changes onto the exact same `parentCommit` workspace + restored `existingTestFiles` + overlaid `testFiles` requiring exit 0, printing per-task wall times and exiting non-zero on unknown ID, history mismatch, unexpected nop pass, or oracle/baseline failure). Keep `eval/harvest.ts` unchanged.
4. Author 20 verified non-security Cairn bug-fix tasks under `eval/tasks/lane/<id>/task.json` compatible with current `node_modules` (each with user-symptom instructions containing no fix/test leakage and `caseId` safe for `eval-public-results.mjs`), and update `eval/suite.json` to `version: 2`, `expectedCounts.lane: 20` (50 total tasks).
5. Update `eval/lane-harness.test.ts`, `eval/harvest.test.ts`, `apps/server/test/eval-suite.test.ts`, and living docs (`eval/README.md`, `docs/ops/eval-daily.md`) with zero dangling references to deleted toy paths.
