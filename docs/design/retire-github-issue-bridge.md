# Retire the GitHub issue bridge — plan, 2026-11-28

## User scenario

Someone installing Cairn today connects their GitHub account so projects can clone, push and open PRs. Until now that connection also silently made Cairn an issue tracker: a task in a GitHub-backed project opened an issue the moment its first leg delivered code, a person could import a labelled issue as a task, and Cairn commented on, renamed and closed those issues as the task moved. Nothing in the product asked for it, and an agent that wants to work on an issue does it better with `gh` or a GitHub MCP connector. After this change the board holds tasks only: a leg that delivers code or opens a PR writes nothing to GitHub, a finished, archived, superseded, moved or deleted task writes nothing to GitHub, a merge commit carries no `Closes #N` line, and no pull request body is edited. The GitHub connection keeps doing what projects need — clone, branch, push, PR, merge, CI reads. Old imported and self-issued cards stay on the board as ordinary cards; their issues stay on GitHub untouched; their local rows stay readable so no board loses a card. A first-time user needs no new account, key or setting; GitHub being down or rate limited costs nothing on this path because Cairn makes no call on it.

## Scope

1. Issue import is gone: `POST /api/projects/:id/github/issues/import` and its service, request schema and repository-label sync are deleted, so importing is impossible and no label vocabulary is copied from a repository. The label-driven `correction` classification that already applies to board tags (`correctionFromGithubLabels`, stored `correctionRequired`) stays exactly as it is; only the import-time `correction` check disappears.
2. Cairn never opens an issue for a task: `createAutonomousTodo` stops marking a code task in a GitHub project as `github-issue-self`, and the creation that actually fires when a leg delivers code (`noteTaskCodeDelivered` from `build-step-complete`) is deleted, together with the `github-issue-create` / `github-issue-title` effect kinds, the title write-back, `retrySelfIssueCreate`, `GET /api/todos/:id/github-issue` and `POST /api/todos/:id/github-issue/retry`.
3. Cairn never writes issue state: the `task-issue-sync` sweep, its `pr-watch` scheduler entry, the `issueState` writes, the `task_issue_close` tombstones written by delete and project move, the donor transfer in `coordinator-request` that moved a card's `sourceRef` between cards, and the `withoutSelfIssue` flag are deleted. A moved, deleted, superseded, archived or done task changes only locally. A legacy `github-issue-self` card keeps its `sourceKind` and `sourceRef` verbatim when it moves to another project — no rewrite, no clearing, no tombstone — and it stops acting as a donor. `creatingThreadIdOf` keeps its `github-issue-self` branch: the Coordinator's `pull_requests` read (`mcp-threads`) and `rewatchCreatingThread` (`chief`) still use it, so an old card keeps listing its pull requests in its creating conversation and keeps being re-watched after a rework; only the mirror that wrote to the issue goes away.
4. No `Closes #N` write: the `pr-closing-line` injection is deleted from `pr-watch` and the REST merge, and the local-merge commit message stops appending `Closes owner/repo#N`.
5. The GitHub issue webhook is gone: `POST /api/webhook/github/:token`, the `github-webhook` service, the settings token mint/revoke routes, their shared schemas (`webhookReceiverResponseSchema`, `GITHUB_WEBHOOK_DELIVERY_LIMIT`, the connection status's `webhookMasked`/`webhookLastUsedAt` fields) and the route's entry in the request body-limit table are deleted; the endpoint answers 404 and no token row is touched. No web page ever called the mint or revoke route, so nothing disappears from Settings; a URL minted through the API earlier starts answering 404, GitHub retries it a few times and disables the hook, and no local state changes.
6. The CI correction ticket is gone: a green ci-fix no longer opens a `correction`-labelled issue, and its dedupe scan is deleted; the `[correction:ci-fix-green]` event keeps being written and read by retry lessons, moved to a module that is not the deleted service.
7. A legacy imported card no longer triggers GitHub writes through its prompt: the `bug`-label orchestration branch that told the agent to run `gh issue comment` and `gh issue edit` is deleted, so an old imported card orchestrates like any other card.
8. Retired effect rows settle: `github-issue-create` and `github-issue-title` rows that are still pending, sending or interrupted in an old database are closed by a no-network retirement handler registered at startup, so they stop occupying `drainEffects` slots and cannot starve web-push, away-push, IM or mail. The handler stays for as long as a database written before this change can be opened (a restored backup included); it costs one indexed read at startup and no network call.
9. The task detail surface loses its issue row: `来源 issue`, `GitHub issue 未建成` and `重试` disappear from the detail pane and side chat with their hooks, mappers, fixtures, design fixtures and translation strings. The `来源 Coordinator 编排会话` row stays, and a Coordinator-created task in a GitHub project now shows it: the slot that used to be taken by the self-issue mirror belongs to the orchestration source, so the link back to the creating conversation appears where before it was hidden. The `verify-cairn` walk proves both surfaces: a Coordinator task in a GitHub project shows the source row, and a legacy imported card shows no issue line.
10. GitHub REST helpers used only by this bridge are deleted with their unit tests: issue read/list/create/retitle/close/reopen/repo-labels, the server-side create-gate wiring, the repo-label sync (`syncGithubLabels`), and the create throttle's server tests. The `machine-relay` rename path drops `issueTitleWriteback` and `writebackSelfIssueTitle` with it (it was the only caller outside the deleted service). The shared `github-create-gate` module and its two `CAIRN_GITHUB_CREATE_*` env vars stay, still covered by `packages/shared/test/github-create-gate.test.ts`: `scripts/lib/github-create-gate.mjs` and `scripts/ops/repo-hygiene.mjs` use them for Cairn's own issue/PR writes.
11. Old data stays readable and startup is unchanged: no migration and no column drop; `source_kind` values, `issue_state`, `github_label`/`todo_github_label` links and `task_issue_close` rows keep their shape. After this change nothing reads `issue_state` and nothing reads `task_issue_close`, so a frozen legacy value can never be shown as live; the rows stay only so an old database opens unchanged. Old `github-issue` and `github-issue-self` cards still list, open and render; their untrusted issue text stays fenced when it is shown to an agent.
12. The Coordinator's `issues` read is unchanged: it lists repository issues and still names the legacy task made from one; `status`, `pull_requests`, `workflow_runs` and every PR/CI read stay as they are.
13. Everything else about GitHub keeps working unchanged: connection and device login, repository picking, project creation and conversion, clone/branch/file reads, push, PR open/watch/feedback, merge gate, checks and recovery, covered by `apps/server/test/github-*` suites other than the deleted ones and `apps/web/e2e/pr-card.spec.ts`.
14. Docs and registries follow: `docs/design/task-issue-sync.md` is deleted, `docs/spec/28`'s intake section states the retirement instead of describing a shipped intake, `CONTEXT.md`'s source, title and label rows describe only what remains, the `github` feature-map row is rewritten and regenerated, the `github-webhook` verify case leaves `vp-registry.json` with its drive script, `features/tags.md` drops its step that ran the deleted issue tests, `packages/shared/merge-gate-paths.json` drops the deleted webhook paths, and the retired names are recorded in `scripts/doc-retired-terms.json`.

## Out of scope

- Task category tags (`github_label` / `todo_github_label`, `set_task_meta` tags, `correctionRequired` from a tag): kept; only the import-time sync that fed new names from a repository goes, and a project's tag vocabulary no longer grows on its own.
- Dropping the now-unused database columns and tables: kept so old rows stay readable without a destructive migration.
- Deleting the Coordinator's remaining GitHub read tools (`issues`, `status`, `pull_requests`, `workflow_runs`) or the `github status` surface; they are audited in the owner's review, not removed here.
- Refreshing `eval/**` fixtures that pin the removed webhook handler to an older parent commit; the eval suite is a judge path and stays untouched.
