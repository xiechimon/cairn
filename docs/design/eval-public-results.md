# Public Daily Eval Results — plan, 2026-11-27

Prior art: `docs/research/2026-11-27-public-eval-results.md`; first independent review findings are incorporated below.

## User scenario

A first-time visitor opens `https://cairn.xmon.me/` (or `/zh-cn/`) and sees the existing proof card. When a complete official daily run is available, the card shows its finish date, per-kind trial counts (`lane`, `runtime`, `canary` separately rather than one misleading total), and a per-case table with pass/fail/incomplete counts plus the model/executor label. When no data can be shown, the neutral fallback says public eval results are unavailable; it does not claim that no run exists. The public page never exposes secrets, internal tailnet addresses, local paths, quota/cost text, stderr/stdout, diagnostics, trace ids, or trace URLs.

The Mac mini daily runner remains the sole automation writer. It first persists the measured private run exactly as today. Only after that private state is durable does it build one sanitized snapshot from an explicit allowlist of already public task ids and fields, then publish `latest.json` on the public `eval-results` branch of `xiechimon/cairn` with non-interactive git commands and per-command timeouts. The static site fetches that file from `raw.githubusercontent.com` in the browser, so a daily data update creates neither a merge-queue commit nor a Vercel rebuild. Publication is a cache of evidence, not the measurement itself: publish failure never changes eval status, exit code, or the private result.

## Scope

1. Add `scripts/ops/eval-public-results.mjs` with one pure builder and one git publisher. The builder reads `eval/suite.json` and the public task ids under `eval/tasks/` from the same synced repo, accepts only complete official runs (`evalExitCode === 0` and exactly the expected `(kind, caseId, repeat)` matrix for the current suite — currently 28 runtime cases ×3 repeats + 10 lane cases ×1 + 2 canary cases ×1 = 96 trials), validates type/shape strictly, and constructs only these fields: schema `version`, `dataset`, `suiteVersion`, run `date`, `sha`, `status`, aggregate `summary` including `byKind`, and per-case `caseId`, `kind`, `status`, `passed`, `failed`, `incomplete`, `trials`, and `model`. Each expected trial must occur exactly once; duplicate, missing, extra, or unknown/non-public trials make the run non-official. A complete matrix may contain incomplete trials, because those are measured outcomes and are shown as such rather than silently converted to pass/fail. No comments, diagnostics, raw output, Langfuse metadata, trace ids/URLs, trial notes, history, or unknown/non-public case ids are copied. A second safety validator rejects URLs, local paths, token-shaped values, env-var assignments, quota/cost wording, and unexpected keys before any git write.
2. Model/executor labels are fixed and evidence-limited: runtime/canary rows say `fauxProvider replay`; lane rows always say `Devin CLI · model not recorded`. This change does not set or switch the mini's model. Exact model attribution is out of scope until the eval harness records the resolved model.
3. Publishing uses ordinary synchronous git in a fresh `mkdtemp` directory inside `$EVAL_DAILY_STATE/tmp` (where `$EVAL_DAILY_STATE` is an operator-configured trusted path whose leaf directory is verified as a non-symlink via `lstat`, canonicalized with `realpathSync` so OS parent symlinks such as `/var -> /private/var` resolve cleanly, and `$EVAL_DAILY_STATE/tmp` under that canonical path is verified as a non-symlink via both `lstat` and `realpathSync` equivalence): derive `remote.origin.url` from `EVAL_DAILY_REPO`, require the canonical GitHub remote that the site reads (tests may inject a local remote explicitly), set `GIT_TERMINAL_PROMPT=0`, bound each git command, fetch `eval-results` depth 1 when it exists or start an orphan branch when absent, remove any pre-existing tracked files other than `latest.json` from the commit tree, inspect `latest.json` with `lstat` and read via `O_NOFOLLOW` (removing any symlink or non-regular file via `git rm` + `rmSync` without following it, and refusing to treat a symlink target as an existing snapshot), write pretty-printed JSON via an exclusive `wx` temp file and `renameSync` as a regular `100644` file, commit as the repository identity, and push without force. Existing identical content returns `unchanged`; an existing newer/equal-dated different snapshot returns `skipped` as stale, except that a remote timestamp more than 10 minutes in the future is treated as invalid rather than allowed to wedge publication forever; push/network/non-fast-forward failure returns `failed` with a scrubbed short reason. There is no retry loop and no destructive recovery.
4. Wire `scripts/ops/eval-daily.mjs` so every terminal run record is first written to `$EVAL_DAILY_STATE` exactly as today, then publication is attempted or skipped. The run record is written a second time only to attach `publicResults` metadata (`state`, branch, optional commit SHA, scrubbed reason), with pruning disabled for that metadata rewrite so the rewrite cannot delete sibling state. Temporary publication checkout entries under `$EVAL_DAILY_STATE/tmp` are cleaned whether they are files or directories. Partial `--only` runs, non-zero eval exits, zero/missing items, and expected-count mismatches are observably `skipped`; no-item infrastructure failures never invoke git. If the process dies during publication, the first private write remains the source of truth and missing metadata is accepted; the next complete run publishes a newer dated snapshot. If git push succeeds but confirmation is lost, a later run either sees identical content or newer data; no attempt is made to rewrite the past.
5. Update `site/src/components/Home.astro` and `site/src/components/copy.ts`: fetch with an 8-second abort timeout in both languages, validate schema version, required fields, count arithmetic, and consistency between per-case sums and `summary.byKind` in the browser, render with DOM nodes/`textContent` only, format the date in the visitor's locale and timezone, draw latest-run per-kind bars in the existing SVG, and put case rows behind native keyboard-accessible `<details>`. Data older than 48 hours keeps its date visible and adds a stale-data note. HTTP 404/429/5xx, network failure, timeout, invalid JSON/schema, inconsistent counts, empty cases, or unknown future schema leave the neutral static fallback in place; disabled JavaScript also leaves it in place. No innerHTML, build secret, new env var, or internal address is added.
6. Update `docs/ops/eval-daily.md` with the public branch contract, canonical-remote check, stale-snapshot rule, failure ordering, and rollback: stop or disable the timer before deleting/replacing the branch, because otherwise the next complete run recreates it; private runner state is independent and is never rolled back. `eval/**`, merge-queue files, the merge-gate `EVAL_ENABLED` switch, and the retired weekly workflow stay unchanged.

## Persisted state, readers, and writers

- **Public state**: exactly one file, `latest.json`, at the root of `refs/heads/eval-results` in the canonical repository. Automation writer: the locked mini `eval-daily` process. Readers: public browsers, GitHub/CDN caches, and maintainers. Maintainers may manually repair the branch only after stopping the timer; otherwise automation recreates or advances it. CDN and browser caches may serve an older snapshot briefly, so rollback cannot erase already copied data.
- **Private state**: `$EVAL_DAILY_STATE/{runs/<runId>.json,latest.json,history.json,index.html}` as today, plus optional `publicResults` metadata. Writer: `eval-daily.mjs`; readers: local review server and maintainers. The builder reads the already written run record, `eval/suite.json`, public task ids, and the synced repo remote; it does not read or copy private history.
- **Transitions**: incomplete/non-official run -> `skipped`; official run + validation failure -> `failed` before git mutation; official run + same content -> `unchanged`; official run + successful push -> `published`; official run + stale remote, git failure, or non-fast-forward -> `skipped`/`failed` with the remote left as git leaves it. A push whose acknowledgement is lost is indistinguishable from failure locally, but the public branch is only a cache and the next run converges by date.

## Out of scope

- Publishing Langfuse trace links, raw logs, quota/cost numbers, internal hostnames, or long-range trend history.
- Exact model attribution or changing the mini's model configuration; that requires the eval harness to record the resolved model and is a separate humanQueue `eval/**` decision.
- A new database, API service, Vercel deployment hook, GitHub Actions schedule, merge-queue commit, or backfill of historical results.
- Guaranteeing removal of data already copied by GitHub/CDN/browser caches after rollback.
