# Design-conformance audit, 2026-11-20

An audit of the five main surfaces against `apps/web/DESIGN-RULES.md`, with the new automatic checks it produced and a proposal to consolidate the design docs. Fixes are dispatched separately; this file is the list they work from.

## Method

- Live stack: `verify-cairn` on an isolated server and vite dev, seeded with three projects (`cairn-web`, `支付网关重构`, `docs-site`), six tasks with realistic titles and specs, two OpenAI-compatible providers (unreachable, so a Coordinator turn fails the way it does when a provider is down), a Coordinator and a task rule, one enrolled computer that went offline, two API keys, and two Coordinator messages (main channel and a project channel).
- Fixture pass for the states the live stack cannot reach: `home-c`, `home-c&pane=tasks`, `home-c&thread=home-c-review`, `home-c-machines&pane=machines`, `chief-md`, `model-routing`, `providers-fleet`, `machines-master-detail`, `secrets-list`. Fixture rows are marked `fixture`.
- Every route at 1440x900 and 390x844, light and dark (locale `zh-CN`). Each capture also ran a DOM probe for the measurable rules (font family, placeholders, backticks, uppercase and tracking, weights, raw errors, mixed language, primary buttons, target sizes, horizontal scroll, background images, icon size and stroke, hue buckets, off-grid spacing, nested cards).
- Screenshots: `/tmp/dogfood/design-audit/<route>-<width>-<theme>.png` (local evidence, not committed). Live routes: `home`, `home-tasks`, `home-tasks-scheduled`, `home-made`, `task-thread-a`, `task-thread-b`, `computers`, `project-chat`, `project-settings`, `project-new`, `usage`, `settings-<section>` for all eleven sections. Fixture routes start with `fx-`.
- Clean on every capture: V2 (fonts), V19 (placeholder text), T3 (backticks), V22 (uppercase, tracking), V23 (800+ weight, italic chrome), C5 (raw error text), R1 (no horizontal scroll at 390), V16 (no background images), V14 stroke.

Tags: `measured` = read off the running page in this audit; `inferred` = follows from a measurement and can be rechecked; `guess` = needs confirmation before a fix.

## Violations

Counts: Coordinator home and chat 4, Tasks panel and task thread 7, Settings 12, Computers and Runners 3, project pages 1. Total 27.

"Guard" says whether an automatic check can hold the fix: `yes` names the check, `ratchet` means the new spec already pins it as an open violation, `no` means taste.

## Checks added in this change

Open violations are pinned as a ratchet: `ONE_PRIMARY_OPEN` (Skills) and `CARD_GRID_OPEN` (Apps, IM) must still fail; a fix makes the ratchet test fail until the page is dropped from the set. Negative control: injecting a non-Cairn font, a dash-only node, a backtick, a nested card, two primaries and a card grid into an open dialog turned every check red.

Two `M` rows named an existing spec only in prose; their Check column now names it: A3 (`e2e/a11y-axe.spec.ts`), L2 (`e2e/sidebar-visual.spec.ts`). The by-hand list in `apps/web/test/anti-slop-foundations.test.ts` shrank from 27 to 20 ids.

## Are the design docs too much to read?

Yes. `DESIGN.md` (446 lines, about 18,900 words), `DESIGN-RULES.md` (139 lines, about 8,000 words) and `COMPONENTS.md` (106 lines, about 1,900 words) total about 29,000 words, near 45k tokens, before the `design-cairn` skill. Line counts understate it: single rows run to 900 words (C14, C10, L5, L9). An agent told to read all three spends a large share of its window and then attends unevenly; that is the sprawl failure.

The bigger cost is that the three disagree, so careful reading does not help:

- The "Aesthetic constraints for agents (paste into prompts)" block in `DESIGN.md` is stale sediment: light layers `#e6e7e1 / #f6f6f2 / #fdfdfb`, sizes 26/20/17, radii 18px, primary `#233127`, icons 14/16/18px. The frontmatter, `shadcn.css` and V14 all say otherwise.
- `DESIGN.md` Dark gives `ink #e6e8e2` and `line #353b36`; the frontmatter gives `#ecebe6` and a 10% white line.
- `SidePanel` has two bullets with different heads (`text-heading` regular vs `text-ui` 600).
- Sidebar item 6 puts a machine-status pill in the footer; item 6d and L9 say the footer has no computers entry.
- The same contract is written twice: C14 and "Task thread panel", C11 and "Coordinator questions", L5/L9 and "Sidebar 6b/6d", V13 and "Typography".

### Proposal (not applied)

One entry point, a short must-read, and per-surface reference reached by pointer.

1. **Entry: `apps/web/DESIGN.md`, at most 150 lines, always read.** It keeps the token frontmatter (the gallery's Doc check reads it), five lines of direction, the rule index, the "which component" table from `COMPONENTS.md` section 3, and one pointer per surface: "touching the Coordinator conversation: read `docs/design/surfaces/conversation.md`", and so on for the Tasks panel and task thread, sidebar, settings, computers, first run, motion.
2. **Rule index: one line per rule.** Each row is the invariant in at most 30 words plus its Check. Dates, owner quotes, measurements and the geometry spelled out in C10, C14, L5 and L9 move to the surface file that owns them. `DESIGN-RULES.md` merges into the entry; the weekly review and "using the rules" sections move to the `design-cairn` skill, which is where an agent doing a review already is.
3. **Surface files under `docs/design/surfaces/`: read the one you touch.** Each surface's components, states, measurements and reference shots in one place (co-location): the `DESIGN.md` Components and Page patterns sections, plus the long tails of the rule rows, de-duplicated so each contract has one home.
4. **Cut:** the paste-into-prompts block, "Migration status", the `COMPONENTS.md` consumption snapshot and history pointers, contrast tables that restate `shadcn.css` (the gallery's Doc check and `test/dark-text-tertiary-contrast.test.ts` already hold them), and every hex value in prose. The environment is the source of truth for values; prose keeps only the reason behind a value.
5. **Keep `COMPONENTS.md`'s inventory block** (its gate reads it) but move it to `apps/web/src/components/ui/INVENTORY.md`, next to the code it lists.
6. **Guard the size:** extend `anti-slop-foundations.test.ts` so a rule row over 60 words and an entry file over 150 lines fail, so sediment cannot regrow.

Must read: the entry (about 2,500 words). Look up: the surface file for the surface you change, `shadcn.css` for values, `/design.html` for how a component looks.
