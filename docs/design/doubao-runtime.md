# Doubao CLI (`doubao`) Runtime — Plan, 2026-11-28

Research: [doubao-cli-2026-11-27.md](../research/doubao-cli-2026-11-27.md) (live `doubao 2.38.4` ACP + Keychain measurement on MacBook, `doubao login --qr=png` stream protocol measurement on MacBook, CDN `darwin-arm64` archive SHA-256 verification, and Mac mini `gui/501` launchd + Keychain environment inspection).

## User scenario

Someone who installed Cairn today turns on **Settings -> Model Routing / Providers -> Add -> Doubao Subscription** and picks Doubao as a model so their existing Doubao personal subscription can run Worker tasks and Coordinator turns inside Cairn. They **never open a terminal on any computer**. Per owner decision (`2026-11-28`), every supported macOS `arm64` computer signs in lazily inside Cairn: whenever Doubao is needed on a computer that is not signed in yet (either in the add-subscription dialog, on subscription detail, or inline inside a waiting Worker/Coordinator turn routed to that computer), that Runner automatically downloads Cairn's pinned managed `doubao` (`2.38.4`) binary (no `npm install`, no `postinstall`, no env/PATH override), runs `doubao login --qr=png`, and relays the QR PNG (`<= 64 KB`) into Cairn's UI. Scanning once with the Doubao mobile app signs that computer in, closes the QR card, and immediately lets the waiting task proceed.

- **Scan target, routing & account isolation**:
  - `AddDoubaoSubscriptionDialog` prefers `team.defaultMachineId` (from `useTeams`) when choosing the default QR target, saves `runnerId: null` so the team subscription supports lazy per-computer QR logins across Macs, and preserves the chosen QR target snapshot (`savedQr`) if machine presence flickers mid-save.
  - Both `resolveChiefCandidates` and `resolveWorkerCandidates` route unbound Doubao turns via shared `doubaoDefaultTarget`: authenticated `darwin-arm64` machines are chosen first (preferring `team.defaultMachineId` if authenticated, otherwise deterministic sort by `(name, id)` ignoring transient online status), so scanning computer A immediately lets generic Worker & Coordinator tasks run on A even if an unauthenticated `defaultMachineId` B sits idle, while explicit/local-project pins on B still prompt QR on B. Once a host is chosen or multiple computers hold distinct accounts, offline disconnects stay pinned to that host (`machine-offline`, exposing other authenticated computers only in `alternateMachines` for explicit manual switch) and never silently hop accounts.
  - Creating an unbound subscription (`runnerId: null`) never seeds or unions `models` across machines (`models: []`); listing models across multiple authenticated hosts exposes the intersection (`sharedRunnerModels`) alongside per-runner `model-unavailable` checks at claim time so the picker does not promise a model absent on the executing host.
- **Why subscription management mirrors Cairn's other runtimes**:
  - Keeping one enabled `doubao_subscription` row, per-model editing, last-24h (`近 24 小时`) step count (`lastUsedAt` / `stepsLast24h`), and on-demand connection verify (`验证连接`) aligns Doubao with Cairn's Claude Code, Devin, and Antigravity integration contracts (shared `SubscriptionDetail`, `ModelRouting`, `useModelCatalog`) rather than inventing a bespoke flag with separate settings UI. Volcengine Ark Coding Plan APIs use a different billing product and are out of scope.
- **Verified platform scope (`darwin-arm64` only in v1)**:
  - Only **macOS arm64** is supported by `doubaoInstallSupported` and `isDoubaoPlatformSupported` in `this change`. `linux-x64` and `win32-x64` remain excluded in v1 and tracked under `later: linux-windows-doubao-verify`.
  - Managed `2.38.4` under `<cairnHome>/tools/doubao` is preferred; if an existing macOS installation already lives at `~/Library/Application Support/doubao_cli/app/current/doubao` before managed download runs, Cairn reuses that standard host install (no `DOUBAO_BIN`, `CAIRN_DOUBAO_PATH`, or arbitrary `$PATH` lookup).
- **Accounts, keys, database schema, and compliance**:
  - Zero API keys, cookies, or OAuth tokens are pasted into or stored by Cairn. Doubao CLI sessions are hardware/Keychain-bound (`os_crypt` + `IOPlatformUUID` + `libMetaSecML`, non-portable across machines), so Cairn preserves real `HOME` / Keychain access (`DOUBAO_CLI_NO_UPDATE_CHECK=1`) on each Runner.
  - Database schema (`apps/server/drizzle/0267_doubao_subscription.sql`): adds table `doubao_subscription` (`runnerId TEXT` nullable defaulting to `null`, unique single enabled row index per team) and additive nullable column `step.doubaoSubscriptionId TEXT`. Server durably stamps monotonic `switchedAt` inside `machine.capabilities.doubao`.
  - Active QR login sessions, `switchingHold` account-switch locks, and verification requests/rate-limit windows live transiently in server memory (`WeakMap`).
- **Diagnostics (`verify` vs QR login)**:
  - Subscription Detail keeps Cairn's on-demand verification (`POST /api/teams/:id/doubao-subscriptions/:cid/verify` via `machine-doubao-verify.ts` + `runner.ts`) separate from QR login: `verify` probes the bound or active Runner without altering credentials or starting QR, distinguishing `ok`, `missing_local_login` (points to per-computer QR scan), `unavailable` (`暂不可用（未安装豆包或正在切换账号）`), `timeout`, and `failed`.

## Edge cases

### State transitions, readers & writers (all 5 state surfaces)

1. **Server `HubLoginBook` & decoupled `switchingHold` (`machine-doubao-login.ts`)**:
   - **States**: `starting` -> `installing`/`starting`/`qr`/`scanned`/`verifying`/`succeeded`/`expired`/`refused`/`cancelled`/`failed`; `installing` -> `installing`/`starting`/`expired`/`refused`/`cancelled`/`failed`; `qr`/`scanned`/`verifying` -> `qr`/`scanned`/`verifying`/`succeeded`/`expired`/`refused`/`cancelled`/`failed`. Unknown/old `loginId` returns `404`; current `loginId` with `revision <= lastAppliedRevision` returns `200` no-op; invalid transition returns `409`.
   - **Terminal & hold races**: `switchingHold` (`Map<machineId, { loginId, heldSince, releaseTimer }>`) is created only AFTER `sendToMachine` returns `true` (failed `sendToMachine` preserves prior hold & timer), preserved on `force: true`, and kept up to 5s on `DELETE` / timeout until Runner confirms exit or `machineHub.onDisconnect` clears it. `logoutFirst` persists `switchedAt` + `authenticated: false` in DB immediately on send; late `succeeded` arriving after session entered terminal state STILL updates active DB `machine.capabilities.doubao` (`switchedAt`) and wakes team before clearing hold; active `succeeded` checks `row.teamId === stored.teamId && row.retiredAt === null` (else emits terminal `failed` SSE + `409`) and commits DB tx *before* clearing timer/hold or setting `stored.session = 'succeeded'` (tx error keeps session active for retry). Server restart clears memory book; Daemon cancels on `hello` / disconnect.
   - **Readers/Writers**: Writers: `startDoubaoLogin`, `cancelDoubaoLogin` (`?loginId=`), `applyDoubaoLoginEvent`, `machineLoginTimeout` timer, `machineHub.onDisconnect`. Readers: `getDoubaoLogin` (`includeQr` redaction for non-owners), `isDoubaoAccountSwitching` (`machines.ts`, `machine-doubao-verify.ts`, `machine-claim.ts`).
2. **Server `HubVerifyBook` (`machine-doubao-verify.ts` + `doubao-subscriptions.ts`)**:
   - **States**: `inFlightByMachine` dedupe Map (`machineId -> Promise`), `byCheckId` timeout/disconnect/abort Map, plus per-subscription `activeVerifications` (`429`) & `verificationWindows` rate limiter.
   - **Transitions / Exit**: Blocked while `isDoubaoAccountSwitching` (`requestDoubaoVerify` returns `unavailable`; late `receiveDoubaoVerify` clamps `authenticated = false` -> `missing_local_login`). Wrong-runner `404` leaves `byCheckId` open until real runner reports, disconnects (`unavailable`), or 40s timeout fires (`timeout`). Before writing `doubao_subscription.lastCheck`, re-checks row existence & matching bound/resolved `runnerId`.
   - **Readers/Writers**: `verifyDoubaoSubscriptionConnection`, `requestDoubaoVerify`, `receiveDoubaoVerify`, `machineHub.onDisconnect`.
3. **Server DB & Queue Projection (`doubao_subscription`, `step`, `machine`, `team`)**:
   - **Writers**: `createDoubaoSubscription` (single enabled constraint, `models: []` when unbound), `patchDoubaoSubscription` / `enable` / `disable` / `delete` (`409` while `step.status === 'claimed' && step.doubaoSubscriptionId === id`), `persistDoubaoMachineUpdate` (`switchedAt`), `machines.ts` (`markPresence` guarded by hold + `pickNewerDoubaoReport`; machine merge rebinds `runnerId`), `machine-claim.ts` (`doubaoSubscriptionId` + `txSwitchedAfterPrior`), `machine-finish-step.ts`.
   - **Readers**: `listDoubaoSubscriptions` (`sharedRunnerModels`), `activeDoubaoSource`, `resolveWorkerCandidates`, `resolveChiefCandidates`, `stepQueueProjector`, `memory-corrections` (`promptMayNotBeResent`).
4. **Daemon Probe Cache, Shared Installer & Login Child (`doubao-probe.ts`, `doubao-managed.ts`, `doubao-login.ts`, `machine-loop.ts`)**:
   - **Probe (`DoubaoController`)**: `{ cached, inFlight, generation }`. `probeDoubaoRuntime` captures `startedAt = now()` BEFORE invoking CLI binaries; `invalidateAuth()` increments `generation`, resets `inFlight = null`, sets `authenticated: false`; `refresh()` commits only if `myGen === generation` and monotonic `probedAt >= cached.probedAt`. Invoked by `onLogoutStart`, ACP `-32000`, login completion probe, verify, and heartbeats.
   - **Installer**: `{ pendingEnsure, pendingController, activeWaiters }`. Coalesces concurrent `ensure(signal)` callers; sole-waiter abort resets `pendingEnsure`/`pendingController` and aborts download before extract/rename.
   - **Login Runner**: `{ activeChild, previousChildExit, abortController, deadlineTimer, killTimer, emitChain }`. Cancelled by `doubao.login.cancel`, SSE `hello`, or stream disconnect; `cancel()` signals `SIGTERM` -> 500ms `SIGKILL` (`clearKillTimer` only on child exit) and awaits child exit BEFORE emitting `'cancelled'` or spawning next login.
5. **Web React Query Cache, SSE & Card Lifecycle (`api/doubao-subscriptions.ts`, `doubao-qr-login.tsx`, `doubao-subscriptions.tsx`, `sse-team-events.ts`)**:
   - **Cache/Events**: `doubaoLoginQueryKey` written by `useDoubaoLoginSession`, `useStartDoubaoLogin`, `useCancelDoubaoLogin` (which preserves existing `qrPngBase64` when stale-tab `DELETE ?loginId=old` returns a QR-redacted newer session), and `sse-team-events` (`doubao.login` / `machine_presence`). Real `EventSource` reconnect calls `recoverQueries` refetches to surface server-restart `interrupted` (`session: null`) recovery CTA.
   - **Card refs**: `AddDoubaoSubscriptionDialog` snapshots `savedQr` across mid-save presence updates; `DoubaoQrLoginCard` uses `autoStartedRef`, `succeededNotifiedRef`, and `preSwitchLoginIdRef` + `awaitingSwitchStart` so cached `succeeded` never closes switch-account (`切换账号`) early or flashes stale success; missing `qrPngBase64` under `status === 'qr'` renders loading + refresh (`刷新二维码`) button.
