> **Red-on-main baseline:** Verified directly against `origin/main` checkout (`f9b6c3340`).

## Ownership & Boundary Alignment with `S7` (`fix-remote-update`)

Both `S5` (`remote-version`) and `S7` (`fix-remote-update`) touch `apps/desktop/src/main.ts`, `apps/desktop/src/preload.ts`, and `apps/web/src/board/desktop-update.tsx`. To satisfy [`docs/design/version-skew.md`](../version-skew.md) Scenarios 1, 2, 3, 4, 7, 8, and 10 simultaneously with zero dead buttons:

1. **`S7` (`fix-remote-update`) owns laptop shell self-update (`desktop-update:state`, `desktop-update:check`, `desktop-update:install` -> `installDesktopUpdate` returning `DesktopUpdateInstallResult`)**:
   - The sidebar `DesktopUpdateButton` updates the **laptop desktop shell** in **both local and remote modes**.
   - When the laptop shell is older than the remote server (`RV-09`) or both shell and server are older than the latest release (`RV-14`), clicking the sidebar update button updates the laptop shell instead of being hijacked by `remoteVersion`.
2. **`S5` (`remote-version`) owns connected server version visibility & remote host auto-update**:
   - `GET /api/server/version`, `POST /api/server/update`, `host-update.ts`, `createRemoteVersionController`, `desktop-update:remote-state` / `desktop-update:remote-retry`, `RemoteUpdateBar`, `preload.ts` fallback bar + `cairn:prepare-reload`, macOS `setAboutServerVersion`, `AccountPage` (`About` section), and `DesktopHostPanel` (`Current host version`).
   - *(Code gap caught before resuming implementation: on `remote-version` HEAD `2b6604a7e`, `apps/desktop/src/main.ts` currently routes `desktop-update:state/check/install` to `remoteVersion` whenever `remoteVersion !== null`. Once implementation resumes, separate `desktop-update:*` [S7 laptop shell] from `desktop-update:remote-*` [S5 remote host] so `RV-09` and `RV-14` work end-to-end.)*

## Gaps Discovered Before Resuming Implementation

1. **`residentWritingReply` and `hostIdleState.serverBusy` vs claimed runner steps (`RV-02`, `RV-06`, `RV-17`)**:
   - `apps/server/src/services/server-version.ts` (`isServerBusy`) already checks both active Chief turns (`turnQueue` / `activeRun`) and active runner claims (`step.status === 'claimed'`).
   - However, `apps/desktop/src/resident-host.ts` (`residentWritingReply`, called by `apps/desktop/src/background-updater.ts`) only polls `/api/teams/:id/chief/threads` and ignores claimed runner steps; likewise `apps/desktop/src/main.ts` never sets `hostIdleState.serverBusy` from active server turns/claims for standalone runners. Both must be wired and covered by red-then-green tests once implementation resumes.
2. **S5↔S7 channel separation in `apps/desktop/src/main.ts` (`RV-09`, `RV-14`)**:
   - Restore S7's local shell `created` + `installDesktopUpdate` on `desktop-update:state/check/install` in remote mode so an older shell connected to a newer (or equally old) remote server can always upgrade itself.
