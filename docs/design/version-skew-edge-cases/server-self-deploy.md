# Version-Skew and Lifecycle Edge Cases: Server Self-Deploy (`server-self-deploy`)

This matrix covers all version-skew, failure, interruption, runner-co-deployment, and rollback edge cases for `scripts/ops/deploy-watch.sh`, `scripts/ops/deploy-self.sh`, `scripts/ops/install-self-deploy.sh`, `scripts/ops/stage-server-artifact.mjs`, `scripts/ops/github-ci-evidence.mjs`, and their interaction with `apps/server` (`deploy_lease`, in-server Coordinator, runner claim gate, `GET /api/server/deploy`), `apps/daemon` (`~/cairn-runner` / `cairn-daemon`), and remote Desktop/Web clients (`docs/design/version-skew.md`).

All six mandatory additional conditions from `docs/design/version-skew.md` are explicitly accounted for in every row:
1. Offline or unreachable (`offline / unreachable`)
2. Restart mid-update (`mid-update restart`)
3. Rollback (`rollback`)
4. Self-hosted owner updates late (`self-hosted late updater / updater.supported=false`)
5. Runner below floor holding a claimed step (`runner below floor holding a claimed step`)
6. Bridge without capability descriptor (`bridge without descriptor`)

Live verification evidence on the real Mac mini (`ssh macmini`) is archived under `~/Pictures/cairn-review/mini-live/server-self-deploy/<row-id>-*.png|.log` after implementation lands.

## Build Version & Commit Resolution Alignment with `S5` (`remote-version`)

When `deploy-self.sh` stages a server release, `<APP_ROOT>` contains only `dist/`, `web/`, `drizzle/`, `node_modules/`, `DEPLOYED_SHA`, and any carried-forward `tsnet-sidecar*` binary (no `package.json`, no `.app/Contents/Info.plist`). Inside `apps/server/src/services/server-version.ts`, `readServerVersionInfo` resolves:
- **Version:** `CAIRN_SERVER_VERSION` -> `SERVER_BUILD_VERSION` (baked into `dist/index.mjs` by `apps/server/build.mjs`) -> `.app/Contents/Info.plist` -> `package.json`.
- **Commit:** `CAIRN_SERVER_COMMIT` -> `SERVER_BUILD_COMMIT` (baked by `apps/server/build.mjs` via `git rev-parse --short=7 HEAD`) -> `<DATA_DIR>/deploy.json` (`deployed.sha`, written by `deploy-self.sh`).

To avoid inventing a second version mechanism in `deploy-self.sh` (and without modifying `deploy-mini.sh`):
1. `server-self-deploy` **reuses `S5`'s `apps/server/build.mjs` fallback** directly (deriving `SERVER_BUILD_VERSION` from `git describe --tags --match 'desktop-v*'` or repo version when `CAIRN_BUILD_VERSION` and `.app` are absent).
2. `check_out_target` in `deploy-self.sh` fetches tags (`git -C "$BUILD_CHECKOUT" fetch -q --tags origin main`) before running `apps/server/build.mjs` from `$BUILD_CHECKOUT/apps/server`, ensuring `git describe --tags --match 'desktop-v*'` resolves the latest `desktop-v*` release tag instead of a stale cached tag (observed live on Mac mini at `606d9c2ec`: `~/deploy-build` stopped at `desktop-v0.1.705` even though `desktop-v0.1.731` already existed on `origin/main`).

## Summary of Red Defects Discovered on `origin/main` (`606d9c2ec`) Requiring Implementation Fixes

1. **SD-04 (`build_target` cwd & `set -e` suppression inside `if !`)**: `deploy-self.sh:259-264,502` runs `node apps/server/build.mjs` from `$BUILD_CHECKOUT` instead of `$BUILD_CHECKOUT/apps/server` (causing `Could not resolve "src/index.ts"`), and `set -e` is disabled inside `if ! check_out_target || ... || ! build_target` so the error was swallowed.
2. **SD-05 (`sqlite3 -readonly` on WAL-mode DB without `-shm`)**: `deploy-self.sh` opens `$SNAPSHOT` (and stopped `$DB`) with `sqlite3 -readonly`, which fails with `unable to open database file (14)` on any WAL-mode DB lacking `-shm` (observed live on Mac mini).
3. **SD-07 (`restart_previous` / `roll_back` `EISDIR` on legacy real directory)**: `deploy-self.sh:384` runs `atomic_link "$PREVIOUS_RELEASE"` even when `$APP_ROOT` is still a real directory before switch, failing with `EISDIR`.
4. **SD-19 (`$BUILD_CHECKOUT` left detached on old/failed `$TARGET`)**: `deploy-self.sh:250` leaves `$BUILD_CHECKOUT` detached on `$TARGET` after failure or older-commit deploy, risking stale `deploy-watch.sh` execution on the next timer tick.
5. **SD-23 / SD-24 / SD-25 / SD-26 (Coupled runner deployment, drain wait, and rollback)**: `deploy-self.sh` does not yet update `CAIRN_DEPLOY_RUNNER_CHECKOUT` (`~/cairn-runner`), wait for active claimed runner steps (`machineId IS NOT NULL`) when runner co-deploy is active, or roll back both runner and server if runner restart fails.
6. **Test coverage gaps on `origin/main`**: SD-03 (offline/API outage non-poisoning + cache hit), SD-10 (unhealthy rollback exit `3`), SD-11 (migration rehearsal failure), SD-12 (`phase=building` recovery), SD-14 (`phase=switching`/`restoring`/`restored` recovery), SD-16 (`404` missing lease endpoint refusal).
7. **SD-27 (Build tag fetch for `S5` fallback)**: `deploy-self.sh` must run `git fetch -q --tags origin main` in `check_out_target` so `S5`'s `apps/server/build.mjs` `git describe --tags --match 'desktop-v*'` fallback resolves the latest release tag without inventing a second version mechanism.
