# Memory backend

Status: B1 design draft; no product implementation. Baseline `f004cd719`, 2026-11-08. Research: [current-source supplement](../research/memory-2026-11-08.md), [personal agent memory](../research/personal-agent-memory-2026-11-07.md). Frontend: [memory](memory.md). Context: [compaction](coordinator-context-backend.md).

## Data model

Keep the existing relational model; do not add vector storage or an extraction call per message. Memory is a curated fact, not a copy of an event transcript.

| Field/group | Meaning |
|---|---|
| `id` | Stable identity of one version, generated by the record-id service; not a title key |
| `teamId` | Authorization boundary |
| `projectId` | Null means team fact; otherwise a project fact, not permission to read another project |
| `layer` | `core`, `log`, `scratchpad`, `searchable` |
| `threadId` | Scratchpad visibility boundary |
| `agentId`, `independent`, `adoptedFrom` | Existing compatibility/independent-memory ownership; not the Coordinator settings selector |
| `title`, `content` | Fact text, validated before write |
| `sourceTodoId`, `sourceBuildId`, `source` | Provenance, not authorization |
| `createdAt`, `updatedAt`, `lastInjectedAt` | Version order and actual injection signal |
| `invalidAt`, `supersededBy`, `history` | Validity and replacement lineage |

`memory_save_conflict` is a conflict acknowledgement record, keyed by SHA-256 of team, project, layer, thread and content. It is not the memory primary key and must never merge facts solely because normalized text overlaps.

## Scope and injection

Team-scoped operations exclude independent entries and adopted duplicates. Scratchpads are visible only with their matching thread; ordinary settings list requests do not expose scratchpads. Only core plus a matching scratchpad can be automatically injected. Log/searchable entries remain queryable without automatic injection.

The Coordinator's team prompt must select team facts; project facts enter only after that project is routed. The existing injection function has broad behavior when `projectId` is undefined, so callers must supply scope deliberately. Do not rely on the UI to enforce isolation.

Retain the existing 3,000-token capped selection: prefer recently updated eligible facts, preserve stable display order, record use only for shown rows, and disclose omitted count with a lookup instruction. The implementation's oversized-newest-row excerpt is not a complete fact; acceptance must test an oversized title/content and ensure the rendered request really stays inside the cap. Injection time is not proof that the model cited or used the fact. Weekly expiry must not relabel it as citation frequency.

## Writes, invalidation and promotion

Save validates quoted-issue fences, checks the active-entry quota and detects exact duplicates. Overlap returns candidates without writing a fact. Repeating an unresolved request returns conflict; explicit `force:true` can preserve a genuinely adjacent fact. Never automatically replace an adjacent fact based on text similarity.

Update reads a valid row inside a transaction. Changed content creates a successor version and invalidates the predecessor atomically. Identical content is a no-op except for validated consolidation absorption. Stale/invalid predecessor updates return 409 naming the successor. No last-writer-wins overwrite is introduced.

Promotion is project-to-team scope expansion, not moving ownership between teams. Show the full fact and destination in confirmation. The target contract requires a still-valid row and duplicate/overlap validation in the destination scope inside the write transaction. Current `promoteMemoryEntry` updates `projectId` in place without those checks; replace that unchecked mutation, retaining the route and successful response shape. Already-team promotion is idempotent. An invalidated fact must not be revived or silently promoted.

User delete is hard deletion of the addressed row and cleanup of conflict fingerprints; automatic expiry is invalidation. Keep this distinction explicit: deleting one fact is not deletion of canonical conversation history or all predecessor versions. The confirmation must not promise complete historical erasure.

## API

Retain existing routes, authenticated with `requireTeam`:

| Request | Result |
|---|---|
| `GET /api/teams/:id/memories` | Active team-owned rows visible to settings |
| Same with `includeInvalid=true` | History including invalidated rows; read-only presentation |
| `POST /api/teams/:id/memories/:mid/promote` | Current promoted record; 404 inaccessible/missing, 409 invalid or destination conflict |
| `DELETE /api/teams/:id/memories/:mid` | 204; 404 missing/inaccessible |

No public write API for editing is added in B1. Existing save/update/delete/list tools remain the correction path through conversation; future inline edit must be separately designed rather than inventing an unimplemented endpoint. Refresh queries after successful mutations. Do not retry a failed promotion/delete automatically.

## Consolidation and pre-compaction flush

Retain the weekly pass already integrated into the daily digest: at least four valid core entries; seven days between completed passes; at most 80 rows, 16,000 total characters, 600 characters per displayed line; at most five merges and ten expirations; merged content at most 500 characters. Truncated entries cannot merge. Only same-project facts may merge. An expiry candidate must be unchanged and uninjected for at least 30 days; age alone does not establish that a fact is false.

The current pass applies validated output automatically, not a new approval queue. Do not implement the older research's propose-only variant. Preserve atomic successor/invalidation for each merge. Improve stale-input safety by binding proposed row ids to the versions actually supplied in the digest; changed rows require a new proposal, not a blind reread of newer text.

The pre-compaction flush uses the same save/update validation and does not delete facts to make quota room. Failure is reported and compaction can proceed; overlap is not permission to discard a new adjacent fact. No shadow mode or second background summarizer is added.

## Failure modes and tests to write first

| Class | Required tests |
|---|---|
| Scope leak | Wrong team cannot list/mutate; routed project excludes other projects; scratchpad excluded outside matching thread |
| Version race | Two updates to predecessor yield one valid successor; stale update is 409; no history loss |
| Destination collision | Promotion rechecks active status and team duplicates; failed promotion leaves original project row unchanged |
| Similar facts | Exact duplicate conflicts, overlap returns candidates, forced adjacent fact persists independently |
| Quota | Boundary save and concurrent saves never exceed active-entry limit; invalidation releases capacity |
| Injection | Deterministic equal timestamps, recency preference, oversized fact/title, truthful omitted count and use stamps |
| Consolidation | Cross-project/self/missing/truncated drops rejected; changed input version rejected; merge rollback preserves all rows |
| Expiry | Recently updated/injected entry retained; invalidated entry never injected; uncertain fact not expired solely by age |
| Delete | Wrong-team 404, conflict fingerprint cleanup, UI failure retains row, explicit historical-erasure limits |
| Flush failure | Reported once, canonical history remains, no duplicate writes on task replay |

Extend existing suites: `memory-invalidation`, `memory-dedupe`, `project-memory`, `memory-injection-cap`, `memory-consolidation`, and Coordinator flush tests. Add route-level authorization and real UI mutation tests. #1773/#1777 own eval work; B1 does not modify `integration/eval/**`.

## Code areas and old code replaced

`services/memory.ts` owns scope, identity and mutations; `services/memory-consolidation.ts` owns bounded weekly validation; `routes-agents.ts` retains the team-memory HTTP contract; `coordinator/memory-flush.ts` owns compaction-boundary extraction. `chief/chief-settings.tsx` must replace retired-agent gating and its old agent-owned empty message, not reintroduce agent selection. The unchecked promotion branch and unversioned consolidation input are the specific remaining mutation mechanisms to replace in separately dispatched implementation.
