## User scenario

Someone who installs Cairn today and wants to run tasks against any local folder that has no Git repository (such as `~/work/notes`) opens **New Project → Local Folder** (`apps/web/src/pages/project-new-page.tsx`), picks or enters the folder path, and creates the project. Today, project creation saves the record, then file reading (`apps/server/src/services/git.ts`) and runner workspace preparation (`apps/daemon/src/workspace.ts`) reject it with `not_git`. With this change, they need zero Git knowledge, zero GitHub account, zero extra keys, and zero payments. Cairn never creates or modifies a `.git` directory inside their folder; it stores a private shadow Git repository (`<workspacesRoot>/shadows/<pathHash>`) and per-task copy-on-write clones (`<workspacesRoot>/<conversationId>`) under Cairn's own workspace root. Normal folders (`<= 2 GiB` after excludes, or CoW-capable) run tasks in isolated copies and 3-way merge only Cairn's delivered delta back into the real folder when a build step completes. Huge folders (or non-CoW cross-volume folders exceeding `2 GiB` total) run one task at a time in place with silent pre/post snapshots. In the task panel, the changes card adds only one button: **「撤销这次任务的改动」** (undoing what that build delivered while preserving later/sibling changes; for in-place mode, Cairn snapshots the whole folder before and after the step, so in-place diff and undo cover non-excluded changes made in the folder during that task window). Protected roots (`/`, `$HOME`, `Desktop`, `Documents`, `Downloads`, and symlinks to them) are refused immediately.

## Scope

1. Fix `apps/daemon/src/git.ts` `isGitDir(dir)` (using `git rev-parse --show-toplevel` + `realpathSync(toplevel) === realpathSync(dir)` and stripped `GIT_*` env, matching `apps/server/src/lib/git.ts`) so subdirectories inside a Git repo without their own `.git` behave consistently as plain folders, while true Git repo roots stay on worktrees and `landLocalMerge` (project mode is evaluated at task preparation against disk root).
2. Validate local paths in `apps/server/src/services/git.ts` (`validateLocalRepoPath`) and `apps/daemon/src/workspace.ts` (`prepare`) to reject `/`, `$HOME`, `Desktop`, `Documents`, `Downloads` (and symlinks resolving to them) with `protected_folder`, and reject plain files/special files with `not_directory`.
3. Support plain non-git folders in server read APIs (`readFiles`, `readFile`, `readProjectReadme`, `readBranches`, `readBuildChangeFile`) applying `packages/shared/src/plain-folder.ts` excludes, symlink escape checks, and size limits (`readBuildChangeFile` reads current folder files on disk, returning 404 when deleted or absent so the viewer falls back to diff hunks).
4. Implement `apps/daemon/src/shadow-repo.ts`: canonical-path shadow repos, deadlock-free lock coordinator (`acquireInPlaceLease` -> `withFolderWriteLock`, overlapping ancestor/descendant guard, non-reentrant `mergeTaskBackUnlocked`), stripped `GIT_*` env + own `gitconfig`/`gitconfig_empty`, built-in excludes + `.cairn-readonly-export`/`.cairn-plain-folder.json` + `CACHEDIR.TAG`, GC-anchored leg refs (`deliveries/<stepId>/pre|post`), `reconcilePendingJournalUnlocked` crash recovery, per-path disk SHA1 TOCTOU verification + rollback, `120 s` session timeout disable, and explicit Git `< 2.38` error.
5. Implement isolated CoW execution (`cp -c -R` / `--reflink=auto` with total-size fallback guard to in-place when non-CoW copy would exceed `2 GiB`), huge-folder serialized in-place execution (`Stop & Discard` delta rewind keeping excluded files; huge readonly reads directly in place without cloning; `isBuildStepKind` gating so `plan`/`review`/`verify` never write back and `AGENT_TOOL_PUSH` never blocks local plain-folder write-back).
6. Implement reverse-merge undo (`POST /api/builds/:id/undo` in `apps/server/src/routes-builds.ts` and `local-folder-action.ts`), `POST /api/builds/:id/merge` conflict-only retry (`409` on `in-place`, `merged`, `undone`), `machine-claim.ts`, `machine-finish-step.ts`, `step-queue.ts`, `runner-offline.ts`, `build-stop.ts`, `build-abandoned-sweep.ts`, and daemon `step-local-folder-action.ts`.
7. Extend `GET /api/builds/:id/changes` (`readBuildChanges`) with `plainFolder` (`mode`, `status`, `undoable`, `undoPending`, `conflictFiles`, `error`) and keep `ChangesCard` visible whenever `plainFolder` holds conflict/error/undone/undoable state even with empty hunks.
8. Add only the single **「撤销这次任务的改动」** button (`正在撤销…`, `已撤销改动`, inline `role="alert"`) to `ChangesCard` (`apps/web/src/board/side-chat.tsx`, `thread-changes.ts`, `use-thread-chat.ts`, `api/hooks.ts`, `i18n/en.ts`), leaving all non-plain-folder UI untouched.

## Out of scope

- Per-turn checkpoint timeline, conflict retry button, or extra controls in `ChangesCard` (snapshots run silently; per `ian 5. 推荐` the task panel adds only the single 「撤销这次任务的改动」 button).
- Re-merging changes back after they were explicitly undone (start or rerun a task instead).
- Interactive 3-way conflict resolution UI in the web app.
- Separating external non-Cairn editor writes during an in-place (`> 2 GiB`) task run.
- Cross-machine execution or synchronization of plain local folders across multiple runners.
