# API request-body limits

A new Cairn user who exposes their server through a tunnel can keep using the same webhook URLs, Runner enrollment, device pairing, and uploads. There is no new account, setting, key, or cost. The server, not the tunnel, rejects oversized requests before the endpoint runs. The bug class is unbounded request buffering before validation; limits on parsed fields or decoded files do not bound the incoming body.

## Admission and sizing

Install one Hono `bodyLimit` dispatcher in `createApp` for `/api/*`, shared by TCP and the tailnet socket. Run it after existing owner/device and enrolled-Runner admission and the machine upload grant lookup, but before payload parsing, handler work, or writes. For declared lengths, the Node adapter enforces HTTP framing and the limiter checks the length without consuming the body. When length is unknown, Hono counts chunks and replays at most the configured budget for an admitted request; it stops at the first chunk that crosses the cap. The adapter may discard unread bytes separately. This is a per-request wire budget, not a concurrency, timeout, or decompression limit.

Default: **2 MiB**. Serialized MCP test calls are 158 bytes for initialize, 58 for tools/list, and 191 for create-todo with a 21-character project ID (`mcp-face.test.ts`); the reply boundary fixture sends 32 KiB of text (`mcp-entry.test.ts`). MCP attachment requests carry IDs; attachment bytes in responses are out of scope. The default leaves room for the 100,000-character draft limit even with JSON escaping and becomes the wire cap for previously uncapped task specs and Chief/MCP prompts. Known larger payloads get explicit exceptions; existing stricter budgets stay in place.

The larger upload routes do not bypass admission. The current browser/Runner clients send FormData, strings, or buffers with a known length over HTTP. They keep their present consumers (multipart `formData()`, Base64/JSONL text and transcript JSON); these are **not** end-to-end disk streams. For known lengths the limiter adds no extra body buffer; a chunked upload is admitted only after it fits the same bounded budget. No wire or storage migration is needed.

## Remaining readers (none → 2 MiB)

`T` = `/api/teams/:id`; `M` = `/api/machine`. Except where noted, the owner token or a permitted paired device/session authenticates before admission (or auth is disabled for local use). Existing owner-only restrictions, same-origin checks, and resource checks still apply. The list groups readers with the same wire budget; GETs, callbacks, and header-only actions are not readers.

Regression checks: unauthenticated enrollment is rejected before JSON parsing for an over-budget declared length; a finite unknown-length request is rejected before the Access handler runs; a file at the existing 10 MiB product cap still uploads and downloads over loopback HTTP, and the Runner can relay the same file size through `attach_file`. Existing tests pin the older, narrower caps and machine credential rechecks.
