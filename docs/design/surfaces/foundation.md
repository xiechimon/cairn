# Foundation: color, type, layout, icons, brand

The shared base every surface sits on. Token values live in `apps/web/src/styles/shadcn.css` (the file `components.json` points the shadcn CLI at): its first `:root` block holds theme-independent tokens (motion, z-index, type, radii, sizes, formulas over color slots) followed by the dark colors; `.light` overrides the colors only. A palette change touches one file. The gallery (`pnpm --filter @cairn/web dev`, `/design.html`) renders these tokens, and its Doc check compares the frontmatter of `apps/web/DESIGN.md` with the rendered values in both themes. Components write token names, never hex values (`scripts/ui-drift-gate.mjs` G2).

## Direction

Cairn is an open-source, self-hostable agent team. The user is a keyboard-first engineer who talks to a project's Coordinator, then checks back on the threads it ran; the core question is "what is waiting for me". Direction A, **Cairn**: a cairn is a pile of stones that marks a trail for the next walker. The paper is cool limestone in light and deep stone in dark; hierarchy comes from three surface steps (canvas → sheet → card) plus hairline rings, not heavy shadows. Three hues carry meaning and nothing else does: ochre `accent` means "waiting on you" and is actionable, lichen green `running` means "working", slate blue means "ready for review". Everything else is the ink ladder. The stone language lives inside the UI: status marks are one circular family that fills as a thread nears done, the Threads inbox reads as a trail with waypoints. The brand is the spiral mark, which is also the Coordinator's avatar and spins while it works.

## Colors

- **Three neutral layers** (claude.ai, `docs/design/claude-ai-spec.md` section 5): `sheet` is the page and the sidebar (`--sidebar-surface`), `canvas` the app background one step off it, `popover` the raised layer for menus and the composer. The layers take the app icon's colours: the dark plate's faintly green near-black and the light plate's warm off-white, with the spiral's green-grey as the light ink. `card` is a 3% tint over the page. Every hover, selection and hairline is an alpha of white (dark) or black (light) over these layers: hover 7.5% / 6%, selected 15% / 12%, `line` 10%.
- **Borders are always 1 CSS pixel**: the main panel, task cards, the active nav item, and the new-task button stay 1px on high-density screens too (they do not follow `--hairline` down to 0.5px); borders must be visible.
- **Three-tier shadow ladder** (claude.ai values, spec section 5): `--e1` is a 1px `line` ring with no drop shadow (claude.ai cards carry none); `--e2` menus and floating surfaces (`0 2px 6px` 20% + `0 8px 24px` 32% black in dark, an inset `--elevated-ring` of white 4%); `--e3` dialogs (`0 1px 2px` 6% + `0 2px 8px` 24% and a `--dialog-ring` of white 5%). Light uses the same shapes at lower alpha with black rings (`0 2px 6px` 8% + `0 8px 20px` 10% and a 10% ring, measured on the Claude Duet row menu). The composer has its own `--shadow-composer` (`0 4px 20px` 7.5% and an 8% inset ring) and the jump button `--shadow-jump`. Shadows never change on hover (V21). Old slot names like `--panel-shadow` / `--shadow-popover` / `--dialog-shadow` are aliases.
- **Four ink steps, each clearly apart**. `ink` is everything the user reads as content: message text, titles, row labels, menu items, form labels and values, list items. `ink-2` is for supporting lines (descriptions, hints, a settled row's title), idle tab and ghost-button labels and sidebar icons. `ink-3` is only for true metadata: times, counts, captions, placeholders. `ink-4` is for decorative icons, never text. Each step sits about 1.4 times the next in measured contrast on every surface, the dark `popover` included. The values come from sampling the reference recording with a script that averages the strongest 8% of glyph pixels in a text box (the same script returns the exact token on cairn's own render): its content text samples `#06`-`#0d`, its supporting and meta text one grey at `#50`-`#58` (dark `#93`-`#98`), its placeholders `#72`-`#74` (dark `#7f`). Cairn keeps two grey levels where the reference has one, with the lighter one no paler than the reference's. The earlier values (`#4f4f4f` and `#5c5c5c`, dark `#a6a6a6` and `#999999`) sat 13 levels apart and read as one grey; `ink-4` was `#878787` (3.5:1) and one caption used it as text. Contrast is measured per text pair; `test/dark-text-tertiary-contrast.test.ts` and the gallery's Doc check hold the numbers, not this file.
- **Focus ring**: `--focus-ring` is the ochre accent, where claude.ai uses its blue (spec section 3). Buttons, checkboxes, switches and badges draw it as a `--focus-width` (2.4px) outline at offset 0, hugging the control's radius; rows and segmented options draw it inset. Text fields (`Input`, `Textarea`, `SelectTrigger`, the `InputGroup` shell, the settings search) instead turn their own 1px border `--focus-ring` and draw nothing outside it: one thin ochre line, no halo. An invalid field (`aria-invalid`) shows one `destructive` 1px border at rest and when focused; it never stacks the focus ring on the red border.
- **Brand marks**: the spiral disc (the Coordinator's face) sits on a stone green (`#2f5a2a`) with a `#f4f6f1` spiral in both themes, setting it apart from the neutral brand plate.
- **Palette roles** (V5): ochre is the one accent and means "waiting on you" (`--waiting-ink` for text and icons, `--badge-attention` for dots); green is a 6px dot for running or online and nothing else; rust (`--destructive`, `--danger-soft`) is failure and destructive actions only. Status chips are one neutral fill (`bg-secondary`) with the status in the text and icon colour; there are no slate and no per-project hues. Exceptions: the task reference in the Coordinator conversation (matching the reference app) takes a status tint from the `tint-*` tokens (`tint-working` calm blue, `tint-wait` ochre, `tint-quiet` neutral, `tint-fail` rust; each has a tile fill, a softer chip fill `-soft` and an ink `-ink`, all text pairs 4.5 or more); the count badge (tab counts, the dot on the desktop `任务` toggle) is `--count-badge` blue with a white digit, and blue appears nowhere else; PR state on the Tasks panel's PR line takes `--pr-open`, `--pr-pending`, `--pr-failed` and `--pr-merged`, as L1 allows. Lists, the sidebar and the tasks panel keep one neutral fill.
- **Accent discipline**: `accent` is used only for: needs-your-attention states and counts, action links on cards, icons of the active nav item, and count-badge backgrounds. It is never decorative and never a large-area background.
- **Status is never color alone**: every status is a triple of "icon + color + text" (failed ⊗ failed / awaiting confirmation ☰ awaiting confirmation / awaiting review ⑂ awaiting review); color-blind users can tell them apart by icon and text.
- **The primary button is `primary`**: the shadcn Button default tier, the ink itself. Ochre is never the primary-button background, so "do this" and "waiting on you" never look alike; the enabled send button and a switch that is on are the accent roles (V5).
- **Pebbles**: the `pebble-*` tokens remain only as palette entries; the inbox tone is drawn with the status glyph family (ToneGlyph, `components/tone-glyph.tsx`).

## Typography

- **Serif voice where claude.ai uses its serif** (`docs/research/serif-typography-2026-11-08.md`): Source Serif 4 through three roles, each a utility over tokens in `shadcn.css`. `voice-title` (500, normal tracking) is the sidebar wordmark and page titles (page shells, settings headers, the project title menu; the task detail header is a one-line sans bar). `voice-greeting` (360 light, 320 dark, normal tracking) is the `Greeting` heading; the Coordinator conversation has no serif greeting (see `docs/design/surfaces/conversation.md`, channels). `voice-response` (400) is the task spec text in the thread header block. Agent reply prose (Coordinator replies, thread agent text and reports) is Instrument Sans at `text-ui` with a 20px line height in the Coordinator conversation and its bubbles (reference recording) and a 22px line in the task transcript. Section and column headings, pane and dialog titles stay Instrument Sans (`font-heading` with `font-title`; `font-heading` is the display role and resolves to the sans). Source Serif 4 has no CJK, so Chinese under the serif falls back to the sans CJK faces (PingFang SC, then Noto Sans CJK SC), as claude.ai does; Chinese under the sans is PingFang SC.
- **Everything else is Instrument Sans** (`--font-sans`): thread titles, user messages, thinking, rows, navigation, buttons, meta. Chinese falls back to PingFang SC. Code, commands and ids use JetBrains Mono (`--font-mono`); every count, time and figure uses tabular figures in whatever face it sits in (V27).
- **Rendering: the platform's default smoothing.** `body` sets no `-webkit-font-smoothing`. On macOS that value turns off Core Text's stem darkening, so every glyph drew thinner than in native apps; the reference app (a macOS app with the system face) keeps the default. Linux and Windows ignore the property, so screenshots taken there do not change (V25).
- **Why Instrument Sans stays**: measured against the reference's SF Pro at the same 14px, Instrument Sans has the same set width (ink width of seven reference words: ratio 0.999), a cap height of 0.72 em (SF Pro 0.705) and an x-height of 0.51 em (SF Pro about 0.53), so the face is not why text read small. Chinese under the sans is PingFang SC on macOS in both apps. The weight gap (reference stems about 1.27px at 14px regular, Instrument Sans 1.13px on Linux) is closed by the default smoothing on macOS and the darker inks, not by a new face.
- Fonts are self-hosted latin subsets in `public/fonts` (SIL OFL 1.1, licenses next to the files), loaded with `font-display: swap` and preloaded in `index.html` and `design.html`; the metric-matched fallbacks keep the swap from shifting layout.
- **Eight font sizes, measured on claude.ai** (spec section 2): 32/38 `Greeting` heading / 24/32 page title / 18/18 sidebar wordmark (`text-brand`) / 15/20 section and dialog headings (headings grow by weight, not size) / 15/21 body text and card titles (messages, plans, composer) / 14/20 UI text / 13/18 meta and code (mono) / 12/18 badges and group labels. Sidebar rows use the 14px UI step and a task row's second line uses the 13px meta step (reference recording: sidebar rows and settings rows are 14px, row metas 13px). Body steps above UI text so reading text and chrome do not blur together. In code, use the corresponding Tailwind theme keys `text-greeting` / `text-page` / `text-brand` / `text-heading` / `text-card-title` / `text-ui` / `text-meta` and `text-code` / `text-caption` (heading font `font-heading`), never arbitrary values like `text-[13px]`; `scripts/ui-debt-gate.mjs` only allows the total count of arbitrary values to decrease.
- **Four font weights** (claude.ai, spec section 2): 400 body text (`font-normal`), 500 titles, labels and section headings (`font-title`), 600 bold and card titles; controls use 450 where the primitive sets it. 650 and 700 are not used. The serif weights come only from the `voice-*` roles above.
- The title of a completed task drops to 400 + `ink-2`, meaning "no longer needs to be read"; a title never drops to `ink-3`.

## Layout and spacing

- 4px grid. Common values: 4 / 8 / 12 / 16 / 24. Card padding 12×14, card gap 8, column gap 16, board padding 18×24.
- Top bar 56px: display page title on the left + "⚠ N items need your attention"; text buttons on the right (filter, schedules) + the ink primary button "New task". All top-bar elements are `nowrap` and do not wrap in narrow windows.
- Sidebar 220px (collapsed: no rail, only the toggle and a hover peek) on the same `sheet` surface as the main area, separated from it by one hairline (see `docs/design/surfaces/sidebar.md`).
- One screen has only one primary action (the primary button); the rest are text buttons or `accent` links inside cards (V6).

## Icons

- Icon library lucide (configured in `components.json`), stroke 1.75 (`svg.lucide` in `app.css` pins it; `test/icon-stroke.test.ts` scans every icon usage in `src`; `InkSpiral` is the one illustration it skips).
- **Three icon steps: 16, 20 and 22px** (measured on the reference recording: its settings, sidebar, menu and panel glyphs equal a lucide box of 18 to 22px where cairn drew 14 to 18). 20px (`size-5`) is the default for rows, navigation, menus, buttons and the header toolbar (the Button default; the toolbar checklist then draws a 13x16.5 glyph against the reference's 13.8x16.0); 18px for menu rows (`MENU_ITEM_CLS`); 22px (`size-5.5`) for the controls that drew 18px before (panel-head and dialog close and add, the sidebar toggle, the phone chrome); 16px (`size-4`) for inline marks inside meta text and for the sidebar's 22px row hover actions (`SIDEBAR_ROW_ACTION`: the filter, `+` and `…` on a hovered row), so the glyph clears the hover fill by 3px as in every other icon button; a 20px glyph there filled the 22px fill edge to edge. Stroke stays 1.75, which draws a 1.46 to 1.6px line at 20 to 22px, close to the reference's measured 1.2 to 1.4px; a heavier stroke at the larger boxes would read bolder than the reference. Inline glyphs inside 12 to 13px text keep 12 or 13px. The custom set in `src/icons` defaults to 20px.
- Colors: meta icons and collapse arrows use `ink-4` (`text-content-dim`); sidebar nav icons take their row's `ink`, 20px at stroke 1.75; menu icons take the row's `ink` (the reference draws them black); other icons with a text label (column headings) use `icon` (`text-icon`); pure-icon buttons without a text label (search, collapse sidebar, collapsed sidebar icons) use `ink-3`, preserving the 3:1 non-text contrast; icons of the active nav item and anything "needs you" use `accent`; running-related icons use `running`.
- Shapes: workbench = three columns (Columns3); collapse/expand sidebar = panel (PanelLeft, no arrow).
- Column heading icons are fixed: `待开始` = dashed circle, `执行中` = pulse line, `待处理` = exclamation circle, `已完成` = check circle.
- **Status glyphs are one circular family** (`StatusGlyph`, Linear's model) used in the task header, search rows, mentions and home rows: dashed ring = to start, ring + clock = queued, a pie that fills with progress (quarter = planning in secondary ink, half = confirm in accent, three quarters = building in `running` or review in accent), filled check = done, filled cross = failed, filled slash = closed. Ochre still means it waits on you.

## Brand mark

- **One construction, two optical sizes.** The spiral is built from semicircles on a 30-unit pitch and drawn as one round-capped stroke in flat ink, never textured. The large cut (about 3 turns) is for marks rendered at 48px and up; the small cut (about 1.5 turns, a heavier band) is for 16–32px, including the favicon, the Coordinator row, the collapsed rail and the phone tab bar.
- **In the UI** the mark is `BrandGlyph` (`src/components/brand-glyph.tsx`), drawn in `currentColor` from `src/lib/brand-mark.ts`; it defaults to the small cut. No component carries its own spiral path. A person or an agent with no picture gets no spiral: `SeededAvatar` draws the default avatar, a round tint of one of six colours picked from the name (`src/lib/avatar-tint.ts`), `--avatar-tint` of it over the surface (15% light, 26% dark), with the name's first letter in `--avatar-ink` of that colour mixed into `foreground` (4.5:1 on `background` and `card`, `test/avatar-tint.test.ts`). The letter is 48% of the disc, between 9px and 24px; at 12px the disc is a plain colour dot. The disc never moves: a working agent is shown by the typing dots, not by its avatar. A supplied picture replaces the disc, and a picture that fails to load falls back to it.
- **Plates are neutral**: dark `#151615` with ink `#cfd0cb`, light `#ecebe6` with ink `#202220`. The SVG favicon (`public/logo.svg`) switches plate and ink with `prefers-color-scheme`; the app icon is the exception to flat ink: `apps/ios/Cairn/AppIcon.icon` is one Icon Composer layer, the large spiral as a filled band with a two-stop diagonal gradient per appearance (light `#202220` to `#737570`, dark `#f2f2ed` to `#8c8f8a`), and the system adds the Liquid Glass light and shadow. Every raster icon is that app icon rendered by Icon Composer: the PWA icons (`icon-192.png`, `icon-512.png`, which the README also shows) in the Default appearance with transparent corners, the maskable icons zoomed 1.2x to full bleed so the mark sits inside the 40% safe circle, and the opaque full-bleed apple-touch PNGs (`icon-192-light.png` Default, `icon-192-dark.png` Dark).
- **One generator**: `node scripts/brand/generate-logo.mjs` writes every file above, including the `.icon` layer and `icon.json`, `public/logo-mark.svg` (the large mark alone, `currentColor`) and `src/lib/brand-mark.ts`; `test/brand-assets.test.ts` regenerates them and fails when a committed file differs. On a Mac with Xcode, `node scripts/brand/export-app-icon.mjs` renders every raster icon from that `.icon` with `ictool`: the web icons above and the macOS `assets/AppIcon.icns` and `assets/AppIcon-1024.png` on the 824/1024 body. The test checks their sizes, corners and glass shading, since CI has no `ictool`. Edit the generator, never the outputs.

## Dark

Dark is the `:root` default (`.light` is the light theme). Values live in the `colors-dark` frontmatter of `apps/web/DESIGN.md` and in the `:root` block of `src/styles/shadcn.css`; the gallery's Doc check compares the two in both themes.

- **The same layers, alphas reversed**: in dark the page and the sidebar are the sheet, the app canvas one step lighter, raised surfaces the popover step; every hover, selection and hairline is an alpha of white. The neutrals carry only the app icon's faint tint, too little to compete, so the ochre accent, the green dot and rust still stand alone.
- **Hairline rings stay drawn**: the `line` alpha keeps a visible ring on the card and the sheet.
- **The ink ladder inverts**, same four roles as light; `ink-4` is decorative only.
- **Text on ochre is dark ochre**: `--text-on-accent` sits on the bright `accent`; dark project letters mix the tile hue with 40% white. Light mode uses white on the darker ochre.
- **Accent hover backgrounds are deep-dyed** (`accent-hover`), with `spot-text-on-tint` for links on it.
- **The running green brightens** for dark (`running`, `running-text`, `running-bar`).
- **Dialog backdrop**: black at 50%, no blur; the dialog surface is the `canvas` layer (light uses the page `background`).
- **Status colors follow the same hues as light**: chips, diff rows, column dots and `badge-attention` use slate / ochre / lichen / rust in their dark steps; every chip text pair measures 7.0 or more.
- **Rule for new semantic tokens**: they must be defined in both `.light` and `:root` of `shadcn.css`; the dark side takes values from this ladder and is measured — never "the closest existing tier".

Dark adds one more slot, `--top` (an `inset 0 1px 0` top highlight at 5% white), spliced only into the `--e2` / `--e3` pools so lifted surfaces read as lit from above; in light it is a zero-alpha no-op (it is not written as `none`, because `none` mixed into a comma list would invalidate the whole box-shadow).
