# Disposable CLI credential profiles

When an account is added through desktop sign-in, Cairn runs the CLI in a new profile. The browser still handles account selection. Cairn saves a credential to the existing encrypted subscription store only after that CLI reports success and has written a credential in this attempt’s profile. A failed or cancelled sign-in saves nothing. Importing an account already signed in on the host remains a separate action.

| Scenario | Profile lifecycle | Result |
| --- | --- | --- |
| Desktop sign-in | Desktop creates a private profile in application data. A supervised login worker takes ownership before starting the CLI. On success the desktop waits for the CLI, reads the credential from that profile, and removes it before saving. | The new subscription is selected, then verified with the existing Verify popover. An existing subscription re-login uses the same verification. |
| Failed, cancelled or timed-out sign-in | Stop the CLI and wait before removing the profile. Never read a credential after a failed authentication. | Use the existing failure or cancellation state. |
| Daemon bound OAuth step or isolated subscription model probe | Create a private profile under the daemon data directory. Set the CLI’s home and storage directories to it; the OAuth step seeds only its bound credential. Remove the profile on completion or failure. | No subscription bearer is stored in the general task scratch directory. |
| Owner process is terminated | A desktop worker stops the CLI and cleans its profile when IPC disconnects. On startup each application scans its own profile root. It removes a profile if the owner PID is gone, or if a comparable start time proves the PID was reused. | Dead owners’ profiles are removed. An unknown version or unreadable start time does not cause a live PID’s profile to be removed. |

The profile envelope is mode `0700` with a private `home` child and an owner record beside it. Before creating the home, the application records the PID and a versioned timezone-independent start time (UTC on macOS and kernel start ticks on Linux). Legacy Linux records use the same ticks. Legacy macOS records use local wall time: startup only reaps one for PID reuse if the current start time is later by more than any supported time-zone offset. The desktop worker verifies the parent’s current-format identity before atomically replacing the owner record with its own. Startup visits only the dedicated profile namespace. Credential collection permits only regular files within the canonical profile home and rejects links outside it. Startup does not sweep general task scratch or first-party host config.

Regression coverage: unchanged and independently updated host fixtures, unsuccessful ACP completion, private-path credential reads, normal/cancelled/failed cleanup, worker disconnect, a real process killed after an OAuth step writes its fixture credential followed by startup recovery, and automatic verification on the new-account and in-place re-login screens.
