# Coordinator first feedback comes from the request, not the model — plan, 2026-11-28

## User scenario

Someone who installed Cairn today opens Home or a project channel, types a question, and presses Enter. Their own message appears at once; what they watch for next is whether the Coordinator heard them. Today the answer to that is "wait for the model": on a warm cache the first Coordinator text took 7.03 s on Claude Opus, 9.74 s on DeepSeek Flash and 23.30 s on a repeat interjection, said nothing at all across three Doubao Lite trials, and Devin's turn was still queued at 85 s. This change puts the first feedback in the request path instead: within about a second of admission the Coordinator writes one short line that names the user's own request in their own words ("I'll check "…"", "On it — "…"" for a task, "Got it — "…"" for a mid-work interjection) and then goes quiet until it has something real to say. That line quotes the user's own words only to name what is being worked on: it never asserts a result, never answers the request, and never appears for a bare greeting or thanks — nor when the model has already spoken first. It asks for no new account, payment, or key, and it is not a second model call: it costs no tokens. Nothing new is stored beyond one line in the thread the user is already looking at, written the way a mid-turn `notify_user` notice is written — one `chief_message` row, `role: 'system'`, inserted once under `ack-<messageId>` and published on `convHub` — but under its own `chief_ack` kind so the client draws it as the Coordinator's line; a reload shows the same line, and it is never replayed into the model's context. When the turn later fails, the failure notice still appears underneath that line; when the user stops the turn, the line stays as the record of what was being worked on.

## Why

The 2026-11-27 plan (`f53c60389`) shipped ack-first prompt wording, a generalised `notify_user`, and a responsiveness middleware. Its own target was warm `TTFR <= 3 s p50` and interjection `TTIR <= 5 s p50`. The gap measured on production afterwards (project-scoped browser probe, sandbox project only, `~/Pictures/cairn-review/followhand/` and the follow-up probe of 2026-11-28):

| Coordinator model | First acknowledge (lookup turn) | Interjection answered | Verdict |
|---|---|---|---|
| Claude Opus | 7.03 s | 1.85 s | Prompt wording cannot move model TTFT |
| GPT (Terra) | 1.97 s (repeat lookup) | 2.99 s | Meets the target only when the model chooses to speak first |
| DeepSeek Flash | 9.74 s | 23.30 s (repeat) | Misses both |
| Doubao Lite | no reply in 3 trials (ACP rejected a history-only session after 3.39–5.91 s active) | — | The model lane never produced text |
| Devin | 85.25 s / 87.71 s queued before failing; one probe merged with later input, first text 87.59 s incl. 76.11 s queue | — | Queue time alone exceeds the target |

The conclusion from the table is that the first writer of the user's screen is the model's first decision: an ack that exists only as prompt wording inherits model TTFT, tool-schema size, thinking budget, queue time and provider health. Two of the five families cannot produce any text on a normal turn, so no prompt or streaming change can meet the target there. Four candidate mechanisms were compared (research note §3, `docs/research/coordinator-responsiveness-2026-11-27.md`):

- a `send_message`/`notify_user` tool the model calls first — still waits for the model's first decision and duplicates an existing channel; rejected.
- a runtime ack generated by a *fast model* — buys a different provider's TTFT while adding a second call per message, a second quota and routing surface, and still fails when that call is slow or rejected; not chosen because the measured gap is structural, not model-specific, and nothing proved it meets the deadline.
- streaming the first text round — kept, it is how real work output arrives; it cannot make absent output arrive.
- splitting ack and work into two turns — with a tool-less first round it would break the shared prompt/tool prefix (the cache hit that keeps warm turns cheap) before the work round; rejected as the ack carrier.

What is left is the one carrier that does not depend on a model at all: the request path itself. That is this change. It removes the dead prompt rule it replaces, keeps streaming and the silence-guard middleware for real progress, and leaves greeting behaviour alone.

## Scope

1. **`apps/server/src/services/first-feedback.ts` (new)**: a per-thread guard that, when armed, publishes one grounded first line if no assistant-visible text arrives within 1200 ms of admission. `firstFeedbackLine()` turns the user's text into that line in the user's script: a question (`？`/`?` or an interrogative word) takes the check line; any other request takes the working line; a message that arrives while the turn is already working takes the got-it line (both Chinese and English wording live in `first-feedback.ts`). The excerpt is the user's own words flattened to one line, ≤ 28 characters plus "…", with markdown, fences and attachment tokens removed. A message that is only a greeting, thanks or an emoji — measured by stripping courtesy words and punctuation and finding nothing left — is never armed. The guard keeps at most one pending ack per thread: a later message inside the same burst replaces the line and the admission time while keeping the earliest deadline, so one ack answers the burst and names its latest words. It never states a result, and it is armed only from the composer path, so an event, gate or mail turn never receives one.
2. **Arm at composer admission (`apps/server/src/services/chief.ts`)**: `sendChiefMessageFromComposer` arms the guard for the message it just admitted, after it knows whether the message landed as a steer into a running turn (`steerChiefMessage(...).steered`), so an interjection gets the interjection line and a fresh request gets the request line. The publish closure writes one `chief_ack` row (`ack-<messageId>`, `role: 'system'`, `provenance: 'user'`, the thread's project) through `insertChiefMessageOnce` and pushes it on `convHub` — the same dedupe and delivery path a `notify_user` notice uses, under its own kind so the client renders it as the Coordinator's line — and relays nothing to IM. Before writing, it re-checks the thread for assistant text newer than the message and stays silent if there is any.
3. **Settle on visible output (`apps/server/src/coordinator/runtime/turn.ts`, `apps/server/src/coordinator/runtime/server-runtime.ts`, `apps/server/src/services/chief-tools.ts`, `apps/server/src/services/chief-turns.ts`)**: the guard records the turn start and the start of every model response, taken from the live view's message timestamp rather than the submit, so deltas still flushing from an interrupted response keep the boundary they started under. A streamed text delta or stored assistant text row settles only a pending line admitted at or before that boundary, so a line for a message that arrives while an older answer is still streaming survives until a response that has actually seen the message produces text. A turn end settles the same way, so a message queued during the turn but not consumed by it keeps its line for its own turn. `notify_user` and `ask_user` settle any pending line because a visible row is in the thread now; withdrawing the message settles that message's line; closing the thread settles all of its lines.
4. **Retire the prompt ack-first rule (`apps/server/src/services/chief.ts`)**: `COORDINATOR_SYSTEM_PROMPT`'s `<responsiveness>` section drops the rule that every tool-using turn must start with a model-written acknowledgement (the runtime now guarantees the first line, and a model ack after it would be the same sentence twice); it keeps the direct-answer rule, the interjection rule and the no-repeat-progress rule, and restores the model's own brief acknowledgement for tool-using turns unless the web chat already showed its receipt line for that message; this leaves IM and other non-composer surfaces with an acknowledgement and accepts that a web turn may occasionally show the runtime line and a short model line. Greeting turns never pass through the composer path and stay exactly as they are.
5. **Latency verification**: on the production mini, per Coordinator model family, report three separate numbers before and after: the first visible line (`TTFR`, composer POST to any visible Coordinator text, which the runtime line meets), the model's first real text (the first visible text after that line, which shows what the provider still costs), and `TTIR` (interjection POST to the first visible text that names it). The table never merges the runtime line and the model's own text into one pass. Save the before/after table plus a screen recording of one lookup question and one interjection under `~/Pictures/cairn-review/coordinator-ack/`.

## Out of scope

- A second model call (a "fast model" acknowledgement lane), new keys, cross-provider routing or quota spend for first feedback.
- A new `send_message` tool, or changing `notify_user`'s contract beyond settling the guard.
- Changing greeting behaviour, the single-bubble opening, or the silence-guard middleware.
- Aborting side-effecting tools mid-execution, or changing the steer/barge-in admission rules.
- IM receipts (the delivered/read states of an IM message) — the IM surface already acknowledges delivery.
