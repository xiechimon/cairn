# Coordinator normal task permissions — plan, 2026-11-28

## User scenario

Someone who installed Cairn today opens the Coordinator chat (main channel or a project channel) and asks it to run a quick command or read a file on its own computer without creating a task (for example: "run `uptime` on your computer and paste the output without creating a task"). They do not need to configure any new accounts, keys, or storage, and nothing new is stored outside the existing thread workspace (`<workspacesRoot>/<conversationId>`). Previously, interactive Coordinator turns ran with `lockedDown: true` (mapped to `AcpTurnPolicy = 'read-only'`), so Antigravity's `cairn-relay-guard` hook and the ACP/Claude permission gates rejected `run_command` / `Bash` immediately ("Cairn read-only turn: built-in tool run_command is disabled.") without asking or running, forcing the Coordinator to suggest creating a task instead.

Why it was read-only (git history) and why we open normal Coordinator turns instead of routing through `user_computer_shell`: commit `30eed3e6c` (2026-11-02) introduced `lockedDown: true` for `isChief || isReview` because coding tasks then ran inside Orb containers while Coordinator and review steps ran directly on the host. After open-by-default permissions (`fe0e2d069`) and the removal of `command-gate` (`0775d0acc`), OS task confinement (`0b0d06261`), and Orb (`867cd5b56`), tasks already run directly on the host under the normal permission policy, leaving `isChief` lockdown as an Orb-era leftover rather than a response to an interactive Coordinator incident. Per the owner's standing product rule ("open permissions first — defaults open, tightening needs evidence"), accepted checklist item D5 ("the Coordinator can do one thing on its own computer (read a file or run a command), and asks only when the product's normal permission policy would ask"), and explicit directive, normal daemon Coordinator turns use the same permission policy as tasks on that computer across every runtime (`antigravity`, `claude-code`, `devin`, `gemini`, `pi`) rather than `user_computer_shell` (which targets the owner's Mac when `CAIRN_OWN_COMPUTER=1` and is unavailable on headless local runners). Note that `cwd` does not sandbox writes to the thread directory; narrow protections stay intact for untrusted mail/memory-edit turns (`remoteToolsOnly: true`), review steps (`isReview: true`), read-only workspaces (`ws.readonly`), and read-only Coordinator sub-agents. The in-server Coordinator runtime (used for API-key models such as Doubao when `coordinatorInServer` is enabled) has no read-only turn lock and stays unchanged.

## Scope

1. Normal daemon Coordinator turns (`isChief && !remoteToolsOnly`) omit `lockedDown` in `composeStepSessionOpts` (`apps/daemon/src/step-session-opts.ts`), applying the policy precedence `relay-only > review/readonly > normal`:
   - `remoteToolsOnly: true` (mail / memory-edit Coordinator turns, highest precedence): `lockedDown: true, remoteToolsOnly: true` across all runtimes (`relay-only`).
   - `isReview: true` or `ws.readonly`: `isReview` keeps `readOnly: true, lockedDown: true`; non-review `ws.readonly` keeps `readOnly: true` unchanged from `main` (Coordinator steps have `repo = null`, so `ws` is always `null`).
   - Normal Coordinator (`isChief && !remoteToolsOnly`): omits `lockedDown`, `readOnly`, and `remoteToolsOnly` while keeping `compactAt: COORDINATOR_COMPACT_AT` and ignoring `skillsAllowlist`/`injectedSkills`:
     - Antigravity (`agy`): `policy = 'normal'`, `isRestricted = false`, `'auto'` mode (fallback `'accept-edits'`), `allow-once` permissions, no `cairn-relay-guard` hook (`syncAntigravityToolPermission` already clears `toolPermission: 'strict'` on non-`relay-only` turns).
     - Claude Code (SDK + ACP): `locked = false`, `permissionMode: 'bypassPermissions'`, full built-in tools (`tools: undefined`) including `Bash`, `disallowedTools: ['AskUserQuestion']`, external MCP per `claimed.mcpServers`, `compactAt` and `ENABLE_TOOL_SEARCH` preserved; ACP `_meta` `undefined`.
     - Devin (`acp`): `policy = 'normal'`, `isRestricted = false`, `'bypass'` mode, `allow-once` permissions.
     - Gemini (`acp`): `policy = 'normal'`, `allow-once` permissions.
     - Pi (daemon): already unlocked on `main` (`PI_BUILTIN_TOOLS`: `read`, `bash`, `edit`, `write` — existing parity, not a change).
     - In-server Coordinator (Doubao / API-key models): no read-only turn gate; uses `user_computer_shell` when `CAIRN_OWN_COMPUTER=1` is active on a local runner (unchanged).
2. Refcounted hook ownership & stale cleanup in `installAntigravityTurnHooks(cwd, policy)` (`apps/daemon/src/backend/antigravity-hooks.ts`, shared across all Antigravity sessions in the same `cwd`):
   - **Actors**: (a) restricted installer (`'read-only'` / `'relay-only'` sessions including concurrent subagents), (b) lease cleanup/restorer (idempotent on turn end, cancel, or spawn failure), (c) normal stale-cleaner (`policy === 'normal'`), (d) Antigravity CLI reading `cwd/.agents/hooks.json`, (e) external user hooks in `cwd/.agents/hooks.json`.
   - **Ownership & recovery**: Maintain an in-process lease map keyed by `resolve(cwd)` (`{ hadAgentsDir, hadHooksFile, leases: Map<symbol, policy> }`). First restricted lease records `hadAgentsDir = existsSync(agentsDir)` and `hadHooksFile = existsSync(hooksPath)`. On install/recompute, read the current `hooks.json` synchronously: if it does not exist, start from `{}`; if it exists and is malformed or not a plain JSON object, fail closed without overwriting the file; otherwise merge `HOOK_GROUP_KEY` with the strictest active policy (`'relay-only' > 'read-only'`) and write `hooks.json` synchronously (`mode: 0o600`). Concurrent restricted leases share the map and recompute the strictest remaining policy on each release. When the last lease exits (normal end, abort/cancel, or startup error), delete the map entry and perform one synchronous read-modify-write on `hooks.json` (no snapshot restore and no `await` between read and write, preserving user edits made during the session): if it is a plain JSON object containing `HOOK_GROUP_KEY`, delete only `HOOK_GROUP_KEY`; if remaining keys exist, write them back; if no keys remain and `hadHooksFile` was true, write `{}`; otherwise (`!hadHooksFile`) remove `hooks.json` and remove `.agents/` only if `!hadAgentsDir` and empty. When `policy === 'normal'` runs with an active in-process lease in `cwd`, it leaves `hooks.json` untouched; when no active lease exists and `hooks.json` is a plain JSON object containing `cairn-relay-guard`, it deletes only `cairn-relay-guard` (keeping unrelated user hooks, removing `hooks.json` only if `cairn-relay-guard` was its sole key, and never deleting `.agents/` or non-JSON / user-owned empty `{}` files).
3. Unchanged narrow protections: mail and memory-edit Coordinator turns (`remoteToolsOnly: true`), `isReview`, `ws.readonly`, Coordinator daemon sub-agents (`apps/daemon/src/backend/subagent.ts` keeps `lockedDown: true, readOnly: true`), Coordinator `compactAt` / ignored skill lists, and in-server Coordinator routing (`serverTakesTurn`).

## Out of scope

- Changing `CAIRN_OWN_COMPUTER` defaults on headless runners.
- Modifying in-server Coordinator routing (`serverTakesTurn`) or `user_computer_shell` gating.
- Reintroducing a command gate or changing task permission modes.
