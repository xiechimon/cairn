# Personal relay: enrollment, control and RPC v1

Status: exact protocol proposal for independent review before implementation. Implements the bounded trusted-relay decision in [installation and trust](connect-do-enrollment.md), based on [primary research](../research/connect-do-enrollment-2026-11-15.md). The merged [transport experiment](connect-do-prototype.md) is not this protocol. This document authorizes no cloud mutation. Initial implementation is offline only, with generated test credentials and local workerd.

## Scope and existing owners

One configured installation UUID, one personal team selected locally, one host and four browser sockets share one SQLite DO named `personal`. No caller chooses a DO name, team, upstream or execution machine. The host uses `paired-devices.ts`, `browser-session.ts`, the existing Coordinator composer/turn/question services, and `ConversationStreamHub`. Existing Coordinator scheduling, client-message deduplication, provider routing and executor credentials remain authoritative. The adapter does not implement a task queue or call the private HTTP listener.

The initial RPC surface is the personal Coordinator and project summaries, not every task pane. Submission goes through its existing composer; watching uses bounded change notifications and subsequent paged reads, not raw model-token streaming. The Coordinator can delegate work through its existing machinery. Arbitrary task control, secrets, settings, filesystem, machine enrollment, generic HTTP and direct provider calls are absent. There is no production UI or installer in the offline slice; the four-action mobile acceptance and six installation stages remain release gates, not claims of this slice.

## Configuration and persistence

Deployment configuration contains `INSTALLATION_ID` (UUID), `ENVIRONMENT_ID` (UUID), `PUBLIC_ORIGIN` (exact HTTPS origin, no path/query/userinfo/port) and `HOST_CAPABILITY` (32 random bytes encoded as 64 lowercase hex characters, secret binding). Missing/malformed configuration rejects all dynamic routes. No cloud management credential is available to either runtime. Local tests alone substitute an explicit loopback origin; production validation never accepts HTTP or localhost by default.

Host configuration comes from locally approved Connect allocation, personal team and capability, not a received frame. Existing Connect intent/generation, exclusive store and `ConnectHandle.ready/close` own enable/disable/remove/shutdown. A relay connector is a handle behind that lifecycle, not another persisted state machine. Allocation's ID is the installation UUID and hostname is the approved relay host; no existing allocation is silently adopted as a relay. Offline tests inject allocation/provision/remove functions and make no cloud calls. Installer, credential journal and production lifecycle wiring remain a separate, explicitly approved stage.

Add nullable `relayScope` to existing host `pairing_grant` and `browser_session` records. Private/Tailscale callers use null; relay grants use `<installation UUID>:<enable generation>`, relay sessions use the installation UUID. Redemption/session resolution matches scope exactly, so neither private grants nor private owner/device sessions cross into relay use, and relay sessions cannot authenticate private HTTP. Existing device rows/cap/revocation remain shared. Scope is host-internal and never accepted from phone input. Existing grant redemption/device creation/session issuance stay one transaction. Remove revokes matching scoped sessions and grants; disable revokes only this installation's pending grants. No second credential table is introduced on the host.

DO tables contain only a singleton installation/ledger marker, current/previous UTC budget rows, at most 20 unconsumed grant digests, and a bounded cache of at most 50 session digests with device IDs/expiry/insertion order. No plaintext bearer, code, cookie, chat or result is persisted. Expired metadata is swept with bounded work. The session index is an admission cache, never an independent credential authority: after host-authorized pairing/admission, insert/update its digest and evict the oldest cache row if full. Cache eviction neither revokes the host session nor drops an already authenticated socket. A returning cookie missing from this cache must undergo the same host validation/commit as a cache hit and may then repopulate it; never accept it on the miss alone. Revoked rows cannot exhaust permanent capacity or cause device creation to fail after grant consumption. SQL read/write failure is not a cache miss: fail closed. A missing ledger for an initialized installation or corrupt state fails closed; deploy/reconnect never initializes another allowance. New database initialization is permitted only for the configured installation's first creation; deleting the entire DO storage is an operator reset outside the threat/budget guarantee, not a recoverable runtime event.

## Syntax and admission

All frames are complete JSON text, at most 65,536 UTF-8 bytes including syntax; binary/oversize closes 1008/1009. Objects accept exactly their listed keys, including nested request objects; unknown version/type/key, invalid correlation and cross-role control close 1008. `v` is integer 1. `uuid` is a canonical lowercase UUID; timestamps are positive safe-integer Unix milliseconds; `seq` is a positive safe integer strictly increasing per browser socket. IDs of existing Cairn records are nonempty strings of at most 128 characters. `digest` is lowercase SHA-256 hex. No compression is requested. Each serialized data/result payload must fit 60KiB UTF-8 before the complete-frame check. JSON uses standard JSON.parse plus shared strict Zod schemas, not a custom parser.

Every route rejects query strings, URL credentials and redirects. Dynamic responses use no-store, no-referrer and no CORS. Browser routes require exact `Origin: PUBLIC_ORIGIN`, reject conflicting Fetch Metadata, any Authorization header, any WebSocket subprotocol and duplicate relay-cookie names. The cookie is the only client transport credential; cookie values are exactly 64 lowercase hex characters. Host routes require exactly `Authorization: Bearer <HOST_CAPABILITY>`, reject Origin/Cookie/subprotocol, and authenticate in the Worker and DO before any upgrade. IDs/roles are derived from the admitted socket, never browser fields.

| Exact route | Admission and result |
| --- | --- |
| `GET /descriptor` | Public minimal `{v:1,installationId,environmentId}`; dynamic-call budget applies. No device, account, provider or host-private details. |
| `POST /pair` | Exact JSON `{code,name}`; code is 32 base64url characters (existing 24-byte grant), name uses existing trimmed 1–80-character device schema. JSON content type and streamed body cap 1KiB. Exact browser origin, no Authorization/subprotocol; no need for a prior cookie. Success 201 `{deviceId,expiresAt}` plus cookie; no secret in body. |
| `GET /connect/host` | Authenticated WebSocket upgrade only; one non-retired host, fixed one-hour lifetime. Second host 409, never replaces a live host by presenting a new claimed epoch. |
| `GET /connect/client` | Cookie + browser-origin checks, digest/expiry lookup, live host validation before upgrade. Maximum four clients, including reserved pending admissions. |
| Everything else | 404/405 without forwarding. No private SPA proxy. A later pinned static client may serve `/app`; it is not implied by this implementation. |

For pairing, set `__Host-cairn_relay=<sessionToken>; Secure; HttpOnly; SameSite=Strict; Path=/` with an absolute Expires at host session expiry (at most 30 days), no Domain or sliding refresh. Returning phones use the secret-free origin. QR generation stays local, uses the existing fragment-only pairing-link helper, and reveals no code until cloud digest registration is acknowledged. A future client clears the fragment before issuing requests and uses no third-party scripts/storage/telemetry.

All dynamic entries reserve the shared dynamic-call allowance before work. Pair attempts additionally reserve the pairing allowance before eligibility checks; admissible upgrades reserve their allowance before upgrade, never refunded. Invalid edge requests consume provider ingress even when they never reach the DO. HTTP failures return only `{error:<code>}`: 400 `invalid`, 401 `denied`, 409 `busy`, 413 `too_large`, 429 `budget`, 503 `offline` or `unknown`. Budget responses include UTC reset milliseconds via `X-Cairn-Reset-At`. No internal exception, echoed credential or application payload enters diagnostics.

## Exact host control grammar

The DO assigns a fresh host epoch UUID at upgrade. Every client attachment has its own UUID and that host epoch; every host callback checks the socket is still the current epoch. The host learns the epoch only from its welcome and rejects later welcomes. Below, optional fields are explicitly marked; all other fields are required. Control IDs are fresh UUIDs, never grant digests, tokens or browser sequence numbers.

| Direction | Envelope | Contract |
| --- | --- | --- |
| DO → host | `{v:1,type:"host.ready",epoch,expiresAt}` | Bind configured installation/current local enable generation to this epoch. No user-supplied scope. |
| Host → DO | `{v:1,type:"grant.put",id,digest,expiresAt}` | Register a locally issued scoped grant; expiry > now and ≤ now+5min; at most 20. Store epoch; registration in a different epoch is not eligible. |
| DO → host | `{v:1,type:"grant.ack",id,ok}` | QR is visible only when matching `ok:true`; otherwise revoke local grant. A 15s registration timeout also revokes locally. |
| DO → host | `{v:1,type:"pair",id,code,name,deadlineAt}` | Reserve/consume matching current-epoch digest before dispatch; one pending redemption per grant. Raw code exists only transiently. Host checks its live lifecycle/epoch/deadline, then redeems using existing transaction with current generation scope. |
| Host → DO | `{v:1,type:"paired",id,deviceId,sessionToken,expiresAt}` | Existing host-issued device session only; DO checks pending pair, host epoch, deadline, token grammar and bounded expiry, then stores digest metadata and sets cookie. No permanent device token crosses the host socket. |
| DO → host | `{v:1,type:"admit",id,connectionId,sessionToken,deadlineAt}` | Allocate UUID before validation, transiently forward presented cookie. Host resolves the existing scoped device session and checks actual device/team existence and expiry. Never persist this frame. |
| Host → DO | `{v:1,type:"admitted",id,connectionId,deviceId,expiresAt}` | Host provisionally binds the actual session resolved from that presented token, installation, epoch and connection ID. DO checks exact pending connection; when its pending cookie digest has a cached row, returned device/expiry must equal that row, not another row for the device. On a genuine cache miss, only this correlated host result supplies those fields. Never extend host expiry. No browser upgrade yet. |
| DO → host | `{v:1,type:"admit.commit",id,connectionId,expiresAt}` | Same admission ID/connection/epoch and original deadline; choose fixed socket expiry ≤ now+1h, host-socket expiry and actual session expiry. Host checks the provisional binding/deadline and revalidates session/device/lifecycle before promoting it independently of application traffic. |
| Host → DO | `{v:1,type:"admit.committed",id,connectionId}` | Exact same still-pending admission, received before original deadline, permits upgrade/welcome. A duplicate identical commit is acknowledged only while that original admission deadline is live; it cannot renew expiry. Missing/late/mismatched commit fails closed, sends drop, and never upgrades another connection. |
| Either direction | `{v:1,type:"drop",connectionId}` | Close/unbind only a client in this host epoch; idempotent for a missing current-epoch client. No browser may send it. Host revocation sends drop; client close/admission loss sends drop to host. |
| DO → host | `{v:1,type:"call",id,connectionId,deadlineAt,request}` | Relay chooses call UUID and recipient from admitted socket; deadline is request receipt+15s. Host requires now < deadline ≤ now+15s before invoking a service, and rechecks binding/session/device/scope/lifecycle before dispatch and before response. Expired work is not first dispatched; already-dispatched work may finish without a deliverable result. Four total operations including pair/admit/register; no queue. |
| Host → DO | `{v:1,type:"result",id,result}` | Must match one current-epoch pending call and its client; correlation supplies recipient, never a host-provided destination. Result grammar below. |
| Host → DO | `{v:1,type:"changed",connectionId}` | Bounded Coordinator invalidation from a currently authorized watch; never contains message content. Only a live watched recipient of this epoch receives it. |
| Host → DO | `{v:1,type:"failed",id,error}` | Finish matching pair/admit/call with `denied`, `busy`, `invalid`, `too_large` or `unknown`; never include raw exception text. Unknown/expired IDs are discarded without redirecting to another request. |

Grant registration shares the operation ceiling: an acknowledgement completes it. DO-generated pair/admit IDs and browser-call IDs occupy a single four-entry account-wide pending pool; an admission holds its slot through commit. Pair and admit deadlines are dispatch+15s, and host checks them before redemption/binding and before returning success. Unsolicited/duplicate host results never create admission, credentials, counters or replay. A consumed grant is not restored after timeout, failure or host replacement. The host revokes any locally committed session when it detects pairing response loss; undetectable loss can leave an orphan device, which the owner revokes through existing device settings. Admission timeout/cancellation/failed upgrade sends drop even if commit may have succeeded. Lost commit acknowledgements and lost drops can retain a host binding until fixed socket expiry or host close; the binding cap remains eight, and local Connect off/on clears such orphans without resetting the account budget.

## Browser RPC grammar and service mapping

DO welcome is exactly `{v:1,type:"client.ready",connectionId,expiresAt}`. Browser sends `{v:1,type:"request",seq,request}`. DO sends `{v:1,type:"response",seq,result}` or `{v:1,type:"changed"}` for an authorized watch. Each result is exactly `{ok:true,value:<JSON value>}` or `{ok:false,error:<code>}`. Error codes are `denied`, `invalid`, `busy`, `not_found`, `conflict`, `too_large`, `unknown`. Success values are explicitly projected public service results below, never dependency/context objects or arbitrary DB rows. Validate request and complete output size again on the host.

| Exact request | Existing operation and projected success value |
| --- | --- |
| `{op:"projects.list"}` | Select only current personal team's unarchived project summaries; return exactly `{projects:[{id,name}],hasMore}` (max50). IDs use existing-record bounds, names are strings and hasMore is boolean. No repo paths, tokens or provider configuration. |
| `{op:"coordinator.read",limit,before?}` | `readCoordinatorPage` for the configured team; limit integer1–20, optional existing message ID ≤128. Return exactly `{threadId,messages:[{id,role,content,createdAt,projectId}],hasEarlier}` with at most20 messages; thread/message/project IDs use existing-record bounds, projectId is nullable, role is system/user/assistant, createdAt is a timestamp, hasEarlier is boolean. Content is a display-only string: existing strings pass through; other JSON content is JSON.stringify-encoded without truncation. It is data, never a control envelope or executable HTML. Output too large returns `too_large`. |
| `{op:"coordinator.send",projectId,content,clientMessageId}` | Require project exists, belongs to configured team and is writable; content1–8192 UTF-8 bytes, UUID client message ID. `sendChiefMessageFromComposer` with server-derived thread/team, existing event publication. Return only `{threadId,messageId,replayed}`. Existing service deduplication remains intact; relay does not generate a second task or client-message ledger. |
| `{op:"coordinator.watch"}` | Subscribe this connection once to the existing personal Coordinator conversation hub; return `{watching:true}`. Coalesce changes to at most one per second per connection using one host timer, not DO polling. Each emission rechecks binding/session/device/scope/intent; no raw hub event crosses the relay. Client rereads a page to see new content. |
| `{op:"coordinator.stop"}` | Resolve configured personal Coordinator thread, call `stopChiefTurn`; return existing `{delegated}`. Stops its current turn, not arbitrary delegated task IDs; absence of a running turn is `conflict`. |
| `{op:"coordinator.answer",requestId,answers}` | Match question in that personal Coordinator thread; invoke the HTTP route's existing `jobSubmitAnswerActor(question.content, false)` authorization first, because a relay device is never an owner. Owner-only job-submit questions are denied; never unconditionally set person attribution to bypass the guard. Then use existing `askUserAnswerBodySchema`/`answerChiefQuestion` with the guard's optional attribution. Return `{answered:true}`. Derive strict answer entries from the existing `{header,choices? | text?}` model: exactly one of choices/text;1–10 answers; header, each choice and text ≤4096 UTF-8 bytes, choices1–10. Existing question count/option validation still applies. |
| `{op:"coordinator.cancel",requestId}` | Match same Coordinator question/thread, call existing `cancelQuestion` with a fixed user-cancel reason; return `{cancelled:true}`. |

The personal team is an authorization boundary, not project isolation between paired phones: all paired phones have the same bounded Coordinator authority in that personal team. A browser cannot select a different team, thread, executor, provider, owner flag, HTTP verb/path or route. The existing composer can create/delegate work on local authority; the installation trust disclosure still applies. These seven operations deliberately do not claim all standalone task panes or full-SPA compatibility.

Success validation is operation-specific, not merely a union of seven shapes. All listed success objects and message/project entries are strict. `coordinator.send` IDs follow record bounds and replayed is boolean; watching/answered/cancelled are literal true; delegated is boolean. `value` has exactly the selected operation's shape, no undefined/non-JSON values, and fits the payload byte cap. Both host and DO validate it; DO pending attachments retain `op` across eviction for this purpose. Errors use the common exact error result. The host maps service403/401 to denied,404 to not_found,409 to conflict, validation to invalid and unexpected exceptions to unknown without leaking their messages.

Host session bindings store only hash/record ID and expiry, never the original bearer after admission. Resolve the actual session/device rows again on every call and delayed watch emission. Revocation uses `deviceStreams.bind` to clear binding/watch and send drop immediately, with row checks as fallback when an invalidation was lost. A lost/expired binding is denied, never reconstructed from the DO's claimed device ID. At most eight provisional/committed bindings exist in total, with at most four actual DO clients/pending admissions. A provisional admission expires at its15s deadline unless the exact commit promotes it; a committed idle browser remains authorized until its fixed socket expiry, independent of first application traffic. A drop always clears binding/watch. DO hibernation preserves IDs, not authorization authority; host process loss or new epoch requires fresh upgrades.

## Failure, budget and hibernation state contract

Retain proposed [account budgets](connect-do-enrollment.md#account-budget-fail-closed-do-not-promise-a-quota-firewall): 64 upgrades/day,400 pair attempts/day,2000 dynamic/control calls/day,10000 inbound frames/day,32MiB/day serialized output;8MiB/socket;1200 host or60 client frames/minute; four total in-flight; fixed sockets≤1h and session expiry. Every host/client frame, including control and invalid frames reaching the DO, reserves inbound/rate allowance before dispatch. Every outbound frame/HTTP control body, including welcomes, acks, errors and session issuance, reserves UTF-8 serialized bytes before send; output reservations never refund. A single bounded emergency HTTP denial/close is allowed after budget/storage failure, not an unmetered response loop. Provider ingress and WebSocket wall-clock duration remain outside this ledger.

| Read/write path | State transition and test obligation |
| --- | --- |
| Fresh DO / daily rollover | Initialize configured install marker and today's row atomically once; retain prior day and monotonic last-clock. Missing/corrupt initialized row, backwards date or SQL failure stops admission/forwarding; no cached fallback. |
| Grant register / pair | Reserve control budget, persist current-epoch digest before ack; reserve pairing attempt, consume digest and pending slot before send. Host scope match/transaction prevents private, expired, replayed, revoked, racing and old-generation redemption. Failure never returns the grant or an old cookie. |
| Pair/admit HTTP await | 15s deadline with at most four transient promises; bounded timeouts may keep DO awake for those15s. Runtime loss returns unknown/disconnect, never restores raw secrets. Late results are ignored. Ambiguous pair session may need local revocation/re-pair. |
| Client upgrade | Reserve slot/UUID and upgrade budget; validate host reply against the pending cookie digest, complete exact commit/ack before original deadline, reserve welcome, then accept. Test idle beyond15s, lost/duplicate/late commit and failed upgrade/drop. Provisional bindings expire at deadline; committed orphan bindings consume bounded capacity until fixed expiry/host close. |
| Session cache capacity / revoke while offline | Evict oldest metadata only after host-authorized insertion; a missing cache row still requires full host validation. Test >50 pair/revoke cycles, valid evicted-cookie return, cached revoked-cookie denial and storage failure distinct from a cache miss. No grant is consumed merely to free cache capacity. |
| RPC request / response | Reserve monotonic seq, correlation/deadline and budget before dispatch. Store bounded pending metadata in the client attachment (UUID,seq,op,deadline,no payload), so workerd eviction preserves routing and operation-specific output validation. Host checks deadline before service dispatch; results search current client attachments, never replay the RPC. Expired pending calls are lazily dropped on any next event; clients impose their own15s UI deadline. |
| Watch / emission | At most one host subscription/timer per client; device revalidation before emitting. DO verifies current epoch/recipient and reserves output before forwarding. Changed notifications may be coalesced/lost; a reconnect reads current state and explicitly watches again. No resume cursor/delivery guarantee. |
| Revoke / expiry / logout | Host removes binding/watch; session/device row deletion immediately defeats later operations/emissions. DO digest removal/drop is best effort, never the authority. Fixed expiry checked on sender and recipient for every callback. Logout uses local session-revocation APIs until an explicit remote logout operation is designed. |
| Disable / remove / shutdown | Existing persisted intent/generation invalidates pending grants first and closes host/watch handles; remove also deletes installation-scoped sessions. Every late callback rechecks current generation/epoch; no successful pairing or new side effect after the transition. Already-dispatched local work may finish; no rollback claim. |
| Host close / replacement | Retire host and all its clients, detach watches, abandon correlations. Old close/error/results cannot retire or send to a later epoch. New host never silently rebinds old clients. No automatic mutation retry. |
| Eviction / send failure / output quota | Attachments retain identity,epoch,expiry,seq,rate,lifetime bytes and bounded pending calls; SQL retains account reservations. Reconnect cannot reset daily totals. Reserve first; failed send closes1011 without refund. Budget closes1013; SQL/metadata uncertainty closes without requiring another successful write. |

No exactly-once delivery or automatic replay is promised. Existing `clientMessageId` deduplication can identify the same composer submission, but relay timeouts still mean inspect current Coordinator state before retrying. No log contains grant, cookie, bearer, raw frame or task content. No fault route or test-time clock mutation is present in deployable entrypoints.

## Delivery and validation boundaries

Land independently reviewable slices under the repository size limit: reviewed design and existing-session scoping; standalone offline Worker with typed controls/budgets; existing-service host adapter and real local-workerd integration. Dependent PRs branch from main only after their prerequisite merges. No production entrypoint or installer enables these components implicitly. Each code slice needs targeted serial tests, normal prepush/CI and exact-head security disposition; the final adapter slice must exercise existing SQLite sessions, Coordinator persistence/event/revocation and Connect lifecycle end to end against real workerd, with provider execution explicitly stubbed or not exercised.

Cloud acceptance is separate: exact Cloudflare account, Worker name, SQLite DO binding/class/migration name, secret/configuration and deployment/version scope must be listed in Chinese to the owner and confirmed before cloud writes. Fresh-account onboarding, supported keyring/minimum OAuth scopes, actual mobile cookie/Origin behavior, no-VPN result and measured platform usage remain unverified until that approved trial. No Paid upgrade, spending-limit changes, custom domain, production8787 restart or automatic deployment is included.
