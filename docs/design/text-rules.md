# Text rules: two type steps for titles and body, two text colours, no helper lines — plan, 2026-11-27

## User scenario

Anyone who opens Cairn meets this on every screen. Titles — page, panel, dialog, settings page and settings section titles — become 18px weight 600 (was 24px serif page titles and 15–16px headings at 500), the Coordinator reply and card titles 16px, all interface and meta text 14px. Text has two colours: primary and secondary. The lines that explained a setting, a dialog or an empty list are gone, so a settings row shows only its label, its control and, when there is one, a status (last backup time, permission blocked, current model). Nothing new to learn, no account, key or storage. The owner picked this from the side-by-side preview on 2026-11-27 (("the text rules are very good, keep them")).

Colours: the owner asked for primary `#181818` and secondary `#6A6A6A` in light. `#6A6A6A` reaches only 4.25:1 on the card surface and 3.26:1 on a selected row, which breaks A3 (WCAG AA 4.5:1, pinned by `test/dark-text-tertiary-contrast.test.ts` and `e2e/a11y-axe.spec.ts`). The secondary is therefore `#545454`, the lightest neutral grey that passes 4.5:1 on every light surface the contrast test checks. Dark: primary `#ededed` (13.96:1 on the dark card, the light pair's 13.95:1) and secondary `#b0b0b0`, the lightest grey that passes 4.5:1 on every dark surface (matching the light secondary's 5.95:1 card ratio would give `#9c9c9c`, which fails on selected rows at 3.72:1). Both substitutions follow a clear standard (A3) and are reported to the owner in the wrap-up with the exact ratios; reverting to `#6A6A6A` is a two-token change but would turn `e2e/a11y-axe.spec.ts` red.

## Scope

1. Tokens in `apps/web/src/styles/shadcn.css` (settings dialog title, settings page head and `SettingsSection` titles move from `text-card-title` to `text-heading` with `font-title`; tasks and side panel titles from weight 400 to `font-title`): `--type-page` and `--type-heading` 18px, `--type-card-title` 16px (the reply follows it), `--type-meta` 14px; `--title-weight` and `--voice-title-weight` 600. `--type-ui` 14px, `--type-brand` 18px, `--type-caption` 12px (badges, keycaps) and `--type-code` unchanged. Font families unchanged.
2. Text colours: light `--foreground`, `--card-foreground`, `--popover-foreground` `#181818`; `--muted-foreground`, `--text-secondary`, `--text-tertiary`, `--text-dim` `#545454`. Dark: the same tokens `#ededed` and `#b0b0b0`. Tokens that alias them (`--icon`, `--sidebar-ink`, `--pebble-idle`, code token greys) follow.
3. `apps/web/DESIGN.md` frontmatter mirrors 1–2 (ink, ink-2..4, icon, primary in both themes; typography page-title, heading, card-title, response, reply, meta).
4. New rule V32 in `docs/design/surfaces/foundation.md`: type steps and the two text colours, measured in `e2e/design-rules-measure.spec.ts` on settings account at 1440 and 390, light and dark: settings page head and section title 18px/600 in `ink`, row label 14px in `ink`, status line 14px in `ink-2`, and every visible text node in the settings labels and titles is `ink` or `ink-2` (the destructive role excepted); the control column keeps its component roles (button, switch, select) and is not part of V32. Pages outside settings are checked by hand on the live stack (computed colours of every text node, recorded in the evidence).
5. Settings rows carry no helper line: `SettingsRow` `hint` becomes `status` (a state line only), `SettingsSection` loses `description`, `SettingsDangerZone` loses `description`, `SETTINGS_HINT_CLS` is no longer exported. New rule C47 in `docs/design/surfaces/settings.md`, checked by `apps/web/test/settings-row-status.test.ts`: every `status=` on a `SettingsRow` or `RuleRow` is pinned per file with its count and the i18n keys it can show; a new one, or a `hint`/`description` attribute, fails with the rule id. The only unpinned pass-through is `RuleRow` forwarding its own `status` prop to `SettingsRow` inside `routing-settings-page.tsx`; its callers are pinned.
6. Removed lines (i18n keys deleted from `en.ts` where unused afterwards): settings rows — route override "Any uses the default Runner", "Leave empty to keep the rule Runner", "Dispatch requires these MCP servers on the executor", backup "Current state is saved before restoring so you can revert in one click.", routing "Compacts a conversation when the context is nearly full", push notifications "Notify you in the system notification center when a task needs you", "Alerts you when something needs you; anything that can wait arrives in a scheduled email digest", remote access "Signed in to this instance with your account", "Turn it on and phones and other computers can reach this computer over your Tailscale network.", project settings "The GitHub repo becomes the source; not available while a build runs" (the build lock moves into the row's existing `info` tip, C7), vault site authorization "Approved sites fill directly on this Runner" (joins the title's `info` tip), MCP servers section "local config files on the server's computer; edit them there", provider removal "Once removed, its models can no longer be picked." (its confirm layer already says "After removal, the models and routes that use it stop working."); empty states — work panel, runners, providers, secrets, skills, vault, API keys, usage, remote-access off; tasks panel "Tell the Coordinator about something and it shows up here.", "Tasks show up here once they finish.", schedules "You can also tell the Coordinator how often a task should run again, and it will write the rule for you."; setup prompt "Run `{command}` on the computer that should run the tasks"; dialog subtitles — route override, mail "Asks you before replying", Composio unconfigured, MCP catalogue descriptions and "Connect {name}", iMessage bridge "The bridge runs on the Mac you pick and shares the outbound channel your Runner already uses. No open ports needed."; form help — secret scope, vault site and name, API key prefix, schedule webhook after the address exists (both; before saving, "Saving creates a webhook URL — an external POST to it runs the schedule once." stays as the one usage step), schedule prompt "Leave empty to use the thread description.", optional MCP token "Works without one; a key raises your limits.", skill import "Importing copies the skill; the original stays unchanged.".
7. Kept, because they are not explanation: status lines (backup time and state, notification permission blocked, current or default model, remote-access state and address, queued count, timezone the server uses, reconnect vs connect, dialog subjects such as an address or endpoint); error and recovery lines; data-safety lines (export excludes secret files — the owner's pick; a secret shown once, C28; values encrypted and hidden after save; restore rolls everything back; feedback uploads no keys or code); steps without which a connect flow cannot be finished (where to create a token or app password, phone pairing, QR expiry, NAME=VALUE format, skill source format, MCP name and URL format, iMessage requirements); disabled reasons (C7) — the route override platform lock moves into the row's `info` tip; a caution tied to the value the user just picked ("Runs on the hour may start a few minutes late." when the minute is 00).
8. The lock-screen push button that sat inside the notifications helper moves to the row's control column, unchanged in behaviour.
