# Retire the autonomy pause

**Owner approval: 2026-11-22 · Design only · Audited `origin/main`: `f32695f65`**

Someone installing Cairn today sees no auto-merge pause control. Finishing a task or explicitly requesting a merge works as before; there is no new setup, account, key, charge, or wait. Retire the API and GitHub marker behavior that still reports a pause without stopping a merge.

| Scenario | Before → after |
| --- | --- |
| Team already paused | Cairn has no banner or switch; `GET /api/teams` reports the open entries, and GitHub may show an open marker. Afterward the fields are absent, existing markers and database rows remain as they were, and closing a marker no longer changes Cairn state. No merge is started or retried. |
| Older client or script tries to pause/resume | A boolean PATCH currently writes state and may publish a marker. Afterward it gets `410` with an explicit retirement message, not a success that implies protection. No retry is needed. |
| GitHub default branch goes red | The poller can currently publish pause markers and prepare a recovery PR. Afterward it can still prepare the recovery PR for human review, but publishes no pause marker. Same poll interval; no new cost. |

## Proof and security answer

**No merge refused by audited Cairn becomes allowed.** Source audit: REST, Coordinator and MCP all enter `requestMerge`. The only production `claimAutonomousMerge` callers are `build-github-merge.ts` and `local-merge.ts`; both pass `true`, which skips the pause and cap before the same transactional duplicate check. Hosted merge steps bypass that helper and do not read pause state at enqueue, claim or landing. `GET .../merge-permission` checks tools only. `mergeReadiness` has only test callers at this SHA; the live required-check projection and verdict compare reader are separate, and `readGithubAutonomyPause` has only test callers. Historical `gate_state` readers use head/digest/time, not blockers. A synthetic readiness result can lose its `autonomy-paused` refusal; this does not authorize a landing. Do not alter tool permission, target/head pins, required checks, local claim/re-authorization, hosted landing checks, duplicate admission or reconciliation. No checked-in workflow or queue rule consumes the marker; out-of-repo automation was not audited. Stop implementation if a deployed merge check is found to depend on it.

**Failure and rollback.** Deploy one server cutover, without a backfill or feature flag. Revert the server release to recover the old API from the same rows. On rollback the old poller can reconcile retained markers that were closed in the interim; rejected PATCHes are not replayed.
