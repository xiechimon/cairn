# Cairn harness self-improvement — plan, 2026-11-28

## User scenario

A newcomer installs Cairn and asks its Coordinator to fix a bug. The Coordinator should clarify or dispatch as appropriate, a runner should do the work, and Cairn should return a verifiable result. The newcomer installs nothing extra, supplies no benchmark credentials, and never sees training traffic. Separately, the operator starts an experiment on the test host and opens a private scorecard: the last retained harness, what the proposed change improved or broke, what it cost, and why it was kept or discarded. A failed or stopped experiment leaves the current harness in place. Only the operator provisions an isolated model account; its credentials stay in the existing secret store or dedicated runtime home, outside the repository, scorecard and candidate workspace. No billing change or account fallback is implicit.

**Approval required before any implementation or paid run.** This plan answers the 2026-11-28 request to let AI repeatedly improve Cairn using an exam. The [research](../research/harness-self-improve-2026-11-28.md) explains the choices. The reported Devin run (12/20, 85m46s) is a legacy reference, not a Cairn baseline. Today the live coding cases bypass the Coordinator and runner; a prompt change there can score identically even if it breaks delivery.

6. **Report, qualification and stop.** Owner reads static HTML, mode `0600`, in an operator-only directory; no listener, upload or public link. Only a digest-bound reviewable export is produced, never a production change.

## Exam and keep rule

- **Separation.** The controller/driver and grader are human-maintained, pinned from the experiment's trusted merge-base, with a signed manifest for private fixtures outside the public repo. Both arms start fresh on the same case snapshot, fixtures, model revision/settings, timeout and budget. Block-randomize case and AB/BA order, pin seed where supported, record actual runtime/model, balance slots, and void on unplanned drift. Use the existing replays/canaries as non-regression checks, not as votes. `eval/compare.ts` stays unchanged: its ordinary merge verdict is not a significance test.
- **Trust boundary.** Only trusted control/grading processes see hidden tests, oracle patches, holdout IDs or the ledger. The model-facing sandbox gets one task prompt and a history-stripped workspace at a time; no other case, production data, credentials, host HOME mounts, shared writeable caches or arbitrary network. An isolated authenticated backend mediates only the approved model; fixture Git/host services replace external side effects. Snapshot artifacts are pinned and scrubbed; apply only the allowed submitted patch in an independent grader, never reuse the agent's tests or dependencies. Use fresh isolation even between arms; no holdout traces/transcripts or scores flow back to the proposer. Test confinement before spending model quota. No security/exploit tasks or live targets.
- **Editable surface.** Initially only validated Coordinator and runner prompt text, presentation/ordering of existing granted tools, existing context settings, bounded retry policy for existing recoverable outcomes, and routing preference among approved equivalent runners on the same pinned model. Deployment and tooling enforce capability, maximum budgets, classifications, tool permissions and eligibility independently. No application-source changes by the optimizer, no new executables, tools or permissions, no edit to `eval/**`, exam/scorers, optimizer/controller, tests, CI, dependencies, secrets, protocol, production settings or Git refs. Exact schema/field allowlist, bounded text/ranges, and defaults matching current behavior; rejected/identical diffs cost no worker starts. Broader code/tool mutations require a new plan.
- **Dev screen and decision.** Reuse the eight screened families; rotate precommitted stratified 24-pair confirmation draws from the other 52 across iterations, without claiming inter-iteration independence. Commit the schedule before search; stop the screen on a guard failure or nonpositive net gain. Never pool screen and confirmation, redraw, or change sample size. Feedback to the proposer is aggregate by capability, never case names, prompts, patches or transcripts; reject policy text tied to specific tasks or fixture identifiers. Each complete binary case votes once, passing only on matching delivery evidence and all trusted tests. `W` = candidate-only pass, `L` = baseline-only pass; retain only if `(W−L)/n ≥ 10` percentage points and one-sided exact McNemar `P(Binomial(W+L, 0.5) ≥ W) ≤ 0.05`. Ties contribute to `n`, not the binomial. Dev p-values guide adaptive search; only fresh holdout measures generalization. Before any search, use A/A discordance with uncertainty and a known-positive control to preregister power for the full screen + confirm decision under plausible paired win/loss scenarios. Require at least 80% power for the first campaign's **large** target effect (30 points); if not feasible in budget, stop at exam-only and propose a fresh profile. The 10-point practical floor is not a promise of power at 10 points.
- **Guard costs and user interruptions.** Categorize broken dispatch/delivery invariants, wrong route outside eligibility, permission errors or unintended side effects as critical; one critical regression vetoes retention. Fix the simulated user's answers before the run, from the problem statement alone, never from tests/oracle; cap clarification at one scripted answer per task and fail unexpected extra turns. Veto any increase in total owner interruptions, and any increase above 20% in cohort median arm wall time or total admitted starts; report p95 descriptively, and keep the hard deadline independent.
- **Held-out qualification.** Preregister the final retained policy digest, root baseline, fixed 40-pair list, guards and thresholds; apply the same gain/significance rule once, against the campaign root rather than a moving incumbent. No retest after an unfavorable or partially exposed exam; a new campaign asking for another qualification needs an independently sealed replacement holdout. Report `W`, `L`, denominator, paired effect and exact p-value; no gain/no clear result is not equivalence. At 40 pairs, four unopposed gains reach 10 points but give p = 0.0625; the plan deliberately rejects that result. Small improvements will often go unresolved. Bind the export to policy digest, Cairn SHA, exact model/runtime roster and exam digest. A newer `main` or different digest makes the result historical, not promotion evidence; any release proposal on new `main` needs fresh qualification on that head and a fresh sealed exam. A release may only target the tested model/backend; extending to other routes/models requires separate evidence and review.
- **Stop and resume.** A confirmed external outage, model drift, failed canary, isolation violation, quota or clock cap, or owner stop prevents a keep and kills owned work; candidate-caused timeout, invalid route or missing delivery is a failure, not an excluded pair. Missing/duplicate results and incomplete arms make the whole comparison inconclusive. Also stop after three successive non-keeps, eight proposals, 600 wall minutes, or 1,200 model-backed starts in dev, whichever comes first. Finalist and public jobs have separate hard reservations below. Do not retry a spent pair. Resume only at a safe checkpoint with the same hashes and remaining budget, never automatically on quota reset; abort interrupted iterations and charge reservations conservatively. Leak/canary failure stops the campaign pending operator investigation.

## Budget and audit

Planning limits, **not measured costs**. Prefer Doubao DeepSeek V4.1 Flash for both Coordinator and runner and for proposing. Require a real probe of the exact model on both supported paths; if unavailable, stop for an explicitly approved cheap alternative. GPT and Devin model-backed starts: **zero** in all candidate, qualification and public runs. Parallelism is at most four isolated single-arm slots on the mini, starting lower until the pilot proves capacity; never take production slots. Estimates assume four slots and four all-in minutes per arm (boot, Coordinator, runner, delivery and grader); this is a target, not observed. Prewarm only pinned artifacts. Deny admission when live service or the daily eval reservation needs capacity, ports are taken, or disk/CPU/memory limits are unsafe; release bench-owned slots on stop. Reap only experiment-owned resources validated against the lease and manifest; fail closed on unrecognised leftovers. The A/A pilot is a separately approved one-off capped at eight pairs, 30 minutes and 64 starts.

| Stage | Arm attempts (ceiling) | Approx. wall minutes / hard cap | Cheap model-start reservations (maximum) |
|---|---:|---:|---:|
| One proposal + screen | 16 | 16 plus overhead / 30 | 65 |
| Dev confirmation, only if screened in | 48 | 48 plus overhead / 70 | 192 |
| Full qualifying dev iteration | 64 | 64 plus overhead / 100 | 257 |
| Once per campaign: sealed qualification | 80 | 80 plus overhead / 120 | 320 |
| Once per campaign: public calibration | 16 | 16 plus overhead / 30 | 64 |

A reservation is a Cairn model-backed start, not a provider token or billing unit. The design budgets one proposer start and up to four starts per arm (including follow-ups and retries); the controller reserves before admission and charges work even when stopped. Report billed tokens or subscription units only if verifiably metered. Today Cairn's Doubao quota view reports activity, not remaining allowance. **No unattended paid search** until an isolated provider-side allowance or trusted metered backend enforces an operator-approved account spend ceiling independent of the candidate; a start counter alone cannot do that. Record actual setup/queue/arm time and available usage on the A/A pilot before approving the run profile. No payment, fallback, or automatic increase.

**State ownership.** Only the controller writes under an OS-backed host lock released on process exit. Iteration: `ready → proposed → screened → confirmed → kept`, or `discarded/aborted → ready` only if the campaign permits another distinct iteration. Campaign: `active → paused` on recoverable interruption, then `paused → active` only by explicit operator command after clearing the fault and verifying hashes, orphan cleanup and remaining budget; `active/paused → invalidated` on leak, bad canary or corrupt state, terminal for that campaign after quarantine. Any permitted stop at a safe checkpoint may freeze a valid retained finalist for `holdout-reserved → qualified/not-qualified/incomplete`, all terminal; never resume hidden grading. Reserve holdout use durably before the first hidden prompt; consume on possible exposure. Atomically commit decisions, budget accounting and retained/prior digest. The grader returns evidence; proposer and renderer have no ledger writes; the operator requests rollback through the controller under the same lock, without deleting history. Record run/candidate/parent/anchor and exam/toolchain digests, order, stage, counts, exact p-value, guard checks, runtime, usage source and terminal reason. Show holdout aggregates to the owner only, with no raw prompts, case-level holdout records, secrets or provider payloads in exported reports.
