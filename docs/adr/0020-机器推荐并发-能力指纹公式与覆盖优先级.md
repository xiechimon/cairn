# ADR 0020 · 机器推荐并发：能力指纹公式与覆盖优先级

> 状态：**推荐并发已裁决**（2026-10-12 用户口径，#1241 施工定案）。负载暂停**未裁决**，移出本次实现，见「负载暂停（后续票）」。取代 #1108 的固定默认 3 + 手填（maxConcurrent 不再只由写面决定）。#1108 的值域（1..16）、排队语义与 claim 闸不动。

## Problem Statement

机器并发上限曾是手填固定数（列默认 3，#1108）。它与机器真实承载无关：弱机过载，强机闲置。

用户口径（#1241 评论，2026-10-12，binding）：并发数是**推荐值**，不是强制值。daemon 上报机器能力，server 算推荐并发落在机器行上，可见可改。用户不改就用推荐值；用户改过以用户值为准并持久化。缺能力数据回退保守默认并标「估算」。**server 不得强制封顶。**

## 公式

输入来自 daemon 每拍现探的指纹（`machineHardwareSchema`，不缓存）：核数 `cpuCores`、可用内存 `memoryAvailableMb`（MiB）。

```
recommended = clamp( min(cpuCores, floor(memoryAvailableMb / (1024 * MEMORY_GB_PER_SLOT))), 1, 16 )
MEMORY_GB_PER_SLOT = 2
```

- 核数与内存各自作上界：每个并发槽按 2 GiB 可用内存计。
- 下沿 1：不给 0 槽（机器在线就能领一步）。上沿 16 = #1108 PATCH 写域的上沿，与 issue 口径「地板1 天花板16」一致。上沿是推荐值的夹取，不是覆盖用户值之后的第二道闸：用户值本身也只能在 1..16 内写入（#1108）。
- 来源标注：有合法指纹 = `measured`；无指纹、或指纹字段非法 = `estimate`，值为保守默认 `CONSERVATIVE_CONCURRENCY = 3`。

| 指纹 | 计算 | 结果 |
|---|---|---|
| 32 核 / 64 GiB 可用 | min(32, 32) = 32 → 夹 16 | 16 measured |
| 8 核 / 6 GiB 可用 | min(8, 3) = 3 | 3 measured |
| 2 核 / 2 GiB 可用 | min(2, 1) = 1 | 1 measured |
| 2 核 / 1.5 GiB 可用 | min(2, 0) = 0 → 夹 1 | 1 measured |
| 无指纹（老 daemon / 探测失败且无上一拍） | 保守默认 | 3 estimate |

## 覆盖优先级

| 状态 | `maxConcurrentOverridden` | 存储的 `maxConcurrent` | `concurrencySource` | claim 闸读的数 |
|---|---|---|---|---|
| 用户写过（PATCH 数字） | true | 用户值，心跳不改 | manual | 用户值 |
| 未覆盖，有指纹 | false | 最近一拍推荐值 | measured | 推荐值 |
| 未覆盖，无指纹 | false | 保守默认 3 | estimate | 3 |

- PATCH 数字 = 覆盖并持久。PATCH `null` = 清除覆盖，立即按当前指纹重算。
- 心跳缺 `hardware`（一次探测失败）沿用上一拍指纹，不把已测推荐打回估算。
- `recommendedConcurrent` 随行下发（覆盖时也发），用于「恢复推荐」面与依据显示。

## 存量迁移（0043）

`maxConcurrent` 的唯一用户写入面是 PATCH，列默认恒为 3（0031）。迁移回填 `maxConcurrentOverridden = 1 WHERE maxConcurrent <> 3`：非默认值视为用户写过并持久。恰为 3 的存量行无法与默认区分，按未覆盖处理（吃推荐值）。测试：`apps/server/test/machine-concurrency-backfill.test.ts`。

## 未决

- 恰为 3 的用户自设值在升级后会被推荐值接管（无法从存量区分）。若要严格保留，需要 PATCH 时记来源位，存量不可追溯。
- 推荐值随空闲内存实时变化，可能在相邻两拍之间抖动。当前不平滑，观察后再决定是否加滞回。
- 磁盘余量（`diskFreeMb`）已上报并展示为依据，但不进公式。
