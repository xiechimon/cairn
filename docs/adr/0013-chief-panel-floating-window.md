# ADR 0013 · Chief panel form = floating window (Multica-style, superseding ADR 0004)

> Status: **Decided** (2026-10-08; all thirteen grill questions converged, user settled each one).
> Supersedes: ADR 0004 (docked right rail, decided 2026-09-30) — ADR 0004's first reopen trigger "persist the open state" was hit, and its motivation source #447 (user feedback "the panel should not float") was reversed by the same user.
> Amendment (2026-10-21, #1428): in D2, "shadow aligned with Multica's `--floating-shadow` dual-theme values" no longer holds — `--floating-shadow` changed to the tier-e3 pool of the three-tier ladder in `tokens.css` (the chief window and dialogs share the tier; dark mode gets one extra `--top` top highlight), while the window's own `--edge-ring` is unchanged; the rest of D2's geometry (380×600, 8px corner offset, 12px radius, opaque card background) stands as decided.
> Geometry canon source: **Multica's "floating chat window"** (measured from source of `multica-ai/multica` main, 2026-10-08 shallow-clone direct read; wiki [[Multica floating chat window implementation facts]]). **Not** the todos original site's 418px inset card — the original-site geometry (0004 F1) is archaeological only, not canon.

## Problem Statement

ADR 0004 changed the chief panel from a floating card to a docked right rail, motivated by #447 user feedback "the panel should not float, it should dock inline" — an overlay covers content. The cost of docking was a whole yielding mechanism: content columns flex-narrowing (0004 D2), the detail route evicting the 488px right rail (D7), the board 280px guardrail + horizontal scroll (D8), plus five shell-level mount points and the detail FAB special position (F5).

Eight days later the same user reversed the ruling: **the yielding cost exceeds the covering cost, and the Multica form language should be aligned with**. The floating window returns as an overlay, but a non-modal one — it does not lock the page, does not grab focus, and does not disturb unless clicked; the covered content is digested via the bottom-right clearance yielding and ⌘J to close. The three yielding special cases, the five mount points, and the FAB special position retire with the form.

A concrete example (why the yielding cost is high): on the detail route, a 418px rail has nowhere to stand, so 0004 could only rule "evict the right rail slot (mutually exclusive)" — the user could have either the plan doc in the right rail or a conversation with the chief, one at a time; on the board, yielding pushed the four columns to the 281→280px floor + horizontal scroll, and the "my card disappeared" perception had to be explained by guardrails and scrollbar disclosure. The floating window eliminates all such structural special cases wholesale.

## Decision

| ID | Decision |
|---|---|
| **D1** | **Single form = floating window**: a non-modal floating card window, anchored to the content area's bottom-right corner. The docked right rail form is deleted; 0004 D2 (flex yielding), D6 (four-shell applicability), D7 (detail evicting the right rail), D8 (board 280 guardrail) **retire wholesale** — an overlay yields nothing. All five routes share one form, no route special cases. |
| **D2** | **Geometry and skin adopt Multica's original values wholesale** (F1): default 380×600; 8px from the content area's right/bottom edges; radius 12px; opaque card background, not glass, no blur; shadow aligned with Multica's `--floating-shadow` dual-theme values. No mixing with todos' 418 inset-card legacy values. Token-slot engineering is decided at construction (change the value of `--chief-shadow` vs a new token; the 12px radius does not use #983's retired-surface `--radius-popover`; the landing spot is booked with the A0 ticket). The containing block = the content area right of the sidebar, not covering the sidebar. No special form for narrow windows / mobile (Multica's <768px fullscreen panel is not copied; the existing detail-narrow discipline stands), separate ticket if ever needed. |

## Consequences

- **Positive**: the three yielding special cases (D2/D7/D8 of 0004) + 5 mount points + the detail FAB special position + the board inline special case retire wholesale — a net code deletion; the resident experience (draft/scroll/open state across pages and refreshes) is complete; the form language aligns with Multica; the "window grows out of the FAB" corner-anchored animation mental model holds.
- **Negative**: the covering cost returns — with the panel open, bottom-right content is covered (digested via clearance yielding + ⌘J close, but inherent); one Esc divergence (D3, on record); the FAB geometry family rule changes values, chief-fab.spec's 20 assertions + shell-consistency.spec's 27 assertions re-pinned; "closed = inert but in the DOM" is a new contract for e2e and a11y, wider than a pure-geometry change's re-pinning surface.
- **Relationship to the todos original site**: the original site's panel was already a floating card (0004 F1); this returns to the floating-overlay family but adopts geometry wholesale from Multica — the divergence count is unchanged (still the 3rd deliberate divergence; the object of divergence changes from "the overlay form" to "the original-site geometry values").
- **Relationship to the #980 map**: A0's probe re-pinning and A1's chat-primitive component mounting share the same fresh reconnaissance ledger (`probe:dump` re-run at kickoff; #913's old line-count ledger void rule stands).

## Reopen triggers
