# ADR 0017 · 双执行源：GitHub 真值 + localPath 同机加速位

> 状态：**已裁决**（2026-10-11，#1173 grill 五问定案）。讨论票 #1173，邻题 #1147（机器可丢地图），前序 ADR 0016（localPath 降级）。

## Problem Statement

pacman 的项目模型照 todos.dev：一个项目绑一个仓库，创建后不可改（无改绑定的入口）。2026-10-10 拓扑验证实撞：本机控制面的 pacman 项目是 localPath 形态，要验证「本机派发 → mea 执行」（远程机只能跑 githubRepo 形态），唯一路径是给同一个仓新建第二个项目——同一仓在看板上裂成两张皮。

问题是：把这个痛点读到哪一层？「一项目一仓不可改」的反面是 Multica 的「项目是容器、仓库是可挂多个的资源」，还是更窄的「同一仓的两种接入形态并存」？

## 侦察事实

| # | 事实 | 出处 |
|---|---|---|
| F1 | 实撞痛点是**同一仓**需要本地接入（localPath，同机直接用）与 GitHub 接入（githubRepo，远程机 clone）两条路并存；「一个项目聚合多个不同仓」在 pacman 使用中无实证需求 | #1173 票面实撞记录 |
| F2 | pacman 的项目页本身是仓库浏览器（文件树/提交历史/文件查看器），与单仓语义深度耦合；Multica **没有任何仓库浏览面**（三平台皆无，源码级负证），它的「资源挂载」是纯执行概念——两产品的项目语义不同构，照抄资源模型要额外付浏览面多资源化的钱 | codegraph 消费面扫描 + wiki《Multica 的仓库面物种》（main @ e0f84dd） |
| F3 | ADR 0016 已把 localPath 定性为单机器缓存形态——「githubRepo 为真值、localPath 为执行位」与之天然同向 | ADR 0016 决策 3 |
| F4 | 「local 形态真值 + GitHub 镜像位」需要本地提交向 GitHub 的推送同步（谁推、何时推、分叉怎么收），复杂度高一个量级，且痛点不需要它（仓本来就有 origin） | grill Q3 推理 |
| F5 | repoKind/localPath/githubRepo 消费面：daemon workspace 物化（镜像 clone）、github-issues 面、github-probe PR 探测、web 项目页/创建流/设置页、chief-tools | codegraph（isGithubRepoRef 10 调用点族） |

## Decision

1. **真问题钉为「同仓两源」，不迁多仓资源模型**（F1/F2）。「项目是容器、仓库是资源」是 Multica 形态借来的假设；pacman 无对应使用证据，且其项目页浏览语义与 Multica 不同构。
2. **双执行源**：`repoKind=github` 的项目允许加挂可选 `localPath`（同机执行加速位）；githubRepo 恒为真值源，localPath 只是执行面的本地读路径。无资源表、无浏览面改造、无既有行迁移（语义不变，只解禁组合）。
3. **真值单向**（F4）：提交先落 GitHub、机器拉取；不开「local 真值 + GitHub 镜像」方向（推送同步留给有实证需求的那天）。
4. **机器选源双条件判定**：`localPath` 存在且其 `.git` remote/HEAD 与项目 `githubRepo` 对得上 → 走本地（省 clone）；任一不符 → 静默回落 GitHub clone，不报错不卡步。防「不同机器同路径巧合误吸」。
5. **UI 最小面**：项目设置页加一个可清空的「本机加速路径」可选字段（仅 github 形态显示）；创建流、项目页、看板不动；「该步走的哪个源」不进 UI（调试看 daemon 日志）。
6. 若将来「真多仓」需求出现，双执行源扩成资源表是自然演进（执行位概念已存在），不是回滚——本裁决不堵路。

## Premortem（假设本裁决错了，三个最可能的死因）

1. 「同仓两源」判窄了，真需求其实是多仓（例如一个产品横跨前后端两仓联合作业）→ 护栏：决策 6 留了演进路；真需求出现时以使用证据 reopen #1173 形态的讨论。
2. 双条件对账的「remote/HEAD 对得上」判定写松了，陈旧本地路径被当成新真值读（本地落后 remote）→ 护栏：localPath 只是读路径，执行面仍走 daemon 镜像 clone + fetch 到远端 tip 再开工（既有 #352 面），加速位省的是传输不是新鲜度判定。
3. localPath 字段复用引发语义混淆（ADR 0016 的「单机器缓存」标注与 0017 的「加速位」并存读岔）→ 护栏：0016 加指针到本文；CONTEXT.md「仓库」词条随施工票同步修订。

## 与 ADR 0016 的关系

0016 裁决 localPath 降级为单机器缓存形态（「机器损坏，进度随机器走」）。0017 不推翻它：localPath 仍是单机器位、不承载真值；0017 只是允许 github 形态项目额外登记这个位作执行加速。可丢性归属不变——真值与可丢性只属于 githubRepo。
