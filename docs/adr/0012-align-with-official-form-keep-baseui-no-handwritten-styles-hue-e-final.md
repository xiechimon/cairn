## Problem Statement

ADR 0010 made "free geometry redesign" (D2) and "C · paper-orchid finalized" (D1) the canon of the site-wide UI overhaul, spec/22 the only value source, and #908 constructed under it and was closed (#953). But two rounds of audit after the overhaul show the canon chain grew systematic drift on the component-carrying surface: of the 16 registry-sourced components, 11 have substantive drift — checkbox / select fully handwritten, input / textarea square corners, button holding its own focus-ring outline form + brand tier, tabs with handwritten segmented / bare skin tiers (#982); plus 8 local handwritten shells / adapters accumulated in `components/ui/` (panel, dialog-shell, floating-shell, alert-dialog-shell, seeded-avatar, status-chip, tag-chip, kbd-hint, #983). In practice, the "free geometry redesign" authorization precipitated local deviations into new debt — the "old face on a new skeleton" problem of structure-only migration was solved, and what came in exchange was "the official form covered by local skins".

The user's nine rulings on 2026-10-07 (canonical record = #980 Notes) reset the destination: `components/ui/` may only hold registry-sourced components + zero-skin adapter layers; geometry takes the registry default as canon, and user-side decisions take effect only through the token layer; Base UI (base-nova) is kept, no switch to Radix; the hue is re-selected once (paper-orchid demoted to historical reference), with full parallel prototypes live-reviewed for finalization; the handwritten ban lands as a mechanical CI gate. This ADR is the booking point of those rulings: ADR 0010's D1 value canon / D2 component-level geometry authorization are partially voided accordingly, and the corresponding sections of spec/22 are marked superseded-in-part.

All three ADR conditions are met: **hard to reverse** = the site-wide geometry canon re-anchors (official 61-component baseline surface, 369 lines of e2e geometry review surface, 671 class-name locators moving with it) + 143 word-level color slots re-flipped; **surprising without context** = spec/22 was still "the only value source for per-domain construction tickets" last week and ADR 0010 still says "Decided and in effect", while the component-level geometry canon has already re-anchored wholesale; **a real trade-off** = free geometry redesign vs official-form alignment, Base UI vs Radix, and the E / D / F candidate palettes live-reviewed.

## Terminology

The canonical definitions of three terms land with this ADR (the write-up point for the wording used in ruling ② of the #980 Notes):

- **Registry-sourced component**: a file under `components/ui/` that is token-for-token equivalent to the shadcn upstream base-nova registry source — equivalence proven mechanically by CI (list + hash ledger + vendored upstream snapshots, #985 / #989); the only allowed adaptations are the repo lint trio (`import type * as React`, `.js` extensions, `'use client'`). When upstream evolves, a refresh script re-pulls on demand, and refreshing restores sameness.
- **Zero-skin adapter layer**: a local file under `components/ui/` that composes registry components and carries **only semantic mapping** — state carriers (`data-tone` / `data-variant`), API reshaping (e.g. controlled props to pass-through), named-behavior-reason defaults (e.g. `type='button'` against implicit submit). The criteria are three negative tests: no accompanying CSS, no arbitrary color classes, no skin tiers beyond the official variant set. Of the eight handwritten shells, the four judged "rewrite" (dialog-shell / seeded-avatar / status-chip / tag-chip) end in exactly this form.
- **Official form (registry default geometry)**: the full set of geometry and skin defaults carried by the upstream base-nova component source (size tiers, radius tiers, focus-ring forms, variant sets). It is the sole canon for component-level geometry; repo-side freedom exists only in the token layer (`--radius` base value, color-slot values) and consumer-side className composition, never inside component files.

## Alternatives considered and rejection reasons

| Alternative | Rejection reason |
|---|---|
| **Switch to Radix** (shadcn's default underlying library) | Rejected by user ruling ③. The slot architecture of #787 / #813 is built on Base UI and has survived two flips; switching libraries means a third site-wide re-pinning, while the two underlying libraries have no substantive capability difference on this repo's consumption surface |
| **Keep free geometry redesign** (ADR 0010 D2 as-is) | Disproven as sustainable by the #982 audit: under the free authorization, 11 of 16 sourced components drifted, drift has no mechanical interception means, and spec/22 must maintain an override registry for every deviation; the official form is a hash-provable anchor, and after the free redesign's payoff surface (the token layer) is kept, nothing is lost |
| **Keep the handwritten-component registered whitelist** | A whitelist can only prove "it is in the list", not "it is equivalent to upstream"; the CI gate's mechanical criteria (hash + vendored snapshots) only hold for registry sourcing — handwritten components always need human review, and after #985 measured and rejected the live-diff form, this is the only path that can be mechanized with zero network |
| **Keep hue C · paper-orchid without re-selection** | User ruling ⑤ explicitly requires re-selection (paper-orchid was the finalization of the "free geometry" era; the warm-paper skeleton and layered soft-shadow language are bound to the old form); after #988's three-candidate live review, E won, and E passes all gates under the official radius base + registry component forms |
| **Keep the 0.875rem repo-held radius base** | Rejected by #988's second live-review answer: the user picked the official 0.625rem over the repo-held tier — the radius base belongs to token-layer freedom (D1), and the exercise of that freedom results in returning to the official default |
