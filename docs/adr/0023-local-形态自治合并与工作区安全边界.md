# ADR 0023 · local 形态自治合并与工作区安全边界

> 状态：**已裁决**（2026-10-24，ian 定原则「一个总管，代码必过闸，开不开 PR 只是代码落地方式」）。票 #1625。修订 ADR 0021 的适用范围（扩到 local 项目）与 #1211 的口径，不改变 ADR 0021 的 D4 判法。

## 决策

local 项目与 GitHub 项目一样支持 `mergePolicy = human | shadow | autonomous`，缺省为 `human`。human 的既有行为保持不变。

自治合并仍先经过 ADR 0021 的合并就绪闸与 D4 判法。local 的补丁摘要由仓库所在机器执行 `git diff <base>...<head>` 得出，摘要元组、证据目录排除规则和重算要求与 GitHub 版一致。合并前重新读取默认分支头；它与判定时的 base 不一致，或重算摘要不一致，均重新求值。

自治执行者是仓库所在机器的 daemon。server 下发合并指令并记录结果；daemon 以 squash 方式生成一个合并提交。项目配置的本机检查命令全部通过后，才可进入自治合并。

## #1211 安全边界

- 用户主检出位于默认分支且工作区干净时，daemon 才能把默认分支推进到 squash 提交。
- 用户检出在其它分支时，只更新默认分支 ref，不触碰用户工作区。
- 用户工作区有未提交改动，或检出在默认分支但工作区不干净时，合并挂起并通知用户，不修改工作区。
- 无法确认当前检出分支时，合并挂起并通知用户。

## 与 ADR 0021 的关系

D4 保护类别与可自动合并集原样复用。local 只是把 D2 的执行位置从 server 的 GitHub REST 端口换成仓库所在机器的 daemon；判定不另起一套。ADR 0021 的 human 默认值与 #1211 的用户主检出安全边界继续适用。
