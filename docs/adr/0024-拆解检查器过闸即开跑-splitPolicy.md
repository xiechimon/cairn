# ADR 0024 · 拆解检查器过闸即开跑：项目级 splitPolicy

> 状态：**已裁决**（2026-10-24，ian 定原则「一个总管，代码必过闸」）。票 #1623。修订 ADR 0018 层 2。
>
> ADR 0018 正文不改：`splitPolicy = human`（默认）时，ADR 0018 层 2「拆解方案进 confirm 关口给人审」原样有效。本 ADR 只改变 `shadow` 与 `auto` 两档下的行为。

## Problem Statement

ADR 0018 层 2 规定 chief 的 `split_todo` 拆完大票后，拆解方案一律停在父卡 confirm 关口等人确认。拆太碎的护栏也压在这一关上（ADR 0018 Premortem 3：人可以驳回整棵拆解树）。

结果是小而清楚的拆解也要人点一下。这与 spec 28「人从逐步审批变成事后抽查」的方向相反，也与 ian 2026-10-24 定的原则不符：一个总管负责编排，能用代码判的事交给代码闸，不交给人工逐张确认。

问题拆成三个子题：

1. 哪些拆解可以不经人直接开跑，判据由谁出？
2. 原来压在人审上的「拆太碎」护栏，改由什么承担？
3. 怎么上线才不改掉现有默认，并留出观察期？

## Decision

### 1 · 层 2 改为「拆解检查器拦下的才进 confirm 人审」

`split_todo` 落库子卡后，由纯代码的拆解检查器判这份拆解方案。检查器不调模型，输入是 `split_todo` 的子卡数组和团队 agent 与其归属机器的快照。任一项不过即回落人审，并写明原因：

- 依赖边：`blockedBy` 序号都在 1..N 范围内、不自指、整张图无环；
- agent：每张子卡的 `agentId` 存在、状态可用、有归属机器且在线；归属机启用了该 agent 所需的 runtime，并满足 `requiredCapabilities`（复用 ADR 0018 决策 4 与 ADR 0020 的机器能力闸判定，判据单源在 `dispatch-eligibility`）；
- 子卡数不超过项目上限（默认 6）；
- 子卡 spec 未点名 ADR 0021 D4 保护类别路径。判法复用 D4 的保护类别匹配，方向保守：命中或判不清（路径含非安全字符）都回落人审。

检查器全过时，按项目的 `splitPolicy` 决定是否开跑（见决策 3）。

### 2 · 拆太碎的护栏改由子卡数上限承担

ADR 0018 Premortem 3 的死因（chief 拆得太碎，协调开销吃掉并行收益）原来由人审关口兜底。`auto` 档下这道人审不再必经，护栏改由检查器的子卡数上限承担：超过上限的拆解回落人审，由人决定是驳回还是放行。ADR 0018 的拆解判据（决策矩阵：单视角单 artifact 直调，不拆）与「子全 done 父自动收」不变。

### 3 · 项目级 `splitPolicy = human | shadow | auto`，默认 `human`

- `human`（默认）：不跑自动开跑分支，拆解照旧停在父卡 confirm 关口，行为与 ADR 0018 层 2 一致；
- `shadow`：检查器照算，只记录「若自动会不会开跑」，拆解照旧停在 confirm 关口。用于上线前观察检查器的判定是否可信；
- `auto`：检查器全过即视同确认：父卡进 building，派发无阻塞子卡；有阻塞的子卡沿用既有波次推进，在前置子卡 done 后自动起跑。检查器不过则回落人审，停在 confirm 关口。

默认值留在 `human`，存量项目与新建项目在未显式切换前行为不变。

### 4 · 团队级 `autonomyPaused` 凌驾

团队级急停 `team.autonomyPaused` 为真时，`auto` 档同样回落人审，原因写「团队自治已暂停」。急停凌驾项目策略，与 ADR 0021 自治合并的急停同一方向：人随时能把整个团队拉回人审。

### 5 · 父卡 transcript 留痕

每次拆解在父卡会话写一条检查器结果，供事后抽查：

- `检查器结果：已自动开跑`（`auto` 且全过）；
- `检查器结果：若自动会开跑（shadow）`（`shadow` 且全过）；
- `检查器结果：回落人审 + <原因>`（检查器不过、团队急停，或策略为 `human`）。

## Premortem（假设本裁决错了，最可能的死因）

1. **检查器放行了不该放行的拆解**：子卡 spec 用自然语言描述要改 CI 或迁移，没写出路径，D4 判法匹配不到。护栏：`shadow` 档先观察；D4 自治合并闸在合并时按真实 diff 再判一次，拆解放行不等于合并放行。
2. **机器快照过期**：检查时机器在线，派发后掉线。护栏：子卡步照常走 claim 闸，掉线时步留 pending 并给可见原因（ADR 0018 决策 4.4），不会因检查器放行而跳过派发闸。
3. **上限设得不对**：默认 6 对某些项目偏紧或偏松。护栏：超限只回落人审，不拒绝拆解；上限按项目取值，首版实现所有项目取默认 6，需要调整时再补项目级设置。

## 与其它 ADR 的关系

- **ADR 0018**：本 ADR 修订其层 2 与 Premortem 3 的护栏归属；名册、层 1、层 3、协调模型不变。
- **ADR 0020**：检查器的能力判定复用其机器能力闸，不另起判据。
- **ADR 0021**：检查器复用 D4 保护类别判法；改 ADR 属 D4 保护类别，本 ADR 的 PR 留人合并。
