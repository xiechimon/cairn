# ADR 0015 · 验证证据留存仓内：存量不可搬，外迁只决策增量

> Status: **superseded** by [ADR 0022](0022-prune-merged-evidence-weekly.md) (2026-10-25). Decided 2026-10-10 from measurements; ticket #1123.
> Trigger: a metrics review proposed moving `docs/verify/` (178M, most of the 264M `.git`) to release assets, Git LFS or a separate evidence repository.

## Problem Statement

体检看到 .git 264M 就提出外迁证据目录。真问题有两个，都要先量化再答：① clone / CI checkout 实测疼不疼？② 外迁能不能省下声称的体积？

## 侦察事实

| # | 事实 | 出处 |
|---|---|---|
| F1 | 全量 clone（`--no-checkout`）**37s**，.git 落盘 209M | 2026-10-10 本机实测（/tmp 双 clone 对照） |
| F2 | `--filter=blob:none` 部分 clone **3s**，.git 3.6M | 同上 |
| F3 | CI `actions/checkout` 步稳定 **~9s**（15 个近期成功 run 逐步采样） | `gh api actions/runs`，2026-10-10 |
| F4 | 已合 PR body 嵌的是**钉 SHA 的 raw 永久链**，每条链依赖对应 blob 永存对象库。新提交删除 `docs/verify/` 不省任何体积（历史照留）；唯一真缩法 = history rewrite = 一次性打断所有已合 PR 的证据链 | git 对象模型；pr-evidence 闸判据（#905/#939/#940，PR #1015） |
| F5 | 外迁到 LFS / release assets 会同时改动交付面与闸的探活判据（raw 响应形态不同），属改判据级变更，要重走 #939/#940 的「先量后改」全流程 | 同上 |
| F6 | 多 lane 的 `git worktree add` 不重新下载——共享本地对象库，是本地操作；37s 是网络面 clone 的上限，不是日常 lane 成本 | git worktree 机制 |

## Decision

**不外迁。** 验证证据继续随 PR 进 `docs/verify/<票号>/`，PR body 继续用钉 SHA 的 raw 永久链。`docs/README.md` 已把该目录标为「只增不改、不外迁」。

- **增量侧**：证据以「够核收」为度，不设硬张数闸；臃肿由 PR 评审把关。
- **逃生舱**（写给未来觉得仓大的人）：CI 与本地均可上 `--filter=blob:none`（F2：3s / 3.6M），这是不动交付面、不动闸的解法。
- **重开判据**（数值化，防下次体检凭指标复读提案）：CI checkout 步 >60s，或全量 clone >3min，或 .git >1G。任一实测命中才重开；重开时第一候选仍是 partial clone，不是外迁。
- `docs/research/`（36M，文本为主）不在本裁决范围；若将来要瘦身，单独立案评估。

## Premortem（假设本裁决错了，三个最可能的死因）

1. 证据按当前速率再长一年，.git 破 1G，clone 真疼 → 护栏 = 上面的数值重开判据 + blob:none 逃生舱已写进文档。
2. GitHub 变更 raw 大文件 / 仓容政策 → 护栏 = pr-evidence 闸逐条探活，政策一变闸先红，信号即时。
3. 「不外迁」被误读成「随便堆」→ 护栏 = 增量侧由 PR 评审把关，README 写明只增不改的理由。
