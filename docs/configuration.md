# Configuration

Server environment variables (all optional):

| Variable | Default | Description |
|---|---|---|
| `CAIRN_TOKEN` | generated on first start | Owner bearer for this machine's CLI and for issuing pairing codes. Unset, the server reads `<CAIRN_HOME>/token` and, on a loopback bind with no file, generates a random token there (mode 0600) and keeps it across restarts; `cairn token` prints it and `cairn token --rotate` replaces it. A browser on a Linux server machine uses a loopback bootstrap session. macOS, Windows and `CAIRN_REQUIRE_TOKEN=1` have no loopback peer proof; mint the first pairing code with the owner token against `POST /api/remote/pairing`. Another device uses a one-time pairing code. SSE uses a short `?ticket=`, not this token. A non-loopback `HOST` never generates a token: set this variable or create the token file first, or the server refuses to start. |
| `CAIRN_AUTH` | unset | `off` disables token auth entirely and is accepted only on a loopback `HOST` (the server refuses to start otherwise, and with `CAIRN_REQUIRE_TOKEN`); it logs a startup warning because every local process and every web page open in a local browser can then call the API. Any other value fails startup. |
| `CAIRN_TAILSCALE_USERS` | unset | Ignored. Tailscale is only a route. A set value logs a startup warning and does not grant access. Sign in with a pairing code. |
| `CAIRN_REQUIRE_TOKEN` | unset (the Docker image sets `1`) | `1`, `true` or `yes`: refuse to start (log the reason, exit 1) when `CAIRN_TOKEN` is unset or empty, and never generate a token file. |
| `CAIRN_TSNET` | unset (off) | `1`, `true` or `yes` starts the embedded Tailscale sidecar (`apps/tsnet-sidecar`) and a private Unix socket listener the sidecar proxies tailnet traffic to. Off by default: no process is spawned and no listener is opened. The sidecar logs in with the owner's own Tailscale account (login URL in the server log); its state lives in `<CAIRN_HOME>/tsnet/state` (mode 0700). The access token is still required on every tailnet request, so tailnet access refuses to start under `CAIRN_AUTH=off`. |
| `CAIRN_TSNET_BINARY` | `<CAIRN_HOME>/bin/tsnet-sidecar` | Path to the sidecar binary. A missing or non-executable file logs an error and leaves the server running without tailnet access. |
| `CAIRN_TSNET_HOSTNAME` | `cairn` | Node name on the tailnet. |
| `CAIRN_TSNET_CONTROL_URL` | unset (Tailscale) | Coordination server URL for a self-hosted control plane. |
| `CAIRN_TSNET_UPLOAD_LOGS` | unset (off) | `1`, `true` or `yes` lets the node upload its operational logs to Tailscale (`log.tailscale.com`). Off by default: the sidecar runs with `TS_NO_LOGS_NO_SUPPORT=true`. |
| `PORT` | `8787` | HTTP listen port. |
| `HOST` | `127.0.0.1` | HTTP bind address. For split deployment (server on an always-on host, daemon on another machine pointing `CAIRN_SERVER` at it), set this to that host's LAN address (or `0.0.0.0`) and set `CAIRN_TOKEN` alongside; a non-loopback `HOST` without a token refuses to start. |
| `CAIRN_HOME` | `~/.cairn` | Data root. Server state lives under `<CAIRN_HOME>/server/` (`server.db`, `secretbox.key`, `vapid.json`, hosted bare repos); the daemon keeps `machine.json`, `daemon.log`, and `workspaces/` at the root. **Backup = copy the whole directory** — the db alone is useless without the keyfile, since secrets are stored encrypted. |
| `CAIRN_VAPID_SUBJECT` | `mailto:push@cairn.dev` | Contact subject used for Web Push VAPID authentication. Set an HTTPS contact URL or a `mailto:` address for your deployment; the VAPID key pair is generated on first server start and stored in `<CAIRN_HOME>/server/vapid.json`. |
| `CAIRN_WEB_ORIGIN` | `https://cairn.local` | Public HTTPS origin used for push navigation, for example `https://cairn.example`. Set this to the address used by your phone; paths, credentials, queries and fragments are rejected. |
| `CAIRN_CLOUD_URL` | `https://cairn-cloud-portal.fly.dev` in Mac Desktop; unset in standalone server | HTTPS origin of the Cairn Cloud control plane used by the sidebar account popover for sign-in, subscription checkout, and billing portal links (`off` disables it cleanly). Paths, credentials, queries, fragments, and non-loopback `http://` URLs are rejected. |
| `CAIRN_APNS_KEY_PATH`<br>`CAIRN_APNS_KEY_ID`<br>`CAIRN_APNS_TEAM_ID`<br>`CAIRN_APNS_BUNDLE_ID` | unset; bundle `dev.cairn.ios` | Apple Push Notification service for the native iOS app (`apps/ios`). Point `CAIRN_APNS_KEY_PATH` at the `.p8` auth key from Certificates, Identifiers & Profiles → Keys (Apple Push Notifications service enabled), and set its 10-character key ID and your Apple Developer team ID. Set all three or none: the server refuses to start on a partial set. Unset, the app can still register its device but nothing is sent to it. The bundle ID must match the app you sign. APNs uses the same triggers, digest and thread-presence suppression as Web Push. |
| `CAIRN_PUSH_DIGEST_TIMES` | `09:00,18:00` | Exactly two distinct server-local times for the twice-daily Web Push digest (comma-separated `HH:MM`). Everything that does not need a human decision — merged, failed, done, plan-ready, build-review — is batched into this digest instead of an immediate push; only decisions (chief questions) push immediately. |
| `CAIRN_GITHUB_APP_SLUG`<br>`CAIRN_GITHUB_APP_BOT_ID` | unset | The GitHub App whose bot user authors the commits cairn makes: the App's slug and its bot user's numeric id (`gh api /users/<slug>%5Bbot%5D --jq .id`, not the App ID). Commits are then authored `<slug>[bot] <<id>+<slug>[bot]@users.noreply.github.com>` whether or not an installation token is available. Unset, cairn commits as `<name> <cairn@localhost>` and agent commits keep their author. Set both or neither; `CAIRN_APP_TOKEN_SOCKET` requires them, and the server refuses to start otherwise. |
| `CAIRN_GITHUB_OAUTH_CLIENT_ID`<br>`CAIRN_GITHUB_OAUTH_CLIENT_SECRET` | unset | Credentials of a self-registered GitHub OAuth App, enabling OAuth provider sign-in. Set both or neither — the server refuses to start on a half-configured pair. |
| `CAIRN_WEB_DIR` | `apps/web/dist` if present | Override for the SPA static-hosting root; unset with no build output = API-only mode. |
| `CAIRN_SKILLS_DIR` | `$CAIRN_HOME/skills` | Skills root. Each immediate subdirectory containing a `SKILL.md` is one skill (id = its frontmatter `name`, falling back to the directory name). Scanned live on every request — skills are never stored in the database; add a skill with Import or New, or by dropping a folder in. Cairn never writes into `~/.agents/skills` or `~/.claude/skills`, which other agent tools share: a server upgraded from an install that used `~/.agents/skills` copies those skills here once on its first start, and writes are refused when this variable points into either directory. |
| `CAIRN_LITESTREAM_BUCKET` | unset (off) | Container only. Set to an S3-compatible bucket name to enable continuous SQLite WAL replication and automatic `server.db` restore on an empty `/data/server` volume using standard `LITESTREAM_ACCESS_KEY_ID` / `LITESTREAM_SECRET_ACCESS_KEY` credentials. Leave unset to execute `node dist/index.mjs` directly with zero overhead. Keep `secretbox.key` backed up separately (volume snapshot or whole-account export). |
| `CAIRN_LITESTREAM_PATH` | `server.db` | Container only. Relative replica key prefix inside `CAIRN_LITESTREAM_BUCKET` (rejects leading slashes, `..` segments, and control characters). |
| `CAIRN_LITESTREAM_ENDPOINT` | unset (AWS S3) | Container only. S3-compatible endpoint URL (e.g. Cloudflare R2, Fly Tigris, MinIO); enables `force-path-style` when set. |
| `CAIRN_LITESTREAM_REGION` | unset (`auto` when endpoint is set) | Container only. S3 region name passed to Litestream. |

Web Push requires HTTPS and notification permission. On iOS, install the site on the home screen before enabling device push in account settings. Back up `vapid.json` with the database, and keep the APNs `.p8` key outside the repository with `600` permissions. To rotate VAPID keys, stop the server, remove `vapid.json`, restart, and disable then re-enable device push in every subscribed browser; subscriptions are bound to the original public key.

Daemon environment variables (alternatives to the CLI flags above): `CAIRN_SERVER` (default `http://127.0.0.1:8787`), `CAIRN_API_KEY`, `CAIRN_TEAM`, `CAIRN_WORKSPACES_DIR` (default `<CAIRN_HOME>/workspaces`). On a Mac, `CAIRN_AGENT_BROWSER` is the path of the `agent-browser` binary that runs the Coordinator's browser; the desktop app sets it for its own Runner, and a Runner without it reports no browser of its own.
