# Error ledger

Things that went wrong during the work and were later fixed, one row per category. Rules: every row must have a protection, and the protection takes the highest feasible level on the ladder below; anything that can be made into a machine check must not stop at prose. Design basis: the `过程错误复盘机制` (process-error retro mechanism) plan confirmed by ian on 2026-10-22.

## Ladder

1. Architecture or types make it unwritable
2. lint, script gates, tests, CI checks
3. Rules in AGENTS.md or prompts
4. Skills
5. Memory (only works within a Claude thread, softest)

## How to write

- One row per error category; merge same-kind rows, do not open duplicate rows.
- A new gate must use the real mistake as a negative control: the old error going red under the new gate is what counts as landed.
- "Intercepted" records how many times the protection actually caught it; "Recurred" records how many times the same category of error appeared again. A recurrence greater than 0 means this layer is not hard enough; raise one level.
- For what cannot be made into a machine check, write the reason in "Notes".
