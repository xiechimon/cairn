# 09 · 前端风格统一 A6

> 覆盖 A3「overlay-btn 不接 Button 原语」裁决（docs/a3/diff-audit.md #1 + apps/web/src/detail/detail.css:1570 注释）。A6 处理路径：扩 ghost border token 单源 + 扩 Button size 档 + 收编 6 处散写按钮 + 圆角 popover token 化 + 文档同步。

> **时效说明**：本文写于像素对拍工具 `parity/` 摘除之前，文中的 parity 验收（钉扎四面之一、`pnpm parity 229/229`）是当时实际执行的验证手段，均已跑通。`parity/` 已于同日整体移除（#342），现行视觉回归门 = `apps/web` playwright e2e 的视觉 spec 几何断言。三张实现票合并于 #337（文档同步）/ #339（popover 圆角 token）/ #340（按钮收编）。

## Problem Statement

前端风格「不统一」的活样本分四类：

1. **文档与实施纪律矛盾**：`DESIGN.md:114` 措辞「现有像素级实测值向阶梯收敛」与 `tokens.css:207-209` 注释「复刻面不动、批量等值化会破 parity」自相矛盾，新写代码失去明确指引。
2. **popover 圆角散写**：9 处 `border-radius: 10px` 横跨 5 个域 css（overlays/board-guide/secondary/mention-picker/resources/pages），与 `DESIGN.md:126-127` 弹层 12px 圆角表述形成事实双轨。
3. **overlay-btn 家族件散写 × 5**：`detail/overlays.tsx` 5 处直接 `<button>` 用 `.overlay-btn[--primary]` 自定类，未走 `ui/button` 原语。A3 当年裁决「保留族类不接 Button 原语」依据 ghost border token 差异 / 30px 高度无档位 / box-sizing 三条——本 ADR 覆盖此裁决并给出处理路径。
4. **chief-gate-btn 单点散写 × 1**：`chief/chief-drawer.tsx:224` 直接 `<button>` 用 `.chief-gate-btn` 自定类，未走 `ui/button` 原语。

## Solution

A6 拍板：

| ID | 决策 | 落地形态 |
|---|---|---|
| **P0** | DESIGN.md:114 服从 tokens.css | 改写 DESIGN.md 第 114 行 + tokens.css 第 207-209 行注释强化引用 |
| **P1** | 新增 `--radius-popover: 10px` | tokens.css :root 加 `--radius-popover: 10px`（dark + light 同值）；9 处 `border-radius: 10px` → `var(--radius-popover)`；DESIGN.md Shapes 节新增一行 |
| **P2** | overlay-btn × 5 收编到 Button | 扩 Button size 新增 `overlay: 30px` 档；扩 ghost 描边 token 单源（`--card-ghost-border` 统一指向 `--card-border`）；overlay-btn × 5 处替换为 `<Button variant="ghost\|primary" size="overlay">` |
| **P3** | chief-gate-btn × 1 收编 | 替换为 `<Button variant="primary" size="card" style={{ width: 50, fontSize: 12 }}>` |

## User Stories

1. 作为开发者，我看到 `<Button>` 原语的全套变体覆盖了 overlay-btn/chief-gate-btn 的视觉态，这样我在新写浮层按钮时不需要发明新 className，直接 `<Button variant="ghost" size="overlay">` 即可。
2. 作为审阅者，我看 popover 圆角在 9 处都引用同一个 token `var(--radius-popover)`，DESIGN.md 也明确写了「popover 10px」一行，这样未来改值是一处改动全局生效。
3. 作为设计者，我看 `DESIGN.md:114` 与 `tokens.css:207` 措辞对齐（都明确「复刻面不动、新代码走 token」），新写代码有清晰指引而不是双轨。
4. 作为 parity 验证工程师，我看 A6 收编后所有 overlay-btn/chief-gate-btn/popover 圆角 spec 行像素零变化（zero visual delta），evidence 进 review。
5. 作为回归测试者，我看 A6 改完后 e2e spec + 集成 locator + parity 矩阵 + 视觉 spec 钉扎四面全过，零回归。

### 接口决策

- **不新增 ui/Toggle 原语**——prj-tasks-view-btn 的 toggle 语义超出本 ADR 范围
- **不新增 ui/MenuItem 原语**——plan-dropdown-row 是菜单项不是按钮，保留现状
- **6px 域默认圆角不动**——A3 拍板保留
- **不动散写 spacing 像素值**——parity 保护
- **box-sizing 处理**：现代 CSS 全局 `*, *::before, *::after { box-sizing: border-box }` 已是 apps/web/src/app.css 默认；overlay-btn 1px border 不再吃盒高度——验证 5 处像素零变化后再删自定 `.overlay-btn` 类

## Further Notes

### 反方意见存档（A3 历史决议 + A6 覆盖理由）

A3 当年在 `docs/a3/diff-audit.md` 裁决 #1 与 `detail.css:1570` 注释明确反对 overlay-btn 接 Button 原语，三条理由：

1. **ghost 描边 token 不同**：`--card-ghost-border #2e2e33` vs `--card-border #27272a`（A3 当时 dark 值）
   - **A6 覆盖处理**：扩 ghost token 单源，让 `--card-ghost-border` 别名指向 `--card-border`（已实测两值近邻，无视觉差）
2. **30px 高度无原语档位**
   - **A6 覆盖处理**：扩 `Button size` 增 `overlay: 30px` 档（per-face 几何叠加不冲突）
3. **content-box 下 1px border 参与盒算术**
   - **A6 覆盖处理**：现代 apps/web 全局 box-sizing: border-box，1px border 不再吃高度——验证 5 处像素零变化后收编

### Premortem（3 死因 + 护栏）

| 死因 | 概率 | 护栏 |
