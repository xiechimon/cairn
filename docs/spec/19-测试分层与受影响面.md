# 19 · 测试分层职责与受影响面（#693）

> 范围：确立四层测试各自的运行职责——开发期本地**不再跑全量 e2e**，改动只跑**受影响面**；全量 e2e 的执行点收敛到 **CI（4 分片）**。含基线量测（2026-10-03，本机 8 核 / 16GB）、受影响面选择机制（`e2e:affected`）、vitest `related` / `--changed` 可用性核验、pi 式廉价结构闸的对照评估（**只评估 + 提议，本票不落地**）。参考实现 = `~/Code/AgentProjects/pi`（599 个 .ts 测试基本是包级 unit/integration，浏览器层只留一个 esbuild 打包冒烟）。

## Problem Statement

1. **最贵层的重复劳动。** 本地全量 e2e 实测 154.3s / 617 用例（见下），CI 本来就跑同一套（223s/步）。开发期在本地跑全量 = 用最贵的方式重复 CI 的活；16GB 本机在多 lane 并行时（压缩器 4.45GB + swap 3.89GB 的真实压力），全量 e2e 的 +44 进程 / +3.4GB 峰值正是压垮点之一。
2. **没有受影响面选择。** 改了 chief 抽屉，只能全跑 83 个 spec，或凭感觉手挑几个——手挑没有机制保底，漏跑读作假绿。
3. **旧口径失真。** 「`apps/web` e2e 完整跑要 1h+」是错的（实测 154s），失真的成本认知让「跑不跑全量」的讨论失焦。

## 基线（2026-10-03 实测，量过一次即封存）

量测环境：本 worktree、pnpm 冷装后、无并发 e2e。e2e 的进程/内存 = 1s 采样器对系统 node/vite/chromium/playwright 家族全程采样，取「跑中峰值 − 跑前水位」。

| 层 | 墙钟 | 规模 | 内存 / 进程贡献 |
|---|---|---|---|
| web e2e 全量（fixture build + preview + playwright） | **154.3s** | 617 用例 / 83 spec 全过 | **+3.38GB / +44 进程**（水位 94 进程 / 3.02GB → 峰值 138 / 6.40GB） |
| vitest light（全部包的 colocated 单测） | 40.1s | — | 单进程 336MB |
| vitest integration（真 server + daemon + Chromium） | 124.1s | 58 用例 / 19 文件 | 采样峰值 +2.3GB / +28 进程 |
| verify-pacman live 探针 | 不量 | — | 票级验收探针，不在开发循环里（见职责表） |

CI 侧（绿 run 37098721348 的步级分解）：check job 7.4min，其中 **e2e 步 223s 是最大单项**；vitest light 45s、integration 112s、typecheck 7s。三层「全跑一遍」的本地耗时占比：e2e 48% / integration 39% / light 13%——重心确实在浏览器层与栈层。

## 分层职责表

| 层 | 形态 | 何时跑（职责） | 入口 |
|---|---|---|---|
| **unit** | vitest projects，每包 colocated `test/`，纯函数 / schema / mapper | **每次改动**（秒级；可按受影响面缩窄） | `pnpm test`；受影响面 `pnpm exec vitest run --changed` |
| **栈集成** | vitest `integration` project：场内起真 server + daemon + Chromium 走完整链路 | **改 server / daemon / shared 契约面时**（受影响面） | `VITEST_PROJECT_SET=integration pnpm test` |
| **web e2e** | playwright fixture 面：83 spec / 617 用例，UI 行为与几何 | **开发期跑受影响面**；**全量归 CI（4 分片）**；本地全量仅在收尾复核确需时 | 受影响面 `pnpm --filter @pacman/web e2e:affected`；全量 `pnpm --filter @pacman/web e2e` |
| **verify-pacman** | 隔离 live 栈（8791/5273 + 独立 PACMAN_HOME）走真用户路径 | **票级验收**（交付前证明「真能跑」，非日常回归） | `.claude/skills/verify-pacman/SKILL.md` |

一句话记忆：**unit 每次改、栈集成看契约、e2e 开发期只看受影响面（全量是 CI 的活）、live 探针票级验收。**

## e2e 受影响面：`e2e:affected`

机制（`scripts/e2e-affected.mjs`，选定 spec 后走**标准 fixture-build 配置**跑——实测 fixture build 只要 ~1s（vite 8），快速性全部来自选择本身（全量 617 用例 vs 单域几十条），保真度与 CI 完全一致，不需要独立的快速通道配置，token-gate 也无需特判（它的自起 server 托管的正是 webServer 刚 build 出的 dist）：

- **选择**：无参 = 工作区 + 分支对 `origin/main` 的全部改动路径；显式路径 = `pnpm --filter @pacman/web e2e:affected -- <paths>`；`--dry-run` 只打印选择结果。
- **映射**：spec 家族 = e2e 文件名前缀（`chief-`、`sidebar-`…）；源路径 → 家族走 `scripts/e2e-affected.mjs` 的表（目录级为主，`src/board/sidebar.tsx`、`src/routes/*` 等文件级覆盖）。**保守过包含**：多跑一个 spec 只花几秒，漏跑一个读作假绿——映射表宁大勿漏，且它是**信号不是保证**：唯一完备的闸是 CI 全量。
- **共享面 → 全量回落**：`src/ui` `src/styles` `src/i18n` `src/api` `src/fixtures` `App.tsx` `main.tsx` `theme.ts` `phase.ts`、playwright/vite 配置、`e2e/evidence.ts` `e2e/png.ts`、lockfile/workspace、未映射的 `apps/web/**` 路径——这些改动的诚实受影响面就是全部 spec。
- **web 单测层 → 不选 e2e**（#1455）：`apps/web/test/**` 与 `apps/web/vitest.config.ts` 只属 vitest，不进 playwright 托管的 fixture build，e2e 也不 import 它们——受影响面为空，覆盖由 `pnpm exec vitest run --changed origin/main` 承担（不带 ref 只看未提交改动，已提交的单测会被漏掉，见下文 `--changed` 一节）。其余未映射的 `apps/web/**`（含被 e2e 读取的 `DESIGN.md`）仍回落全量。
- **e2e 目录的 helper 模块 → 按 import 收窄**（#1463）：`e2e/` 顶层的非 spec 模块（`.ts`/`.mjs`/`.js`，如 `helpers.ts`）改了，只选 import 了它的 spec，顺着中间模块追下去（spec → `helpers.ts` → 改动文件，穿过被别的 spec import 的 spec）。只在「提到这个文件的地方全是顶层 e2e 文件之间的静态相对 import」时收窄；其余一律全量回落：非顶层模块（子目录、css/png/json、点文件、新建目录）、以非 import 方式被提到（spawn 路径、读文件、模板字符串）、链上碰到全量表里的文件或子目录文件、`playwright.config.ts` 或 `apps/web/package.json` 提到、或一个 spec 都没找到。链上经过有文件映射的模块时并入它映射的 spec。`e2e/evidence.ts` `e2e/png.ts` 仍在全量回落表里；`live-server.ts`、`live-server-tether.mjs`、`live-server-spawner.ts` 三个仍走文件映射。
- **`apps/server/**`**：e2e 面只有 token-gate 一条会起真 server；真正覆盖面是上面的栈集成层。
- **端口**：受影响面默认 `E2E_PORT=8398`（`E2E_AFFECTED_PORT` 覆写；显式设了 `E2E_PORT` 则尊重之）——与全量的 8399 分道，多 lane 机器上 `reuseExistingServer` 才不会悄悄测到别人的 build（#137 同款纪律：撞端口换号，不杀邻道）。

- **同机名额**（#1628）：`pnpm prepush` 与 `e2e:affected` 先到 `scripts/heavy-slots.mjs` 取名额才开跑，满了就打印「排队中，第 N 位」。名额数读 `CAIRN_HEAVY_SLOTS`，默认 2；0 或非数字按 1 处理并告警。锁文件放 `os.tmpdir()/cairn-heavy-slots`（`CAIRN_HEAVY_SLOTS_DIR` 覆写），每个名额一个以 `O_EXCL` 创建的文件，内容记 pid；取锁前清掉 pid 已不存在的条目，所以 `kill -9` 后排队者约一个轮询周期内接手。名额编号决定端口与构建目录：名额 N 用 `E2E_PORT` 基数加 `(N-1)*10`，构建输出到 `os.tmpdir()/cairn-heavy-slot-N/web-dist`（`e2e:affected` 生成该名额专属的 playwright 配置，live-server 经 `E2E_DIST_DIR` 读同一目录），同一 worktree 里两条也不互踩 `dist/`。`CI` 环境变量非空且不是 `false`/`0` 时跳过排队，行为同改前。`--dry-run` 不取名额。

维护规则：新增 spec 时，若其前缀不在任何家族里、且它不是共享面专属，就把前缀挂进对应源路径的表项；映射表里匹配不到任何 spec 的前缀会在运行时打 WARNING（表腐化的显性信号）。

## CI 分片（覆盖面不降）

`.github/workflows/ci.yml`：e2e 从 check job 摘出为独立 `e2e` job，`strategy.matrix` 4 分片、`--shard=i/4`（playwright 按用例精确切分，**并集 = 全量 83 spec**），`fail-fast: false`（一个 shard 红不掩盖其余）。chromium 安装随迁（不再 apt 装 ffmpeg：分片里没有调系统 ffmpeg 的 spec，那一步曾卡住 42 分钟）；check job 不再装浏览器面。收益：e2e（223s 串行步）离开 check job 关键路径，单 shard ≈ setup + build + 1/4 用例量；check job 剩 drizzle / typecheck / vitest×2 / lint。分片各自独占 runner，token-gate 与 webServer 在各自的 dist 上工作，「同 runner 互写 dist」约束随 job 边界消失。

**分片真的在分吗（#765 判据）**：`pnpm --filter @pacman/web e2e -- --shard=i/4` 这种写法**不分**——pnpm 把 `--` 原样转给脚本，playwright 收到一个 `--` 位置参数、`--shard` 被吞，四条分片各跑全量（run 37134551409：四个 job 都打 `Running 688 tests`，同一条探针 spec 在四条里全红；单 shard 4m03–5m32）。去掉 `--` 才是转发：`pnpm --filter @pacman/web e2e --shard=i/4`（实测 173/171/… 用例/分片，并集 = 全量 688 用例 / 90 spec）。判据留在 job 的日志上：每条分片的 `Running N tests` 之和 = 全量且互不重叠。

「覆盖面不降」的另一半在**合并闸**：分支保护的 required contexts 引 `e2e-gate`（needs 全部分片的聚合 job，context 名稳定）而非逐分片名——名单若编码 matrix 基数，将来分片数一调就静默失配、新分片不阻塞合并。

聚合 job 自己也有判据（#762）：必须 `if: always()` 且显式判 `needs.e2e.result == 'success'`。分支保护把 `skipped` 与 `successful` / `neutral` 同等放行，而只写 `needs` 时任一 shard 失败会让聚合 job 整个 skip——**闸会在唯一需要它的时刻敞开**。实测三条红 run（37130371196 / 37128928219 / 37125498051）的 `e2e-gate` 结论都是 `skipped`；`always()` + 显式判定后同条件上报 `failure`。

## vitest 受影响面（可用性已核验，2026-10-03）

- `pnpm exec vitest related <源文件>`：**可用**——根目录跨 project 生效（实测 `apps/web/src/board/dnd.ts` → 恰选 `dnd.test.ts` 7 用例，2.1s）。
- `pnpm exec vitest run --changed [since]`：**可用**（vitest 5.0.1 原生；缺省比对 HEAD 的未提交改动，给 ref 则比对该 ref，按 git 变更取 related 测试）。2026-10-20 实测：`--changed a1e7254~1` 选中 22 个测试文件。
- `pnpm exec vitest related --changed`：**不可用，恒选 0 个测试**。`related` 子命令把位置参数（这里是空数组）写进 `config.related`；`filterTestsBySource` 只在 `!config.related` 时才走 git 取变更文件，空数组为真值，于是跳过查找，随后 `related.length === 0` 直接返回空（`vitest/dist/chunks/index.*.js` 的 `filterTestsBySource`）。同一 ref 下实测 `No test files found`，exit 0——不报错，所以看起来像「没有受影响的测试」。#1398 因此漏掉一条被改坏的单测（`test/chief-identity.test.ts`）。
- 定位：vitest 层的量本来就小（light 40s），受影响面是**顺手缩窄**不是必需；栈集成层保持整层跑（它的「受影响面」判据 = 你改没改契约面，这是人判的语义问题，脚本替不了）。

## pi 廉价结构闸对照评估（评估 + 提议，本票不落地）

| pi 的闸 | pacman 现状 | 评估 |
|---|---|---|
| pinned-deps（依赖全钉死） | pnpm catalog + `--frozen-lockfile`（CI）+ pre-commit 锁文件闸 | **已有等价物**，形态不同（pi 无 workspace catalog 所以要脚本钉） |
| runtime-deps（禁构建期引运行时依赖） | biome `noRestrictedImports` 缝纪律（backend/MCP/LLP 缝） | **已有等价物**（lint 面更强：直接锁 import 路径） |
| ts-imports（相对导入风格统一） | biome organizeImports | 已覆盖，非风险面 |
| entry-graphs（浏览器包不得吸入 node-only 模块） | 单浏览器应用（apps/web），vite build 本身就是这道闸 | **低价值不提议**：pi 是多包发布的 browser/node 双形态才有此险 |
| shrinkwrap / install-lock（发布产物可复现安装） | CI 的 `pack-smoke` job（#264）冒烟主包 tarball | **已有等价物** |
| 密闭测试环境（test.sh：空 env + 临时 HOME + 零凭据） | 部分等价：栈集成/token-gate 各自 `mkdtemp` + 独立 `PACMAN_HOME`；但 vitest 全量仍继承本机 env | **唯一值得提议的**：本机测试可能读到真实 `~/.pacman` / 凭据造成假绿假红。提议后续单票：本地 `test:hermetic` 包装（空 env + 临时 HOME）。CI 天然密闭，无需动 |

结论：六项里五项 pacman 已有不同形态的等价物，照抄是重复建设；值得补的只有密闭环境一项，且应该独立票做（改动面是全部测试的启动方式，不混进本票）。

## 全局手势单源（#1267）

线程任务书模板的 blast-radius 条引用本文件时，全局手势的单源是 `apps/web/src/overlays/gesture-machine.ts`。

⌘J、Escape 关层、总管抽屉开合的下一状态只在该文件的 `reduceGesture` 里计算。消费点派发事件，不自持开合布尔，也不再注册第二条 window 上的 Escape 或 ⌘J 监听。新的全局手势加在该文件的事件表和 `bindGestureKeys`。

页面私有和弦（⌘K 搜索、C 开新任务、抽屉内 N、新建任务 Tab）不是这台机器的状态。它们不另持一份总管开合态。
