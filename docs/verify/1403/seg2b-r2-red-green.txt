The vector (pr-gate suggestion 6)
---------------------------------
mergeThroughGithub sent commit_title = `${pull.title} (#n)`. The PR author check admits
OWNER / MEMBER / COLLABORATOR, and MEMBER / COLLABORATOR include read-only accounts
(github.ts WRITE_AUTHOR_ASSOCIATIONS comment). Such an account can retitle the build's PR
to hold a closing keyword and an issue reference; the squash commit lands on the default
branch and closes that issue, bypassing closingLine (only the task's own same-repo issue).
The body has the same hole by another field: with no closing line, commit_message was not
sent, and GitHub then fills the squash body from the repository default
(squash_merge_commit_message: PR_BODY, COMMIT_MESSAGES or BLANK), i.e. possibly the PR body.

GitHub's rules, quoted from docs.github.com, "Linking a pull request to an issue"
(/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue,
fetched 2026-10-22):

  "You can link a pull request to an issue by using a supported keyword in the pull
   request's description or in a commit message. ...
   * close * closes * closed * fix * fixes * fixed * resolve * resolves * resolved"
  "Issue in the same repository | KEYWORD #ISSUE-NUMBER | Closes #10
   Issue in a different repository | KEYWORD OWNER/REPOSITORY#ISSUE-NUMBER |
   Fixes octo-org/octo-repo#100"
  "The keywords can be followed by colons or in uppercase. For example: Closes: #10,
   CLOSES #10, or CLOSES: #10."
  "You can also use closing keywords in a commit message. The issue will be closed when you
   merge the commit into the default branch"

and "Autolinked references and URLs" lists the reference forms: an issue URL, #26, GH-26,
Username/Repository#26. REST "Merge a pull request": commit_title "Title for the automatic
commit message", commit_message "Extra detail to append to automatic commit message"; the
repository object carries squash_merge_commit_message: PR_BODY | COMMIT_MESSAGES | BLANK.

Fix (95f2a30e)
--------------
- Title: CLOSING_SHAPE = /(?<![a-z])(?:close[sd]?|fix(?:e[sd])?|resolve[sd]?)\s*:?\s*\S*\d/i
  is tested on the composed title "<PR title> (#n)". A match sends pacman's own title
  "Merge pull request #n" (no PR text at all). The shape is wider than GitHub's documented
  syntax on purpose: any keyword followed by a token holding a digit counts, so every
  reference form above (and undocumented ones such as a URL without a scheme) is covered;
  a false match only loses the PR title. Not a rewrite in place: a rewritten title would
  rely on GitHub not parsing the rewritten form, the fallback relies on nothing.
- Body: commit_message is always sent: the closes line when closingLine gives one,
  otherwise "Merged by pacman.". The PR body never reaches the squash body.
- ADR 0021 D2 ("标题取 PR 标题") still describes the normal case; spec 02 A6 states the
  fallback and the body.
