== Readings (what S4b may rely on, and what it must not) ==

1. Conditional reads work through gh with If-None-Match on pulls, branches, check-runs and the combined
   status: each answered 304 with an empty body. The 304 echoes the ETag in strong form ("...") even when the
   200 had sent the weak form (W/"..."), so a cache must keep the ETag it got from the 200.
2. Permissions GitHub states per endpoint (X-Accepted-Github-Permissions / X-Accepted-Oauth-Scopes):
   pulls: pull_requests=read; contents=read / repo. branches: contents=read. rules/branches: metadata=read / repo.
   compare: contents=read. check-runs: checks=read. commits/{sha}/status: statuses=read / repo, repo:status.
   contents: contents=read / repo. The team connection's `read:user repo` covers all of them.
3. rules/branches/{branch} for a branch that does not exist answers 200 [] with the same ETag as main: an empty
   rule list does not show that the branch exists (S4b reads the base branch separately).
4. compare, per_page=2, 3 commits: page 1 has 2 commits and the files; page 2 has 1 commit and no "files" key at
   all (not an empty list). total_commits is 3 on both pages. Link uses the /repositories/{id}/ form, not the
   requested /repos/{owner}/{repo}/ form, which is one more reason the transport returns Link and never
   follows it.
5. check-runs at 39a108e under filter=latest: total_count 14; pr-evidence twice from github-actions in two
   check suites (107778555113 and 107777805272); "e2e (3)" was in_progress at capture time. filter=all returned
   the same ETag at this SHA (no re-run happened). per_page=5&page=2 returns 5 runs with prev/next/last/first
   Links.
6. Combined status at 39a108e: sha present, state pending, total_count 0, statuses [] (this repository's CI
   reports through check runs only).
7. 404 bodies are JSON: {"message": "Not Found", "documentation_url": ..., "status": "404"}, for a missing PR,
   a compare with an unknown head SHA and a missing contents path alike.
8. contents of a directory at a SHA: a JSON list, one object per entry (6 entries, all type "file", for
   docs/verify/1490 at 93b9ce2).
