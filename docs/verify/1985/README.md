# Routing execution boundary evidence

## Scope

`integration/eval/routing/boundary.mts` executes a command inside a Linux x86_64 filesystem boundary. It requires gcc, ldd, Landlock ABI 3 or newer, seccomp, and ptrace syscall tracing. Missing enforcement, timeout, or incomplete audit evidence returns `enforced: false`. `gradeBoundedRun` rejects that result even when the oracle passes. No model runner or reporting module is included.

Landlock enforces access in the kernel for the shell and its descendants. Shell syntax does not determine access. The workspace is writable. Exact runtime executable and shared-library files are readable through a separate manifest. The manifest also includes the dynamic linker cache, NSS configuration, passwd database, `/dev/null`, and `/dev/urandom`. These explicit runtime resources are outside the task data boundary. No parent directory receives recursive read access.

The environment excludes caller credentials and startup hooks. Node uses `/dev/null` for OpenSSL configuration. Infrastructure denials stay denied and appear in `runtimeDenials`: io_uring and socket capability denials, and denied reads of the exact runtime probes `/proc/self/maps`, `/proc/self/cgroup`, `/proc/meminfo`, `/proc/stat`, `/proc/version_signature`, `/proc/mounts`, `/proc/filesystems`, `/sys/devices/system/cpu/online`, and reads under locale data directories (`/usr/share/locale/`, `/usr/share/coreutils/locales/`). They do not grant file access or count as task data violations. Other permission denials appear in `violations`, including caught errors and successful shell commands that hide a failed read.

The native supervisor follows forks, clones, and execs. Seccomp blocks untraced clones, process-memory access, networking, mount operations, and io_uring. Inherited descriptors above stderr close before execution. The audit remains outside the workspace. Kernel enforcement follows symlink targets.

Enforcement availability is reported only through the audit protocol: the supervisor writes `COMPLETE` after the supervised exec finished, and `ENFORCEMENT_UNAVAILABLE` when the child never reached a successful exec, which covers helper setup failures, a broken runtime manifest, and kernels without Landlock ABI 3. The task's own exit code no longer signals helper failure, so a task that exits 125 stays `enforced: true`. `landlockAbiOverride` compiles the helper with a fixed ABI probe result so the kernel-unavailable path is exercised on modern kernels.

`grade.mts` is the routing grading entry. It extracts the seeded implementation detector from closed PR #1888 at `dd34ea21f592a37e695843338f0cf3f4aea62960`. A file is flagged when a module specifier (`import`/`export ... from`, dynamic `import()`, `require`, side-effect `import`) resolves to the decoy path or its extensionless stem from the changed file's directory, or when at least 90% of the decoy's nonempty lines are copied. Mentions of the decoy path in comments, strings, or prose are not references. This is a reuse heuristic, not proof of semantic independence after arbitrary rewrites. The model runner is out of scope for this PR; the merged routing bench (#1984) holds its own oracle and benchmark fixtures and does not import these grading functions.

`boundary-check.mts` is the standalone verification harness. It seeds a workspace, runs the oracle, the external-read attacks, the reuse controls, an independent implementation that mentions the decoy, the task-exit-125 case, and the kernel Landlock unavailability case through `executeBounded` and `gradeBoundedRun`, and exits nonzero when any control breaks.

## Failure modes and controls

The subprocess suite covers direct and quoted reads, command chains, substitutions, multiline commands, sed, Node filesystem reads, parent traversal, symlink escapes, and nested child processes. Every external sentinel case checks that the sentinel is absent from stdout, that the target path appears in the audit, and that grading fails while a real oracle execution passes in the same verdict. Positive controls cover `cd lib && cat ../lib/adder.mjs`, quoted internal reads, local Node checks, child-process reads inside the workspace, a real `node --test` run, and a runtime capability probe (a UDP socket creation that seccomp denies), graded to pass together with a real oracle execution. Reuse controls reject importing, re-exporting, requiring, and copying the seed; each verdict derives `oraclePass` from a real oracle run and asserts that the recorded violation list is empty, so the reuse flag alone fails the run. The independent implementation passes, a failed oracle run fails, and missing execution evidence fails.

Real-process controls run only where they can run: the suite skips them unless Linux x86_64 with gcc and ldd is present, instead of failing on macOS or on machines without a C toolchain. Grading verdicts that do not need the boundary (helper-build failure, missing execution evidence, and the pure reuse detector) run everywhere, and `executeBounded` itself returns `enforced: false` on unsupported platforms, so grading fails closed everywhere.

`read-target-red.log` records seven failures before runtime handling was corrected. Two Node cases previously failed before attempting the sentinel read. `untraced-red.log` records the missing audit event for `CLONE_UNTRACED` before seccomp rejected that flag. `prepush-runtime-red.log` records two additional optional CPU probes from Node under the prepush runner before those probes were classified as runtime denials. `selfcheck-red.log` records the review-round red run: the pre-fix implementation flagged four decoy mentions outside module specifiers, missed a same-directory import of the decoy, reported `enforced: false` for a task that exits 125, and reported `enforced: true` with the kernel Landlock unavailability control. `selfcheck-green.log` records the same suite after the fixes. `boundary-check.log` records the standalone harness, which also failed closed during development when its oracle control could not run. `ci-runtime-red.log` records the real-process probe control failing on the committed helper, whose exact-path probe list missed socket capability denials; the fixed classification by syscall and path prefix is green in `ci-runtime-green.log`. The classification was needed because the exact-path list was distro-coupled: the CI runner denied coreutils locale data, `/proc/version_signature`, `/proc/mounts`, `/proc/filesystems`, and socket calls during benign local checks and oracle runs.

`prefix-length-redgreen.log` records the negative control for the locale prefix compare. The first pushed classification compared `/usr/share/coreutils/locales/` with a duplicated length of 30 against a 29-character literal, so that prefix never matched and every denial beneath it was graded as a task violation; three local-check cases were red on the CI runner while the same paths passed locally. A harness that includes `read-boundary.c` and calls `is_runtime_denial` on `/usr/share/coreutils/locales/uucore/en-US.ftl` returns `VIOLATION` on that head and `RUNTIME_DENIED` after the lengths are derived with `strlen`.

The test command is `pnpm --filter @cairn/integration exec vitest run test/routing-boundary.test.ts`. The harness command is `pnpm --filter @cairn/integration exec tsx eval/routing/boundary-check.mjs`. Heavy repository checks run serially through `flock /tmp/cairn-heavy.lock`. No web server is required.
