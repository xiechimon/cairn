Notes per surface:
- machines.ts claim payload: adds sourceKind / sourceRef of the todo being claimed.
  The claiming machine is authenticated by its machine token and the step is already
  scoped to its team; it already receives the same todo's title and spec. The two
  fields (`github:owner/repo#N`, `chief:<uuid>`, or null) add no data the machine
  could not already see through the todo, so no new exposure.
- chief-tools.ts saveMemoryEntry: a new refusal (400) for title/content carrying the
  fence marker. It only narrows what is written; no bypass or authorization change.
  It does not stop a paraphrase (stated in the code comment and in the failure-mode
  list); that part is a prompt-level control, not a security boundary.
- prompts.ts fenceIssueText / chief.ts rule: prompt-injection hardening of
  third-party text in the user layer. The fence is structural (every body line
  prefixed after folding all line terminators; header label limited to GitHub name
  characters), and no third-party text is added to a system layer. The skill's
  rules exclude "user-controlled content in AI prompts" as a vulnerability class;
  recorded here as hardening, not as a finding.
- web mappers / classifyUserText: only decides whether a transcript row renders as a
  user bubble (React text rendering, no raw HTML). A user message that exactly equals
  the fenced task text would be hidden from the transcript; this is a display
  choice, not a security issue.
