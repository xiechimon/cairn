== Blocking 1: image tokens in issue-sourced task text are no longer delivered ==

Paths, read from the code:
  Q1 plan / build / merge new session, #720 composite (restart, ci-fix, plan contract), #1312 degraded
     fresh session: daemon runner buildTaskPrompt -> shared buildTaskPromptText fences title + spec
     -> runner resolveStepImages (runner.ts:537 and :1384).
  Q2 verify: server builds.ts maybeEnqueueVerifyStep fences the task text inside the verify instruction;
     the daemon runs resolveStepImages on the instruction.
  Q3 steer (machine-loop.ts) and review / chief instructions: no fence; steer text goes through
     resolveStepImages, chief does not.
  Other users of ATTACHMENT_TOKEN_LINE: shared records/chief.ts (chief thread title) and task-meta.ts
  (title derivation). They read the raw spec or message, never fenced text; they keep the regex as is.

Failure modes:
  A1  Inline image (png/jpeg/gif/webp) token line in the spec of an issue-sourced task is not delivered
      (no image, no "not delivered" note). Must be delivered again on Q1 and Q2.
  A2  The rewrite of a quoted token line leaves the fence: the anchor line "[image attached: <name>]"
      replaces the token line without the "> " prefix, so a bare line appears between head and close.
      Every rewritten or added line must carry the prefix of the line it came from.
  A3  Same for the materialized path note (svg/bmp/ico/avif) and the two "not delivered" notes
      (download failure, key grammar). A download error message can hold "\n" (MachineApiError carries
      the raw response body, e.g. a proxy HTML page); every line of a note inside the fence gets the prefix.
  A4  Non-image token (pdf, txt) inside the fence: untouched, the quoted line stays byte for byte.
  A5  Alt text is issue-author text. A token line whose alt text holds the closing line or the head of
      the fence must not produce a bare closing line; the alt text never leaves the quoted line.
  A6  A blockquote in the issue body ("> ![x](attachment:...)") arrives as "> > ![x]...". It was not a
      whole-line token before #1475 either; it stays undelivered (only one quote level is the fence).
  A7  Quoted token lines outside a fence (a user's own markdown blockquote in a steer, restart feedback,
      a plain task spec) stay as today: not downloaded, no note. The #730 whole-line contract and the web
      chip rendering (no chip for a quoted token) stay aligned; only the fence's own prefix is peeled.
  A8  The fence region ends at the real closing line: a "> " token line after it (for example in
      restart feedback composed after the fence) is outside the fence (A7 applies).
  A9  Spoofing the region: issue text cannot open or close a fence region, because every issue line
      starts with "> ". Only the bare head line (starts with 【GitHub issue 原文, is not the closing
      line) opens, only the bare closing line closes.
  A10 Plain tasks (sourceKind null, orchestration, github-issue-self): resolveStepImages output is
      byte for byte what it was (bare token lines, no fence).
  A11 Mixed versions: a daemon older than this fix running a verify step for a server at or after
      #1475 gets the fenced verify instruction and does not deliver the image (no note either). Not
      fixable on the server without dropping the fence for those lines; reported, fixed by upgrading
      the daemon. Plan / build on a daemon from before #1475 is unfenced and delivers as before.

== Suggestions folded in ==

  C1  Format characters (Unicode Cf: bidi overrides U+202A-202E / U+2066-2069, zero-width U+200B-200D,
      U+FEFF, soft hyphen, tag characters U+E0000-E007F) in issue text pass into the fence. Strip them
      in fenceIssueText (same rule as cleanGithubText for GitHub text in tool results); the fence
      structure is unaffected.
  C2  Plain tasks keep Cf characters byte for byte (only issue text is cleaned).
  C3  Known limit: a transcript row logged by a #1475 daemon for an issue task whose title or spec
      holds Cf characters no longer equals the new fenced form; web classifyUserText then shows it as a
      user bubble. Needs Cf characters in an imported issue and a daemon from the #1475 window.
  S1  quotesIssueFence: one-line helper, one call site; inline it (AGENTS.md).
  S2  docs/spec/02 §4.4 does not mention that save_memory refuses fenced text.
  S3  Prompt variants named in #1475 without a direct test: merge new session, ci-fix composite,
      degraded fresh session (#1312), and classifyUserText for a fenced row with the confirmed-plan note.

== Added after /code-review (round 2) ==
  A3b A file name (isValidFileName lets U+2028, U+2029 and U+0085 through) or a download error reason
      ("\r") carries a line-break variant other than "\n"; a per-"\n" prefix still leaves an unprefixed
      line for a model that splits on it. Rewritten lines inside the fence go through the fence's own
      quoting (shared quoteIssueLines: Cf strip, line-break fold, per-line prefix).
  A3c (added after the second /code-review) The materialized path note names the file written to disk.
      Inside the fence the note is quoted, which strips Cf and breaks lines at U+2028; if the on-disk
      name keeps those characters, the path the agent is told to Read does not exist. Clean the name where
      it enters the daemon (safeFileName drops U+0085 / U+2028 / U+2029 and Cf as well), so the on-disk
      name and the note path are the same string, inside and outside the fence.
