# Weekly failed-trial review

The existing `scripts/ops/eval-weekly.sh` job generates the review after archiving all flows, under its state directory at `reviews/<day>/review.json`. Set `CAIRN_EVAL_REVIEW_PACKS` to a labeled JSONL export to include failed builds. Without it, the review explicitly records zero available attributed packs. It does not invoke a labeler.

Run `pnpm eval:sample-failures --week 2026-11-16 --packs path/to/labeled-packs.jsonl` after the weekly eval/export. Repeat `--packs` for multiple exports. `--week` is the review batch date, not a timestamp filter: eval rows do not have reliable timestamps. Point `--flows` at that week's archived flow directories (default `.claude/hillclimb`). Each flow must contain `baseline/results.jsonl`, optionally `baseline/errors.jsonl`, and `baseline/traces/`.

The command chooses up to ten failed trials and ten attributed failed builds. `--count` changes each budget. Seeded round-robin selection covers flow/failure-class strata before taking another item from a stratum. If the budget is smaller than the stratum count, a seeded ordering chooses which strata fit. Failures are zero/false grade dimensions or error rows; failed builds use the labeler's merged/reverted/fixed outcome rule. Duplicate builds across exports count once; conflicting model labels fail. Successes are excluded. Sparse inputs remain sparse, and the review records available and sampled counts. Missing traces are explicitly marked and retain the result/error row for investigation; do not infer an agent mistake from a missing trace.

The output is `.claude/hillclimb/reviews/<week>/review.json` beside the flow results, with local transcript links and a separate `answer-key.json`. Existing directories are never overwritten. The review and copied pack transcripts omit model attribution. Do not open the answer key or the original labeled exports before completing hand labels. This is procedural blinding for local files, not access isolation. Keep the answer key with the review for reproducible reporting.

For each item, fill `verdict` with `agent_mistake`, `grader_bug`, or `unfair_task`, plus `reviewer` and `note`. For packs, fill `hand` with independent `where` and `why` labels using `packages/shared/src/failure-attribution.ts`. `unknown` is a valid where label; `other` is a valid why label. Leave unread items' verdict as null. For grader bugs or unfair tasks, file a GitHub issue on the owning flow with the trial id, transcript evidence and proposed correction, then record its full `https://github.com/xiechimon/cairn/issues/N` URL in `issue`. The report rejects these verdicts until their ticket is recorded. No network writes occur in this command.

Use the same weekly record for ADR 0026 R6: add at least five merged autonomous PR reviews to `autonomousPrReviews`, weighted toward protected paths and large diffs. Record PR URL, reviewer, note and any correction issue there. This command supplies the shared review record; it does not select or verify PRs. ian reads this record once a week. A cross-vendor reader may perform the initial pass, with ian spot-checking five items and recording that in the notes.

After hand labeling, run `pnpm eval:sample-failures --report .claude/hillclimb/reviews/2026-11-16/review.json`. Repeat `--report` to accumulate weeks. Reporting deduplicates build ids so repeated weekly samples do not inflate the label count. Conflicting verdicts, hand labels or model attributions for the same build are rejected instead of silently choosing the first week. It reports verdict counts, correction tickets, raw agreement, Cohen's kappa, and a 95% Wilson interval for raw agreement per dimension. Null kappa means no labels or degenerate marginals; it is not perfect measured reliability. The interval assumes independent sampled items and does not adjust for stratification. Unknown labels participate as ordinary categories.

E3 must not consume attribution labels until at least 30 distinct builds have hand labels and raw where agreement is at least 80%. `e3Eligible` reports that necessary condition; it does not enable E3. Review the interval, labeler version in the answer key, and disagreements before trusting labels. Do not combine exports from different labeler revisions when validating a revision. No E3 consumer is introduced here.

`red.log` records the CLI test failing before implementation. `green.log` records the same end-to-end fixture test passing against the command and its generated review artifacts. No live labeler, paid eval, server or external ticket creation is needed.
