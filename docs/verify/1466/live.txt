Outbound observation
  The server's GitHub base (https://api.github.com) is hard-coded in apps/server/src/lib/github.ts,
  so it was not repointed. Instead every outbound HTTPS request of the server process goes
  through a logging forward proxy (NODE_USE_ENV_PROXY=1 + HTTPS_PROXY/https_proxy, both case
  variants, because the sandbox exports a lowercase https_proxy that wins over the uppercase
  one). The logging proxy appends "CONNECT host:port" with a timestamp for every tunnel and
  chains it to the sandbox egress proxy (127.0.0.1:36147). Its source is in the appendix.
  Each call below prints the proxy lines that appeared between sending the call and
  +settle ms after the response (printed per call: 1.2-3 s for routes that could reach
  GitHub, 3 s for the todo creates that fire the self-issue write in the background,
  0.2-0.3 s for setup and MCP calls). Before the final log dump the driver waits 5 s more,
  then matches every CONNECT line in the log against the control calls.
  Note on the GitHub answers: this sandbox's egress proxy refuses api.github.com for
  repositories not enabled for the session (HTTP 403, "GitHub access to this repository is
  not enabled for this session ..."), so every call that does leave the server ends in the
  server's mapping "502 github api 403: <url>". The 403 comes from the sandbox, not from
  GitHub; what matters here is whether a CONNECT to api.github.com happened at all.

How the calls were made
  A Node driver ran each HTTP call as the literal curl command printed after "$" (plus
  -w '\n%{http_code}' to capture the status) and each SQL statement through better-sqlite3
  on $H/server/server.db while the server was running. "->" is the status and body.
  The API key is masked to its first 8 characters everywhere ("pacman_1…[masked]"); the
  server's own "masked" field is masked the same way.
  GitHub connection row (check 2b): there is no API to create one without the OAuth flow, so
  the row was inserted in SQL with a made-up token string sealed by the server's own
  createKeyfileSecretBox() over the scratch keyfile (seal.mts, appendix); the server opens
  it with openGithubToken like an OAuth-written row (GET .../github/connection says
  connected, and the control calls send it to api.github.com).
  Second team (check 3): the API serves one team (GET /api/teams returns only the seed
  team), so team B is a row inserted in SQL; its project and todo were created through the
  API in team A and then moved to team B with SQL UPDATEs (shown in place).
  An earlier run of the same driver on another fresh scratch home was discarded and that
  home deleted: the driver sent spec "" on the MCP create_todo control call, which the
  MCP face rejects with "error: invalid spec" (driver bug, not a server finding). The
  driver was fixed to send a non-empty spec on all three create_todo calls and the whole
  leg was rerun from an empty PACMAN_HOME; only that rerun is recorded below.

// Logging forward proxy for the #1466 live leg: every CONNECT / plain proxy
// request is appended to LOG (ISO time + target), then chained to UPSTREAM.
import http from 'node:http';
import net from 'node:net';
import { appendFileSync } from 'node:fs';

const PORT = Number(process.argv[2]);
const LOG = process.argv[3];
const UPSTREAM = new URL(process.argv[4]);
const log = (line) => appendFileSync(LOG, `${new Date().toISOString()} ${line}\n`);

const server = http.createServer((req, res) => {
  log(`HTTP ${req.method} ${req.url}`);
  res.writeHead(502, { 'content-type': 'text/plain' });
  res.end('plain http proxying not supported by logproxy\n');
});
server.on('connect', (req, clientSocket, head) => {
  log(`CONNECT ${req.url}`);
  const up = net.connect(Number(UPSTREAM.port), UPSTREAM.hostname, () => {
    up.write(`CONNECT ${req.url} HTTP/1.1\r\nHost: ${req.url}\r\n\r\n`);
    if (head?.length) up.write(head);
    up.pipe(clientSocket);
    clientSocket.pipe(up);
  });
  up.on('error', (e) => { log(`UPSTREAM-ERROR ${req.url} ${e.message}`); clientSocket.destroy(); });
  clientSocket.on('error', () => up.destroy());
});
server.listen(PORT, '127.0.0.1', () => log(`logproxy listening 127.0.0.1:${PORT} -> ${UPSTREAM.host}`));
