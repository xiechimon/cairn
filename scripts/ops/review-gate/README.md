# Review gate

`.github/workflows/review-gate.yml` runs `codex-gate.mjs evaluate` (decision logic in `codex-gate-core.mjs`) on `pull_request_target`, on issue comments by `chatgpt-codex-connector[bot]`, every 10 minutes on a schedule (`codex-gate.mjs sweep` dispatches the workflow for each open non-draft PR whose head check has not passed, so every evaluation of a PR runs in that PR's concurrency group), and by hand through `workflow_dispatch` with the PR number. GitHub Actions has no event for resolving a review thread, so the sweep picks that up. It always runs the script from `main`, never executes PR code and uses no secrets. It writes one check run named `review-gate` per head SHA through the Checks API (the newest run of the `github-actions` app is updated, never duplicated).

The check reads the Codex state comment (`<!-- codex-review-state:v1 ... -->`, trusted only from the Codex bot) and the PR review threads:

- Review not finished for the head: in progress. If Codex has not started a review of the head 10 minutes after the check was created (PRs opened before Codex was enabled get no automatic review on push), the workflow comments `@codex review` once per head (marker `<!-- review-gate-request:<sha> -->`).
- Code review completed: success unless an unresolved Codex thread carries a P0 or P1 badge, outdated threads included. Ordinary code-review P2 and P3 findings do not block. A thread on a still-current right-side line range that contains no added line and sits in no hunk that removes lines is pre-existing: it is listed in the check summary and does not block. Outdated threads, left-side threads, files whose diff GitHub omits and threads without a location always block. Rounds 1 and 2 follow that rule. From round 3 the convergence rule below narrows it.
- Convergence: the first evaluation of a head that is blocked by P0/P1 threads comments `<!-- review-gate-block:<sha> -->` once. The marker count is the block round. Rounds 1 and 2 fail on every unresolved P0/P1. From round 3 the title and summary tell the author to name the bug class, fix every instance or change the approach, and the PR gets the `review-gate-human` label once per head. A P0 anywhere still blocks. A P1 blocks only when a current right-side line in its range is in the GitHub compare of the newest other blocked head to this head (`base...head`), and only when that compare reports `behind_by` 0, so the hunks are the lines changed since that head. A thread with no current right-side line blocks only when that compare changes its file. Other open P1 threads do not block: the gate comments once per head (`<!-- review-gate-carried:<sha> -->`) listing them as pre-existing in this PR, record in Risk, and the check passes when no blocking thread remains. A diverged, truncated (300 files) or unavailable compare does not narrow. A pass reports how many blocked heads preceded it (cycles to pass).
- Failed: the workflow comments `@codex review` up to 2 times per head (marker `<!-- review-gate-retry:<sha>:<k> -->`); after that the check fails and the PR gets the `review-stalled` label.
- Allowance exhausted: the newest Codex comment is the usage-limit notice, it applies only if it is newer than the current attempt's start. The single rule: the current attempt's start time = the latest of this head's request marker, this head's retry marker, or the update time of the state comment when its `commit_sha` is the current head (a state comment for another head is not an anchor; Codex reuses and edits one summary comment across heads). Times tie-break by comment id, and `attemptStart` in `codex-gate-core.mjs` is the only place that computes it; every comment time read in the core goes through `stampOf` and `stampOrder`. A notice older than the attempt start, or a head with no attempt start, takes the normal path (including the request after 10 minutes). While the notice stands the check fails with `Codex allowance exhausted` and the PR gets `review-stalled`. Two hours after the head's latest request or retry the gate retries once (marker `<!-- review-gate-retry:<sha>:<k> -->`), then waits two hours again if Codex answers with another notice, so recovery needs no human comment. The label is removed when the head passes.
- No result: if a head has no new request, retry or state activity for 30 minutes while its review is unseen, `running` or `failed` with a retry pending, the gate retries (markers above) and, once the retries are used, fails with `Codex did not finish the review`. No incomplete state waits without a deadline.

Agents must resolve a Codex thread once its finding is fixed (GraphQL `resolveReviewThread`); the next sweep, within 10 minutes, re-evaluates the PR. Commenting `@codex review` instead re-runs the gate as soon as Codex edits its state comment. Through rounds 1 and 2 an old thread stays blocking until it is resolved. From round 3 it blocks only as the convergence rule says. A Codex thread whose newest matching reply from a writer (owner, member, collaborator) or the cairn App has a line starting `valid, out of scope for this PR, tracked in #N` is a deferral: it blocks when the finding is P0/P1 on lines this PR changed, or when `#N` is not an issue in this repository (that still fails from round 3) (a pull request or a missing number); an issue lookup that fails for another reason, or a thread with more than 100 comments, fails the check as unreadable input. A reply on a review thread re-runs the gate (`pull_request_review_comment`), so a deferral is judged when it is written. Draft PRs, closed PRs, Mergify merge queue branches and authors without write access are skipped.

## Security review (D84 / D88)

The live check requires the Codex code review only (ian, 2026-11-06). A security-surface PR follows `AGENTS.md`: run `/security-review`, fix findings or record them in Risk, then ian merges it once required CI passes and the code review has no unresolved P0/P1. `pr-evidence` keeps that disposition bound to the head. Path class does not add `coordinator-hold`. The credentials, machine and external-entry lists route to ian.

The `credentials`, `machineAndCommandBoundary` and `externalEntryAuth` lists in `packages/shared/merge-gate-paths.json` name those surfaces. An incomplete or unavailable PR file list fails the check for every PR.

The D84/D88 Codex security-review receipt rules are retired. The check does not read `security_review`, does not request `@codex security review`, and does not ask ian when that review is absent.
