## 实测坑

- server 是 tsx 无 watch。改完码必须 cleanup 再 launch，否则探针打在旧进程上。
- stub 不写 README 时产物闸会把步打成 failed。本探针用 bash 追加一行，终态
  词是 `done`。断言是旁路写，failed 与 done 都会落检查行。
- `message.content` 是 drizzle json。检查行以 JSON 字符串落库，sqlite 只读
  要 parse 两次才得到对象。
- 探针 spawn 的 daemon 可能被 pnpm 重新挂到 pid 1，`stub.close()` 会等它的
  keep-alive。脚本在收尾后 `process.exit`。
