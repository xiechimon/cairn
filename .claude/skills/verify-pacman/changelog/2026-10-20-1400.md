#1400 one meaning for 待处理: new probe `scripts/drive-1400-chip-word.mjs`.

Pure live stack, no daemon, no LLM. Seeds one project and three todos over REST, moves one to `queued` and one to `confirm` with a direct `UPDATE todo SET phase` on the scratch SQLite (manual gate-phase PATCHes answer 409 on the live server), and adds a daily schedule on the fresh todo. Browser leg in the light theme with real clicks reads the word on every surface: board columns (待开始 holds todo + queued, 待处理 holds confirm), detail header chip for each of the three, ⌘K search row chips, the schedule card chip and the project task row status.

`--expect=new` (default) wants 待开始 for todo / queued. `--expect=old` records the base build, where those read 待处理: run it from a worktree of the base commit with `VERIFY_REPO_ROOT=<worktree> VERIFY_RUN_DIR=<worktree>/.claude/verify-run VERIFY_PORT=8792 VERIFY_WEB_PORT=5274`, after launching that worktree's own stack.

Gotchas:
- The project page opens on the 文件 tab; click the 任务 page tab before waiting for `task-row`.
- ⌘K search shows client-filtered rows until `/api/search` answers, and those rows carry the fixture project name for a frame. The probe waits for the response to the full query before reading chips or taking the screenshot.
- A rerun on the same stack duplicates the seeded titles and breaks the row filters. Run `cleanup.mjs` and `launch.mjs` again first.

Evidence: `docs/verify/1400/` (`new/` and `old/` probe legs, e2e logs, README index).
