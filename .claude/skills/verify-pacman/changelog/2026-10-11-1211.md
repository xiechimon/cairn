# 2026-10-11 · #1211 local 落地不再动用户主检出

local-repo 项目 build 落地语义变更:删掉 merge 步在用户仓库目录的 `git merge --ff-only`(旧 `landLocalFastForward`/`mergeFfOnly`,连带 shared `WorktreeOps` 槽位),落地 = conv 分支 push 回用户仓库 refs/heads——用户主检出的分支/reflog/工作树永不被 pacman 触碰,合并到默认分支由用户自取(用户仓库只多 `pacman/` 前缀分支)。

**feature map 面变化**:`local-daemon-executor.md` 的 `ff-only-landing` 条目改为 `branch-landing`(判据 = conv 分支 tip = merge checkpoint + 用户 main HEAD/reflog/status 前后对拍零变化);Gotchas 改为「用户仓库交付面只有 refs/heads/pacman/ 分支、脏工作区不影响任何步收尾」;README.md 索引行同步。

**测试面变化**:`integration/test/g2t2-local-lifecycle.test.ts` 失败方式 3/4 重写(merge 后主检出零变化;脏工作区变体从「步 failed 含 git 拒绝原文」翻为「步照常 done 且用户脏文件原样」);`apps/daemon/test/runner-local.test.ts` 失败方式 1/2/4/7/8 翻向 + 新增真 git 全链用例(真 WorkspaceManager + 真用户仓,验 reflog 逐字不变);`local-executor.test.ts` 落地面改为 push 契约。

**实测证据**:`docs/verify/1211/`(before-red 3 失败 = 旧码 ff 推进用户 main 的实锤;after 全绿)。spec 12 的落地条款、premortem、测试决策同步改写。

**实测坑**:git push 到非 bare 用户仓只写 `refs/heads/pacman/conv-<id>`、不动用户 reflog(main 的 reflog 逐字不变可当 #1211 判据);`git reflog main` 在 fresh 仓即有种子行,前后快照对拍即可,无需计数假设。
