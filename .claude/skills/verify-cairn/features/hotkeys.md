# Hotkey group (new task C + Space opens chief + drawer open-state N)

Pressing `C` on any shell page (outside input state) opens the new-task dialog — the sidebar `新任务` row's action entry (Plus icon + a C badge in `sidebar-kbd`, the upstream todos.dev shape) and the hotkey share the same opener; pressing `⌘J` summons the chief drawer with the focus landing in the draft box (the dialog-family autofocus rule; since #442 ⌘J replaces Space, Space returns to its native semantics). Guard rules: in input state (input/textarea/select/contenteditable) neither key fires; in interaction state (button/a/role family) Space keeps its native activation semantics; modifier combos (⌘C, Ctrl+Space for the input method) pass through. The key changes from N to C at XMON-41 (`n` no longer opens a surface, consistent across lowercase and Shift states); #645 brings N back in **drawer scope** — bare `N` with the drawer open = the header + (new theme), the closed-state listener is not on the window (XMON-37's global-retirement rule still holds).

## Sub-features

- `hotkeys-new-task` C opens `.new-task-dialog`: the board goes through this page's dialog (save lands a local card), the project page through its own page dialog (save anchors the route's project, PageShell's `onNewTask` passes through), other routes go through the AppSidebar-internal global dialog (`useNewTaskSurface`, the same live save path). The sidebar row click = the same opener.
- `hotkeys-chief-wake` `⌘J` opens `.chief-drawer` + `[data-testid="chief-composer-input"]` holds focus; ⌘J toggles it closed (ADR 0013 D3: Esc does not close the window; since #442 Space is no longer the summon key). The next open/close state lives only in `apps/web/src/overlay/gesture-machine.ts` (#1267). The drawer is a single instance resident-mounted with the root layout (ADR 0013 D6, hidden-but-mounted when closed) — the open criterion = visibility, not DOM count.
- `hotkeys-kbd-hint` (#468) the FAB's `⌘J` hover tip: the `.kbd-hint` class retires with #983/#1004/#1008, the carrier = the registry Tooltip + Kbd composition — trigger = `button[aria-label="总管"]`, shell = `[data-slot="tooltip-content"]`, keycap = `[data-slot="kbd"]` inside the shell. Rest = the tooltip not mounted; hovering the parent control floats it out. Three placement variants: above (the FAB family) / right (rail rows) / below (#645's drawer header row — the header hugs the viewport top, above would fall off-screen).
- `hotkeys-chief-new-thread` (#645) bare `N` with the drawer open = the header + new theme (same handler as the button: trigger + close the switcher popover). The scope gate = `useHotkey`'s enabled parameter (the closed-state listener is not on the window); the guard = the _plain_ input-state rule (**without** the drawer-internal exemption for ⌘J: the drawer's autofocus lands on the composer, an `n` while focused goes to the typist). The button carries a `KbdHint` N hover tip (below) + `aria-keyshortcuts="N"`.
- `hotkeys-guards` input-state / interaction-state negatives: with the search-panel input focused, C/Space do not misfire and characters enter the box normally; with a button focused, Space natively activates the button (no hijacking).

## Gotchas

- **The first hotkey press may land before hydration** (the listener registers in a passive effect): the probe's `pressUntil` re-presses until the target is visible; both keys are open-only (not toggles), re-pressing is idempotent.
- **OverlayMount's mounted lags open by one frame** (`useOverlayMount` sets mounted only in an effect): a popup's "focus after open" attached only to the `[open]` effect finds the node not yet existing on a fresh open = the focus silently lost. The family rule = the ref callback carries the first focus + the `[open]` effect catches the retained-mount reopen (SearchPanel attachInput precedent; #389 brought NewTaskDialog/ChiefDrawer under the same rule).
- The fixture-surface regression (guards / badge / two paths) lives in `apps/web/e2e/hotkeys.spec.ts`, not through this probe.
- **`.kbd-hint`'s visibility flipped on the first frame of the transition** (historical note: before `.kbd-hint` retired, a single `isVisible()` within the 120ms `transition-[opacity,visibility]` after hover read hidden at progress 0, the #645 probe measured one FAIL); floating-out assertions always go through `waitFor({ state: 'visible' })` (= the retry rule of e2e `expect().toBeVisible()`) — equally applicable under the registry Tooltip form (both the tooltip mount and the entry animation happen in async frames).
