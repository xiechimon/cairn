# 2026-10-11 · #1171 team-skill native plugin channel

New custom probe `scripts/drive-1171-native-plugin.mjs` (two phases, daemon
self-spawned and self-reaped):

- **Wire phase (zero LLM)**: `PACMAN_CLAUDE_BIN` injects a fake claude CLI
  (answers `--version` / `auth status`, every other spawn captures argv then
  exits 1) — turning the wire surface "the SDK translates plugins into
  `--plugin-dir` flags + settings.permissions.deny into argv" into an assertable
  artifact. Four legs 32 checks: A delivery surface (native-plugin line / plugin
  directory shape / hardlink same inode / argv double assertion / zero worktree
  leftovers), B version gate (2.0.5 -> skipped line + no flag in argv),
  C `[]` empty manifest, D null full manifest (including the P3 live demo:
  injected selection hits zero while native still delivers).
- **Behavior phase (real-model leg)**: the task text names no skill -> the
  transcript's `Skill` tool call names `pacman-team-skills:<name>` + marker
  parroting + the pre-planted `.claude/skills/repo-native` preserved byte for
  byte. 10 checks. Evidence `docs/verify/1171/` (wire/ + behavior/ + README +
  diagram).

Feature map: `features/skills-injection.md` gains the `skills-native-plugin`
sub-feature and the Driving-section probe row; SKILL.md's Drive list gains one
line for this probe.

## Measured pitfalls

- **Reusing a fake daemon home = old identity re-enrolls**: `PACMAN_HOME`'s
  device.json persists the machineId, spawning twice against the same home comes
  online under the **old machine name** (`--name` does not override the stored
  name), and the probe polling machines by the new name waits forever (90s
  timeout suicide, symptom = daemon.log clearly says Online). Fix = `rmSync(home)`
  before spawning (an fs call inside the probe, does not go through the Bash
  hook).
- **The claude backend's tool-call persistence shape is a segment row, not a
  content block**: `message.content` =
  `{"kind":"toolcall","call":{name,arguments,result}}` as a string (ADR 0011
  shape five); asserting a Skill call must look for the segment-row shape;
  scanning only content blocks `tool_use` false-reds (the root cause of the
  first behavior run's 9/10).
- **Server authorization filtering runs before the daemon**: team skills outside
  the whitelist never enter the manifest -> absent from the local view ->
  the deny set contains only locally-whitelisted-out skills. Before writing an
  expectation "deny contains a certain team skill", first confirm it is in the
  manifest.
- **drawio CLI canvas anomaly**: an edge's label offset
  (`<mxGeometry y="-14" relative="1">`) combined with edgeports pinning drags
  the exported PNG canvas to 8000+px tall (content only at the top); either one
  alone is normal. Workaround = edge labels become borderless annotation
  vertices (`text;fillColor=none;strokeColor=none`).
- **The zombie-claim window (same root as #1025) also applies between multi-
  daemon phases**: when switching daemons between legs, wait 80s before creating
  the next step, otherwise the dead machine's waiter steals the new pending step
  on behalf of the dead machine.
