# 2026-11-21 — #5382 Coordinator `docs` reads GitHub projects without a local cache

## What changed for the product

`docs` (and the project file listing behind `GET /api/projects/:id/files`) no longer
depends on a repository cache that only a daemon workspace prepare creates. For a GitHub
project whose cache is absent on the Coordinator host, the read goes through the GitHub
API: resolve the ref to a commit (`/repos/{o}/{r}/commits[/{ref}]`), then read the file
(`/contents/{path}?ref={commit}`, falling back to `/git/blobs/{sha}` for files over 1 MB)
or the tree (`/git/trees/{commit}?recursive=1`). An existing cache still wins, so a
machine that ran a task in the project behaves as before.

## How to observe it on a stack

1. `CAIRN_GITHUB_API_BASE_URL` unset: bind a project to a public repository and call
   `GET /api/projects/:id/files` on a stack that never ran a task for it — the listing and
   its `commit` come back from GitHub instead of `github repository cache unavailable on
   this server`.
2. Coordinator turn: register a custom `openai-completions` provider pointed at a stub that
   answers with `tool_search` then `call_tool {name:"docs",arguments:{projectId,paths}}`
   (deferred tools are not in the model's tool list, so a direct `docs` call is refused with
   "Tool docs is not available"), start a chief thread in the project, and read the turn's
   tool row: it carries `{path, ref, commit, encoding, content}` from the API.
   Seed a GitHub project over `emulate` or a loopback fake for the endpoint shape; the real
   anonymous API is rate limited per IP and returns 403 under a busy host.

## Measured pitfalls

- `tool_results` inside a turn decide the stub's next step; the chief replays the thread's
  whole history, so count only the messages after the last `user` row or the stub loops.
- The turn above is real (server, Coordinator runtime, tool executor, SSE); only the model
  and, in the stub run, the GitHub endpoint are stubbed. A real `api.github.com` file
  listing is recorded separately in the evidence.
