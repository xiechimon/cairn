## Measured pitfalls

- "Repo on another machine" has a single-machine live-stack equivalent:
  `mv` the repo directory away — the daemon's reachability judgment only looks
  at the local fs (existsSync + `rev-parse --git-dir`), the two situations are
  indistinguishable on the execution surface.
- The local-project creation gate (`validateLocalRepoPath`) validates the path
  on the **server** filesystem — the probe must create the project with a real
  existing path first and then mv it away; creating a nonexistent path directly
  = 400.
- Do not use step duration as the fail-fast criterion (it drifts under load):
  `withGitNetRetries`' 1s+5s backoff drags "clone of a nonexistent path" past
  6s under the old behavior, the new behavior makes zero clone attempts, the
  deterministic criterion = no `Cloning` line in daemon.log.
- `waitBuildTerminal` polling must look at the **step table's status** (the
  build table has no status column; errorMessage is on the build row, same root
  as the #920 gotcha).
