#1313 empty-commit review closure. Custom probe `scripts/drive-1313-empty-review.mjs` (`--expect=before|after`).

The probe creates two review cards on a live stack: an empty `changesDiff` and
a one-file diff. The executing Agent has only `推送分支`. Open the board
`完成` popup, screenshot and assert whether the merge row appears and whether
the complete button is clickable. In after mode, click complete and verify
phase done, zero merge steps, and the timeline `标记为已完成`.

Measured pitfalls:

- Current main requires `machineId` for Agent creation. The probe creates the
  api-key and enrolls first, then passes the machineId from the enroll response
  to the creation. Re-running the provider 409s, the probe accepts 201 or 409.
- The complete popup opens first, the changes query arrives later. While the
  query is unfinished the criterion is unknown, the merge row will flash in
  first. Poll the merge-row count before screenshotting, up to 8 seconds.
- The server is tsx without watch. After changing `readBuildChanges`'s
  `reported` you must cleanup and relaunch, the DB is wiped.

Evidence directory: `docs/verify/1313/`. Stack ports follow the skill defaults
8791 / 5273.

Same-ticket supplement: `--focus=hunkless` creates a 100% rename card
(`changesDiff` has the `diff --git` header but no hunks). Before the fix the
complete popup treated it as an empty commit. After the fix `changed: true` and
the merge row is still there. The server still has no watch, after changing
`readBuildChanges` you must cleanup and relaunch.
