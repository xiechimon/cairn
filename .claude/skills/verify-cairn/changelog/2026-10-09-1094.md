# 2026-10-09 · #1094 chief switcher long-list scroll

New custom probe `scripts/drive-1094-threads-scroll.mjs` (two-way: `--expect=new`
21 checks / `--expect=old` 14 checks), evidence `docs/verify/1094/`. No new
surface in the feature map — this probe is the live evidence entry point for the
chief drawer switcher surface.

New seeding technique: **long thread lists are all created via the public REST
`POST /chief/threads`** (22 threads, zero daemon zero LLM zero SQL; title =
first-sentence truncation, the API readback is authoritative) — cleaner than
inserting into chief_thread via sqlite (no guessing the chiefId / sessionId
columns), cheaper than stub rounds (no steps created, no claims). `listChiefThreads`
orders by updatedAt descending, so the last row is the earliest-created thread;
the probe pins "click the last row -> the header chip switches to the last row's
title" on this.

New measured pitfalls:

- **`locator.click()` does no hit-testing against fixed-ancestor clipping** —
  before the fix the last row was clipped away by the window's
  `overflow-hidden`, and `locator.click()` still passed (it only checks
  elementFromPoint within the element's own box? No — it skips the fixed-clip
  check). To pin "cannot be clicked" you must use `page.mouse.click(coordinates)`
  + a consequence assertion (the active switch), or `elementFromPoint` at the
  last row's center (before the fix = null, the row is outside the viewport).
  The e2e surface follows the same rule: the new spec's clicks carry
  `force: true` with the reason written in a comment, and the geometric
  criterion goes through boundingClientRect separately.
- **`--available-height` is only injected by the Base UI Positioner**: only
  `dropdown-menu.tsx` / `select.tsx` consume it inside a Positioner; on a plain
  absolutely-positioned div `getComputedStyle().getPropertyValue('--available-height')`
  is permanently empty — the "registry default is canonical" capped form must
  not be copied to containers outside a Positioner; probe N13/O12 pins this
  measurement into the evidence.
- **The strongest evidence that a short-list surface is unchanged is
  byte-identical screenshots** (`cmp` the two surfaces' `01-short-list.png`,
  identical sha) — this supplements the geometric assertions (68px/262px) and
  rules out even anti-aliasing differences.
