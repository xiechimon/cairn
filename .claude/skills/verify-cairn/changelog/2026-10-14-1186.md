# 2026-10-14 — #1186 machine assertions for the skill-injection three preconditions

New custom probe `scripts/drive-1186-skill-injection.mjs` (live stack + stub
LLM + real daemon). Two agents: an allowlist `["demo-skill"]` task names that
skill but the stub does not read SKILL.md; an allowlist `[]` task of the same

claim-time hits, and there was no `skill_injection_check` (before 5/5). After
the fix both steps are still `done`, the open surface yellow
`injected-unread`, the closed surface red `allowlist-closed` (after 6/6).
Evidence `docs/verify/1186/`.

## Measured pitfalls

- The server runs under tsx with no watch. After changing code you must cleanup
  and relaunch, otherwise the probe hits the old process.
- When the stub does not write a README, the artifact gate beats the step to
  failed. This probe appends one line with bash, the terminal word is `done`.
  The assertion is a side-channel write, both failed and done land a check row.
- `message.content` is drizzle json. Check rows persist as JSON strings, the
  sqlite read needs two parses to get the object.
- The daemon spawned by the probe can be re-parented to pid 1 by pnpm, and
  `stub.close()` waits on its keep-alive. The script calls `process.exit` after
  teardown.
