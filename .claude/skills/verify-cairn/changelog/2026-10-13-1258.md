## New measured pitfalls

- **Agent creation must carry machineId (since #1259)**: the probe's seed order
  changes from "provider -> agent -> key -> enroll" to "provider -> key ->
  enroll -> agent" — createAgentBodySchema's machineId is a required recordId,
  the server validates that the machine is in the team and the runtime matches;
  reusing the old 702/903-era probe seed order 400s with
  `invalid body at machineId`. The enroll response is already the machine.json
  shape, the id is directly usable.
- **The done(failed) error text must avoid the quota-bucket wording**:
  classifyStepFailure hitting quota (402 / usage limit / quota / credits /
  rate limit etc.) takes the #1257 hang leg — the step is not judged dead, the
  todo does not land failed, the probe stalls at the phase assertion.
  Stack/git-error-style wording lands in the other bucket, the failure funnel
  works normally.
- **The failure row's title = errorMessage in full** (multiple lines enter the
  DOM as-is, rendered with line folds visually becoming spaces): row-level
  assertions must not be written against the "first line" — textContent
  byte-equal to the full text is the correct criterion for "the row title
  carries the full text".
