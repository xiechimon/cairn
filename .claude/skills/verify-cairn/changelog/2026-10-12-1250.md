## New measured pitfalls

- **run_builds dispatches and immediately watches -> chief gate rounds can cut
  in line**: any phase change (build done entering review, a child card done)
  enqueues a gate chief step, and the fake machine's linear claim takes the gate
  round as the target step (symptom: the claim payload's agent block = the
  chief-bound Agent instead of the persona). Fix = a claimUntil(kind) loop —
  when a gate round is taken mid-way, close it with an empty round done success
  and claim again.
- **The worker step's material carrier is the claim payload `instruction`**:
  stepRecordSchema's step body carries no prompt (machines.ts concatenates
  stepRow.prompt into the instruction for delivery) — assertions on the review
  meta header / verify material must hit either the DB step row's prompt column
  or the claim's instruction; hitting step.prompt is permanently undefined.
- **A review step's agentId exists only in the prompt meta header**: the step
  table has no agentId column (agent resolution is the claim surface's
  agentForStep business, landing in the claim payload's agent block); fan-out
  assertions use the meta first-line JSON, do not compare against a nonexistent
  step agentId column.
- **message.content's double-wrapped JSON**: the new form of the #902 pitfall —
  when insertMessageRow stores `JSON.stringify(obj)` the drizzle json column
  wraps it in another layer of quotes, read raw it is "a JSON string of a JSON
  string", one JSON.parse yields a string starting with '{' that needs a second
  parse; a plain-text announcement line (`发起了拆解`) terminates after one
  parse — judge `startsWith('{')` and parse twice.
- **run_builds originally persisted only the plan/build two slots**: the
  assignment four-slot extension changed the shared assignmentSchema and the
  REST surface, but the chief relay path's parameter mapping
  (services/chief-tools.ts) was still handwritten with two slots — four-slot
  assignments were silently dropped from review/verify, symptom = the verify
  step never enqueued. This ticket completes it (vocabulary def + persistence
  mapping synced).
- **DONE_ANNOUNCEMENT's value is `标记为已完成`**: not `🎉 任务已完成` (the
  latter is the merge step done's celebrate line, an inline string that does
  not go through the constant). settleSplitOnDone goes through
  insertGateAnnouncement -> content column and actor column separate, the DB
  assertion compares content === `标记为已完成` and actor === 'Chief'.
