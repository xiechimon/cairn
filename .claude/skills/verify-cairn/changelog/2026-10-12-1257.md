## New measured pitfalls

- **launch.mjs's portFree false-positives on macOS**: a fetch probe to 8801
  gets a timeout (not ECONNREFUSED) and judges "occupied", while
  `nc -z`/`net.createConnection` prove nobody listens — do not fight for the
  original port, per the brief "on collision bump the port and report" switch
  ports (this ticket 8801 -> 8802).
- **Custom probes' jfetch semantics differ from drive-1025's**: 1025's jfetch
  wraps the third argument as `{ body }`; when writing your own probe pass the
  bare body directly — wrapping the wrong layer makes the server report
  `providerId expected string, received undefined`, and the error surfaces at
  provider create (the earliest POST), not obviously a wrapping problem.
- **A probe script's indentation changes after one biome --write**: a
  python whole-block replace's old string must match the file's then-current
  indentation or it silently does not match (zero feedback without an assert) —
  grep -n the actual shape on the spot before editing.
- **A stub that always answers toolcall = an infinite tool loop**: pi sends each
  tool result back, the stub emits another toolcall... daemon.log fills with
  usage lines at several per second (measured 497 lines and still going). The
  stub must alternate by turn: the first real answer gives the plan.md-writing
  toolcall, everything after is plain text closing the round (same rule as
  drive-1025's responses array — forgotten when writing the single server
  yourself).
