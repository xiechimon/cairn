## Measured pitfalls

- `waitForSelector` is not strict but **waits only for the first DOM match** — with a
  root-level resident hidden dialog around, any bare `[role="dialog"]` visibility wait
  false-reds; new probes write dialog assertions with content scoping or incremental
  counting, always.
- Attribute a probe's red state before fixing: this round's 7 reds = 6 drifts (the
  #1108 gate cascading 5 items + the chief window 1 item) + 1 intentionally removed
  old behavior (the resident sub-line); the attribution rests on the FAIL-detail
  measured counts in result.json (switch=1 button=1) + screenshots (the dialog
  really open in 06-final), not on guessing.
