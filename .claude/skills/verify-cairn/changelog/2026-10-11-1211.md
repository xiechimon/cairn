# 2026-10-11 · #1211 local landing no longer touches the user's main checkout

Build landing semantics change for local-repo projects: the merge step's
`git merge --ff-only` in the user's repo directory is deleted (the old
`landLocalFastForward`/`mergeFfOnly`, along with the shared `WorktreeOps` slot);
landing = pushing the conv branch back to the user repo's refs/heads — the
user's main checkout's branches/reflog/worktree are never touched by pacman,
merging into the default branch is left for the user to take (the user repo
only gains `pacman/`-prefixed branches).

**Feature-map surface change**: the `ff-only-landing` entry in
`local-daemon-executor.md` becomes `branch-landing` (criterion = the conv
branch tip = the merge checkpoint + the user's main HEAD/reflog/status
unchanged before/after) ; the Gotchas become "the user repo's delivery surface
only has refs/heads/pacman/ branches, a dirty worktree does not affect any
step's close"; the README.md index row synced.

**Test-surface change**: `integration/test/g2t2-local-lifecycle.test.ts`
failure modes 3/4 rewritten (zero change to the main checkout after merge; the
dirty-worktree variant flips from "step failed carrying git's refusal text" to
"step closes done as usual and the user's dirty file is intact");
`apps/daemon/test/runner-local.test.ts` failure modes 1/2/4/7/8 flipped + a new
real-git full-chain case (real WorkspaceManager + real user repo, verifying the
reflog byte-for-byte unchanged); `local-executor.test.ts`'s landing surface
becomes the push contract.

**Measured evidence**: `docs/verify/1211/` (before-red 3 failures = the old
code fast-forwarding the user's main, proven; after all green). spec 12's
landing clause, premortem and test decisions rewritten in sync.

**Measured pitfalls**: git push to a non-bare user repo only writes
`refs/heads/pacman/conv-<id>` and does not touch the user reflog (main's reflog
byte-for-byte unchanged can serve as the #1211 criterion); `git reflog main`
already has seed rows on a fresh repo, a before/after snapshot comparison
suffices, no counting assumption needed.
