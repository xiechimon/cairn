# 2026-10-10 — #1166 drive.mjs api-key/search probes migrate to semantic carriers

## skill

The api-key and search probe paths in `scripts/drive.mjs` migrate to the spec 22 §5
semantic carriers (the debt left after the #950/#910 class-name retirement, ticket
#1166):

- **api-key**: empty state `.keys-empty` -> `getByTestId('keys-empty')`; the create
  button -> the empty-state-scope `getByRole('button', { name: '新建密钥' })`; the
  dialog `.apikey-form-create` -> `getByRole('dialog', { name: '新建密钥' })` scope
  with `getByRole('button', { name: '创建' })`; the one-time plaintext
  `.keys-once-value` -> the `<code>` semantic element (hasText `pacman_`); the masked
  row `.keys-row` -> `[data-slot="card"]` filtered by "text contains pacman_ and has
  no code descendant".
- **search**: panel `.search-panel` -> `getByRole('dialog', { name: '搜索' })`;
  input `.search-input-row input` -> the panel-scope `getByRole('textbox')`;
  result row `.search-row--todo` -> panel-scope `[data-row-kind="todo"]`
  (same rule as the e2e `search-focus.spec.ts`).

## New measured pitfalls

- **The plaintext entry also renders a list-row card**: the api-keys page feeds the
  runtime `plaintext` entry (id `once`) into the list `keys.map` too, so the total
  card count in the once state = 3 (one-time block Card + real masked-row Card +
  once empty-row Card). Masked-row discrimination = "text contains `pacman_` and
  has no `<code>` descendant" — `hasNotText('仅显示一次')` was measured not to
  exclude it while the one-time block is present (root cause not fully
  investigated), a pure card-count `>= 1` criterion misses it; `hasNot:
  locator('code')` is the stable one.
- **Take red-half evidence before the change**: the failure shapes of the #1166 two
  probes (15s timeout / six ⌘K presses do not open) match the ticket surface
  exactly — one run before the change gives the red half immediately, re-run on the
  same stack after the change gives the green half.
