# 2026-10-12 · #1261 relay quota-empty / rate-limit explicit feedback

New custom probe `scripts/drive-1261-quota-wait.mjs` (stub relay mode-gated
(429 + Retry-After <-> 200 SSE) + real daemon + Playwright dual surfaces):
the dry-leg — two tasks on the same relay get 429 -> the daemon circuit-breaks
(breaker line x2, auto_retry=0, storm=0) -> steps hang at `waiting_quota`
(todo not judged dead, build.errorMessage empty, quotaBlock.retryAfterMs =
5000 taken from the Retry-After header) -> board banner (SSE live-push,
create-task -> banner in 6-20s, acceptance line 3min) + two cards' `等额度`
chips + detail-header chip/progress row + one quota_wait notification per
task; the recovery leg — the stub flips to 200 -> probeAt expiry sweep
releases -> wake -> re-claim continues the session to completion -> both steps
done + todo enters review + the banner exits (flip -> done in 10-14s, zero
manual action). 14/14 x 2 runs (live-run1/ live-run2/), evidence
`docs/verify/1261/`.

Measured pitfalls (whoever writes the next probe, do not step on these again):

- **The stub's ok turn must answer by the last message's role in the request
  body** (`tool` -> plain text to close, otherwise -> a write-class tool call):
  answering by request-sequence parity crosses sessions when two tasks resume
  concurrently (B gets a plain-text turn -> zero change judged dead by the
  artifact gate, reproduced in the first real run).
- **The waiting-for-quota row's label priority must rank above the active
  phase**: during the hang the act is a stale signal from before the dry-out,
  `正在连接模型` lies across the whole silent period (reproduced in both runs
  in both shapes — a race-y red, do not dismiss it as a flake); signalAt/skills
  disclosure follow the same rule and go silent with the hang row.
- **Filter notification-row assertions by this round's todoId**: the isolated
  stack's DB accumulates across probe runs, a global count pulls in the
  previous round's rows (a 3 != 2 false red).
- **The HTTP Retry-After header is bare seconds**: `parseRetryAfterMs`'s
  vocabulary wants the "retry-after" keyword in the text — when consuming the
  header value, concatenate it back into the header shape before parsing,
  otherwise quotaBlock.retryAfterMs is permanently absent.
