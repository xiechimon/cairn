新增的三条判别规则（已写进 chief.ts 的工作约定）

· 交付物优先于路径：归属看交付物，不看请求里出现的路径或技术词——要更新的是 README 就归文档职责，哪怕那个 README 躺在 apps/web 下。
· 主任务定归属：一句请求含多个子项时按主任务定归属，不拆成多个 todo，次任务随主任务交给同一个 Agent。
· 症状按改动范围定：同一个用户可见症状可能归不同职责，看要改的代码在哪——接口返回错归后端，界面上点不到归前端。

之所以必须先补规则：难例之所以难，通常是因为落在类别边界上；边界上若无明文判据，两个专家会给出不同答案，评测就变成测歧义而不是测能力。

场景团队编制

阿岚 doc · qwen3.8-max
负责 README、用户手册、教程、变更日志、发布说明等面向读者的文档产出。交付物是文档内容本身，不修改业务代码。
老周 code · glm-5.3
负责后端功能实现、缺陷修复、重构与性能优化。改动范围是 apps/server、apps/daemon 与 packages；不处理界面样式。
小柯 frontend · kimi-k3
负责 Web 界面的布局、样式、交互与前端组件，改动范围是 apps/web。不处理后端接口与数据结构。
铁手 ops · glm-5.3
负责 CI 流水线、构建与打包脚本、依赖升级、部署配置与本地开发环境。不实现业务功能。
