Cairn brings no model of its own and resells no compute. Threads and the Coordinator run on a model source you already have. Pick whichever you have; one is enough to start.

| You have | Where it goes |
|---|---|
| Claude Code, signed in | On a Runner. Cairn picks it up by itself. |
| Codex CLI, signed in | On a Runner. Cairn picks it up by itself. |
| A Claude subscription token | `Settings` → `Model routing` → `Add provider` → `Claude` |
| An API key from a provider | `Settings` → `Model routing` → `Add provider` → the provider |
| Any OpenAI- or Anthropic-compatible endpoint | `Settings` → `Model routing` → `Add provider` → `Custom endpoint` |

<Tabs syncKey="model-source">
<TabItem label="Claude Code">

Install [Claude Code](https://claude.com/product/claude-code) on the Runner machine and sign in there with `claude`, as the same user that runs `cairn`. The Runner reports it to the server; it appears under `Model routing` as `Claude Code` on that Runner, with a status such as `Signed in`.

Its models come from the slots in that machine's `~/.claude/settings.json` (`env.ANTHROPIC_*_MODEL`). While a Runner with Claude Code is online, new work defaults to Claude Code.

</TabItem>
<TabItem label="Codex">

Install the [Codex CLI](https://github.com/openai/codex) on the Runner machine and run `codex login` as the same user that runs `cairn`. The Runner reports the login (it reads `~/.codex/auth.json`, or `$CODEX_HOME/auth.json`). When no Runner has Claude Code, work defaults to Codex.

</TabItem>
<TabItem label="Claude token">

On any machine where Claude Code is signed in, run:

```sh
claude setup-token
```

Then in Cairn open `Settings` → `Model routing` → `Add provider`, pick `Claude` under `Subscription sign-in`, and paste the token. You can also enter the date it expires.

</TabItem>
<TabItem label="API key">

Open `Settings` → `Model routing` → `Add provider`. The list is grouped into model vendors (Anthropic, OpenAI, Google, xAI, DeepSeek, Mistral, Moonshot, Kimi For Coding, MiniMax, Qwen, Z.ai and more), cloud platforms (Amazon Bedrock, Google Vertex AI, Cloudflare Workers AI), inference platforms (Groq, Cerebras, Fireworks, Together and more) and gateways (OpenRouter, Vercel AI Gateway, Cloudflare AI Gateway, OpenCode). Pick one and paste the key. xAI also offers a `Sign in with SuperGrok or X Premium` button.

The key is stored encrypted on your server and cannot be viewed again after saving. `Test connection` sends one minimal request without showing the key.

</TabItem>
<TabItem label="Custom endpoint">

For a relay, a self-hosted model or anything not in the list, pick `Custom endpoint` under `Other` and fill in:

- **Name**;
- **API key**: leave it empty for a gateway with no key;
- under `Connection`: **Provider ID** (for example `my-relay`), **Base URL** (for example `https://api.example.com/v1`), **API protocol** (`OpenAI Completions`, `OpenAI Responses` or `Anthropic Messages`), and whether to send the key as an `Authorization: Bearer` header (on by default);
- **Models (optional)**: `Add model`, then type a model id.

Save, open the provider and press `Test` next to `Test connection` to check it.

</TabItem>
</Tabs>

<Aside type="note" title="Not available yet">
The provider list also shows OpenAI Codex sign-in, marked `Not yet available`; use the Codex CLI on a Runner instead. GitHub Copilot sign-in works only when the server is started with your own GitHub OAuth App (`CAIRN_GITHUB_OAUTH_CLIENT_ID` and `CAIRN_GITHUB_OAUTH_CLIENT_SECRET`). Gemini CLI appears on a Runner but is locked until it goes through the command gate.
</Aside>

## Which model the Coordinator uses

You do not have to set a model for the Coordinator. Without a rule of its own it uses a default: the team's Anthropic API key if there is one, otherwise the first provider you added that it can run on, such as one with an API key. `Settings` → `Rules & policies` shows the default on the `Coordinator` card, for example `Current default: {model} · {provider} (the first provider you added that the Coordinator can use)`.

To use a different model, create a rule on that card:

1. `Runtime`: `Built-in (pi)`, which runs your providers' models;
2. `Model`: one of the models you added;
3. press `Create`.

If the card says `No default yet: add a provider with an API key, or create the rule here`, the Coordinator has nothing to run on, for example when your only model source is Claude Code on a Runner. Only then does the home page show a third setup step, `Open work routing`, which leads to this card.

The `Session` card on the same page shows which default new work uses and why, for example `Current default: Claude Code (a Runner has Claude Code installed)`.

## Where credentials live

- Provider keys and tokens you add in the web app are encrypted on the server under `~/.cairn/server/`. Back up the whole `~/.cairn` directory; the database is useless without `secretbox.key`.
- Claude Code and Codex sign-ins stay in those tools' own files on the machine where you signed in.
