Before you start, [connect a model](/docs/models/), review the Coordinator model in **Confirm settings** (tasks default to it), then click **Confirm and start chatting**. A fresh ChatGPT-only setup uses GPT-6.1 Sol, with pi running tasks. You also need [a Runner](/docs/runner/) online. Desktop starts that Runner for you; npm does not.

This walk uses a local repository and goes from a request to a finished task, in a few minutes.

## 1. Create a project

Use a small existing Git repository, or create a throwaway one on the Runner machine:

```sh
mkdir -p "$HOME/cairn-first-task"
git -C "$HOME/cairn-first-task" init
printf '# First task\n' > "$HOME/cairn-first-task/README.md"
git -C "$HOME/cairn-first-task" add README.md
git -C "$HOME/cairn-first-task" -c user.name='Cairn demo' -c user.email=demo@localhost commit -m 'Initialize demo'
```

The identity applies only to this initialization command, not your global Git configuration. Cairn supplies its task commit identity to subsequent agent commands. Use a new directory, not a repository with existing work.

A project is one code repository. Click `New project` in the sidebar and fill in:

- **Project name**, for example `My App`;
- **Repo** → `Select repo`, one of two:
  - `GitHub repo`: authenticate GitHub, or type `owner/repo`. Progress lives on GitHub, so any Runner can pick the work up.
  - `Local folder`: the absolute path of a git repository on the Runner's machine, or `Browse`. Only that Runner can run it, and if the machine is lost, progress goes with it.

Click `Create project`. The project appears under the Coordinator in the sidebar, and the conversation moves into it.

<Aside type="tip">
For the first run, use a small repository or a throwaway copy, and see how the agent changes things before you point it at one that matters.
</Aside>

## 2. Say one thing

Type what you want in one sentence, for example:

```text
Change the title in the README to Hello. Do not push or merge.
```

The Coordinator opens a task, and its reply shows the task title with its state. The `Tasks` panel at the top right lists it too; click it to open the task and see what the thread is doing.

## 3. Watch it work

The task starts `Queued` until a Runner claims it, then runs in that Runner's own git worktree. Open the task to see which files it read, what it changed, which commands it ran and how long each step took.

While it runs, the thread may stop to ask you something:

- `Needs input`: it is missing information, or a decision is yours. Answer in `Reply to this task` at the bottom of the task, and it carries on.
- *Needs your decision* at the end of a report: at most three items, each with options and a recommendation.

<Aside type="caution" title="Stuck in Queued">
If the task stays `Queued`, check the reason shown next to it and inspect **Settings → Runners** to confirm an eligible Runner is online. For a local-folder project, the bound Runner must be online; for an optional runtime such as Claude Code, confirm that runtime is installed on the Runner and check `cairn logs -f`.
</Aside>

## 4. When it is done

When the work succeeds, the task turns `Done`. The thread commits on its own branch and never edits your main branch directly.

- To ask for more: say so in `Reply to this task`.
- To merge: say so in the conversation.
