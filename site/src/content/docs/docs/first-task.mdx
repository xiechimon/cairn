Before you start, the setup hint under the home page's message box should be gone, which means setup is done: you [connected a model](/docs/models/) and [a Runner](/docs/runner/), and the Coordinator has a model to use, by default the first provider you added. If the hint is still there, click it and it takes you to the missing step.

This walk uses a local repository and goes from a request to a change waiting for your review, in a few minutes.

## 1. Create a project

A project is one code repository. Click `New project` in the sidebar and fill in:

- **Project name**, for example `My App`;
- **Repo** → `Select repo`, one of two:
  - `GitHub repo`: authenticate GitHub, or type `owner/repo`. Progress lives on GitHub, so any Runner can pick the work up.
  - `Local folder`: the absolute path of a git repository on the Runner's machine, or `Browse`. Only that Runner can run it, and if the machine is lost, progress goes with it.

Click `Create project`. The project appears under the Coordinator in the sidebar, and the conversation moves into it.

<Aside type="tip">
For the first run, use a small repository or a throwaway copy, and see how the agent changes things before you point it at one that matters.
</Aside>

## 2. Say one thing

Type what you want in one sentence, for example:

```text
Change the title in the README to Hello
```

The Coordinator opens a task, and its reply shows the task title with its state. The `Tasks` panel at the top right lists it too; click it to open the task and see what the thread is doing.

## 3. Watch it work

The task starts `Queued` until a Runner claims it, then runs in that Runner's own git worktree. Open the task to see which files it read, what it changed, which commands it ran and how long each step took.

While it runs, the thread may stop to ask you something:

- `Needs input`: it is missing information, or a decision is yours. Answer in `Reply to this task` at the bottom of the task, and it carries on.
- *Needs your decision* at the end of a report: at most three items, each with options and a recommendation.

<Aside type="caution" title="Stuck in Queued">
If the task stays `Queued` with a note that the task sandbox is not ready, that Linux Runner is not its own systemd user unit, or bubblewrap (`bwrap`) is not installed. Fix that, then run `cairn restart` on the machine; see [Keep it running on Linux](/docs/runner/#keep-it-running-on-linux).
</Aside>

## 4. Review the change

When the work is done, the task turns `Ready for review`. The task shows a card such as `Changed 1 file`; open it to read the diff. The thread commits on its own branch and never edits your main branch directly.

- To ask for more: say so in `Reply to this task`.
- When you are happy: choose `Complete` in the task's `…` menu.

A merge goes through the merge gate first, which counts only review verdicts bound to the current patch. Anything that cannot be undone waits for your yes.
