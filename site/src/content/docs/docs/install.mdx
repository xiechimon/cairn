The desktop app is the recommended starting point: it bundles the web app, Coordinator, SQLite database, and local pi Runner with owner sign-in built in, and ships for macOS, Windows x64 and Linux x64. Running a standalone server with `npx @xiechimon/cairn` or Docker on a headless host is the advanced path once you want to separate the server or attach extra machines.

## Desktop app (recommended)

On macOS, download the appropriate DMG from the [latest release](https://github.com/xiechimon/cairn/releases/latest): arm64 for Apple silicon, x64 for Intel. Drag Cairn to Applications and open it. It is not notarized: if macOS blocks it, use System Settings → Privacy & Security → Open Anyway (on macOS 14 and earlier, right-click the app and choose Open). The app starts its server and pi Runner and signs you in as the owner. Node.js, a separate pi installation and the Codex CLI are not required. Continue with [Connect a model](/docs/models/).

On **Windows x64**, download the `-win-x64.exe` installer or ZIP from the same release and run it. It starts its own server and Runner, signs you in as the owner, and updates itself in place.

On **Linux x64**, download the `-linux-x64.tar.gz` portable archive from the same release and extract it, or follow the [desktop build and extraction commands](https://github.com/xiechimon/cairn/blob/main/apps/desktop/README.md#linux-x64-archive) to build it. There is no Linux automatic update. It requires a graphical Linux session and Git. It starts its own server and Runner; quit the app to stop them. For a headless Linux server, use npm below.

## Advanced: self-hosted server requirements

- **Node.js 22.19+ on the 22 or 24 LTS line, and Git.** These LTS lines ship prebuilt `better-sqlite3` binaries; other versions may fall back to compiling from source and need a build toolchain.
- Linux or macOS for the server. Windows needs the pairing step below.

## Advanced: start the standalone server

<Steps>

1. Run Cairn with one command:

   ```sh
   npx @xiechimon/cairn
   ```

   It downloads Cairn and serves it on loopback. It prints no URL; the address is below. The first boot creates the database under `~/.cairn`, runs migrations and seeds a default team. To use another port: `PORT=9000 npx @xiechimon/cairn`; Runners then need `--server http://127.0.0.1:9000`.

2. Open **[http://127.0.0.1:8787/app](http://127.0.0.1:8787/app)** in a browser on the same machine.

3. Sign in the browser:

   <Tabs syncKey="os">
   <TabItem label="Linux">
   A browser on the server's own machine is signed in automatically through a loopback session. There is nothing to paste.
   </TabItem>
   <TabItem label="macOS / Windows">
   These systems have no loopback peer proof, so the first browser session uses a pairing code minted with the owner token. The first start writes that token to `~/.cairn/token` (mode 0600):

   ```sh
   curl -s -X POST -H "Authorization: Bearer $(cat ~/.cairn/token)" \
     http://127.0.0.1:8787/api/remote/pairing
   ```

   Open the returned code on the browser's pairing page.
   </TabItem>
   </Tabs>

</Steps>

The interface follows your browser's language. The first-run wizard shows **Connect models**, then **Confirm settings** for Coordinator (tasks default to the Coordinator model). Follow [Connect a model](/docs/models/), then confirm the selection. A separate npm install also needs [a Runner](/docs/runner/) online.

On macOS and Windows the paired npm browser is not an owner session: it cannot yet add model connections or approve Runners. Use the owner-token API as described in [getting started](https://github.com/xiechimon/cairn/blob/main/docs/getting-started.md#run-the-server), or use the desktop app for owner access. Do not interpret browser pairing as completion of model setup.

<Aside type="caution">
The server listens on `127.0.0.1` only and always requires a token for non-browser clients. Do not bind it to a public address without a token; see [Run it in Docker](#run-it-in-docker) and [Reach it from your phone](#reach-it-from-your-phone).
</Aside>

## Where your data lives

For npm, everything is under `~/.cairn` (set `CAIRN_HOME` to move it): the server keeps `server/server.db` and `server/secretbox.key`; a Runner keeps `machine.json`, `daemon.log` and `workspaces/`. Desktop uses `~/Library/Application Support/@cairn/desktop` on macOS and `$XDG_CONFIG_HOME/@cairn/desktop` (normally `~/.config/@cairn/desktop`) on Linux. **To back up, copy the whole data directory.** The database is useless without the key file, because secrets are stored encrypted.

## Run it in Docker

Only the server and web app are containerized; agents still run through a Runner on your own machines. The image binds `0.0.0.0`, keeps all state under `/data` and refuses to start without a token:

```sh
docker build -t cairn .
docker run -d --name cairn -v cairn-data:/data \
  -e CAIRN_TOKEN="$(openssl rand -hex 32)" -p 8787:8787 cairn
```

Build from a checkout of the [repository](https://github.com/xiechimon/cairn). Terminate TLS in front of the container, since the token travels in a header. Back up the whole `/data` volume.

## Reach it from your phone

Put [Tailscale Serve](https://github.com/xiechimon/cairn/blob/main/docs/deploy/tailscale-mobile.md) in front of the loopback server. It makes Cairn reachable on your private tailnet without a public address; each new device still signs in with a one-time pairing code from `Remote access` in settings. HTTPS through Serve also lets iOS add Cairn to the home screen and receive push.

## Build from source

Requires Node.js 22.19 or later and pnpm (for example through `corepack enable`):

```sh
git clone https://github.com/xiechimon/cairn
cd cairn
pnpm install --frozen-lockfile --ignore-scripts
pnpm start
```

`pnpm start` builds the web UI and starts the server hosting it on the same origin. Every server and Runner environment variable is listed in [configuration.md](https://github.com/xiechimon/cairn/blob/main/docs/configuration.md).
