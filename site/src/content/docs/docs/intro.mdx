Cairn is an open-source agent harness for your own machines: a desktop app for macOS, Windows x64 and Linux x64, with a self-hosted server path for extra machines. You tell one Coordinator what you want, in one conversation. It opens a thread for each piece of work, the thread runs on your own machine with your own model subscription, and it comes back to you only when a decision is yours. Over time it gets better at your work.

- **It remembers what you correct.** A correction worth keeping becomes memory, brought back when it matters; a failed run writes its lessons into the next attempt.
- **A repeated mistake becomes a check.** When the same mistake comes back, the agent points at the rule and offers to add a repository check as a task; it never installs one unasked.
- **Its changes are measured.** The eval suite's cases and scorers are a protected path read from the merge base, so an agent change cannot rewrite the exam it is judged by. Keeping a change only after it beats the current harness on that exam is being built.
- **Nothing irreversible without your yes.** Merging, sending, deleting and credential changes wait for you.

Cairn is for one person. You run your own copy; someone else who wants it runs theirs.

## The three pieces

| Piece | What it is | Where it runs |
|---|---|---|
| **Server** | The web app you open in a browser, the Coordinator and the database. One per person. | Any machine you browse from, or an always-on host. Data lives in `~/.cairn`. |
| **Runner** | The `cairn` daemon that claims work and runs threads, each in its own git worktree. | Every machine where agents should work. The server's machine can be a Runner too. |
| **Model source** | Your own subscription or API key: Claude Code, ChatGPT / Codex, or an API key from a provider. | Connect your ChatGPT subscription with Cairn's device login, or add a subscription token or API key under **Settings → Model**. ChatGPT/Codex tasks use bundled pi. Today Cairn resells no compute. |

You need all three before the Coordinator can answer. The pages below walk through them in order.

## What is planned, not shipped

- **Keep it only if it scores better.** A change to prompts, skills, routing or tool use is kept only when it beats the current harness on the protected eval exam, with guards for delivery and your interruptions. The memory, check proposals and retry lessons it builds on work today. Plan: `docs/design/harness-self-improve.md`.
- **Your own affairs.** Mail, calendar and job search as a project with no repository, where agents read, sort and draft, and sending and submitting wait for you. Not available yet.
- **Showcase recordings.** End-to-end recordings of real work, with the pull requests and numbers you can trace.

## It is not the right fit if you want

- a tool a team shares, with shared channels, roles and billing ([Amp Spaces](https://ampcode.com/docs/spaces) or [Multica](https://github.com/multica-ai/multica));
- only a better interface for driving Claude Code or Codex yourself ([T3 Code](https://github.com/pingdotgg/t3code));
- an assistant that lives in your chat apps ([OpenClaw](https://github.com/openclaw/openclaw) or [Hermes Agent](https://github.com/NousResearch/hermes-agent));
- today, a hosted service with nothing to install or keep running.
