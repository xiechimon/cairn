Cairn keeps your source code, API keys, and credentials strictly on your own hardware without passing through any Cairn-operated cloud server. When you install the Mac desktop app (or the advanced self-hosted server), SQLite storage stays on your disk, agents run inside local git worktrees on your machines, and model calls travel straight to the provider or custom endpoint you configured.

## What stays strictly on your hardware

- **Encrypted secrets (`secretbox.key`):** Model API keys, subscription tokens, team secrets, Vault entries, and integration credentials are sealed before storage in `server.db`.
- **Isolated per-agent config homes:** Cairn maintains its own managed agent directories separate from your personal `~/.claude` or `~/.gemini` logins.
- **macOS Seatbelt & Linux confinement:** Task harnesses run inside OS-level confinement rather than sharing unrestricted shell credentials across tasks, and team secrets are never exported into child shell environments.
- **Secret redaction in transcripts:** Before saving a step record to your own server, the Runner replaces token-like patterns (`sk-`, `token=`, bearer headers) with `[REDACTED]`.

## What leaves your machine (only when configured)

Nothing leaves automatically at rest. Outbound requests only go to services you explicitly enable:

1. Your chosen **model provider or custom endpoint** under **Settings -> Model**.
2. **GitHub** when you attach a GitHub repository (choosing **Local folder** keeps Git entirely local).
3. Optional integrations you configure (**MCP servers**, **Telegram / Slack / WeChat**, **Tailscale**, **Web Push / APNs**, or optional **OTLP/Langfuse** export via `CAIRN_OTEL_ENDPOINT`).
