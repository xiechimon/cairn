All Cairn project data, SQLite databases, git worktrees, and encrypted credentials stay on your own disks—never on a Cairn-hosted server. Model prompts and code snippets only travel directly from your Runner or server to the model provider or custom endpoint you explicitly configured.

## Exact storage paths by install method

| Install mode | Server DB & encryption key | Runner state & git worktrees |
|---|---|---|
| **Mac desktop app** | `~/Library/Application Support/@cairn/desktop/` (`server.db`, `secretbox.key`, `vapid.json`) | Bundled `runner/` inside `@cairn/desktop` (`machine.json`, `daemon.log`, `workspaces/`) |
| **Linux desktop archive** | `$XDG_CONFIG_HOME/@cairn/desktop/` (default `~/.config/@cairn/desktop/`) | Bundled `runner/` inside `@cairn/desktop` |
| **Advanced: npm server / CLI Runner** | `~/.cairn/server/` (`CAIRN_HOME` overrides) | `~/.cairn/` (`machine.json`, `daemon.log`, `workspaces/`) |
| **Advanced: Docker server** | `/data` volume (`CAIRN_HOME=/data`) | Separate Runner host `~/.cairn/` |

## How credentials and agent logs are protected

- **At-rest encryption:** Model API keys, subscription tokens, team secrets, Vault items, and integration credentials inside `server.db` are encrypted with `secretbox.key`. Always back up `secretbox.key` alongside `server.db` ([Backup guide](/guides/backup-and-migrate-cairn-data/)).
- **No plaintext shell leaks:** Team secrets are retrieved explicitly through Cairn's audited retrieval channel instead of being exported into every child shell environment.
- **Runner log redaction:** Before step transcripts are saved on your own server, the Runner scrubs token patterns (`sk-`, `token=`, bearer headers) with `[REDACTED]`, and skips upload if redaction cannot run.
- **Browser profile separation:** On macOS, the Coordinator's browser keeps its own isolated profile directories under `mac-browser/profiles/` rather than reading your personal Chrome profile.
