When Cairn logs `claude binary: not found` or **Settings -> Runners** lists Claude Code as unavailable, the Runner cannot find an executable `claude` binary on its daemon `PATH`. Install the Claude Code CLI on that machine (or expose its install folder via `PATH` / `CAIRN_CLAUDE_BIN`), then restart the Runner so capabilities refresh.

## Step-by-step fix

1. **Check if `claude` is installed in your shell:**
   ```sh
   command -v claude
   ```
   If nothing prints, install Claude Code on that host first.
2. **Fix non-interactive `PATH` mismatches:** Daemons launched from macOS Finder (`Cairn.app`) or Linux `systemd` do not always inherit shell additions in `.zshrc` or `.bashrc` (such as `~/.local/bin` or NVM paths). Either:
   - Symlink or install `claude` into a standard path like `/usr/local/bin` or `~/.local/bin`, or
   - Set `CAIRN_CLAUDE_BIN` to the exact binary path on CLI Runners, or ensure the systemd unit `Environment=PATH=...` includes the directory containing `claude`.
3. **Restart and verify:**
   - On Mac desktop: quit Cairn from the menu bar and reopen it, then check **Settings -> Runners**.
   - On a CLI Runner: run `cairn restart && cairn doctor` and check `cairn logs -f` for `claude binary: <path>`.

Remember that bundled **pi** runs ChatGPT and API-key tasks without `claude`; only Claude Code tasks require the `claude` CLI ([Claude token setup](/guides/setup-claude-code-subscription-token/)).
