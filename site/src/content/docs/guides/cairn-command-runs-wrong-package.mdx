If typing `cairn start` or `cairn doctor` launches the server or fails with unexpected server behavior, both `@xiechimon/cairn` (server) and `@xiechimon/cairn-cli` (Runner daemon) were installed globally on the same machine. Because both npm packages define a `cairn` binary, whichever package was installed last overwrote the `cairn` command on your `PATH`.

## How to resolve the binary collision

1. **Check which package currently owns `cairn`:**
   ```sh
   cairn version
   command -v cairn
   ```
2. **Use the clean split for npm setups:** Uninstall any global `@xiechimon/cairn` package and keep **only** the Runner CLI installed globally:
   ```sh
   npm uninstall -g @xiechimon/cairn
   npm install -g @xiechimon/cairn-cli@latest
   ```
   Run the standalone server via `npx @xiechimon/cairn` (or Docker) so it never claims the global `cairn` binary name.
3. **Or use the Mac desktop app:** On macOS, the desktop app bundles both the server and the Runner without requiring any global npm binaries. If you need CLI subcommands on the Mac app's bundled Runner, invoke `cli.mjs` inside `Cairn.app` directly rather than installing a second global `cairn-cli` ([Web tools guide](/guides/enable-scrapling-and-agent-reach-web-tools/)).
