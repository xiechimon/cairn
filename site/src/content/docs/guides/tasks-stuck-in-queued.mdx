When a Cairn task remains in `Queued` despite a Runner showing **Online**, Cairn cannot match the task's hard constraints to any available Runner. Read the exact reason badge displayed beside `Queued`, then check whether a local-folder project is pinned to another machine, an optional CLI runtime is missing, or the selected model provider is expired.

## Three most common causes and fixes

| Queue blocker | Why it happens | How to unblock |
|---|---|---|
| **Local-folder project bound to another machine** | `localPath` projects can only execute on the specific Runner holding that directory | Bring that Runner back online, or switch the project to a GitHub repo so any Runner can clone it |
| **Missing optional runtime (`claude`)** | Task targets Claude Code, but the online Runner does not detect `claude` on `PATH` | Install `claude` on that Runner, restart it, and verify in **Settings -> Runners** |
| **Missing or expired model credential** | Selected provider token under **Settings -> Model** expired or was removed | Re-verify or reconnect the provider under **Settings -> Model** |

## Inspect live Runner diagnostics

On any standalone CLI Runner, check readiness and live logs:

```sh
cairn status
cairn doctor
cairn logs -f
```

If you are using the Mac desktop app, open **Settings -> Runners** to verify that the bundled local Runner is online and lists the runtimes your task requires ([First task guide](/docs/first-task/)).
