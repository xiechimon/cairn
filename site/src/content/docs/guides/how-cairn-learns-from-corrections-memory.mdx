Cairn learns across three loops rather than treating every conversation as a blank slate: what you correct becomes persistent memory for future turns, repeated mistakes prompt the Coordinator to propose an automated check in your repo, and failed runs pass their failure lessons forward to retries.

## The three self-improvement loops

1. **Persistent Coordinator memory (`MEMORY.md`):** When you correct a convention or preference in conversation, the Coordinator saves an entry in memory that is automatically loaded into subsequent sessions. You can also inspect and edit memory entries directly inside the app.
2. **From repeated correction to repo check:** If you catch yourself correcting the same class of error more than once, Cairn proposes creating a task to encode that rule into your repository (such as a lint rule, test assertion, or CI check) so future agents cannot repeat it.
3. **Retry lesson handoff:** When a task build fails or stalls, Cairn preserves the structured failure context and trace so the next retry does not blindly repeat the identical broken command.

## Measured against a public eval suite

To verify that Coordinator behavior and coding runs actually get better rather than drifting, Cairn includes a public `eval/` suite in the repository combining Coordinator turn replays, real coding tasks, and canary checks.
