开始之前，首页输入框下面那条设置提示应该已经消失了，也就是设置都做完了：[接入了模型](/zh-cn/docs/models/)和[一台 Runner](/zh-cn/docs/runner/)，Coordinator 也有模型可用（默认是你最早添加的服务商）。提示还在的话，点它就会带你去缺的那一步。

下面用一个本地仓库，从提需求一路走到任务完成，大约几分钟。

## 1. 建一个项目

一个项目对应一个代码仓库。点侧栏的 `新建项目`，填：

- **项目名称**，比如 `My App`；
- **仓库** → `选择仓库`，二选一：
  - `GitHub 仓库`：先认证 GitHub，或手动输入 `owner/repo`。进度在 GitHub 上，任何一台 Runner 都能接着跑。
  - `本地文件夹`：填 Runner 那台机器上 git 仓库的绝对路径，或点 `浏览`。只有那台 Runner 能跑，它坏了进度也跟着没了。

点 `创建项目`。项目出现在侧栏的 Coordinator 下面，对话也切到这个项目里。

<Aside type="tip">
第一次先拿一个小仓库或者一次性的副本试，看清楚 agent 会怎么改，再放到重要的仓库上。
</Aside>

## 2. 说一件事

在输入框里用一句话说你要什么，比如：

```text
把 README 里的标题改成 Hello
```

Coordinator 会开一个任务，回复里显示任务标题，后面跟着它的状态。右上角的 `任务` 面板也会列出这个任务；点它打开任务，看 thread 在干什么。

## 3. 看它干活

任务先在 `排队中`，等一台 Runner 接手，然后在这台 Runner 自己的 git worktree 里跑。打开任务，可以看到它读了哪些文件、改了什么、跑了什么命令，以及每一步花了多久。

thread 跑的过程中可能会停下来问你：

- `待你回答`：它缺信息，或者有一件该你定的事。在任务底部的 `回复这个任务` 里回答，它会接着干。
- 报告最后的“需要你定的”：最多三条，每条带选项和推荐。

<Aside type="caution" title="一直在“排队中”">
任务停在 `排队中`，后面写着“任务沙箱没就绪”，说明那台 Linux Runner 不是独立的 systemd 用户单元，或者没装 bubblewrap（`bwrap`）。装好之后在那台机器上运行 `cairn restart`，见[在 Linux 上保持常驻](/zh-cn/docs/runner/#在-linux-上保持常驻)。
</Aside>

## 4. 做完之后

做成了，任务直接变成 `已完成`。thread 在自己的分支上提交，不会直接改你的主分支。

- 要它再改：在 `回复这个任务` 里说。
- 要合并：在对话里说。

## 接下来
